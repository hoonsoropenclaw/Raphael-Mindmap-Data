# Micro-Skill: Anti-Pattern and Panic Management

## Target Skill Name
anti_pattern_and_panic_management

## Target Summary
識別並解決常見的反模式，同時管理系統的恐慌反應，以確保系統的穩定性和響應性。

---

## 1. Anti-Pattern: Infinite Loop

### 1.1 說明
無限循環是一種常見的反模式，會導致程序進入無法終止的狀態，從而使系統掛起或無響應。這種情況通常發生在循環缺乏適當的終止條件或循環條件永遠為真的情況下。

### 1.2 關鍵代碼片段
```javascript
// 錯誤的無限循環範例
while (true) {
    // 無限循環
}
```

### 1.3 問題原因
- **缺乏終止條件**: 循環沒有設置任何條件來終止執行。
- **條件永遠為真**: 循環條件始終為真，導致循環無法停止。

### 1.4 解決方法
確保每個循環都有明確的終止條件，並在循環內部設置適當的跳出機制。例如，使用 `break` 語句在滿足特定條件時退出循環。

```javascript
// 正確的循環範例
while (condition) {
    // 執行操作
    if (exitCondition) {
        break;
    }
}
```

### 1.5 錯誤預防
- **審查循環條件**: 在編寫循環時，仔細檢查循環條件是否會在某些情況下變為假。
- **設置計數器或超時**: 為循環設置一個最大迭代次數或超時機制，以防止無限循環。

## 2. Anti-Pattern: Blocking I/O

### 2.1 說明
阻塞 I/O 操作是指在執行 I/O 操作時，程序會等待操作完成才能繼續執行其他任務。這在單線程環境中特別危險，因為它會阻塞事件循環，導致系統超時或無響應。

### 2.2 關鍵代碼片段
```javascript
// 錯誤的阻塞 I/O 操作範例
function fetchDataBlocking() {
    const data = fs.readFileSync('/path/to/large/file'); // 阻塞操作
    return data;
}
```

### 2.3 問題原因
- **單線程環境**: 在單線程環境中，阻塞操作會阻止其他任務的執行。
- **長時間運行的 I/O 操作**: 長時間運行的 I/O 操作會導致系統資源被佔用，從而影響系統的整體性能。

### 2.4 解決方法
使用非阻塞 I/O 操作，例如異步函數或流來處理大型文件或網絡請求。這樣可以確保 I/O 操作不會阻塞事件循環，從而保持系統的響應性。

```javascript
// 正確的非阻塞 I/O 操作範例
async function fetchDataNonBlocking() {
    const data = await fs.promises.readFile('/path/to/large/file');
    return data;
}
```

### 2.5 錯誤預防
- **優先使用異步方法**: 盡量使用異步方法來處理 I/O 操作，而不是同步方法。
- **使用流處理**: 對於大型數據處理，使用流（streams）來逐步處理數據，而不是一次性讀取整個文件。
- **錯誤處理**: 在異步操作中，確保適當處理錯誤，以防止未處理的異常導致程序崩潰。

## 3. Anti-Panic Protocol

### 3.1 說明
此技能確保在面對緊急或異常情況時，系統能夠保持冷靜並採取合理的行動，而不是陷入恐慌或做出不當決策。

### 3.2 關鍵代碼片段或模式
```python
def handle_emergency_situation(situation):
    if situation == "prompt_injection":
        # 採取防禦措施
        apply_defense_measures()
    elif situation == "timeout":
        # 調整策略以避免卡住
        adjust_strategy()
    else:
        # 記錄並報告
        log_and_report(situation)
```

### 3.3 常見錯誤及避免方法
- **錯誤**: 在緊急情況下做出過度反應。
  **解決方法**: 設定明確的應對流程，避免倉促決策。
- **錯誤**: 未能識別真正的緊急情況。
  **解決方法**: 結合多個指標進行判斷，並設置合理的閾值。

### 3.4 錯誤預防
- **設置應急響應機制**: 定義清晰的應急響應流程，確保在緊急情況下能夠迅速採取行動。
- **定期審查和更新應急策略**: 根據系統的變化和新的威脅情況，定期審查和更新應急策略。
- **模擬緊急情況**: 進行緊急情況模擬測試，以驗證應急響應機制的有效性。

---

## 總結
通過識別和修復無限循環和阻塞 I/O 操作，可以顯著提高程序的穩定性和系統的響應性。同時，實施有效的反恐慌協議可以確保系統在面對緊急情況時能夠保持冷靜並採取合理的行動。關鍵在於編寫具有明確終止條件的循環，優先使用非阻塞的 I/O 操作，並建立穩健的應急響應機制。
