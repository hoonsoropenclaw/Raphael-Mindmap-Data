+# RBAC Flow · Dynamic Permission Designer
+
+Interactive RBAC flow designer with React Flow (browser) + Node.js/Express (backend).
+
+## What's in here
+
+- **`index.html`** — single-file frontend. React 18 + React Flow 11 loaded via CDN.
+  The JSX is **pre-compiled** (no runtime Babel — babel-standalone 8 has bugs
+  with the UMD bundle path), so it works by opening the file directly.
+- **`server.js`** — Express backend on port 4000. Holds the RBAC store
+  (4 users / 5 roles / 8 permissions / 4 resources) and exposes:
+  - `GET  /api/health`
+  - `GET  /api/rbac/snapshot` — full RBAC state, used to seed the canvas
+  - `GET  /api/rbac/check?action=…&resource_type=…` — who can do what
+  - `GET  /api/rbac/user/:id/permissions` — drill-down for one user
+  - `POST /api/rbac/flow/evaluate` — **the main endpoint** — takes the
+    React Flow canvas (nodes + edges), walks the graph per user, and returns
+    effective permissions with which role granted them
+  - `POST /api/rbac/user/:id/role` — runtime mutation endpoint
+  - `GET  /api/rbac/log` — last 50 mutations
+
+## Running it
+
+```bash
+npm install
+node server.js          # backend on :4000
+# open index.html in any browser
+```
+
+The frontend lives at `index.html` — opening `file://…` directly works because
+React and React Flow are loaded from a CDN and there's no bundler step.
+
+## How the integration works
+
+1. Page loads → frontend fetches `/api/rbac/snapshot` and seeds the canvas with
+   one node per entity plus the user→role and role→permission edges from the
+   store.
+2. Operator drags nodes around, drags from palette to add new entities, drags
+   handles to connect them, or clicks a node to bind it to a real snapshot
+   reference via the sidebar picker.
+3. Every change to `nodes` or `edges` triggers a **debounced (350ms) POST** to
+   `/api/rbac/flow/evaluate`. The backend does a BFS per user node, attributes
+   each reachable permission to the roles actually visited (not roles owned by
+   other users), and returns the verdict.
+4. Sidebar re-renders with the live effective permissions. Each perm shows the
+   action, resource type, and the **via roles** that grant it.
+
+## Design choices
+
+- **Editorial brutalism**: dark canvas (#0a0b0e), monospace headers (JetBrains Mono
+  fallback chain), acid lime accent (#d4ff00), neon dots on each node type.
+  Avoids the purple/indigo SaaS gradient template.
+- **No runtime bundler**: JSX pre-compiled at write-time and inlined. Anyone can
+  open `index.html` from disk and it works.
+- **Backend stays authoritative**: the canvas is just a *view* of the RBAC
+  store. Permission evaluation always happens server-side so the same
+  algorithm runs in any frontend, test, or CLI consumer.
