+def read_cpu_times(proc_stat: Path = Path("/proc/stat")) -> tuple[int, int]:
+    fields = proc_stat.read_text(encoding="utf-8").splitlines()[0].split()
+    if not fields or fields[0] != "cpu" or len(fields) < 5:

+# Linux System Monitor
+
+零第三方依賴的 Linux 維運檢查器，監控 CPU、記憶體、磁碟、每核心負載及 systemd journal 錯誤。
+
+## 使用
+
+```bash
+chmod +x linux_monitor.py
+./linux_monitor.py --dry-run
+./linux_monitor.py --json
+```
+
+Exit codes：`0` 正常、`1` 有 WARNING、`2` 有 CRITICAL/指標不可用、`3` 設定或告警投遞失敗。
+
+## 設定
+
+編輯 `monitor_config.json`：
+
+- `thresholds`：各指標閾值；值等於閾值即告警。
+- `disk_paths`：可監控多個 mount point。
+- `journal.units`：空陣列代表所有 unit；可填 `ssh.service` 等。
+- `alerts.console`：stderr 告警。
+- `alerts.syslog`：送入本機 syslog。
+- `alerts.webhook_url`：非空時 POST JSON；建議由權限 `0600` 的獨立設定檔提供。
+- `alerts.cooldown_seconds`：同一指標的重複告警冷卻時間。
+
+## Cron 範例
+
+```cron
+*/5 * * * * cd /absolute/path/to/project && ./linux_monitor.py >> monitor.log 2>&1
+```
+
+腳本本身不修改 crontab。正式使用時，建議將工作目錄與設定檔設為只有服務帳號可讀，或以 systemd timer 搭配 `UMask=0077` 啟動。
+
+## 驗證
+

+python3 -m unittest -v
+python3 -m py_compile linux_monitor.py test_linux_monitor.py
+./linux_monitor.py --dry-run
+```

+# 實作思路與審查紀錄
+
+## 1. 架構
+
+採用「收集 → 評估 → 去重 → 投遞」四階段，使資源讀取、閾值規則和通知通道彼此可獨立測試：
+
+1. 收集器平行讀取 `/proc`、檔案系統及 `journalctl`。
+2. `Metric` 保留 value、threshold、available、source；不可用與真正的零值不混淆。
+3. 評估器將超標分成 WARNING / CRITICAL，收集失敗則為 ERROR。
+4. 冷卻狀態以 atomic replace 寫入 `0600` JSON，避免 cron 重複洗版與半寫檔。
+5. 投遞支援 stderr、syslog、HTTP webhook；任一投遞失敗都反映在 exit code 3。
+
+## 2. Senior Architect 回饋吸收
+
+- 安全檔案權限：啟動即 `os.umask(0o077)`，狀態檔明確 chmod 0600。
+- 並發驗證：I/O 型收集器用有限 ThreadPoolExecutor；單元測試驗證核心計算與狀態去重，實機 smoke test 驗證並發收集結果。
+- 底層正確性：CPU 使用兩次 `/proc/stat` 差分，不把 load average 誤當 CPU%；記憶體使用 `MemAvailable`；load 依 CPU 核心數正規化。
+
+## 3. 安全與可靠性
+
+- `journalctl` 使用 argv list、沒有 shell interpolation，並設 10 秒 timeout。
+- 設定檔有必填欄位、正數與磁碟路徑驗證。
+- webhook 有 timeout；回應非 2xx 視為失敗。
+- 無第三方 Python 套件，適合最小化 Linux 主機。
+- 腳本不自行更動 crontab / systemd，部署是明確的第二階段操作。
+
+## 4. 可測試性
+
+- `/proc` parser 可注入 Path。
+- CPU counters、sleep、journalctl 可 mock。
+- 冷卻時間接受明確的 `now`，避免測試依賴真實時鐘。
+- dry-run 不發通知、不寫 cooldown state，適合部署前驗證。
+
+## 5. Exit code 契約
+
+- 0：所有指標正常。
+- 1：至少一個 WARNING。
+- 2：至少一個 CRITICAL 或 ERROR。
+- 3：設定錯誤或通知投遞失敗。
+
+此契約讓 cron、systemd、Nagios/Icinga 或外層 watchdog 能直接判讀，不必解析自然語言。
