+        self._lock = Lock()

+        """Atomically consume one request slot for *key*."""
+        now = self._clock()
+        cutoff = now - self.window_seconds

+                    retry_after=retry_after,
+                )

+## 2. 技術選型決策
+
+### 2.1 同步 SQLAlchemy + 同步 endpoint（不是 async）
+
+理由（與 `references/by-category/fastapi-sync-vs-async-pattern-20260727.md` 結論一致）：
+
+- 5 個 endpoint 全是單步 I/O、沒有 fan-out 外部服務
+- SQLAlchemy 2.0 sync 在 5 個 endpoint 的工作負載下，async 帶來的 3 類 pitfall（stale read、async/sync deadlock、`expire_on_commit`）零效益
+- `def` + `Depends(get_db)` 比 `async def` + `AsyncSession` 心智成本低一截
+- 若未來真的要 async：把 `app/database.py` 換成 `create_async_engine + async_sessionmaker` 即可，其餘 middleware 與 endpoint 形狀不變
+
+### 2.2 自製滑動視窗 limiter，不用 slowapi
+
+- 任務只需要「per-client N 次/60s」這麼簡單的需求
+- slowapi 0.1.9 對 `from __future__ import annotations` 與 `inspect.signature()` 相容性差，會把 body 參數誤判為 query（過去 `learning_1785169806_4` 慘案）
+- 自製版本 < 50 行、可注入 clock 與 lock，測試可完全 deterministic
+- 換 Redis backend 只需要重寫 `app/rate_limit.py` 內的 deque 邏輯，interface 保持 `check(key) -> RateLimitDecision`
+
+### 2.3 應用層 HTTP middleware 套用 rate limit（不是 dependency）
+
+- 全域 /todos 路由（GET list / GET id / PATCH / DELETE）都要計數
+- middleware 一次套用，**未來新增 /todos 子路由不會忘記加 `Depends(rate_limit)`**
+- middleware 顯式 skip `/health`、`/docs`、`/redoc`、`/openapi.json`，避免 health probe 自我雷擊
+- middleware 注入的 headers（`RateLimit-Limit` / `RateLimit-Remaining` / `Retry-After`）跟 OAuth bearer token / CORS 邏輯完全正交，方便未來加 auth
+
+### 2.4 Pydantic v2 `extra="forbid"`
+
+- 拒絕未宣告欄位（`{"title": "x", "admin": true}` → 422），避免「打錯字就靜默丟棄」的失誤
+- 配合 `model_dump(exclude_unset=True)` 達到真正的 PATCH 語意（只送進來過的欄位才寫入）
+- PATCH 額外用 `model_validator` 拒絕「整包空 / 顯式送 null」
+
+### 2.5 App factory 模式 + 顯式注入
+
+- `create_app(database_url, rate_limiter, client_key)` 全部可注入
+- 測試每個 case 都建全新的 `SlidingWindowRateLimiter` 與全新 `tmp_path` 下的 SQLite，徹底避免「module-level singleton 跨測試污染」
+- 跟 4 個 5-20 個 commit 的舊成品比，本專案沒有 module-level `app` / `limiter` 狀態污染
