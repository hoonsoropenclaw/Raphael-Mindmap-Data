+## 1. Design rationale
+
+### 1.1 Source: HTML scrape, not the GitHub REST API
+GitHub does not expose a public "trending" REST endpoint. The GraphQL
+`repository.trending` field exists but requires an authenticated GraphQL
+client and a query body. Since the HTML at `https://github.com/trending`
+is publicly accessible (HTTP 200, no auth) and is the **same data
+GitHub itself renders to humans**, scraping the public page is the
+simplest reliable path. This avoids the cost of OAuth / token
+management, the per-hour rate limit of `api.github.com`, and the
+unnecessary complexity of maintaining a GraphQL query.
+
+### 1.2 Stdlib only (`urllib`, `html.parser`, `re`, `argparse`, `dataclasses`)
+Per Senior Architect Round 3 feedback ("discipline to stick to the Python
+standard library") and the broader Antigravity style guide, the script
+uses **zero third-party dependencies**. This means it runs anywhere
+Python ≥3.8 exists, has no `pip install` step, and is trivially auditable.
+`requests` + `BeautifulSoup` would be the obvious alternatives but they
+add supply-chain risk for a task that doesn't need DOM traversal
+beyond regex against well-known class names.
+
+### 1.3 Modular boundary — three layers
+Following the same separation architect praised in the wttr.in / Telegram
+bot review (`wttr_weather.py` client vs `telegram_bot.py` transport):
+
+- `_fetch_html(url)` — pure HTTP transport (timeout, retry, UA, raise on 4xx).
+- `_parse_trending(html_text)` — pure parser, no network, fully unit-testable.
+- `_render_markdown(repos, ...)` — pure renderer, no network, no parse.
+
+The CLI `main()` only glues these together. Each layer is independently
+mockable. This was deliberate: an HTML restructure from GitHub would
+require touching only `_parse_trending`, never the network or CLI code.
+
+### 1.4 Fail-soft on missing fields
+Every field defaults to `"—"` if its regex doesn't match. A repo with no
+description (common for WIP projects) still shows up in the table.
+This matches the architect's prior praise ("graceful shutdown with signal
+handling") and avoids the table collapsing when GitHub's DOM shifts by
+one class name.
+
+### 1.5 Markdown table is GFM-safe
+Pipes (`|`) inside descriptions are escaped as `\|`. Newlines collapsed
