+# Linux system monitor
+
+`linux_monitor.py` is a dependency-free Linux maintenance monitor for small servers and workstations.
+It is read-only with respect to the system: it reads `/proc`, filesystem usage, recent `journalctl`
+records, and optional traditional log files. It emits warnings to stderr when thresholds are crossed.
+
+## Checks
+
+- CPU usage, sampled from `/proc/stat`
+- Memory usage, using `MemAvailable` from `/proc/meminfo`
+- 1-minute load average
+- Disk usage for one or more mount points
+- Recent `warning..alert` journal records when `journalctl` is available
+- Optional tail scans of files such as `/var/log/syslog` and `/var/log/auth.log`
+
+Alerts are rate-limited by `(rule, severity)` and persisted atomically in a JSON state file. A JSON
+webhook can be enabled with `--webhook-url` or `LINUX_MONITOR_WEBHOOK`. The process handles SIGINT
+and SIGTERM cleanly, finishing the current check before stopping.
+
+## Requirements
+
+- Linux
+- Python 3.10+ (tested with Python 3.12)
+- No third-party Python packages
+- `journalctl` is optional; if absent or inaccessible, file checks still work
+
+## Run once
+
+```bash
+python3 linux_monitor.py --once --json --state-path /tmp/linux-monitor-state.json
+```
+
+Exit status is `0` when no threshold is crossed, `1` when findings exist, and `2` for an operational
+failure. The JSON output contains `snapshot`, all `findings`, and the number actually dispatched
+after cooldown suppression.
+
+## Watch continuously
+
+```bash
+python3 linux_monitor.py \
+  --interval 60 \
+  --mount / \
+  --mount /home \
+  --log-file /var/log/syslog \
+  --log-file /var/log/auth.log \
+  --state-path /var/lib/linux-monitor/state.json \
+  --webhook-url https://monitoring.example.invalid/hooks/linux
+```
+
+The process only needs permission to read the selected logs and write its state directory. It does
+not modify logs, restart services, or remediate the machine.
+
+## Threshold examples
+
+```bash
+python3 linux_monitor.py --once \
+  --cpu-warn 80 --cpu-crit 95 \
+  --memory-warn 80 --memory-crit 95 \
+  --disk-warn 80 --disk-crit 95 \
+  --log-warn 10 --log-crit 50
+```
+
+## systemd service example
+
+Copy the following to `/etc/systemd/system/linux-monitor.service`, adjusting paths and the state
+location for the deployment account:
+
+```ini

-- 同一 inode + `offset > size` → in-place truncate → 重置
-- inode 變了 → logrotated → 重置 + 從新檔讀
-
-**b) Cooldown 用 (rule, severity) 而非 (rule) 為 key**:
-- `cpu:warn` 跟 `cpu:crit` 應有獨立 cooldown(crit 不應該被 warn 抑制)
-- 但 `cpu:warn` 跟 `cpu:warn` 應該被壓制,避免風暴
-
-**c) Sliding window 用 list of timestamps 而非 counter**:
-- 實作簡單(`[t for t in hits if t >= now - 60]`)
-- 視覺化/debug 友善(可看命中分布)
-- 缺點:命中多時 list 變大(但 60s 內通常 < 100)
