+# React State Management Demo
+
+Minimal but complete React app that demonstrates **complex state management**:
+
+- `useReducer` (single source of truth for state transitions)
+- Context (cross-component dispatch without prop drilling)
+- Custom hooks (narrow selectors so each component only re-renders on its slice)
+- LocalStorage persistence (side-effects isolated in the Provider)
+- Pure reducer (zero React imports → trivially unit-testable)
+
+## Run
+
+```bash
+npm install
+npm run dev          # dev server on http://127.0.0.1:5173
+npm run build        # production bundle into dist/
+npm run preview      # serve dist/ on http://127.0.0.1:4173
+```
+
+## File layout
+
+```
+src/
+├── main.jsx                      # ReactDOM bootstrap
+├── App.jsx                       # Composition root (Provider + sections)
+├── hooks/
+│   └── useTodos.js               # Pure reducer + selectors + action types
+├── context/
+│   ├── TodoContext.js            # Context object + guard hook
+│   └── TodoProvider.jsx          # Provider, persistence, memoization
+├── components/

+└── styles/

+    └── App.css                   # Component-level styles

+## What this demonstrates
+
+1. **Reducer-only state transitions** — every change goes through `dispatch({ type, ... })`. The reducer is a pure function; no `setState` is scattered across components.
+2. **Narrow consumer hooks** — `useTodoStats` re-renders only when stats change, not when the input text changes. Demonstrates why splitting selectors matters at scale.
+3. **Persistence side-effect** — the Provider owns `localStorage`. Components know nothing about storage. Swapping to IndexedDB / a server later is a one-file change.
+4. **Defensive state** — empty/whitespace input doesn't crash; it lands as `lastError` in state. UI surfaces it inline.
+5. **CSS design tokens** — palette/spacing/radius all live as `--vars` in `global.css`. Component CSS only references tokens, not raw values.
