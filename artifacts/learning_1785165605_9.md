+### 2.3 fd 3 分離 status 與人類輸出
+
+**Bug**：第一版 `run_resources` 把 `printf '%s\n' "$worst"` 寫到 stdout，跟人類訊息混在一起。`r1="$(run_resources)"` 命令替換捕獲**所有**輸出，r1 變成「----- resources -----\n CPU: 0.0%\n ...」多行字串，`[[ "$r1" == CRIT ]]` 永遠 false → exit code 全錯。
+
+**修法**（學 `set -Eeuo pipefail` 派典範）：
+- status 走 **fd 3**、人類訊息走 **stdout**
+- `check` 模式：`r1="$(run_resources 3>&1 1>&2)"` — fd 3 (原 stdout) 進 `$()`、fd 1 (原 stderr) 出去給使用者
+- `resources-only` 模式：`r1="$(run_resources 3>&1 1>/dev/null)"` — 不印人類訊息、純抓 status
+
+**L3 教訓**：bash 函式不能**同時**用 stdout 當人讀輸出**又**用 stdout 當 status return。要分 channel，fd 3 是最簡單的解。
