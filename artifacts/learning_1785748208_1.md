+## 1. 問題與目標
+
+行政文件常同時包含可選取文字、掃描影像、表格化欄位與自然語言內容。人工逐份複製、摘要、分類與輸出容易漏字，也沒有可追溯的處理紀錄。
+
+DocPilot 的目標是提供一個可在桌面執行、也可由 CLI 自動化的安全文件處理工作台：
+
+1. 接收 PDF、DOCX、TXT/Markdown/CSV/JSON 與常見圖片。
+2. 優先讀取原生文字層；只在文字不足時啟用 Tesseract OCR。
+3. 將抽取結果交給本機規則規劃器，或可選的 OpenAI-compatible LLM。
+4. LLM 只產生受限 JSON 工作流 DSL，不產生或執行 Python、Shell、JavaScript。
+5. 使用者在桌面介面預覽文字與工作流，勾選核准後才執行。
+6. 所有輸出寫入隔離工作目錄，不覆寫原始文件，並產生 SHA256 稽核紀錄。
+

+# DocPilot — 智慧文件工作台

+
+## CLI 範例
+
+```bash
+./run_cli.sh doctor                       # 環境健康檢查

+./run_cli.sh run samples/memo.txt --approve   # 解析、規劃、預覽、執行
+./run_cli.sh run samples/memo.txt --dry-run  # 只跑流程，不寫入
+```
+
+## GUI
+
+```bash
+./run_gui.sh          # 在桌面環境啟動工作台
+```
+

+
+## 安全設計
+
+- 原始文件永遠只讀，執行前後 SHA256 必須一致。
+- LLM 只能輸出受限的 JSON DSL，DSL 通過 JSON-Schema 風格的嚴格驗證才會被執行。
+- 寫入目標必須在本次 job 目錄內；不可使用絕對路徑或 `..`。
+- 沒有 `approved=True` 時 executor 不寫任何檔案。
+- 稽核日誌（`.docpilot-audit.jsonl`）以 append-only 模式寫入並立即 `fsync`，權限 `0600`。
+- 每個 job 都會建立獨立目錄 + `manifest.json` + 各輸出檔的 SHA256，方便事後核對。

    5. 人類批准閘門雙保險：CLI 用 --approve flag、GUI 用 QCheckBox 必須打勾才能 enable 執行按鈕；無論哪個都必須顯式核准。
    6. append-only audit：每次成功執行追加一行 JSONL + fsync，檔案 mode 0600；manifest 內含每個輸出檔的 SHA256。
    7. 彈性設定三件套：--planner/--ocr-languages/--pdf-text-threshold CLI 覆寫 + auto 規則 + 預設值。
    8. GUI 框架選擇：系統無 tkinter，採 PySide6 venv（不污染系統 Python），安裝時由 install.sh 補齊。
    9. Tkinter 不裝：避免改動 /usr，採用專案 venv 的 PySide6（headless smoke 透過 QT_QPA_PLATFORM=offscreen）。
    10. Subprocess 設定：所有需要 LLM 連線的測試用本地 ThreadingHTTPServer 模擬，無外部依賴且可重現。
