+## 為什麼選 trending HTML 而不是 GitHub Search API
+- **不需要 API token** — 趨勢頁是公開 HTML,Search API 卻要 `GITHUB_TOKEN` 才不會被 401
+- **無 rate limit 壓力** — REST API 未認證 60 req/h,Trending 頁只有一般流量控管
+- **資料語意更貼近需求** — "trending" 就是 GitHub 內部統計(specific time window stars),Search API 沒有對應 endpoint
+- **離線可重跑** — 同樣 HTML 重新解析得到一樣結果,debug 友善
+
+## 設計
+- `fetch_github_trending.py` — 單檔、無外部依賴(標準庫 + `requests` + `bs4`,環境已驗證)
+- 三層分離:`fetch_trending_html()`(I/O) / `parse_trending()`(純函式) / `render_markdown()`(輸出)
+- CLI 介面:`--since daily|weekly|monthly` `--language <lang>` `--top N` `--out <path>` `--auto-name`
+- 內建 retry(429 等 `Retry-After`、其他錯誤指數退避)+ 失敗時把 raw HTML 留到 `/tmp/github_trending_last_response.html`
+
+## 解析上踩到的坑
+1. **語言 URL 不是 query,是 path** — `https://github.com/trending/python?since=weekly` 而非 `?language=python&since=...`,這常被搞錯
