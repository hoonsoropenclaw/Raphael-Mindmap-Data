+# Implementation Notes — Telegram Weather Bot
+
+## 任務
+建立一個可執行的 Telegram 機器人：收到使用者文字後，將文字視為城市/地區，呼叫 wttr.in 天氣 API，並把目前天氣回傳到 Telegram。
+
+## 開始前吸收的架構回饋
+
+目前環境沒有可直接讀取的 `~/.hermes/architect_feedback.md` 或 `~/.hermes/review_queue.md`（先前 shell 嘗試也證實指定路徑不可直接寫入）。改採同類、已驗證的 weather-bot 產物與 `stdlib-production-tool-pattern`：
+
+- 簡單的「訊息 → API → 回覆」流程採 Python 標準函式庫，不引入 `requests` 或 Telegram SDK。
+- 天氣 API 模組與 Telegram 輪詢邏輯分離，方便獨立測試和重用。
+- Telegram 使用 long polling，不需要公開 HTTPS endpoint。
+- 加入 allowlist、每使用者 rate limit、輸出 sanitization 三層防護。
+- `getUpdates` 使用絕對 offset：`update_id + 1`，避免重複處理更新。
+- 使用原生 UTF-8 emoji/中文，不使用 surrogate-pair escape，避免 `UnicodeEncodeError`。
+- API 欄位缺失採 fail-loud，回傳可辨識的 `BAD_JSON`，不以假預設值掩蓋上游格式變動。
+
+## 檔案
+
+- `telegram_bot.py`：Telegram Bot API、指令處理、long polling、signal shutdown。
+- `wttr_weather.py`：wttr.in API client、資料解析、中文格式化，可獨立作 CLI。
+- `test_unit.py`：無網路 mock 單元測試。
+- `test_smoke.py`：真實 wttr.in 網路 smoke test。
+- `run.sh`：環境載入、檢查、測試與啟動入口。
+- `.env.example`：設定範本。
+- `README.md`：使用說明。
+
+## 使用方式
+
+```bash
+cp .env.example .env
+# 編輯 .env，填入 TELEGRAM_BOT_TOKEN
+# 建議填 TELEGRAM_ALLOWED_USERS，例如自己的 Telegram numeric user ID
+./run.sh --unit
+./run.sh --smoke
+./run.sh
+```
+
+## 驗證策略
+
+先完成 Python compile check，再跑 mock 單元測試；最後才跑真實 wttr.in smoke test。Telegram 本身需要真實 bot token，因此不在沒有憑證時偽造線上驗證結果；可用 `./run.sh --check` 檢查設定。
+
+## 安全界線
+
+不把 bot token 寫入程式碼或版本控制；`.env` 僅供本機使用，`.env.example` 不含秘密。allowlist 未設定時程式會明確警告 bot 對所有人公開。
