### 2.1 純 stdlib，不用 requests / BeautifulSoup

**為何這樣決定**：

- `urllib.request` 1 行程式碼就能 GET，呼叫端零學習成本
- `re` + `html.parser` 處理 GitHub Trending 這種「結構穩定、有明確邊界」的 HTML 已經夠用
- BeautifulSoup 對 `<article class="Box-row">` 這種 root 結構有效，但對「`<a>` 內含 `<svg>` + 數字」這種混雜結構反而麻煩 — 正則表達式直接對原始 HTML 處理更靈活
- 依賴最小化 = 安裝/部署成本 = 0

**避免的反模式**：

- ✗ 拉 `requests` 套件（教訓 36：stdlib 生產工具）
- ✗ 拉 `beautifulsoup4` 套件（對這個場景 over-engineering）
- ✗ 用 `subprocess` 呼叫 `curl`（教訓 33：subprocess timeout 不穩）

### 2.2 解析器：正則 + 結構化 fallback

**4 個 anchor 的 regex**：

```python
H2_RE           = <h2 class="h3 lh-condensed"><a href="/(owner/name)">
OWNER_NAME_RE   = <span>owner /</span> name
STARGAZERS_RE   = <a href="/.../stargazers">...<svg>...</svg> number </a>
PERIOD_LABEL_RE = number + ("stars today"|"stars this week"|"stars this month")
```

**踩坑紀錄**：第一版 `STARGAZERS_RE` 寫成 `<a...>number</a>` 直接拿數字，但 GitHub 真實 DOM 是 `<a>` 內包 `<svg>` 才到 number — `\s*` 失效導致 total_stars 全空。修正後改成 `(?:.*?)</svg>\s*number</a>` 跳過 SVG。

**L3 教訓：永遠先送一個 live probe 抓 3KB HTML 看真實 DOM**

```python
# 寫解析器前必跑這一步
data = urllib.request.urlopen(URL).read().decode()
arts = re.findall(r'<article class="Box-row">.*?</article>', data, re.DOTALL)
print(arts[0][:1500])  # 看真實結構
```

不這麼做，光看 GitHub 「公開 API」文件會以為有 JSON、但 `/trending` 沒公開 REST API — 只能 HTML 解析。

### 2.3 Retry / backoff 機制

```python
def fetch_url(url: str, *, timeout: int = 20) -> bytes:
    for attempt in range(MAX_RETRIES):  # 4 attempts
        try:
            return urllib.request.urlopen(url, timeout=timeout).read()
        except (HTTPError, URLError) as exc:
            if 4xx (not 429) → 不 retry
            sleep_for = 0.6 * (2 ** attempt) + random.uniform(0, 0.3)
            time.sleep(sleep_for)
    raise last_exc
```

**L3 教訓**（來自教訓 28：retry/backoff 是抓取類工具的標配）：

- 4xx client error 通常 = 程式碼寫錯，不該 retry（會浪費配額）
- 429 = rate limit → 要 retry 但尊重 `Retry-After` header
- 5xx / network → exponential backoff + jitter（避免 thundering herd）
- jitter = `random.uniform(0, 0.3)` 防止多個 client 同步重試

### 2.4 Markdown table 的 `escape` 設計

**問題**：repo #6 (NanmiCoder/MediaCrawler) 的描述是 `小红书笔记 | 评论爬虫、抖音视频 | 评论爬虫...`，**裡面的 `|` 會打斷 Markdown 表格 column 解析**。

**解法**：`_escape_markdown_table(text)` 把 `|` 換成全形 `｜`，newlines 折成空格。

```python
def _escape_markdown_table(text: str) -> str:
    if not text:
        return text
    return text.replace("|", "｜").replace("\r", " ").replace("\n", " ").strip()
```

**為何不直接 `\|` escape**：

- `\|` 在 GitHub Markdown 裡 valid 但視覺雜亂（被當 escape 顯示）
- 全形 `｜` 跟半形 `|` 視覺相近，閱讀者看不出差異
- 折衷：保持表格可讀性、又不會破壞 column 結構

**驗證**：smoke_test.py 跑 `assert_valid_markdown_table()` 檢查每 row 必須有 7 個 `|`（6 個 column + 2 邊界），如有 row 不對就 fail。

### 2.5 描述截斷（word-boundary）

**問題**：描述長度不一（30 字 ~ 500 字），markdown table 寬度需要控制。

**解法**：`_truncate(text, max_len)` — 從 max_len 往前找最後一個空格，截斷 + 加 `…`。

```python
def _truncate(text: str, max_len: int) -> str:
    if max_len <= 0 or len(text) <= max_len:
        return text
    cut = text[:max_len].rsplit(' ', 1)[0]  # 找最後一個空格
    return (cut or text[:max_len]).rstrip() + "…"
```

**為何不在字元數剛好時切**：

- 看起來像 `...Neuro-sama's altitu` — 突兀
- word boundary 切出 `...Neuro-sama's altitude.` 更自然
- 預設 140 chars，CLI 可調（`--max-desc 0` = 不截斷）

### 2.6 Period label 從 CLI 注入

GitHub 同一頁 HTML 對 daily / weekly / monthly 期間會出現不同 label (`today` / `this week` / `this month`)，但 A/B test 期間可能有微妙的 label 漂移。**信任 CLI 參數 (`--since`) 而非 scraping 結果**：

```python
period_label = {"daily": "today", "weekly": "this week", "monthly": "this month"}[args.since]
# 寫進 TrendingRepo 時 override 掉 HTML 抓的
repos.append(TrendingRepo(..., period_label=effective_period))
```

**L3 教訓**：當 CLI 參數跟遠端資料都描述同一個概念時，**以 CLI 為準**（單一事實來源），避免 redundant parsing error。

| 層 | 工具 | 範圍 | 速度 |
|----|------|------|------|
| **Unit test** | `test_trending.py` | 純函式（parse / render / escape） | 0.004s |
| **Smoke test** | `smoke_test.py` | 真實 HTTP + 表格結構 + JSON 結構 | ~5s |

## 6. L3 抽象教訓（給未來的自己）

**1. Live probe 必跑在寫解析器之前**

```python
data = urllib.request.urlopen(URL).read().decode()
arts = re.findall(r'<article.*?</article>', data, re.DOTALL)
print(arts[0][:1500])  # 永遠先看真實 DOM
```

不要相信 API 文件、不要相信 sample code。**真實的 HTML 是 single source of truth**。

**2. 正則的 `.*?` 能優雅處理 tag 內混雜 inline element**

`<a><svg>...</svg>number</a>` 不要寫 `<a>.*?number</a>`（會 capture 到別的 a），要明確寫 `<a[^>]*stargazers.*?</svg>\s*number</a>` 鎖定 anchor。

**3. Markdown table 的 `escape` 要在 render 階段，不在 parse 階段**

parse 階段保留原始資料（含 `|`），render 階段才 escape。這樣日後想輸出 JSON / HTML / CSV 都不用重新解析。

**4. CLI 參數優先於 scraping 結果**

當 CLI 跟 HTML 都有同一個資訊（例如 period label），以 CLI 為 single source of truth — 因為 CLI 是使用者 intent,HTML 是 GitHub 自己的 labeling。Intent 永遠比第三方資料可信。

**5. 三層驗證（unit + smoke + live）對 tool 類專案是最低標準**

- Unit 0.004s 跑完 → 內部邏輯正確
- Smoke 5s 跑完 → fetch + parse + render 全程 OK
- Live → 人眼看 output 對不對

少了任何一層,bug 都會在使用者手上才發現。

**6. 純 stdlib 對 scraper 是對的**

`requests` / `beautifulsoup4` 對複雜網頁有效，但對 GitHub Trending 這種「root 結構穩定、無 JS 渲染、無登入」場景 over-engineering。**純 stdlib 1 個檔 14KB 就能做出 production-quality scraper**。
