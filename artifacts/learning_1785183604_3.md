+# GitHub Trending Markdown Exporter
+
+`github_trending.py` uses only Python 3 standard-library modules to fetch GitHub Trending, parse repository cards, and atomically write a Markdown table.
+
+## Usage
+
+```bash
+python3 github_trending.py
+python3 github_trending.py --language python --since weekly --limit 10 --output reports/trending.md
+```
+
+The output file defaults to `github-trending.md`. The script uses a unique temporary file plus `os.replace()` so overlapping runs do not share a fixed `.tmp` path, and failed writes do not replace a previously valid output.
+
+## Design notes
+
+- `urllib.request` avoids an external dependency for a small public HTTP client.
+- `HTMLParser` extracts `<article class="Box-row">` cards.
+- Void HTML elements such as `img` and `br` do not affect parser nesting; `<br>` contributes a space.
+- Markdown cell content is escaped and HTML entities are decoded.
+- HTTP, parsing, and filesystem failures produce a non-zero exit status and a concise stderr message.
+- The parser has no GitHub token requirement because the public Trending page is used.

+# Implementation Review — GitHub Trending Markdown Exporter
+
+## Architecture
+
+1. `fetch_html()` uses Python standard-library `urllib.request` with a descriptive User-Agent and a bounded timeout.
+2. `TrendingParser` is a stateful `HTMLParser` that extracts one repository per GitHub Trending `<article class="Box-row">` card.
+3. `render_markdown()` converts typed `Repository` records into a Markdown table, escaping pipes and normalizing whitespace.
+4. `atomic_write()` uses a per-run `tempfile.mkstemp()`, `flush()`, `fsync()`, and `os.replace()` to prevent fixed-temporary-file collisions and partial output.
+5. `main()` validates CLI arguments, limits rows, reports network/parser/filesystem failures, and returns a non-zero exit status on failure.
+
+## Feedback absorbed
+
+- The Senior Architect feedback emphasized concurrency, race conditions, and file-permission safety. For this network/file exporter, the equivalent protections are bounded HTTP timeout, immutable dataclass records, no shared mutable parser state across runs, and unique temporary files for overlapping executions.
+- The existing parser-specific lessons were applied: void elements (`img`, `br`, `meta`, etc.) do not increase nesting depth, and `<br>` becomes a space instead of concatenating words.
+
+## Trade-offs
+
+- GitHub Trending is an HTML page rather than a documented API, so markup changes can require parser updates.
+- No third-party scraping dependency is introduced; this keeps deployment simple but intentionally limits parsing to the fields needed by the table.
+- The script does not authenticate to GitHub, which is sufficient for public Trending and avoids storing credentials.
