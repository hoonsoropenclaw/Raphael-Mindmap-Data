+## 4. 技術選型理由
+
+### a. 純標準庫 sqlite3（不引 SQLAlchemy）
+- 教學規模 demo；SQLAlchemy 拖 30+ 個 transitive deps
+- 1 table / 5 CRUD operations → raw SQL 仍可讀
+- 每請求新 connection（context manager） → 天然 thread-safe
+
+### b. slowapi（不自己寫 middleware）
+- 業界標準（基於 Flask-Limiter 移植）
+- 內建 sliding window + in-memory storage
+- `@limiter.limit()` decorator 語意直覺
+
+### c. Pydantic v2 `min_length=1, max_length=200`
+- 明確的產品邊界（不要讓使用者塞 1MB 字串爆 DB）
+- 422 自動驗證錯誤格式
+
+### d. `create_app(db_path, rate_limit)` factory pattern
+- production 用預設值
+- test 注入隔離 temp DB 與自訂 rate limit
+- 這是 FastAPI canonical pattern（避免 module-level singleton 帶來的污染）
+
+### e. PATCH 而非 PUT
+- 接受 `title` / `completed` 兩個 optional 欄位
+- 比 RFC 純 PUT 語意寬鬆、對前端更實用
+- 沒給欄位 → 維持現況（idempotent）
