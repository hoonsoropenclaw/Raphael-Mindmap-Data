+## 🏗️ 架構設計
+
+### 狀態管理策略
+
+採用**雙層 reducer + Context** 設計：
+
+**Layer 1：全域 todos 狀態（`useReducer` + Context）**
+- 6 種 action：`ADD` / `TOGGLE` / `DELETE` / `EDIT` / `CLEAR_COMPLETED` / `LOAD`
+- 每個 todo 帶 `id / text / completed / createdAt / priority` 4 個欄位
+- 透過 `TodoContext.Provider` 把 dispatch + handlers 傳給所有子組件
+- 用 `useMemo` 鎖定 context value，避免無謂 re-render
+
+**Layer 2：UI 元狀態（`useReducer`）**
+- 3 種 action：`SET_FILTER` / `SET_SORT` / `TOGGLE_THEME`
+- 與 todos 完全獨立，方便未來拆成 router query string 或持久化
+
+**Layer 3：本地 UI 狀態（`useState` × N）**
+- `draft` — 新增 todo 的輸入框文字
+- `priority` — 新增時的優先級選擇
+- `showClearConfirm` — 清除確認 modal 的開關
+- `isEditing` + `editText` — 每個 TodoItem 自己的編輯狀態
+
+### 為什麼這樣分層？
+
+- **Context 只放「跨組件共用」的狀態**（todos + handlers）— TodoItem 必須能 toggle / delete / edit
+- **UI 元狀態（filter / sort / theme）放獨立 reducer** — 容易持久化 / 易於測試 / 不污染 todos reducer
+- **單組件 UI 狀態用 useState** — 編輯框的 isEditing 只有 TodoItem 自己關心，不需要 Context
+
+### 衍生資料（derived state）
+
+- `useFilteredTodos(todos, filter, sort)` 自訂 hook — 用 `useMemo` 快取
+- `stats = useMemo(...)` — 總計 / 未完成 / 已完成 / 完成率
+
+### 效能優化
+
+- `useCallback` 包裝所有 dispatch handlers（避免 TodoItem 因 App re-render 而 re-render）
+- `useMemo` 包裝 context value、filteredTodos、stats
+- `React.memo` 沒用 — 因為 handler 已經 useCallback 穩定，且 React.memo 對 React DevTools 除錯不友善
+
+### 副作用（side effects）
+
+- `useEffect` 1: localStorage 持久化（`hermes-react-todo:v1` key）
+- `useEffect` 2: 鍵盤快捷鍵（Esc 清空 draft / 取消 modal）
+- 兩個 effect 的 cleanup 都正確處理
