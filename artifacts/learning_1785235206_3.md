+## 4. 關鍵技術細節
+
+### 4.1 rate limit 正確實作
+
+**錯誤版本 1**: 在 endpoint 內呼叫 `limiter.limit("30/minute")(lambda: None)()` → slowapi 拋 `No "request" argument` 因為 lambda 沒 `request: Request` 參數。
+
+**錯誤版本 2**: 移除 `@limiter.limit` 改用手動呼叫 → rate limit 從未觸發，因為 slowapi middleware 看不到手動呼叫。
+
+**正確版本**: `@limiter.limit("30/minute")` decorator + endpoint 函數第一個參數是 `request: Request` + FastAPI app 裝 `SlowAPIMiddleware`。實測驗證：3 次 POST 在 `RATE_LIMIT_CREATE=2/minute` 設定下，第 3 次回 429。
+
+### 4.2 Pydantic body param 解析
+
+**坑**: `from __future__ import annotations` 讓所有型別變 forward ref。FastAPI 透過 `get_type_hints()` 解析 Pydantic model 作為 body param 時，某些情況下解析失敗、fallback 為 query param（症狀：`loc=["query","payload"]`）。
+
+**修正**: routers/todos.py 移除 `from __future__ import annotations`，讓型別直接是 class object。
+
+### 4.3 DELETE 204 無 body
+
+FastAPI 對 `status_code=204` 預期無 response body。**必須**加 `response_class=Response`，否則 Pydantic 序列化器會嘗試序列化空回應、AssertionError 啟動時就死。
+
+### 4.4 Test isolation
+
+- **DB**: in-memory sqlite + `StaticPool`（共享 connection）+ `Base.metadata.create_all` per-test
+- **Limiter**: rate limit 測試**獨立檔案** (`test_rate_limit.py`)，不污染 conftest fixture 的 app instance
+- **Client**: `dependency_overrides[get_db]` 注入測試 session；fixture teardown 自動 `clear()`
