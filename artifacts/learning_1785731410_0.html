Async Event-Driven Playwright Crawler

整合異步事件驅動架構以提升抓取效率 — Demo Dashboard

Architecture · 事件流拓樸

Crawler.run(urls)
   │  (1) enqueue
   ▼
EventBus  ────────── async queues (one per subscriber)
   ▲      ▲          ▲
   │      │          │
   │  ────┐     ────┐
Crawler._observer    WorkerPool._on_event
   │                            │
   │ append to                  │ page.on('request'/'response'/'console')
   │ EventStore                 │   → publish PAGE_* events
   │                            │
   ▼                            ▼
EventStore                N async workers (semaphore-bounded)
(items + events)            │   each owns its own BrowserContext
                            │   extractor(html, url, page) → items
                            ▼
                       bus.publish(ITEM_FOUND)  ──→ EventStore.items

Event types:  job.dispatched → job.started → page.request/response
              → job.completed → item.found (when extractor yields)
              → job.failed (on any exception, isolated from siblings)

API · 用法

from src.crawler import Crawler
from src.extractors import hackernews_extractor

crawler = Crawler(
    workers=4,                    # async page concurrency
    headless=True,                # run Chromium headless
    extractor=hackernews_extractor,  # async (html, url, page) -> list[dict]
)
result = await crawler.run([
    "https://example.com/",
    "https://example.com/news",
])

print(result["stats"])   # {'ok': N, 'fail': M, 'items': K, 'events_recorded': …}
print(result["items"])   # [{'title': …, 'href': …, 'source_url': …}, …]
print([e["type"] for e in result["events"]])   # full event stream

Event Types · 事件型別

dispatched URL enqueued by Crawler.run(); consumed by WorkerPool.
started A worker claimed the slot (semaphore acquired); about to fetch.
page.request Browser-level sub-request observed via page.on("request").
page.response Browser-level sub-response observed via page.on("response").
completed page.goto + content() + extractor all returned; status captured.
failed Exception caught & isolated; siblings continue. Payload has error repr.
item.found Extractor returned ≥1 item. Each item is a dict; payload.items is the list.
crawl.done Crawler idle-detected; stops WorkerPool. stats has aggregate counts.

Why event-driven? · 為什麼用事件驅動

1. Back-pressure is natural.  Each subscriber has a bounded
   asyncio.Queue(maxsize=1024); overflow drops for THAT subscriber
   only — never blocks the producer or other subscribers.

2. Decoupling.  A future RATE_LIMITED consumer can throttle ALL
   workers without producer/consumer refactor.  A WebSocket dashboard
   is just another subscriber — no plumbing changes.

3. Observability.  Every page lifecycle observation (request,
   response, console.log, error) becomes a stream event.  Replay the
   event log to debug "why did extraction fail on this URL?".

4. Concurrency is bounded in TWO places: the bus queue (memory) and
   the worker semaphore (CPU/RAM for live pages).  Both bounds are
   necessary; either alone can OOM at scale.
