🚀 核心實作

① 跨瀏覽器平行執行

單一 Python 程式同時啟動 Chromium、Firefox、WebKit 三個真實瀏覽器引擎,每個引擎執行同一組測試,確保應用在不同渲染引擎下的行為一致。

# app/cross_browser_runner.py
BROWSER_MATRIX = [
    {"name": "chromium", "engine": "chromium", "viewport": {"width": 1280, "height": 800}},
    {"name": "firefox",  "engine": "firefox",  "viewport": {"width": 1280, "height": 800}},
    {"name": "webkit",   "engine": "webkit",   "viewport": {"width": 1280, "height": 800}},
    {"name": "chromium-mobile", "engine": "chromium", "viewport": {"width": 390, "height": 844}},
]

with sync_playwright() as p:
    for spec in BROWSER_MATRIX:
        browser = getattr(p, spec["engine"]).launch(headless=True)
        context = browser.new_context(viewport=spec["viewport"])
        page = context.new_page()
        # 跑功能測試 + 視覺截圖...
        context.close()
        browser.close()

② 像素級視覺差異比對

使用 Pillow 對截圖進行 RGB 空間像素比對,容差 5% (8/255 per channel),自動產生 baseline / actual / diff 三聯圖。

# app/visual_diff.py
def pixel_diff_ratio(img_a, img_b):
    a_rgb = img_a.convert("RGB")  # 忽略 alpha 通道雜訊
    b_rgb = img_b.convert("RGB")
    diff = ImageChops.difference(a_rgb, b_rgb)
    total = a_rgb.width * a_rgb.height
    pixels = diff.getdata()
    threshold = 8  # anti-aliasing tolerance
    diff_count = sum(1 for p in pixels if any(c > threshold for c p))
    return diff_count / total

③ 視覺回歸測試流程

STEP 1 建立基準 (--update-baselines) — 在三引擎各截 3 場景(首頁、計數器+3、表單填寫),存為 baselines/<browser>-<label>.png。
STEP 2 執行測試 — 對同一份被測目標重新截圖,逐張比對 baseline。差異 ≤ 5% 視為通過,> 5% 視為回歸失敗。
STEP 3 產生差異視覺化 — 每張失敗截圖自動產生三聯圖(baseline / actual / 紅色高亮差異像素)。
STEP 4 產出報告 — JSON 結構化結果 + HTML 自含式報告(差異圖以 base64 內嵌,離線可開)。

④ Mutation Test 自驗框架

為了驗證視覺回歸框架真的有在做事(而不是永遠回報 pass),我寫了一個 mutation test:故意把 CSS 主色 #2563eb 改成 #dc2626,然後跑測試,預期 12 張截圖全部 fail。

# tests/test_mutation_catches.py
# 1. 備份原檔
shutil.copy2(src, backup)

# 2. 注入突變
mutated = text.replace("--primary: #2563eb;", "--primary: #dc2626;")
src.write_text(mutated)

# 3. 跑測試 (不更新基準)
subprocess.run(["python3", "cross_browser_runner.py"])

# 4. 驗證 12 張全部 fail
caught = sum(1 for v in visual if v["diff_ratio"] > 0.05)
assert caught > 0, "framework broken!"

# 5. 還原 (try/finally 確保)
shutil.move(backup, src)

📚 實作過程中發現的 3 個關鍵 bug(都已修復)

  1. 表單驗證被 HTML5 required 攔截 — 原本的 required 屬性讓瀏覽器原生驗證先擋下 submit,JS 處理器不會跑。
    → 改加 novalidate 屬性,讓 JS 邏輯接管。
  2. 基準命名空間衝突 — 第一版的 baseline 用 home.png,但每個瀏覽器都會覆寫同一個檔,造成跨瀏覽器比較永遠 self-equal。
    → 改為 <browser>-<label>.png 命名。
  3. RGBA alpha 通道讓 getbbox() 失效 — Playwright 截圖是 RGBA,alpha 通道微差讓 ImageChops.difference.getbbox() 誤判無差異。
    → 比對前先 .convert("RGB") 去掉 alpha。
