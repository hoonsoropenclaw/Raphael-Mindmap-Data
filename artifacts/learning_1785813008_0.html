Cross-Browser Automation + Visual Regression

A self-contained Playwright harness that renders a deterministic fixture page in Chromium Firefox WebKit three engines in parallel, captures full-page screenshots, and pixel-compares them against committed baselines using a 60-line Pillow + numpy fallback in place of the Node.js pixelmatch library.

What's in the box

demo.html   deterministic test target with data-testid hooks, grid + flexbox coverage, zero network calls
cross_browser_runner.py   Playwright sync wrapper that fans out to Chromium / Firefox / WebKit, sets viewport, captures full-page screenshot, plucks [data-testid] values
visual_diff.py   standalone diff_images(baseline, candidate, threshold, output) returning a DiffResult with mismatch ratio + max delta + an optional red-highlight diff PNG
run.py   the orchestrator: smoke + diff + report. CLI flags for target URL, baseline dir, output report, browser list, viewport, and --write-baselines to refresh

Reproduce in three commands

# 1. Seed baselines on a clean checkout (one-shot)
python3 run.py --write-baselines

# 2. Catch regressions on every PR
python3 run.py           # exit code 1 if a pixel diff exceeds 0.1%

# 3. Open the human-readable report
xdg-open report.html     # or: open report.html

How the visual diff works

  • Both PNGs are loaded as RGB numpy.int16 arrays so per-channel subtraction cannot overflow.
  • Per-pixel max channel delta is compared against threshold (default 12 — same magnitude pixelmatch uses at threshold: 0.2).
  • A boolean mismatch mask is converted into a red-highlight diff PNG for human inspection.
  • mismatch_ratio > 0.001 (0.1%) marks the run as failed — wide enough for sub-pixel anti-aliasing variance, narrow enough to catch real CSS changes.
  • Dimension mismatch raises a clear ValueError rather than silently comparing different images — matches the pitfall the micro-skill warns about.

Pitfalls this build encodes (sourced from the Hermes micro-skill)

  • Browser leaks. Each launch() is wrapped in try / finally browser.close(); sync_playwright() shuts the driver process itself.
  • Viewport drift. Viewport is set inside new_context() before navigation, so first-paint pixels are stable across runs.
  • Network-pending. wait_until="load" instead of "networkidle" because the demo makes zero requests — networkidle would still work but is misleading.
  • Dynamic content. The demo is fully static (no fetches, no clocks, no animations) so screenshots are byte-stable per browser.
  • First-run baseline seeding. Missing baselines are seeded from the current run; --write-baselines is the only way to refresh them.
