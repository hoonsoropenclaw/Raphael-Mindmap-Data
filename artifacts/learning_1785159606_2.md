+# system-monitor
+
+A lightweight Linux system monitor that scans resource usage (CPU / memory /
+disk / load) and log files (`/var/log/*` + `journalctl`), evaluates against
+configurable thresholds, and dispatches alerts when exceeded.
+
+## Why this exists
+
+Existing monitoring stacks (Prometheus, Datadog, Nagios) are heavyweight:
+agents, time-series DBs, web UIs. For a small Linux box — a homelab NUC, a
+school server, an edge device — you don't need any of that. You need:
+
+1. **A daemon that scans every N seconds.**
+2. **Writes alerts somewhere durable** (file / stdout / webhook).
+3. **Doesn't spam you** when something is broken for hours.
+4. **Survives restart** without losing its place in the logs.
+5. **No third-party deps** so it runs on a minimal image.
+
+That's what this is.
+
+## Architecture (5 modules, 1 main)
+
+```
+src/
+├── config.py          # YAML config loader + typed dataclasses
+├── log_parser.py      # Inode-aware incremental log reader + journalctl
+├── resource_monitor.py# CPU/mem/disk/load via /proc + shutil (no psutil)
+├── alerter.py         # Multi-sink dispatcher + cooldown rate-limiter
+├── state.py           # Atomic JSON state persistence
+└── monitor.py         # Main loop + signal handler + CLI
+tests/
+└── test_all.py        # 28 unit tests, 9 ms total, no network, no /proc
+config/
+└── monitor.yaml       # Sample config (syslog + auth.log + kern.log)
+```
+
+Each module is small (<300 LOC) and has a single responsibility. The main loop
+in `monitor.py` is ~120 lines including the signal handler.
+
+## Quick start
+
+```bash
+# 1. Generate a default config (once)
+python3 src/monitor.py --init ./my-config.yaml
+
+# 2. Edit thresholds / log paths to suit your box
+
+# 3. Single scan (good for cron / CI):
+python3 src/monitor.py --once -c ./my-config.yaml
+
+# 4. Long-running daemon:
+python3 src/monitor.py -c ./my-config.yaml
+
+# 5. Stop gracefully:
+kill -TERM <pid>      # saves state, then exits
+```

+### 1.3 關鍵設計選擇
+
+**a) Inode-aware rotation detection**:
+傳統做法是 `tail -F`,但 Python `tail -F` 不存在,`while True: read()` 會
+重複讀。解法:每個檔記 `(inode, size, offset)`。
+- 同一 inode + `offset <= size` → 從 offset 讀到 size(增量)
+- 同一 inode + `offset > size` → in-place truncate → 重置
+- inode 變了 → logrotated → 重置 + 從新檔讀
+
+**b) Cooldown 用 (rule, severity) 而非 (rule) 為 key**:
+- `cpu:warn` 跟 `cpu:crit` 應有獨立 cooldown(crit 不應該被 warn 抑制)
+- 但 `cpu:warn` 跟 `cpu:warn` 應該被壓制,避免風暴
+
+**c) Sliding window 用 list of timestamps 而非 counter**:
+- 實作簡單(`[t for t in hits if t >= now - 60]`)
+- 視覺化/debug 友善(可看命中分布)
+- 缺點:命中多時 list 變大(但 60s 內通常 < 100)
+
+**d) YAML 不用 PyYAML**:
+寫 150 LOC 的小 parser。理由:
+- 這個工具目標是部署在 minimal Linux 鏡像(無 pip、無網路)
+- 安全敏感 ops 工具減少供應鏈 = 好
+- 設定檔 < 4 KB,sub-parser 夠用
+
+**e) journalctl fallback**:
+實機 N100 box 有 systemd,`journalctl -p err -n 100` 拿到 100 行 crit-level
+(很多 mcp-dashboard / sshd / cron 失敗),/var/log/syslog 反而沒寫。
+所以 journalctl 不是可選,是必要的 fallback。
