+# PRD — FormLogic Studio
+
+---
+date: 2026-07-29
+topic: Next.js + React Flow dynamic form validation
+status: approved-by-explicit-autonomy
+---
+
+## 1. Product goal
+
+Build an executable visual validation studio where a form designer can model complex validation as a directed acyclic graph (DAG), edit the graph, fill the generated form, and inspect an immediate execution trace.
+
+## 2. User journeys
+
+1. A form designer selects a realistic template and sees both its generated form and validation graph.
+2. The designer adds fields, rules, and AND/OR logic nodes, connects them, and edits node configuration.
+3. A tester enters values and sees field-level errors plus pass/fail/blocked status propagated across graph nodes.
+4. The tester submits the form and receives accessible success/failure feedback.
+5. The designer exports the complete graph as JSON and can import it later.
+6. A reviewer can open a standalone `index.html` without a build step and exercise the core product.
+
+## 3. Functional requirements
+
+### Must
+
+- Next.js App Router + strict TypeScript.
+- React Flow canvas with draggable custom nodes and connectable edges.
+- Four graph primitives: field, rule, logic gate, outcome.
+- Rule operators: required, email, min length, minimum number, regex, same-as, conditional required.
+- AND and OR gates, including nested gates.
+- Live form generated from field nodes.
+- Deterministic graph evaluator with node-level traces and field-level errors.
+- Semantic connection checks, duplicate-edge prevention, and cycle prevention.
+- Template switching: account signup, expense approval, event registration.
+- Node inspector, add/delete operations, import/export JSON, reset, sample-data filling.
+- Accessible labels, focus states, `aria-live`, keyboard-delete handling, and reduced-motion support.
+- A complete standalone `index.html` in the working directory.
+
+### Should
+
+- Visual node status: idle, pass, fail, blocked, configuration error.
+- Form progress and graph health metrics.
+- Clear instructions for valid connection direction.
+- Responsive desktop/tablet/mobile layout.
+
+### Won't (this delivery)
+
+- Persistence to a remote database.
+- Authentication or multi-user collaboration.
+- Executing arbitrary JavaScript expressions from graph data.
+- Deployment to a public URL.
+
+## 4. Validation graph contract
+
+- Field nodes emit current form values.
+- Rule nodes consume field values through named target handles.
+- Logic nodes consume rule/logic booleans and combine with ALL/ANY.
+- Outcome nodes consume rule/logic booleans and determine submission validity.
+- Graphs must remain acyclic.
+- Regex rules are compiled safely; malformed expressions become configuration errors, never runtime crashes.
+- Empty optional values pass format/range rules; presence is controlled by a separate required rule.
+
+## 5. Non-functional requirements
+
+- No `eval` or `new Function`.
+- Evaluation is pure and independently unit tested.
+- Production build completes without type/lint errors.
+- Unit coverage target >= 80% for the evaluator.
+- E2E covers invalid submission, valid submission, template switching, graph editing, and standalone HTML.
+- No uncaught browser console errors.
+
+## 6. Acceptance criteria
+
+- `npm test`, `npm run test:coverage`, `npm run typecheck`, `npm run lint`, and `npm run build` pass.
+- Playwright E2E passes against the actual Next.js UI and `index.html`.
+- Invalid signup reports errors and failed graph nodes.
+- Valid sample reaches a passing outcome and success state.
+- Switching template changes both fields and graph.

+# FormLogic Studio
+
+A working Next.js 16 + React Flow system for designing and executing complex dynamic form-validation logic as a DAG.
+
+## What is included
+
+- React Flow custom nodes for fields, rules, ALL/ANY gates and outcomes.
+- Pure deterministic validation engine; no `eval` or arbitrary JavaScript.
+- Required, email, min-length, min-number, regex, same-as and conditional-required rules.
+- Cycle-safe, semantics-aware connection validation.
+- Three realistic templates and live generated forms.
+- Node inspector, add/delete, import/export JSON, graph trace and accessibility feedback.
+- Dependency-free standalone `index.html`.
+- Vitest unit coverage and Playwright E2E.
+
+## Run
+
+```bash
+npm install
+npm run dev
+# open http://127.0.0.1:3000
+```
+
+Standalone mode:
+
+```bash
+python3 -m http.server 8765
+# open http://127.0.0.1:8765/index.html
+```
+
+## Verify
+
+```bash
+npm test
+npm run test:coverage
+npm run typecheck
+npm run lint
+npm run build
+npm run test:e2e
+```
+
+## Graph semantics
+
+```text
+FIELD -> RULE -> LOGIC (ALL/ANY) -> OUTCOME
+                 LOGIC ---------> LOGIC
+RULE ---------------------------> OUTCOME
+```
+
+Connections that violate direction, duplicate an edge, provide a rule with a second field input, or introduce a cycle are rejected.
+
+See `docs/prds/prd_dynamic_validation.md` and `docs/specs/spec_dynamic_validation.md` for the requirements and implementation contract.
