+# Linux 日誌與資源監控器
+
+零第三方依賴的 Python 3 維運工具。檢查 CPU、記憶體、load、磁碟、新增的文字日誌，以及 systemd journal；超過閾值時輸出 JSON 警告並可送到 HTTP webhook。
+
+## 安全與可靠性
+
+- Webhook 只從 `MONITOR_WEBHOOK_URL`（或設定指定的環境變數）讀取，不接受 CLI URL，避免憑證暴露於 `ps`。
+- state 與 lock 權限為 `0600`，runtime 目錄為 `0700`。
+- state 使用同目錄暫存檔 + `fsync` + `os.replace` 原子更新。
+- 文字日誌以 inode + byte offset 游標讀取；支援 append、truncate 與 log rotation，不重複掃整檔。
+- journal 以 systemd cursor 續讀。
+- `fcntl.flock` 防止 cron/daemon 重複執行造成 race condition。
+- cooldown 抑制同一警告的告警風暴；SIGTERM/SIGINT 可優雅停止。
+- 網路請求有 timeout；Webhook 失敗會回報 stderr，不會偽裝成功。
+
+## 快速執行
+
+```bash
+cp monitor-config.example.json monitor-config.json
+chmod 600 monitor-config.json
+./run-monitor.sh --validate-config
+./run-monitor.sh --once --dry-run
+```
+
+有 webhook 時：
+
+```bash
+export MONITOR_WEBHOOK_URL='https://your-webhook.example/secret'
+./run-monitor.sh --once
+```
+
+持續監控：
+
+```bash
+./run-monitor.sh --daemon
+```
+
+`--once` 若有未被 cooldown 壓制的警告會回傳 exit code 2；正常回傳 0；設定或執行錯誤回傳 1。這可直接供 cron、systemd 或其他監控框架判斷。
+
+## 設定重點
+
+- `cpu_percent` / `memory_percent` / `disk_percent`：百分比閾值。
+- `load_per_cpu`：1 分鐘 load average 除以 CPU 核心數。
+- `disk_paths`：要檢查的 mount/path。
+- `log_files`：要增量掃描的純文字日誌。無權限或不存在會產生讀取警告。
+- `log_patterns[].threshold`：單次新增資料中達到幾筆才警告。
+- `journal.priorities`：journalctl priority 範圍，預設 `0..3`（emerg 到 err）。
+- `cooldown_seconds`：同一 alert key 再次通知前等待時間。
+
+## 建議部署
+
+建議用專屬帳號，將程式放 `/opt/linux-monitor`，設定放 `/etc/linux-monitor/config.json`，state/lock 放 `/var/lib/linux-monitor/`。部署前先以本目錄測試；正式搬移會涉及系統目錄與權限，需依變更管理流程執行。
+
+cron 範例（每分鐘檢查一次）：
+
+```cron
+* * * * * /opt/linux-monitor/run-monitor.sh --once >>/var/log/linux-monitor.jsonl 2>&1
+```
+
+若使用 cron，讓 `cooldown_seconds` 大於或等於排程間隔。若使用 `--daemon`，不要再用 cron 週期啟動。
+
