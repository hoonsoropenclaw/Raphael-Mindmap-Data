+# Linux Health Check
+
+`linux-health-check.sh` is a read-only Bash monitor for basic Linux resource and system-log health.
+
+Checks:
+- normalized `/proc/loadavg` against `LOAD_WARN_PER_CPU`
+- memory utilization from `/proc/meminfo`
+- disk and inode utilization for `ROOT_FS`
+- recent system/kernel journal errors when `journalctl` is available
+- failed systemd services when `systemctl` is available
+
+Warnings are printed to stdout and also sent to syslog via `logger` when available. The optional `WEBHOOK_URL` sends a compact JSON warning summary with `curl`.
+
+Exit codes:
+- `0`: healthy
+- `1`: one or more warning thresholds exceeded
+- `2`: checker/configuration error
+
+Examples:
+
+```bash
+./linux-health-check.sh
+./linux-health-check.sh --json
+CPU_WARN_PCT=90 MEM_WARN_PCT=90 DISK_WARN_PCT=90 ./linux-health-check.sh
+WEBHOOK_URL='https://example.invalid/health' ./linux-health-check.sh
+```
+
+For cron, keep the job quiet when healthy only if the caller redirects normal output; preserve exit codes for monitoring systems:
+
+```cron
+*/5 * * * * /absolute/path/linux-health-check.sh >>/var/log/linux-health-check.log 2>&1
+```
+
+The script does not install packages, alter services, restart processes, or modify logs.

+
+## Architecture
+
+- Bash with strict mode (`set -Eeuo pipefail`), quoted variables, and explicit exit codes.
+- Read-only data sources: `/proc/loadavg`, `/proc/meminfo`, `df`, `journalctl`, and `systemctl --failed`.
+- Each check is isolated in a function so a missing optional command does not prevent resource checks.
+- Thresholds are environment-configurable without editing the script.
+- Warnings are emitted to stdout, mirrored to syslog where `logger` exists, and optionally posted to `WEBHOOK_URL`.
+- No automatic remediation is performed; this prevents an alerting script from unexpectedly restarting or deleting anything.
+- `--json` provides a machine-readable summary while retaining diagnostics on stderr.
+
+## Risk controls
+
+- No `rm`, `mv`, package installation, service restart, or configuration write.
+- Webhook requests have a 10-second timeout and failure becomes a warning rather than an unhandled crash.
+- Missing `journalctl`/`systemctl` is handled as an informational skip.
+- Threshold and filesystem inputs are validated before checks run.
+
+## Verification performed
+
+1. Shell syntax validation with `bash -n`.
+2. Executable-bit verification.
+3. Normal live run against the current host.
+4. JSON-mode run.
+5. Forced-threshold run to verify warning and exit code behavior.
+6. Temporary fake command fixtures to exercise the journal-unavailable path.
+
+## Known limitation
+
+The script counts journal entries, not unique incidents. A burst of repeated messages can produce multiple warnings; this is intentional for a simple monitor and should be paired with alert deduplication in the external monitoring system for production use.
