    1. 技術選型
    - 語言：Python 3.12（系統已有）

    - CLI：argparse（stdlib，零成本）
    
    2. 設計分層
    - TrendingRepo dataclass — 一個 repo 一個物件，欄位明確（rank / full_name / url / description / language / total_stars / forks / today_stars）
    - fetch_trending_html() — 純抓取，回傳 HTML 字串
    - parse_trending_html() — 純解析，HTML → list[TrendingRepo]
    - render_markdown() — 純渲染，repos → markdown 字串
    - main() — 串接三段，回傳 exit code
    
    這層分層的好處：每段可獨立測試（壞 HTML 直接餵 parser、假 repo 直接餵 renderer），CLI 邏輯責任單一。
    
    3. HTML Selector 設計（容錯）
    - 主要錨點：<article class="Box-row">（GitHub 從 2020 至今沒換過，15 個 repo 卡片就是這個）
    - repo 連結：<h2 class="h3"><a href="/owner/repo">
    - 描述：<p class="col-9 ...">（可能缺）
    - 語言：<span itemprop="programmingLanguage">（可能缺）
    - stars / forks：掃所有 <a> 找 /stargazers / /forks 或 /network 結尾
    - today stars：掃所有 <span> 找含 "stars today" 或 "stars this" 字串（這樣 weekly/monthly 不用寫分支）
    
    4. 錯誤處理（不悄悄失敗）
    - TrendingFetchError 自定義 exception
    - 網路失敗 → 明確報錯（不是空表格）
    - HTTP 非 200 → 明確報錯
    - 找不到 article → 明確報錯「GitHub 可能改版或被擋」
    - 找到 article 但全部解析失敗 → 明確報錯
    - argparse 拒絕無效 --since

    - description 內可能有換行 → 替換成空格

    | --quiet / -q      | False  | 隱藏進度訊息             |
