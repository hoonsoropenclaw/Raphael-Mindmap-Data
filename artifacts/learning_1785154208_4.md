    1. 為什麼拆 YAML 跟 Python 兩層？
    閾值、關鍵字、忽略 pattern 全在 YAML，未來調監控規則不動 code。這也是讓「使用者明確說要改邏輯」跟「改參數」分開——前者才需要找我，後者自己改 YAML。
    
    2. 為什麼按 service 聚合，不按檔案？
    第一次跑 --test 時 syslog 顯示 16020 條匹配，看起來很可怕——但其實 99% 是同一個 mcp-dashboard.service 反覆失敗。按 (service, keyword) 聚合 後變 10 條有意義的告警：472 條 → 1 條聚合，31 條 OOM 仍然是 1 條（這次是真的有問題）。
    
    3. 為什麼排除 snap / tmpfs / squashfs？
    psutil 把 snap loop mount 當成正常 partition，會一直報 100% — 那是 read-only 的 squashfs，不是真的滿了。屬於「一定要排除的噪音」。
    
    4. cooldown 機制為什麼寫進磁碟？
    Daemon 重啟後不該又 spam 一遍昨天的告警——所以 fingerprint → last_sent_ts 寫到 .state.json，下次啟動載入。
    
    5. graceful degrade
    - journalctl 不存在（macOS、其他 init）→ 跳過
    - log 檔讀不到（沒 adm 群組）→ info 提示，不中斷
    - subprocess timeout → warning + 不卡死迴圈
