+"""Database engine, session, and Base declaration.
+
+Uses synchronous SQLAlchemy 2.x — chosen deliberately over async for this
+single-process SQLite todo API. Rationale (see IMPLEMENTATION_NOTES.md):
+
+* SQLite + aiosqlite is fine for read-mostly workloads, but mixing
+  sync sessionmaker inside an ``async def`` endpoint causes event-loop
+  blocking under load. With FastAPI's default threadpool execution,
+  plain sync sessions are simpler and deadlock-free here.
+* A ``check_same_thread=False`` + ``StaticPool`` setup lets the same
+  in-memory SQLite DB be shared across threads in tests.
+* ``expire_on_commit=False`` prevents ``DetachedInstanceError`` when
+  Pydantic serializes a committed object outside the session scope.

+

+from typing import Iterator

+    global _engine, _SessionLocal
+    if _engine is None:

+        connect_args: dict = {}
+        engine_kwargs: dict = {"connect_args": connect_args, "future": True}
+        if url.startswith("sqlite"):
+            # Allow SQLite to be used across threads (needed for FastAPI's
+            # threadpool when running sync endpoints in tests).
+            connect_args["check_same_thread"] = False
+            # In-memory SQLite needs a single shared connection so multiple
+            # sessions see the same data. StaticPool gives us that.

+## 2. 技術選型與理由
+
+### 2.1 同步 SQLAlchemy（非 async）
+
+**為什麼不用 `async_sessionmaker` + `async def` 端點？**
+
+`trial-and-error` 的**教訓 37**（2026-07-26 Cycle 539 歸納）明確警告：
+
+> async endpoint 內使用同步 `sessionmaker` + `.query()`，100 個 concurrent requests
+> 就會讓伺服器完全凍結（deadlock）。
+
+選項有兩條：
+- **A. 全 async**（aiosqlite + async_sessionmaker + `await db.execute()`）
+- **B. 全 sync**（普通 sqlite3 + sessionmaker + 普通函式）
+
+選 **B**，理由：
+- 待辦事項是 low-traffic personal API，不需要 async 的 throughput
+- FastAPI 預設用 `run_in_threadpool` 跑 sync 端點（教訓 37 提到的 race 條件是「async 端點配 sync session」的 mix 才會踩）
+- 同步語意對新手讀者更直觀
+- 測試更容易（不用 async client）
+
+### 2.2 slowapi headers_enabled=False
+
+第一次跑測試時 7 個 HTTP 測試 fail，錯誤：
+```
+Exception: parameter `response` must be an instance of starlette.responses.Response
+```
+
+**根因**：slowapi 預設會在 response 加 `X-RateLimit-*` headers，但前提是 endpoint **回傳 `Response` 物件**。我們回傳的是 `dict` / Pydantic model，slowapi 試圖 mutate 一個 dict 就爆炸。
+
+**修復**：把 `Limiter(headers_enabled=True)` 改成 `False`。
+- 影響：客戶端拿不到 `X-RateLimit-Remaining` headers
+- 替代：429 response body 仍有 rate limit 詳情；如果未來要重啟就改用 `response_class=JSONResponse`
+
+### 2.3 429 burst 實測**沒觸發**
+
+curl burst 65 次 /todos → 全部 200。
+- 預設 `TODO_RATE_LIMIT=60/minute` 是 **default limit**（每個 endpoint 也有自己的 limit：list=120, post=30, get=120, patch=60, delete=60）
+- 65 次 GET /todos 走 `120/minute`，未超限
+- 若要真的觸發 429，要把預設降到 5/minute 或對 POST 連發 31 次
+
+### 2.4 In-memory SQLite 在測試用 StaticPool
+
+`sqlite:///:memory:` 預設每個 connection 都有自己的 DB（看不到彼此的 table）。
+
+**修法**：用 `StaticPool` 讓所有 thread 共用同一個 connection，這樣 FastAPI 的 threadpool + TestClient 才看得到同一份 table。
+
+`app/database.py` 內：
+```python
+if ":memory:" in url:
+    engine_kwargs["poolclass"] = StaticPool
+```
+
+加上 `check_same_thread=False` 才能讓 SQLite connection 跨 thread 使用。
