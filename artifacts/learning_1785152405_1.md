+## 2. 設計決策（為什麼這樣做）
+
+### 2.1 純 stdlib — 拒絕 requests/bs4/scrapling
+**理由**：
+- N100 主機 Python 3.12 受 PEP 668 限制，**任何 pip install 都要先建 venv**
+- 既然 GitHub Trending 是純 HTML（無 JS 渲染、無 Cloudflare 保護），stdlib `urllib + html.parser` 完全夠用
+- 0 依賴 = 0 部署摩擦 = `chmod +x` 後直接能跑，這對「自動化腳本」是最高優先
+
+**替代方案比較**：
+| 方案 | 優點 | 缺點 | 結論 |
+|------|------|------|------|
+| `urllib + html.parser` (本方案) | 0 依賴、即開即用 | parser 程式碼較多 | ✅ 選 |
+| `requests + BeautifulSoup` | 程式碼簡潔 | 需 venv、需 pip | ❌ 殺雞用牛刀 |
+| `scrapling` (skill 內建) | 自適應解析 | 需 venv、啟動慢、針對反爬設計 | ❌ over-engineering |
+| `gh api` (CLI) | GitHub 官方 | **Trending 無官方 API** | ❌ 不可行 |
+
+### 2.2 HTML 解析策略 — state machine 而非 regex
+GitHub Trending 每個 repo 在 `<article class="Box-row">` 內，內含多個 anchor / span。
+
+**用 `html.parser.HTMLParser`** 自己寫 state machine 追蹤：
+- `Box-row` article 邊界（巢狀深度）
+- `h2` 內的 `<a href="/owner/repo">` 與文字 → `name` + `url`
+- `p.col-9` 文字 → `description`
+- `span[itemprop="programmingLanguage"]` → `language`
+- `a[href$="/stargazers"]` 文字 → `stars`
+- `a[href$="/forks"]` 文字 → `forks`
+- `span.d-inline-block.float-sm-right` 文字 → `stars_today`
+
+**絕對不能用 regex 抓 HTML**：HTML 巢狀結構 + entity encoding + whitespace 變化會讓 regex 100% 失靈。
+
+### 2.3 沒有官方 Trending API
+GitHub **沒有公開 REST API for trending**（`/trending` 頁面是 server-rendered，不走 GraphQL 也不走 API endpoint）。所以「抓 HTML 解析」是**唯一公開方案**。
+
+這也表示：
+- 頁面結構若 GitHub 改版，腳本需更新
+- 已加 try/except 與 fallback，HTTP 失敗時回 exit 1 而非崩潰
+

+GitHub 不會阻擋 `urllib`，但會對 `python-urllib/3.12` 預設 UA 偶發回 403。
+**用 Chrome 120 偽 UA** + `Accept-Language: en` → 實測 daily/weekly/python 三種 URL 全部 200。
+
+### 3.2 `since=daily|weekly` + `l=<language>` query 拼接
+- `?since=daily` / `?since=weekly`
+- `&l=python` / `&l=go` / `&l=typescript`（GitHub 對大小寫不敏感）
+
+### 3.3 Markdown 表格欄位
+```
+| # | Repo | Description | Language | ⭐ Total | 🍴 Forks | 🔥 Today |
