+# linux-ops-monitor
+
+Dependency-free Linux operations monitor for resource thresholds and system log anomalies.
+
+It reads Linux's `/proc` filesystem, `statvfs`, configured log files, and (when available) `journalctl`; it does not install packages, modify system configuration, or auto-remediate incidents.
+
+## Features
+
+- CPU utilization from `/proc/stat` two-sample delta, with guest time de-duplicated.
+- Memory and swap utilization from `/proc/meminfo`; uses `MemAvailable` when available.
+- Load average normalized by CPU count.
+- Disk and inode utilization using `os.statvfs`.
+- Incremental, rotation-safe scanning of text log files using inode + byte offset.
+- Optional systemd journal scan with bounded lookback and line count.
+- Strict JSON configuration validation: unknown keys, null thresholds, invalid regexes, and inverted warning/critical levels fail at startup.
+- Warning and critical threshold evaluation with explicit severity precedence.
+- Append-only NDJSON alerts, private `0600` runtime files, atomic JSON state writes.
+- Cooldown deduplication with bounded state and immediate delivery when severity escalates.
+- Optional HTTP/HTTPS JSON webhook using Python stdlib `urllib`.
+- SIGINT/SIGTERM graceful shutdown for long-running mode.
+- One-shot exit codes suitable for cron/systemd monitoring.
+
+## Requirements
+
+- Linux
+- Python 3.10+ (tested with Python 3.12.3)
+- No third-party Python packages
+
+## Quick start
+
+From this directory:
+
+```bash
+# Validate the example configuration.
+./bin/linux-ops-monitor --config examples/config.json --check-config
+
+# One resource/log check; JSON report on stdout.
+./bin/linux-ops-monitor --config examples/config.json --once --json
+
+# Long-running monitor. Stop with Ctrl-C or SIGTERM.
+./bin/linux-ops-monitor --config examples/config.json
+```
+
+`examples/config.json` writes runtime state and alerts relative to the config directory. Copy it to a private local `config.json` before adding a webhook URL; local config files are ignored by `.gitignore`.
+
+## Exit codes
+
+| Code | Meaning |
+|---:|---|
+| 0 | No threshold/pattern alerts emitted by this check. |
+| 1 | At least one warning-level condition is active. |
+| 2 | At least one critical-level condition is active. |
+| 3 | Configuration, collection, state, or alert-delivery failure. |
+
+The exit code reflects the highest observed alert severity. Cooldown suppresses repeated delivery, but does not hide the active severity in the JSON report.
+
+## Configuration
+
+Configuration is a partial override of the defaults in `src/linux_ops_monitor/config.py`; nested objects are deep-merged. Unknown keys are rejected rather than ignored.
+
+Important fields:
+
+- `interval_seconds`: delay between daemon checks.
+- `sample_seconds`: CPU measurement interval.
+- `state_file`: atomic JSON state containing log cursors and alert cooldown state.
+- `resources.disk_paths`: mount paths to inspect.
+- `resources.thresholds.<metric>.warning|critical`: numeric threshold pairs.
+- `logs.files`: text logs to scan. `start_position: end` avoids replaying history on first run.
+- `logs.patterns`: named regex rules with `warning` or `critical` severity.
+- `logs.journal`: optional bounded `journalctl` query.
+- `alerts.cooldown_seconds`: repeated alert suppression period.
+- `alerts.max_state_entries`: upper bound for cooldown state.
+- `alerts.ndjson_path`: append-only alert output.
+- `alerts.webhook_url`: optional `http://` or `https://` endpoint.
+
+The monitor reports `monitor.no_log_source` as a warning when all configured file logs are absent/unreadable and journal collection is disabled/unavailable. Resource collection still runs.
