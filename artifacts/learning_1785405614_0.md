+    const OriginalDate = Date;
+    class FrozenDate extends OriginalDate {
+      constructor(...args) {
+        super(...(args.length ? args : [frozenTimestamp]));
+      }
+      static now() {
+        return frozenTimestamp;
+      }
+    }
+    Object.defineProperty(globalThis, 'Date', { value: FrozenDate });
+  });

+# PRD：Playwright 跨瀏覽器 UI 元件視覺迴歸
+
+## 使用者旅程
+
+身為 UI 元件維護者，我要在 Chromium、Firefox、WebKit 與 mobile Chromium 上，以可重現的 baseline 比對元件狀態，讓非預期的像素變動在合併前使 CI 失敗並留下差異證據。
+
+## Must
+
+1. `web_output.html` 為不依賴 CDN 的完整 UI 元件展示頁。
+2. Playwright projects 覆蓋 Chromium、Firefox、WebKit；另加 mobile Chromium。
+3. baseline 依 project 隔離，不能把不同渲染引擎互相比較。
+4. 測試涵蓋淺色、深色、互動/驗證三種元件狀態。
+5. 固定時間、locale、timezone、color scheme、reduced motion，停用 animation/caret，等待字型。
+6. baseline 更新只能由明確的 `test:visual:update` 命令觸發。
+7. 正常比較回傳 0；故障注入必回傳非 0 且留下 actual/diff/trace。
+8. 產出 list、JSON、HTML 三種 Playwright 報告。
+9. 需提供單元測試，防止 URL 雙 port、錯誤 launcher 名稱、跨引擎 launch args 汙染。
+
+## Non-goals
+
+- 不跨作業系統共用像素 baseline；OS/font/Playwright 版本升級需重新審核 baseline。
+- 不自動接受視覺變更。
+- 不繞過網站反自動化或存取控制。
+
+## 驗收標準
+
+- 三個桌面瀏覽器與 mobile Chromium 全部可啟動。
+- `npm run test:visual:update` 產生每 project 3 張 baseline。
+- `npm run test:visual` 為 12/12 通過。
+- `npm run test:fault` 證明刻意視覺異常會被攔截。
+- 最終再跑一次 clean compare，HTML 報告為全綠。
