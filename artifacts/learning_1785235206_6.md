+## 2. 設計決策
+
+### 2.1 為什麼不依賴 psutil / requests
+- N100 環境 PEP 668 = 是（不能 `pip install` 全域）
+- 即便可以，**stdlib-only 是好習慣**：cron job 任何時候都能跑、
+  升級風險可控、sub-second 啟動時間。
+
+### 2.2 日誌來源探測順序
+1. `journalctl --since -Nm`（systemd 系統首選，含 priority 標籤）
+2. fallback `/var/log/syslog`（Debian/Ubuntu）
+3. fallback `/var/log/messages`（RHEL/CentOS）
+4. 兩者都沒有 → `backend=none`，pattern hit=0，**退出碼仍 0**（不算錯誤，
+   因為記錄「找不到來源」本身就是資訊）
+
+### 2.3 速率閾值 vs 累計閾值
+預設都是「**每分鐘**」速率，不是「視窗內累計次數」。
+理由：
+- 短時間突然爆量（突然 50 筆 OOM）比平時 50 筆 OOM 更嚴重
+- 速率自動 normalize 視窗長度（30 分鐘窗 × 2/min ≠ 10 分鐘窗 × 2/min）
+
+### 2.4 dmesg 為什麼不走速率
+`kernel panic / OOPS / BUG / ACPI Hardware Name` 是**個體事件**——
