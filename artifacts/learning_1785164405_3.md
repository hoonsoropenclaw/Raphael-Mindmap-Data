+import time
+from collections import defaultdict, deque
+from threading import Lock
+
+from fastapi import HTTPException, Request, status
+
+
+class InMemoryRateLimiter:
+    def __init__(self) -> None:
+        self._requests: dict[str, deque[float]] = defaultdict(deque)
+        self._lock = Lock()
+
+    def check(self, key: str, max_requests: int, window_seconds: int) -> None:
+        now = time.monotonic()
+        cutoff = now - window_seconds
+
+        with self._lock:
+            timestamps = self._requests[key]
+            while timestamps and timestamps[0] <= cutoff:
+                timestamps.popleft()
+
+            if len(timestamps) >= max_requests:
+                retry_after = max(1, int(window_seconds - (now - timestamps[0])))
+                raise HTTPException(
+                    status_code=status.HTTP_429_TOO_MANY_REQUESTS,
+                    detail="Rate limit exceeded",
+                    headers={"Retry-After": str(retry_after)},
+                )
+
+            timestamps.append(now)
+
+    def clear(self) -> None:
+        with self._lock:
+            self._requests.clear()
+
+
+limiter = InMemoryRateLimiter()
+

+        return forwarded_for.split(",", 1)[0].strip()
+    return request.client.host if request.client else "unknown"

+# Todo FastAPI
+
+A compact Todo REST API using FastAPI, Python's built-in `sqlite3`, and a per-client in-memory sliding-window rate limiter.
+
+## Endpoints
+
+- `GET /health`
+- `POST /todos`
+- `GET /todos?completed=true|false`
+- `GET /todos/{id}`
+- `PATCH /todos/{id}`
+- `DELETE /todos/{id}`
+- Interactive docs: `GET /docs`
+
+## Run
+
+```bash
+python3 -m venv .venv
+.venv/bin/pip install -e '.[test]'
+.venv/bin/uvicorn app.main:app --reload
+```
+
+The SQLite database defaults to `./todos.db`.
+

+export TODO_DATABASE_PATH=/path/to/todos.db
+export RATE_LIMIT_MAX_REQUESTS=60
+export RATE_LIMIT_WINDOW_SECONDS=60
+```

+# Senior Architect Review: Todo FastAPI API
+
+## 1. Architecture summary
+
+- Framework: FastAPI with synchronous route handlers.
+- Persistence: Python standard-library `sqlite3`; no ORM is required for this small CRUD service.
+- Schema: one `todos` table with integer primary key, title, completion flag, and UTC timestamps.
+- Validation: Pydantic request/response models reject blank titles and enforce a 200-character title limit.
+- Rate limiting: process-local sliding-window limiter keyed by `X-Forwarded-For` when present, otherwise the client host.
+- Testing: FastAPI `TestClient` tests the HTTP contract and uses a temporary SQLite database through `TODO_DATABASE_PATH`.
+
+## 2. Key implementation decisions
+
+### Sync FastAPI handlers
+
+The API performs short, local SQLite operations and has no external I/O in request handlers. Synchronous handlers keep the session/connection lifecycle explicit and avoid mixing `async def` with blocking database calls.
+
+### SQLite connection lifecycle
+
+Each request receives a fresh connection through `get_db()` and closes it in a `finally` block. `initialize_database()` is idempotent and runs during application lifespan plus before dependency use, making the app reliable in both production startup and direct `TestClient(app)` usage.
+
+### Rate limiter behavior
+
+The limiter stores monotonic timestamps in a deque for each client key. Expired entries are removed before checking the limit. When the limit is exceeded, middleware returns:
+
+- HTTP `429`
+- JSON body `{ "detail": "Rate limit exceeded" }`
+- `Retry-After` header
+
+The `/health` endpoint is excluded so monitoring can still determine service health during client throttling.
+
+### Update semantics
+
+`PATCH` only changes fields explicitly supplied by the caller. An omitted `title` or `completed` field preserves the current value. Every update refreshes `updated_at`.
+
+## 3. Verification evidence

+## 4. Operational boundaries
+
+The current limiter is process-local. It is appropriate for a single-process deployment or a simple example. For multiple workers or multiple instances, replace the in-memory store with Redis or another shared atomic counter store.

+The SQLite database is also suitable for lightweight workloads. For high write concurrency or horizontal scaling, move persistence to PostgreSQL and retain the same API schemas and route contract.
