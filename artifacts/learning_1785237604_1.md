+### 1.1 為什麼選 Python + stdlib 而不是 shell/perl/Ruby
+
+| 選項 | 取捨 |
+|---|---|
+| **Python + stdlib** ✅ | 跨 Linux 發行版一致、/proc 直讀、無外部依賴、易測試 |
+| Bash + awk | 部署簡單但 regex/JSON 處理痛苦,測試基礎設施差 |
+| Go/Rust | 部署單一二進位佳,但需要 build toolchain,且 /proc 直讀反而比 Python 麻煩 |
+| nodejs | 需要 runtime,對純 CLI 工具是 overkill |
+
+**結論**: Python 3 + stdlib 是 Linux 維運腳本的最佳甜蜜點。
+- `/proc/loadavg`、`/proc/meminfo`、`os.statvfs()` 都是 stdlib
+- `urllib.request` 內建 webhook(不需要 `requests`)
+- `subprocess` 呼叫 `journalctl` 即可
+- `json` 處理 state 檔與 alert log
+- 完全沒有 `pip install` 需求
+
+### 1.2 為什麼模組分離 (config / resource_check / log_scanner / alerter)

+```
+sysmonitor/
+├── bin/sysmonitor          # CLI entry,signal/lock/loop 編排
+├── lib/config.py           # YAML 載入 + dataclass 驗證
+├── lib/resource_check.py   # /proc 直讀資源
+├── lib/log_scanner.py      # tail + journalctl pattern matching
+├── lib/alerter.py          # dispatch + debounce
+├── config/sysmonitor.yaml  # 所有閾值集中此處
+└── tests/test_smoke.py     # 15 個無依賴 smoke test

+**Why modular**:

+- 換 alerter 通道(Telegram → PagerDuty)只動 `alerter.py`
+- 換資源來源(加入 Prometheus exporter)只動 `resource_check.py`

+## 監控什麼
+
+| 資源 | 來源 | 預設閾值 |
+|---|---|---|
+| CPU load avg (1-min) | /proc/loadavg | 1.5 load/core |
+| Memory 使用率 | /proc/meminfo | 90% |
+| Swap 使用率 | /proc/meminfo | 50% |
+| Disk 使用率 | shutil.disk_usage | 85% per mount |
+| Inode 使用率 | os.statvfs | 85% per mount |
+| 日誌錯誤 pattern | syslog / auth.log / kern.log / journalctl | 5 分鐘內 >= 3 次 |
+
+預設的 8 個 log patterns:
+- `kernel_oom` (critical) - Out of memory / oom-killer
+- `kernel_panic` (critical) - Kernel panic / BUG / general protection fault
+- `disk_full` (critical) - No space left on device
+- `auth_failed` (warning) - Failed password / Invalid user
+- `sudo_failed` (warning) - sudo authentication failure
+- `service_failed` (warning) - systemd Failed with result
+- `segfault` (warning) - segfault at / general protection fault
+- `error_keyword` (warning) - ERROR / FATAL / CRITICAL 關鍵字
+
