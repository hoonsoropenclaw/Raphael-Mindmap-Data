+## 2. 設計思路（4 條核心決策）
+
+### 決策 A — **用 HTMLParser 切塊、正則在塊內抽取**
+不用 BeautifulSoup / lxml。理由：
+- stdlib only → 部署零成本（`chmod +x` 就能跑）
+- 不會炸 CSS/第三方依賴更新
+- HTML 結構每季都在變，但每個 `<article class="Box-row">` 都包成一塊是穩定介面
+- **進 article 區塊後退化成正則** — 比 nested state machine 強健一個量級
+
+實作：把 HTMLParser 簡化成「**只**找 `<article class="Box-row">` 邊界、抓文章塊」的 ArticleSegmenter；進 article 後**針對性 6 條正則**抽取（href / desc / lang / stars / forks / today）。第一版寫成 inline state machine 時，立刻在 P 標籤/星數 anchor 跨 SVG 多個 data event 的轉折處爆掉；改切成「段落局部匹配」後一次就穩。
+
+### 決策 B — **Markdown table 注入防禦**
+- 每個 cell 過 `md_cell()`：escape `\` 和 `|`，collapse whitespace，empty → `—`
+- 真實測試資料集的第 6 列 `NanmiCoder/MediaCrawler` description 含 6 個 `|`，escape 後維持單一 row delimiter
+- 數字欄右對齊（`---:`），Repository/Description/Language 左對齊
+
+### 決策 C — **寫檔走 atomic**
+```
+mkstemp → write → flush → fsync(file) → os.replace → fsync(dir)
+```
+即使中途 SIGKILL，磁碟上 `trending_repos.md` 要嘛是舊的、要嘛是新的、絕不會半截。`tmp` 預設 mode 0o600 — 這也呼應 Architect 上次 carry-forward 的「umask + chmod 自我驗證」L3 模式。
+
+### 決策 D — **CLI 對齊「可重跑 + 可篩選 + 可串接」**
+```
+python3 github_trending.py                           # 全域、寫 trending_repos.md
+python3 github_trending.py --language python --out trending_python.md
+python3 github_trending.py --stdout | head -20      # 串接
+```
+`--stdout` 走 atomic 跳過、純印 Markdown，可被下游 `gpt -` / `gh gist create -` 直接吃。
