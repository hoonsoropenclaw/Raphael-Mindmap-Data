+## Architecture decisions
+
+### 1. Single reducer, discriminated action union
+Every state change goes through `dispatch({ type: '...', ... })`. The reducer
+is a pure function — trivial to test, trivial to trace, no hidden state
+inside components. The `_exhaustive: never` switch arm makes TypeScript
+catch every missed case at compile time.
+
+### 2. Version counter on every task
+Every `task/update`, `task/create`, `task/move` calls `bumpVersion()` which
+increments `version` and updates `updatedAt`. This mirrors the Senior
+Architect's `useReducer for interrelated state slices` guidance from
+Round 2 of the review log — and lays the groundwork for conflict
+detection when a future server sync introduces concurrent edits.
+
+### 3. Debounced `localStorage` persist
+**Direct lift of Senior Architect Round 2 feedback:**
+> "When persisting to localStorage via effects, consider adding a debounce
+> or throttle if state updates become highly frequent (e.g., during
+> drag-and-drop reordering later). Also, ensure you gracefully catch
+> `QuotaExceededError` if storage gets full."
+
+We ship both:
+- A 400 ms debounce on the bulk persist hook
+- A 200 ms debounce on the smaller config stores
+- Explicit `QuotaExceededError` + `SecurityError` handling
+- A visible "unsaved / saved" pill in the status bar
+
+### 4. No `dangerouslySetInnerHTML`, ever
+All user-supplied text flows through React's safe text interpolation.
+A `card-conflict` warning pill surfaces unresolved sync conflicts without
+ever rendering the conflicting payload as HTML.

### 架構決策(完整內化 Round 1-4 feedback)

**1. 集中式 useReducer + 區分性 Action union**
- 28 個 action type,7 個 state slice(tasks / columnOrder / filter / ui / sync / toasts / columnOrder 元資料)
- `default: { const _exhaustive: never = action; ... }` switch arm 讓 TS 編譯時就抓到遺漏
- `bumpVersion(task)` 在每個寫入 reducer 自動遞增 `task.version` + 更新 `updatedAt`
- 直接呼應 Round 2「useReducer for interrelated state slices」

**2. Debounced localStorage persist(直接複用 Round 2 feedback)**
- `useDebouncedPersist` hook: 400ms debounce + 顯式 catch `QuotaExceededError` + `SecurityError`
- `lastWrittenRef` identity-equal 短路,避免 identity churn 重複寫入
- Status bar 「unsaved / saved」pill 即時反映狀態
- 獨立 config stores(theme / failure rate)走 200ms debounce

**3. 模擬 flaky network sync(直接複用 Round 2 feedback)**
- `useNetworkSync`: 600ms tick 排空 pendingOps queue
- Failure rate 0-100% 可調(slider 即時生效)
- 失敗時 `sync.status='error'` + re-queue,UI 紅色 Error pill
- latency / pendingOps / lastSyncAt 都 surface 在 StatusBar

**4. CSS variables 完整 design system(直接複用 Round 1 anti-bloat 原則)**
- 909 行單一 index.css,2 個 theme via `[data-theme]`
- 所有顏色 / 間距 / 圓角 / 陰影都 token 化
- Editorial / monospace 設計語言(brand + columns 用 JetBrains Mono)
- 零 utility framework,零 CSS-in-JS

**5. 無 dangerouslySetInnerHTML,全程**
- grep 結果: 0 處 dangerouslySetInnerHTML
- 所有 user input(title / description / tags)走 React 安全文字插值
- `conflict: boolean` 旗標 + UI 徽章,但絕不把 payload 當 HTML 渲染
