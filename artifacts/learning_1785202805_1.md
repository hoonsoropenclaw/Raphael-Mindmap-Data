+# GitHub Trending → Markdown
+
+零第三方依賴的 Python 3 自動化工具：抓取 GitHub Trending repositories，解析 repository card，輸出 Markdown 表格。
+
+## 需求
+
+- Python 3.10+（本機驗證版本：Python 3.12.3）
+- 可連線至 `https://github.com/trending`
+- 不需要 GitHub token
+
+GitHub 沒有官方 Trending REST API，因此本工具解析公開 HTML，並在解析不到任何 repository 時 fail closed，不會用空表覆蓋前一次成功輸出。
+
+## 快速使用
+
+```bash
+cd /home/hoonsoropenclaw/.hermes/projects/learning_1785202805_1
+
+# 每日全語言 Trending，最多 25 筆
+./github_trending.py --output github-trending.md
+
+# 每週 Python Trending，最多 10 筆
+./github_trending.py \
+  --language python \
+  --since weekly \
+  --limit 10 \
+  --output github-trending-python.md
+```
+
+完整參數：
+
+```bash
+./github_trending.py --help
+```
+
+| 參數 | 預設 | 用途 |
+|---|---:|---|
+| `-o`, `--output` | `github-trending.md` | Markdown 輸出路徑 |
+| `-n`, `--limit` | `25` | 最大 repository 筆數，必須 ≥ 1 |
+| `-l`, `--language` | 無 | GitHub 語言 slug，例如 `python`、`typescript` |
+| `--since` | `daily` | `daily` / `weekly` / `monthly` |
+| `--timeout` | `20` | 單次 HTTP timeout 秒數 |
+| `--retries` | `3` | transient failure 最大嘗試次數 |
+| `--input` | 無 | 讀本機 HTML，不連網；供測試與 debug |
+
+Exit code：
+
+- `0`：抓取、解析、寫入成功
+- `1`：參數值、網路、HTML 解析或檔案系統錯誤
+- `2`：`argparse` 無法解析 CLI 參數
+
+## 自動排程範例
+
+每天 08:00 更新：
+
+```cron
+0 8 * * * cd /home/hoonsoropenclaw/.hermes/projects/learning_1785202805_1 && /usr/bin/python3 github_trending.py --since daily --limit 25 --output github-trending.md >> github-trending.log 2>&1
+```
+

+## 2. 架構與資料流
+
+```text
+GitHub public Trending HTML
+        ↓ urllib.request
+explicit timeout + bounded transient retry
+        ↓
+TrendingParser(HTMLParser state machine)
+        ↓
+Repository dataclass[]
+        ↓ URL-preserving de-duplication + limit
+Markdown renderer
+        ↓
+mkstemp(unique) → UTF-8 write → flush → fsync → os.replace
+        ↓
+Atomic Markdown report
+```
+
+GitHub 沒有官方 Trending REST API，所以 HTML parsing 是明確且不可隱藏的 trade-off。工具完全使用 Python 標準庫，避免 `requests` / BeautifulSoup 安裝與供應鏈成本。
+
+## 3. 核心設計決策
+
+### 3.1 Stateful `HTMLParser`，不用全頁 regex
+
+每個 `<article class="Box-row">` 是獨立 record boundary，解析以下欄位：
+
+- repository name + absolute URL；
+- description；
+- language；
+- total stars；
+- forks；
+- selected period stars。
+
+使用 `VOID_ELEMENTS` 集合阻止 `<img>`、`br`、`meta` 等無 closing tag 元素增加 nesting depth。`<br>` 在文字 capture 中轉成空白，避免兩行黏成一個詞。
+
+### 3.2 Fail closed 與保留上一份有效報告
+
+只有在 `parse_repositories()` 得到至少一筆 repository 後才呼叫 `atomic_write()`。如果 GitHub 回傳 challenge page、空 HTML 或 markup 改版：
+
+- stderr 顯示具體錯誤；
+- exit code = 1；
+- 原本的 Markdown 不變；
+- 不留下 `.tmp` 檔。
+
+截斷的最後一張 article 也會丟棄，避免發布不完整資料。
+
+### 3.3 有界重試，不無差別 retry
+
+- 重試：HTTP 429、500、502、503、504、`URLError`、timeout、socket/OSError；
+- 不重試：404 等 permanent 4xx；
+- 預設最多 3 次；
