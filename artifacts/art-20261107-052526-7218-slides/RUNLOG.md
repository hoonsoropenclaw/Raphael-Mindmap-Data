## 6c. ★★ 本輪最重要的發現：不是版面缺陷，是**驗證鏈的 DAG 違反**

**實測事實**：

```
make_charts.py   mtime 03:57:31   ← 圖表原始碼（已修好標註位置）
*.pptx           mtime 03:55:11   ← 簡報（比圖表原始碼舊 2 分 20 秒）
charts/*.png     mtime 03:57:35   ← 圖表（比簡報新）
```

**後果**：第一次載入渲染圖時看到的是**修好前的舊圖**。
若沒有比對 mtime，我會把舊圖的缺陷寫成「今天修好了」→ **假綠燈**；
或把新圖的缺陷誤判成「還沒修」→ **假紅燈**。

**這是 SOP §1.9 的實際違反**：被檢產物比它的輸入原始碼舊 → 檢查器全綠也不代表檢查的是最終版。

**機械化防線（本輪已實作）**：`make_visual_review.py` 產出報告前，
先比對**所有輸入原始碼**的 mtime 與被檢產物的 mtime；
輸入比產物新 → **報告拒絕產出**並印出差異清單。
（與 code SOP §23-3「簽章時點 vs 使用者到手時點」同族：都是「簽章對象與被驗對象不是同一個」。）

## 6b. 為此新增的兩支機械檢查器（互相補位）

1. `audit_chart_annotations.py`（幾何層級）：比對每支 Annotation 的**純文字**範圍、引線路徑取樣點、長條矩形、數值標籤矩形，四條命題：① 標註文字壓長條 ② 引線穿過**非目標**長條 ③ 引線壓數值標籤 ④ 長條內文字被裁切。
2. `verify_chart_annotations_pixel.py`（像素層級）：把灰階長條做一維形態學閉運算（把被字筆打斷的長條接回來），再檢查長條內部是否出現橘色像素。

**兩支互相補位的實證**：修正第 3 頁時把 `xy` 寫成 `(3, values[0])`（x=3 是講師教學的位置，值卻是 141）→ 箭頭斜穿講師教學長條。**幾何檢查器把「宣告的目標」當合法 → 跟著錯 → 漏掉**；是**像素檢查器**獨立抓到的。
反過來，像素檢查器第一版用「灰階 run ≥ 30px」判長條 → 被打斷的長條長度不足 → 靜默報「無壓疊」→ **假綠燈**；改成閉運算後才正確。

→ 結論：單一方法的驗證器一定有盲區，**兩種方法互相補位**才有效。

> ② **設定檔的瑕疵必須由設定檔自己的守門擋下**，不得變成對被檢產物的假缺陷（缺陷 1、2）。
> ③ **他日的工作記錄不可沿用**（缺陷 4）：逐字複製來的段落會攜帶舊檔名，既誤導讀者、又會被交付閘門判成「宣稱有、實體無」。
