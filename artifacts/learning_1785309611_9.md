+## 2. 关键技术决策

+### 2.1 为什么用 ECDSA P-256 而不是 secp256k1
+
+W3C DID 规范推荐用 **ECDSA P-256 (secp256r1)** 作为默认曲线 —— 它是浏览器 Web Crypto API 唯一原生支持的椭圆曲线。生产中 Bitcoin/Ethereum 用 secp256k1,需要额外引入 noble/ed25519 之类的库(约 100KB+),在单 HTML 文件 demo 里性价比不高。
+
+但**JWK 输出格式和签名算法标识都是 W3C 兼容的**,生产换 secp256k1 只需替换 `namedCurve` 即可。
+
+### 2.2 真实加密 vs 模拟加密 — 选真实
+
+三种选择:
+- (a) `Math.random()` 假装加密 → 没有教育意义
+- (b) 引入外部 JS 库(noble/ed25519 等)→ 200KB+ 依赖,单文件 64KB 内破了
+- (c) 浏览器原生 Web Crypto API → **零依赖、零注入,真 ECDSA P-256 + SHA-256**
+
+选 (c)。所有密钥生成、签名、验证、哈希都用 `crypto.subtle` —— 工业级实现,经过 FIPS 认证,生产环境会用的就是这个。
+
+### 2.3 链上只存哈希承诺 — 不存 PII
