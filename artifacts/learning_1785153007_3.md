+## 設計決策(為什麼這樣做)
+
+### 1. 選 Open-Meteo 而非 OpenWeatherMap
+- **不需 API key**:降低 setup 摩擦,本地 dry-run 不需註冊
+- **免費額度無限制**:非商業使用免費
+- **CORS 友善**:雖然 bot 不用瀏覽器,但保留 web extension 可能性
+- **多語言 geocoding**:`language=zh` 讓台灣城市回中文名
+
+### 2. 拆 4 個 function 而非一鍋煮
+```
+resolve_city_name()  → 中文別名處理(純函式,易測試)
+geocode_city()       → API 呼叫 #1,獨立可替換
+fetch_weather()      → API 呼叫 #2,獨立可替換
+format_weather()     → JSON → Markdown(純函式)
+```
+每個 function 單一職責,可獨立 mock、測試、替換實作。
+
+### 3. 內建中文城市別名表
+直接打中文進 Open-Meteo geocoding,「台北」會回日本東京(因為語言預設是英文)。預先映射到「Taipei」等英文 query 避免誤判,覆蓋台灣六都 + 常見亞洲/歐美城市 30+ 個。
+
+### 4. Dry-run 模式
+無 Telegram token 也能跑 `python3 weather_bot.py --dry-run 台北`,直接驗證 geocode → fetch → format 全鏈。讓:
+- CI 可以整合測試
+- 開發者不用先申請 BotFather 就能驗證邏輯
+- 失敗時 console 直接看到錯誤訊息(不必翻 Telegram 對話紀錄)
+
+### 5. 完整錯誤處理
+- 城市找不到 → 友善訊息 + 建議英文名
+- API 連線失敗 → 「稍後再試」訊息
+- 未預期例外 → error_handler 攔截,bot 不會當機
+- 沒 token 啟動 → 印 usage + exit code 1
+
+### 6. python-telegram-bot 22.x async API
+- 官方推薦的 modern API(ApplicationBuilder)
+- 與 httpx.AsyncClient 整合天然,不必為了 bot 多開 sync client
+- 支援 `/start`、`/weather`、`自由文字` 三種入口
