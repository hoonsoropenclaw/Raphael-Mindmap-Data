+# React Flow × Tailwind CSS 協同設計模式研究
+
+> **研究主題**：當 React Flow（節點-邊圖引擎）遇上 Tailwind CSS（utility-first 樣式系統），協同設計的 6 個有效模式為何？哪些模式會強化彼此、哪些會相互抵消？
+
+## 1. 研究框架
+
+### 1.1 為什麼這兩者值得研究？
+
+React Flow 跟 Tailwind CSS 看似毫不相關 — 一個是節點圖的視覺化引擎，一個是 HTML class 的 utility 系統。但深度使用後會發現：
+
+- **React Flow 預設樣式來自 `@xyflow/react/dist/style.css`**，包含節點卡片、Handle、Edge、Controls、MiniMap、Background 等十幾個視覺元素，**全部都是 div / span 標籤 + 一堆 low-level class**（`.react-flow__node`, `.react-flow__handle`, `.react-flow__edge`）
+- 這些 low-level class **通常得寫 CSS 覆寫或 `:where()` 變體**才能跟專案 design system 接軌
+- Tailwind 提供 `@apply` 機制把樣式抽象成語意 class，也提供 `arbitrary value`（`bg-[#FAF9F5]`）跟 **data-attribute selectors**（`data-[selected=true]:ring-2`）— 後兩者跟 React Flow 的 `data-id` / `data-testid` / 自訂 `data-state` 高度契合
+
+這份研究展示 6 個能落地的協同模式，每個都有：
+- 🎯 **動機**：這個模式解決什麼問題
+- 🔧 **實作骨架**：核心 React Flow 配置 + Tailwind 慣用語
+- ⚠️ **陷阱**：踩過的雷 + 防雷建議
+- 🔬 **可運行 demo**：在 `index.html` 對應 anchor section
+
+---
+
+## 2. 六個協同設計模式
+
+### 模式 1：節點即語意（Node-as-Semantics）
+
+**🎯 動機**：React Flow 的 node 默認是「白色盒子 + 黑 handle」，但現實中一個 node 代表的是「審核中」「已通過」「失敗」等**業務語意**。Tailwind 的 utility 系統可以讓你用 `data-state="approved" | "pending" | "rejected"` 來對應 class — **把節點從純視覺元素升級為語意容器**。
+
+**🔧 實作骨架**：
+
+```jsx
+// React Flow 自訂節點
+function StatusNode({ data }) {
+  return (
+    <div
+      data-state={data.state}                              // ← 三狀態：approved / pending / rejected
+      className="rounded-lg border-l-4 px-3 py-2 bg-white shadow-sm
+                 data-[state=approved]:border-emerald-500
+                 data-[state=approved]:bg-emerald-50
+                 data-[state=pending]:border-amber-500
+                 data-[state=pending]:bg-amber-50
+                 data-[state=rejected]:border-rose-500
+                 data-[state=rejected]:bg-rose-50"
+    >
+      <Handle type="target" position={Position.Left} />
+      <div className="text-xs font-semibold uppercase tracking-wide text-slate-700">
+        {data.label}
+      </div>
+      <Handle type="source" position={Position.Right} />
+    </div>
+  );
+}
+```
+
+**Tailwind 慣用語**：`data-[attr=value]:class` 是 Tailwind v3.2+ 的 **data-attribute selector**，會被編譯成 `[data-state="approved"]:not(:has(...)) { ... }`。在 React Flow 自訂節點中極其好用 — 不必引入 CSS-in-JS，**所有節點視覺變化純靠 attribute + class**。
+
+**⚠️ 陷阱**：
+- 不要用 `className={... data.state === 'approved' && '...'} ` 三元判斷 — 失去 data-attribute 的好處，且每個狀態得寫一次三元判斷。改用 `data-state={data.state}` + `data-[state=X]:class`。
+- Tailwind 的 `data-` 變體預設 `config.data` 啟用，**確認你的 Tailwind 版本 ≥ 3.2**。
+
+**🔗 對應 demo**：`index.html#pattern-1-node-as-semantics`
