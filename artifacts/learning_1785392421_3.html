1. 測試金字塔 (Testing Pyramid)

越下層越快、越便宜、覆蓋率應該越高;上層昂貴但最貼近真實使用者。

E2E 端到端 瀏覽器、HTTP、JS 真實流程 | 慢、貴、信心高
Integration 整合 test_client、跨模組協作 | 中速、中價、信心中
Unit 單元 純函式、零 I/O | 極快、極便宜、信心來自覆蓋率

6. Anti-Patterns(本框架明確避免的陷阱)

陷阱症狀本框架的對策
用 == 比浮點數偶爾紅燈、難以重現用 math.isclose(...)
unit 測試碰 I/O慢、不穩定unit 層只能 import 純函式,任何 requests / open() 都不該出現
寫死的 sleepCI 上假性失敗E2E 用 wait_for_timeout 但搭配 wait_until="networkidle"
沒區分例外錯從哪來的不知道定義 CalculatorError / InvalidNumberError / DivisionByZeroError
瀏覽器沒掃 console error壞 JS 沒人發現E2E fixture 必裝 page.on('console', ...)
