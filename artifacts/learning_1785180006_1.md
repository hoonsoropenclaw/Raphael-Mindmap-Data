+# Linux Health Monitor
+
+A dependency-light Bash monitor for Linux hosts. It checks:
+
+- CPU busy percentage using two `/proc/stat` samples
+- 1-minute load average normalized by online CPU count
+- memory and swap saturation from `/proc/meminfo`
+- disk-block and inode usage for one or more mount points
+- failed systemd units
+- recent journal entries at a configurable priority
+- optional alert delivery with per-warning cooldown
+
+## Quick start
+
+```bash
+chmod +x linux-health-monitor.sh
+./linux-health-monitor.sh --no-journal
+./linux-health-monitor.sh --config ./linux-health-monitor.conf.example
+./linux-health-monitor.sh --format json
+```
+
+Exit codes:
+
+- `0`: healthy, or `--no-warning-exit` was requested
+- `1`: one or more thresholds exceeded
+- `2`: invalid arguments, missing dependency, or runtime/configuration error
+
+## Alert delivery
+
+`--alert-command` is run only when warnings exist. The complete report is sent to its standard input. It receives `LHM_STATUS`, `LHM_HOST`, `LHM_WARNING_COUNT`, and `LHM_SUBJECT`.
+
+Examples:
+
+```bash
+# Local syslog/journal warning
+./linux-health-monitor.sh \
+  --alert-command 'systemd-cat -t linux-health-alert -p warning'
+
+# Custom webhook, if curl is installed and URL is in the environment
+./linux-health-monitor.sh \
+  --alert-command 'curl -fsS -X POST -H "Content-Type: text/plain" --data-binary @- "$ALERT_WEBHOOK_URL"'
+```
+
+Identical warning sets are suppressed during the cooldown period. State is stored under `~/.local/state/linux-health-monitor` by default. Failed delivery does not create cooldown state, so the next run retries.
+
+## Scheduling
+
+User cron, every five minutes:
+
+```cron
+*/5 * * * * /absolute/path/linux-health-monitor.sh --config /absolute/path/linux-health-monitor.conf >> "$HOME/.local/state/linux-health-monitor/run.log" 2>&1
+```
+
+A systemd service/timer is preferable for a system-wide install because it offers bounded execution, journal capture, and explicit lifecycle management. This project intentionally does not install files under `/etc` automatically.
+
+## Threshold semantics
+
+- Percent thresholds trigger on `observed >= configured`.
+- `LOAD_WARN` is load per online CPU, not raw host load; default `1.50` means sustained runnable demand 50% above CPU count.
+- Set `FAILED_UNITS_WARN=0` or `LOG_ERRORS_WARN=0` to disable only that alert while retaining the corresponding detail.
+- `--no-journal` skips both journal and failed-unit checks, useful for containers or unprivileged environments.
+- Journal visibility follows the invoking user's permissions. For complete system logs, run under an account in `systemd-journal` or through an appropriately hardened system service.
+
+## Security and operational notes
+
+- Configuration files and `--alert-command` are trusted shell input. Keep config mode `0600` and never populate it from untrusted data.
+- No secret value is printed by the script. Put webhook tokens in a protected environment file or credential store rather than command-line history.
+- All variable expansions and filesystem arguments are quoted; Bash strict mode and a restrictive umask are enabled.
+- The script does not mutate monitored resources. Its only writes are alert cooldown timestamps in `STATE_DIR`.
+

+Provide a directly executable Linux operations monitor that inspects both host saturation and recent system failures, emits machine-readable or human-readable reports, and triggers a configurable warning action only when a threshold is crossed.
+
+No Senior Architect feedback file was present in the project at implementation time. The project initially contained only `local.log` and `nohup.out`; neither matched a feedback artifact.
+
+## Architecture
+
+The implementation is one dependency-light Bash program with three layers:
+
+1. Collection layer
+   - `/proc/stat`: two samples 200 ms apart for CPU busy percentage
+   - `/proc/loadavg`: 1-minute load normalized by online CPU count
+   - `/proc/meminfo`: memory and swap saturation
+   - `df -P` / `df -Pi`: block and inode saturation
+   - `systemctl --failed`: failed systemd unit count
+   - `journalctl`: bounded recent error sample
+2. Evaluation layer
+   - Every resource has a configurable threshold.
+   - Percentage and load comparisons support decimal observations.
+   - A warning is recorded when observed value is greater than or equal to threshold.
+   - Missing mount paths and unavailable samples become explicit warnings rather than silent omissions.
+3. Output/delivery layer
+   - Text output is optimized for terminals and cron logs.
+   - JSON output supports ingestion by another tool.
+   - `ALERT_COMMAND` receives the full report on stdin plus bounded metadata in environment variables.
+   - Cooldown state prevents repeated alerts for the same warning category.
+
+## Design decisions
+
+- Bash was selected because all metrics are available through standard Linux pseudo-filesystems and tools; no package installation is required.
+- Strict mode (`set -Eeuo pipefail`) and `umask 077` reduce silent failures and accidental state exposure.
+- Configuration remains flexible through a trusted Bash config file while command-line values override config defaults.
+- Load is normalized by CPU count to make the default meaningful across differently sized hosts.
+- CPU usage is sampled instead of inferred from load; load and CPU represent different failure modes.
+- Disk blocks and inodes are separate because inode exhaustion can break writes while byte capacity appears healthy.
+- Journal output is bounded by `LOG_LIMIT` to avoid unbounded cron output.
+- Alert delivery is decoupled from providers. The same interface can invoke `mail`, `systemd-cat`, `curl`, or a custom relay.
+- Cooldown signatures normalize changing percentage/load observations. Otherwise CPU 2.5% and 3.7% would create separate alert keys and defeat deduplication.
+- No automatic installation under `/etc` or system-wide scheduling was performed; the artifact is reversible and does not alter host configuration.
+
+## Failure found and fixed during verification
+
+Initial functional testing revealed a strict-mode control-flow bug: false threshold checks written as `comparison && add_warning` caused a function to return status 1, which terminated the script under `set -e` before output rendering. All optional threshold branches were changed to explicit `if ...; then ...; fi` statements.
+
+Initial cooldown testing also showed two alerts for two CPU samples because the raw numeric warning string was hashed. The signature now normalizes dynamic percentage and load values before hashing. Re-test confirmed one state file and unchanged alert-capture size on the second run.
