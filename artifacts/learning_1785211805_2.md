+# Signal Board — 實作思路與架構審查
+
+## 1. 任務理解
+
+目標是交付一個可直接運行的 React UI 元件／小型介面，而不是靜態 mockup。核心要求包括複雜狀態管理、完整 CSS、真實互動與可驗證的成品。
+
+開工前已掃描專案根目錄與 Markdown 文件；原目錄只有 `local.log`、`nohup.out`，沒有找到可辨識的 Senior Architect 回饋檔，因此本輪沒有可吸收的既有架構意見，也沒有覆寫既有程式碼。
+
+## 2. 架構決策
+
+### 單一 reducer 作為狀態轉移中心
+
+`src/workflow-store.jsx` 使用 `useReducer` 集中管理：
+
+- 工作項目集合
+- 搜尋條件與狀態篩選
+- 選取項目與側邊面板狀態
+- 最多 10 份資料快照的 undo history
+- toast 回饋
+- ID 生成序列
+
+所有資料修改都透過 action：`ADD_TASK`、`MOVE_TASK`、`UPDATE_PROGRESS`、`DELETE_TASK`、`UNDO`。純 UI 狀態與資料變更都可追蹤，但只有資料變更建立歷史快照，避免搜尋或開關面板污染撤銷堆疊。
+
+### Context 僅負責注入，不承擔商業邏輯
+
+`WorkflowProvider` 將 `state`、`dispatch` 與 memoized derived state 提供給 UI。衍生資料包含：
+
+- `visibleTasks`：搜尋與篩選結果
+- `selectedTask`：當前工作
+- `metrics`：總數、執行中、阻塞與平均進度
+
+這避免元件各自重算或維護重複狀態。
+
+### 可逆操作
+
+每個具資料副作用的 action 先保存快照。刪除、狀態切換、進度更新、新增都能由 `UNDO` 回復；history 只保留最近 10 筆，防止長 session 無限制成長。
+
+## 3. UI 組成
+
+- `Header`：搜尋、同步狀態、撤銷入口、全局完成度線
+- `Metric`：衍生指標
+- `TaskCard`：工作摘要、優先級、進度與狀態
+- `AddTask`：受控表單與空字串防護
+- `DetailPanel`：進度 slider、狀態切換、刪除與 Escape 關閉
+- `Dashboard`：篩選、空狀態、鍵盤快捷鍵與 toast lifecycle
+
+## 4. 視覺方向
+
+美學採用「Editorial Operations Console」：暖灰紙張底、黑色結構線、酸性螢光綠作唯一主強調色，搭配 Syne、Manrope、DM Mono。差異化錨點是超大型雙層描邊標題與穿過畫面的黑色 sticky 控制帶。
+
+這避免一般 SaaS 常見的白底圓角卡、紫色漸層與過度陰影。CSS 同時處理 950px、560px 斷點、鍵盤焦點、reduced-motion 與水平 overflow。
