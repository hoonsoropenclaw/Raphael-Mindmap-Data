+### 決策 A：純 stdlib，不用 `python-telegram-bot`

+雖然環境已裝 `python-telegram-bot 22.8`，但我刻意不用。理由：
+
+1. **教訓 36**（trial-and-error 收錄）：stdlib-first 生產工具建構，`urllib` + `signal` + `dataclass` 就夠
+2. **零依賴部署** — Dockerfile 從 200MB → 50MB，CI pip install 時間歸零
+3. **依賴鎖定 = 維護負擔** — `python-telegram-bot` v22 breaking change 風險、API 變更風險
+4. **這個任務的複雜度用不到** — 只用 getUpdates / sendMessage / getMe 3 個 endpoint
+

+### 決策 B：天氣 API 選 wttr.in，不用 OpenWeatherMap
+
+| 比較 | wttr.in | OpenWeatherMap |
+|------|---------|----------------|
+| API key | ❌ 不需要 | ✅ 需要（免費額 60 calls/min） |
+| 城市名直接查 | ✅ | ✅ |
+| 中文回應 | 部分（只 one-liner，JSON 仍是英文） | 看 plan |
+| 免費額度 | 無限（社群服務） | 60/min |
+| SLA | 無保證 | 99.9% |
+
+選 wttr.in：**不需要 API key = 零設定** + 使用者可以立刻在本地跑測試。
+
+**已知怪行為**：wttr.in 對未知城市回 HTTP 500（不是 404），且會自動選最近的氣象站（Taipei → Chunglun、Tokyo → Shikinejima）。已在 README「已知限制」說明。
