+# Linux Ops Monitor
+
+A dependency-free Python 3 monitor for Linux resources and recent system errors.
+
+Checks:
+- aggregate CPU utilization from `/proc/stat` (two-sample delta)
+- memory utilization from `/proc/meminfo` (`MemAvailable`)
+- one-minute load average normalized by logical CPU count
+- disk utilization for configured paths
+- recent priority 0..3 journald entries; falls back to bounded tails of `/var/log/syslog` and `/var/log/messages`
+
+Alerts go to stderr and optionally to a JSON webhook. Repeated alert classes are suppressed by a persisted cooldown state. Input log reads, webhook payloads, timeouts, and samples are bounded.
+
+## Run
+
+```bash
+chmod +x linux_ops_monitor.py
+./linux_ops_monitor.py --config monitor.example.json
+./linux_ops_monitor.py --config monitor.example.json --json
+```
+
+Exit status:
+- `0`: healthy
+- `1`: at least one threshold exceeded (including cooldown-suppressed active warnings)
+- `2`: monitor/configuration failure
+
+The script does not require root. Without journal permissions it attempts standard log files; if neither source is readable, resource checks still run and the log sample is empty.
+
+## Configure webhook
+
+Set `alerts.webhook_url` in a private config copy. The monitor sends a bounded JSON POST with `User-Agent: LinuxOpsMonitor/1.0`. Do not commit credentials embedded in a webhook URL.
+
+## Cron example
+
+Use absolute paths because cron has a minimal environment:
+
+```cron
+*/5 * * * * cd /absolute/path/to/project && /usr/bin/python3 linux_ops_monitor.py --config monitor.json >> monitor-cron.log 2>&1
+```
+
+Cooldown prevents repeated notifications while the process remains unhealthy. A nonzero exit on an active but suppressed warning is intentional so monitoring supervisors still see degraded state.
+
+## systemd example
+
+`/etc/systemd/system` is intentionally not modified by this project. Example unit definitions are in `systemd/`; review paths first, then install manually as root:
+
+```bash
+sudo cp systemd/linux-ops-monitor.service systemd/linux-ops-monitor.timer /etc/systemd/system/
+sudo systemctl daemon-reload
+sudo systemctl enable --now linux-ops-monitor.timer
+```
+
+Edit `WorkingDirectory`, `ExecStart`, and `User` before installation.
+
+## Test
+
+```bash
+python3 -m unittest -v
+python3 -m py_compile linux_ops_monitor.py test_linux_ops_monitor.py
+```
+
+## Security/operational notes
+
+- No shell interpolation is used for `journalctl`; arguments are passed as an array.
+- State updates use `mkstemp`, `fsync`, atomic `os.replace`, mode `0600`, and a guarded POSIX directory sync.
+- Log and network reads are capped to prevent unbounded memory consumption.
+- Config regexes are compiled during startup and invalid thresholds fail closed.
+- This is alerting, not remediation: it deliberately does not kill processes, rotate logs, or delete files.

+
+## Architecture and implementation reasoning
+
+### 1. Standard-library-only Python rather than Bash-only parsing
+
+Python 3 stdlib provides safer structured configuration, precise `/proc` parsing, bounded reads, atomic JSON state, webhook delivery, testability, and explicit exit codes without adding packages. The result remains appropriate for minimal Linux hosts.
+
+### 2. Resource collection methods
+
+- **CPU**: two aggregate `/proc/stat` samples; utilization is computed from total and idle counter deltas. This avoids misleading instantaneous load-only checks.
+- **Memory**: `/proc/meminfo` using `MemAvailable`; a legacy `MemFree + Buffers + Cached` fallback exists.
+- **Load**: one-minute load average normalized by logical CPU count, making the threshold portable across machines of different sizes.
+- **Disk**: `shutil.disk_usage()` over configurable paths.
+- **Logs**: recent journald priority `0..3` entries first; bounded tails of `/var/log/syslog` and `/var/log/messages` as fallback. Regex false-positive suppression handles phrases such as `0 errors` and `no errors`.
+
+### 3. Alert behavior
+
+- Thresholds are JSON-configurable.
+- Human warnings go to stderr; complete machine-readable reports are available via `--json`.
+- Optional bounded JSON webhook POST includes an explicit User-Agent and timeout.
+- Per-alert-class cooldown state prevents notification storms.
+- Exit `1` remains active even when notification is cooldown-suppressed, so cron/systemd/supervisors still see degraded state.
+- Exit `2` means the monitor itself failed or configuration is invalid.
+
+### 4. Safety and failure design
+
+- No destructive remediation is attempted: no process killing, deletion, or log rotation.
+- No shell interpolation is used; `journalctl` receives an argv list.
+- Configuration thresholds and regexes validate at startup and fail closed.
+- All large/remote inputs are bounded to resist accidental or malicious memory exhaustion.
+- State is atomically replaced and mode-locked to `0600`.
+- The supplied systemd service is hardened (`NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=strict`, `ProtectHome=read-only`) but intentionally remains a reviewable template because installing under `/etc` is a privileged external action.
