+# GitHub Trending → Markdown Exporter
+
+Scrape `https://github.com/trending` and emit a GitHub-Flavored-Markdown table
+suitable for committing to a repo, posting to Slack/Discord, or feeding into a
+static site.
+
+Zero external dependencies. Stdlib only (`urllib`, `re`, `tempfile`).
+Python 3.10+.
+
+## Why this exists
+
+The Senior Architect's standing review (rounds 1-5) repeatedly flagged two
+failure modes for any "fetch + write" script:
+
+1. **Half-written files** when a cron job or supervisor is SIGKILLed
+   mid-write. Solved with atomic `tempfile + fsync + os.replace`.
+2. **Quietly wrong data** when the upstream DOM changes. Solved with
+   explicit sentinel checks that fail-closed (exit 2) instead of writing
+   a misleading table.
+
+Round 2 also called out Cloudflare 403 on default-`urllib` requests, so a
+modern `User-Agent` is the default and 403 is treated as a hard failure
+(no silent retries).
+
+## Install
+
+```bash
+# No pip install needed — stdlib only.
+chmod +x github_trending.py
+```
+
+## Usage
+
+```bash
+# Daily trending, all languages, write to ./trending.md
+./github_trending.py
+
+# Weekly trending, Python only, print to stdout
+./github_trending.py --since weekly --language python --stdout
+
+# Cap rows and write to a custom path
+./github_trending.py --max 10 --output reports/weekly.md
+
+# CI-friendly: a non-zero exit means "do not publish"
+./github_trending.py && git add trending.md && git commit -m "update trending"
+```
+
+### CLI reference
+
+| Flag | Default | Description |
+|------|---------|-------------|
+| `--since {daily,weekly}` | `daily` | Trending window |
+| `--language LANG` | _none_ | Optional GitHub language filter (`python`, `go`, …) |
+| `--output PATH` | `trending.md` | Markdown output file |
+| `--stdout` | off | Print to stdout, do not write file |
+| `--max N` | `0` (all) | Cap number of rows |
