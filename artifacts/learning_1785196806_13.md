+
+> **作者**：赫米斯 (Hermes Agent) — 2026-07-28

+## 1. 目標與限制
+
+* **目標**：以單一 Bash 腳本定期檢查 Linux 主機的「資源使用（CPU / Memory / Swap / Disk / Inode / Load）」與「系統日誌（journalctl / 認證失敗 / OOM / systemd failed units）」，超過設定閾值時輸出結構化警報並支援 webhook / syslog / 本地告警檔。
+* **不做的事**：不安裝 daemon、不修改 kernel 參數、不取代既有的監控系統（Prometheus / node_exporter / Zabbix / Nagios）。設計上是 **「在它們之外的快速、低成本、能用 cron 跑的 fallback」**。
+* **環境依賴**：bash ≥ 4.2、`awk`、`df`、`nproc`（可選）、`curl`（webhook 用，可選）、`systemctl`（failed units，可選）、`journalctl`（systemd journal，可選）。**所有可選依賴缺一都有 fallback**，不會因此失敗。
+* **權限**：讀 `/proc`、`/sys`、磁碟；`webhook URL` 從 `WEBHOOK_URL_FILE` 讀（mode 600）。建議在容器或 root 環境跑（systemd 失敗單元必須有 D-Bus 權限）。
+

+### 2.2 為何這樣設計
+
+| 決策 | 理由 |
+|---|---|
+| **單一 Bash 腳本** | 監控腳本必須在「主機剛開機、crash 救援、容器 minimal image」等任何環境下能跑，**沒有套件管理依賴**最安全。 |
+| **stdin / proc / df / journalctl** | 都是 Linux 內建介面，不需額外 agent。CPU 用「兩次 `/proc/stat` 取樣差分」精準計算 busy%，避免 `top` 一次性誤差。 |
+| **awk 解析，不用 grep+sed+cut** | awk 對浮點、寬鬆空白、`-` 開頭的數字都能處理；grep/sed 容易在中文/特殊字串時爆。 |
+| **純文字設定、拒絕 shell 評估** | 設定行 `KEY=value` 嚴格 regex `^[A-Z][A-Z0-9_]*=`、值再拒絕 `` ` $ \ ( ) { } | & < > ; ' " ``。**任何 `$(...)` 都會被拒絕**，杜絕 injection。 |
+| **可選 `--fixture-dir`** | 為了能完整單元測試。**正式執行不應帶這個參數**。 |
+| **互斥鎖（手寫、不靠 `flock`）** | 用 `pid` 寫入 lock 檔、`kill -0` 驗存活、trap EXIT 清理。在沒有 `flock` / `util-linux` 的 minimal image 也能用。 |

+| **Recovery 自動 rearm** | 連續 OK 把 fingerprint 清空，下次觸發同一組代碼會重新發。 |
+| **`umask 077` + 顯式 `chmod 600/700`** | 來自 Senior Architect 的「CWE-276 防禦」原則：**就算目錄被繼承較寬鬆 mode，主動 chmod 收緊**。state dir 700、state files 600、alert log 600。 |
+| **拒絕未知 key（fail-closed）** | 配置 typo = 立刻 exit 2。**寧可壞在啟動、不可默默用錯誤值跑整天**。 |
+| **JSON / text 雙輸出** | text 給人看、JSON 給 Prometheus textfile collector / Loki pipeline 接。 |
