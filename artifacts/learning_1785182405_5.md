+# Engineer Log — GitHub Trending Scraper
+
+## 任務
+撰寫自動化腳本，抓取 GitHub Trending repositories 並輸出成 Markdown 表格。
+
+## 交付物
+- `/tmp/github_trending.py` — 主程式（純 Python 標準庫,零外部依賴）
+- `/tmp/trending_python_weekly.md` — 驗證產物(python weekly 範例)
+
+## 執行驗證
+```
+✅ python3 github_trending.py --since daily            → 15 條,7 欄全填
+✅ python3 github_trending.py --lang python --since weekly -o xxx.md  → 20 條
+✅ python3 github_trending.py --lang go                → 20 條 daily
+```
+
+## 實作思路
+
+### 1. 設計選擇：純標準庫,不用 BeautifulSoup
+- 目標是「可立刻執行」、無需 `pip install`
+- GitHub Trending 頁面結構固定,用 `html.parser.HTMLParser` 已足夠
+- 單檔 < 10KB,部署零成本
+
+### 2. 解析器策略 — 不依賴 class 命名,改依賴語意
+**第一次失敗教訓(GitHub 改了 class 名)**：原本用 `class="muted-link d-inline-block"` 識別 stars/forks 連結,結果 2026 年 GitHub 改成 `class="tmp-mr-3 Link Link--muted d-inline-block"`,語意沒變但 class 變了。改用 `href` 結尾識別:
+- `href$="/stargazers"` → stars
+- `href$="/forks"` → forks
+- `itemprop="programmingLanguage"` → language
+- `class*="float-sm-right"` → today stars(這個 class 較穩定)
+
+**啟示**:寫 GitHub scraper 不要相信 class 字串,要用語意屬性(itemprop, href 結尾,role)。
+
+### 3. 文字累積 — 處理 DOM 換行
+- h2 內 repo 名稱會被 `/` 換行切成多個 text node
+- 解法:`handle_data` 累積 → `handle_endtag` 時 `split() + join()` 合併
+- 同樣應用於 description / stars / forks
+
+### 4. URL 構造
+- GitHub Trending 支援 `/{lang}?since={daily|weekly|monthly}`
+- 預設 daily 不加 query string(更乾淨)
+
+### 5. 後處理
+- `today_stars` 從「1,234 stars today」整理成「1,234 (today)」,Markdown 更緊湊
+- `stars`/`forks` 移除逗號(雖然表格裡會再顯示原始 Markdown,但若 future-use 當數字用就乾淨)
+- 描述截斷 140 字(超過加 ...)
+
+### 6. 邊界處理
+- 無語言 → `—`
+- 無描述 → `_(no description)_`
+- URL 缺失 → 純文字(不會製造壞連結)
+- 網路錯誤 → stderr 印訊息 + exit 1
+- 結果為空 → 顯示「（無資料）」而非空表
+
+### 7. 設計刻意不做的事
+- **不做快取** — GitHub Trending 每次都新鮮,快取反而過期
+- **不做 rate-limit 處理** — 公開頁面無 API token,單次就 1 個 HTTP,不需
+- **不做平行抓多語言** — 單線程夠快,平行會反增加 IP 被偵測風險
+- **不做 js fallback** — GitHub Trending 是純 SSR,不用 Playwright
+
+## 用法
+```bash
+python3 github_trending.py                            # daily 全部
+python3 github_trending.py --lang python              # python daily
+python3 github_trending.py --lang go --since weekly   # go weekly
+python3 github_trending.py -o report.md               # 寫檔
+```
+
+## 可改進點(L3 抽象給未來)
+- 若 GitHub 改 `itemprop` 屬性 → parser 會全空,要 fallback 用顏色色塊 + Sibling 文字
+- 若要支援 `since=monthly` 顯示「XXXX stars this month」 → regex 已涵蓋
+- 若要做 cron 排程 → 加 lock file 避免重複跑
+- 若要輸出 CSV/JSON → 多寫一個 format 函數就好
