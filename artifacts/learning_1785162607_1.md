+# Telegram Weather Bot
+
+A small Telegram bot that receives a city/place as text, queries wttr.in, and replies with current weather.
+
+## Design
+
+- Python 3.12 standard library only: no `requests`, no `python-telegram-bot`.
+- `wttr_weather.py` owns the weather API, input normalization, translation, and a 10-minute in-process cache.
+- `telegram_bot.py` owns Telegram Bot API calls, long polling, allowlist checks, rate limiting, and graceful shutdown.
+- Long polling is intentional for a headless machine without a public HTTPS endpoint. A serverless deployment should use Telegram webhooks instead.
+- External network boundaries are injectable, so the tests do not need Telegram credentials or network access.
+
+## Requirements
+
+- Python 3.10+ (tested with Python 3.12)
+- A Telegram bot token from BotFather
+- Network access to `api.telegram.org` and `wttr.in`
+
+## Run
+
+```bash
+cd /home/hoonsoropenclaw/.hermes/projects/learning_1785162607_1
+export TELEGRAM_BOT_TOKEN='<your-bot-token>'
+# Recommended: restrict the bot to your numeric Telegram user ID(s).
+export TELEGRAM_ALLOWED_USERS='123456789'
+./run.sh
+```
+
+If `TELEGRAM_ALLOWED_USERS` is omitted, the bot accepts all users and logs a warning. Do not omit it for a publicly reachable bot unless that is intentional.
+
+## Supported messages
+
+- `Taipei` — query Taipei weather
+- `/weather Taipei` — explicit query
+- `/start`, `/help` — usage help
+
+## Optional environment variables
+
+| Variable | Default | Purpose |
+|---|---:|---|
+| `TELEGRAM_ALLOWED_USERS` | unset | Comma-separated numeric user IDs; unset means allow all |
+| `WEATHER_CACHE_TTL_SECONDS` | `600` | Cache lifetime per normalized location |
+| `REQUEST_TIMEOUT_SECONDS` | `40` | Telegram HTTP timeout; weather timeout is capped at 30 seconds |
+| `TELEGRAM_POLL_TIMEOUT_SECONDS` | `25` | Telegram long-poll timeout, 0-50 seconds |
+| `LOG_LEVEL` | `INFO` | Python logging level |
+
+## CLI weather check
+
+The weather client can be exercised independently:
+
+```bash
+python3 wttr_weather.py Taipei
+```
+
+## Tests
+
+```bash
+python3 -m unittest discover -s tests -v
+python3 -m py_compile wttr_weather.py telegram_bot.py
+```
+
+The unit tests use fake HTTP boundaries and never print or require a secret.
+
+## Security notes
+
+- Never commit `TELEGRAM_BOT_TOKEN`.
+- Keep `.env` files outside version control; this project includes only `.env.example`.
+- Use `TELEGRAM_ALLOWED_USERS` to prevent arbitrary users from consuming the weather upstream quota.
+- User location input is length-limited, control-character sanitized, URL-encoded as one path segment, and never interpreted as Telegram HTML/Markdown.
+- The bot logs chat IDs only when processing errors; it does not log message text or tokens.
+
+## Serverless note
+
+Do not run this long-polling process inside a short-lived serverless function. Use a webhook endpoint with HTTPS and persist any required state if moving to Vercel or another stateless platform.
