+# Linux Monitor
+
+`monitor.py` is a dependency-light Linux operations check suitable for cron,
+systemd timers, or a manual health probe.
+
+Checks:
+
+- CPU utilization from `/proc/stat` delta sampling
+- memory utilization from `MemAvailable`
+- load average normalized by CPU count
+- disk usage for explicitly configured paths
+- recent `journalctl` entries at `err` priority or higher
+
+Alerts are emitted when configured thresholds are reached. Exit codes are
+machine-readable:
+
+- `0`: all available checks are healthy
+- `1`: warning or unavailable metric detected
+- `2`: critical threshold detected
+- `3`: configuration/operation failure
+
+## Usage
+
+```bash
+python3 monitor.py --config config.json --dry-run
+python3 monitor.py --config config.json --log-file /var/log/linux-monitor.jsonl
+python3 monitor.py --config config.json --json
+python3 monitor.py --config config.json --webhook-url https://example.invalid/hook
+python3 monitor.py --config config.json --loop 300
+```
+
+The webhook is only called when alerts exist. Keep the URL out of config files
+when possible; pass it through a protected service wrapper or environment-aware
+launcher. The script sets process umask to `077` and applies mode `0600` to its
+JSONL output.
+
+## Configuration
+
+`config.json` is a complete example. YAML (`.yaml`/`.yml`) is also accepted when
+PyYAML is installed; JSON needs no third-party dependencies.
+
+## Tests
+
+```bash
+python3 -m unittest -v test_monitor.py
+python3 -m py_compile monitor.py test_monitor.py
+python3 monitor.py --config config.json --dry-run
+```
+
+## Operational notes
+
+- `journalctl` absence, timeout, or non-zero execution is reported as an
+  unavailable metric rather than confused with a real count of zero.
+- Commands are passed as argument arrays and have timeouts; no shell evaluation
+  is used.
+- Explicit disk paths avoid duplicate bind-mount alerts. The filesystem exclude
+  list is retained for compatibility and future mount discovery.
+- Loop mode exits cleanly on SIGINT/SIGTERM. In loop mode the highest observed
+  exit severity is returned after shutdown.
