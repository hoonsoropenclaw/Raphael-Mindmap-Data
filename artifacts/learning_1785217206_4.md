+# Linux Health Monitor
+
+`linux_health_monitor.py` is a standard-library-only monitor intended for a cron job or a systemd timer.
+
+Checks:
+
+- 1-minute load average
+- available-memory usage from `/proc/meminfo`
+- swap usage
+- filesystem capacity and inode usage
+- error/alert priority entries from `journalctl`
+
+The journal collector uses a finite timeout and bounded output buffer. The monitor never writes into the system journal and does not require root for normal user-readable journal access.
+
+## Exit codes
+
+- `0`: all checks are within thresholds
+- `2`: a threshold was exceeded; output is still a valid report
+- `3`: a collector or monitor error occurred
+
+A non-zero exit code makes it suitable for cron/systemd alerting. `ALERT:` is written to stderr when a threshold is exceeded.
+
+## Examples
+
+```bash
+# One text report
+./linux_health_monitor.py
+
+# Machine-readable output
+./linux_health_monitor.py --format json
+
+# More sensitive thresholds
+./linux_health_monitor.py --disk-percent 80 --memory-percent 85 --journal-errors 3
+
+# Run continuously; terminate with Ctrl-C or SIGTERM
+./linux_health_monitor.py --interval 60
+```
+
+## Cron example
+
+```cron
+*/5 * * * * /absolute/path/linux_health_monitor.py --format json >> /var/log/linux-health-monitor.jsonl 2>> /var/log/linux-health-monitor.err
+```
+
+Use a logrotate rule for the two output files if this runs as a long-term cron job. For a systemd deployment, run it as a oneshot service from a timer and route stdout/stderr to the journal rather than appending indefinitely to a file.
+
+## Design notes
+
+- `journalctl -o json` is parsed defensively; malformed lines are counted rather than crashing the whole report.
+- Journal output is capped at 2 MiB by default; this prevents an unexpectedly large journal response from exhausting memory.
+- Commands are killed after 10 seconds by default.
+- The report is fail-closed: unavailable `/proc`, filesystem, or journal collectors produce `CRITICAL` findings and exit code `3`.
+- Resource findings are initially `OK`, then evaluated against CLI thresholds. This keeps collection separate from policy and makes the behavior testable.
+- The script is Linux-specific by design. It uses `/proc`, `os.getloadavg()`, `statvfs`, and `journalctl`.

+# Implementation Review — Linux Health Monitor
+
+## Scope
+
+Implemented a standard-library-only Linux maintenance monitor in `linux_health_monitor.py`. It checks system resources and error-level systemd journal entries, emits text or JSON, and returns an alertable exit code.
+
+## Architecture
+
+1. Collection layer
+   - `/proc/meminfo` for memory and swap.
+   - `os.getloadavg()` for one-minute load.
+   - `shutil.disk_usage()` and `os.statvfs()` for capacity and inode pressure.
+   - `journalctl --no-pager --quiet --since ... -p err..alert -o json` for recent system errors.
+
+2. Safety layer
+   - Journal subprocess has a bounded timeout (10 seconds by default).
+   - Journal stdout is capped at 2 MiB before parsing.
+   - Timeout and non-zero command exits are converted into explicit `CRITICAL` collector findings.
+   - The monitor fails closed with exit code `3` when a collector cannot provide trustworthy data.
+   - JSON parsing is per-line and malformed journal lines do not crash the entire report.
+
+3. Policy layer
+   - Collection does not decide policy. `evaluate()` applies CLI-configurable thresholds.
+   - Threshold breaches become `WARNING` findings and return exit code `2`.
+   - Healthy checks return exit code `0`.
+
+4. Presentation layer
+   - Human-readable text is the default.
+   - `--format json` produces structured output suitable for log shippers or alerting wrappers.
+   - Alerts are written to stderr so stdout remains machine-readable.
+
+## Threshold defaults
+
+- 1-minute load: `4.0`
+- memory used: `90%`
+- swap used: `80%`
+- filesystem used: `85%`
+- inode used: `85%`
+- journal error entries in the window: `0`
+
+All are overrideable from the command line.
