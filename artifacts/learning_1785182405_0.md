+@dataclass
+class RateLimiter:
+    cooldown_seconds: float = 3.0
+    _last_seen: dict[int, float] = field(default_factory=dict)
+
+    def allow(self, user_id: int, now: float) -> bool:
+        previous = self._last_seen.get(user_id)
+        if previous is not None and now - previous < self.cooldown_seconds:
+            return False
+        self._last_seen[user_id] = now
+        # Keep memory bounded during long-running polling.
+        if len(self._last_seen) > 10_000:
+            cutoff = now - max(self.cooldown_seconds * 10, 60)
+            self._last_seen = {
+                key: value for key, value in self._last_seen.items() if value >= cutoff
+            }
+        return True

+# Telegram Weather Bot
+
+一個不依賴第三方 Python 套件的 Telegram 天氣機器人：接收 `/weather 地點`，透過 Open-Meteo 查詢目前天氣，再以繁體中文回覆。
+
+## 功能
+
+- `/start`、`/help`：顯示使用說明
+- `/weather 台北`、`/weather Tokyo`：查詢目前天氣
+- 使用 Telegram long-polling，不需要公開 IP、網域或 HTTPS webhook
+- 使用 Open-Meteo geocoding + forecast API，不需要天氣 API key
+- API request timeout、暫時錯誤處理、有限次重試間隔
+- 可選 Telegram user/chat allowlist
+- 每位使用者查詢冷卻時間，避免過度呼叫免費 API
+- HTML escape，避免地點名稱造成格式注入
+- SIGINT/SIGTERM graceful shutdown
+- 內建離線 mock 單元測試，不需要 token 或網路
+
+## 檔案
+
+- `telegram_weather_bot.py`：Telegram client、long-polling、訊息處理
+- `weather_api.py`：Open-Meteo API client，可獨立作為 CLI 使用
+- `run.sh`：啟動腳本
+- `test_weather_bot.py`：離線單元測試
+
+## 設定與啟動
+
+1. 在 Telegram 找 `@BotFather`，執行 `/newbot`，取得 bot token。
+2. 在 shell 設定 token（不要寫進程式碼或 Git）：
+
+```bash
+export TELEGRAM_BOT_TOKEN='<你的 Telegram bot token>'
+```
+
+3. 可選：只允許特定 Telegram user ID 使用。留空代表不啟用 allowlist：
+
+```bash
+export TELEGRAM_ALLOWED_USERS='123456789,987654321'
+```
+
+4. 啟動：
+
+```bash
+./run.sh
+```
+
+也可以直接使用：
+
+```bash
+python3 telegram_weather_bot.py
+```
+
+## 測試與驗證
+
+```bash
+python3 -m py_compile weather_api.py telegram_weather_bot.py test_weather_bot.py
+python3 test_weather_bot.py

+```
+
+最後一行需要網路，但不需要 Telegram token。Telegram bot 本身需要先設定 `TELEGRAM_BOT_TOKEN` 才能啟動。
+
+## 實作思路與設計決策
+
+### 1. 為什麼用 Python standard library
+
+這個需求只有「接收訊息 → 呼叫兩個 HTTP API → 回傳訊息」三段流程。使用 `urllib.request`、`json`、`signal`、`dataclass` 已足夠，避免引入 `requests`、`python-telegram-bot` 等額外依賴，降低安裝、更新與部署失敗面。
+
+### 2. 為什麼選 long-polling
+
+機器人預期在 headless 主機上執行，未假設有公開網域與 HTTPS 憑證。long-polling 可直接由主機向 Telegram 發起連線，部署比 webhook 簡單；如果未來要支援大量流量或低延遲，再改 webhook。
+
+### 3. API 流程
+
+1. 將使用者輸入 trim、壓縮連續空白，拒絕空值、控制字元與過長輸入。
+2. 呼叫 Open-Meteo geocoding API，把地點轉成 latitude/longitude。
+3. 呼叫 Open-Meteo forecast API，取得目前溫度、體感、濕度、風速、降水量與 weather code。
+4. 以本機繁體中文 weather-code 對照表格式化結果。
+5. 以 Telegram `sendMessage` 搭配 HTML parse mode 回覆。
