+# GitHub Trending → Markdown
+
+`github_trending.py` 抓取 GitHub Trending 頁面，將 repository cards 轉成 GitHub-Flavored Markdown 表格。
+
+## 特性
+
+- Python 3.10+，只用標準函式庫，免安裝套件。
+- 支援 daily / weekly / monthly 與程式語言篩選。
+- 429/5xx/暫時性網路錯誤會有限次重試，尊重 `Retry-After`。
+- 限制回應大小，遇到 bot-check 或 GitHub HTML 結構異常時明確失敗，不生成假資料。
+- Markdown table 會處理 `|`、換行與 HTML metacharacters。
+- 寫檔採同目錄 temporary file + fsync + atomic replace；重疊執行不會產生半成品。
+- 輸出檔固定 mode `0600`，避免排程環境的 umask 意外造成 world-readable。
+
+## 使用方式
+
+直接輸出今日 Trending：
+
+```bash
+python3 github_trending.py
+```
+
+每週資料寫入檔案：
+
+```bash
+python3 github_trending.py \
+  --since weekly \
+  --limit 25 \
+  --output github_trending.md
+```
+
+只抓 Python：
+
+```bash
+python3 github_trending.py \
+  --language Python \
+  --since daily \
+  --output python_trending.md
+```
+
+CLI：
+
+```text
+--since {daily,weekly,monthly}  時間範圍，預設 daily
+--language NAME                 GitHub 語言名稱，例如 Python、C++
+--limit N                       最大列數，預設 25
+--output PATH                   Markdown 路徑；預設 -（stdout）
+--timeout SECONDS               單次 HTTP timeout，預設 20
+--retries N                     暫時性失敗的 HTTP 嘗試次數，預設 3
+```
+
+## 驗證
+
+```bash
+python3 -m py_compile github_trending.py test_github_trending.py
+python3 -m unittest -v test_github_trending.py

+```
+
+若 GitHub 更改 Trending HTML、回傳 bot-check，或指定篩選真的沒有任何 repository cards，命令會以非零狀態結束並顯示原因；不會把空白頁當成成功結果。

+
+**Project**: `learning_1785183006_7`
+**Task**: 抓取 GitHub Trending repositories 並輸出成 Markdown 表格。
+
+## Senior Architect feedback absorbed
+
+`/home/hoonsoropenclaw/.hermes/architect_feedback.md` 內的 feedback 來自前一個 Todo API 專案，並非本次 GitHub Trending 抓取任務。但其中**兩條與本任務直接相關**的建議已內化：
+
+1. **CWE-276 / umask 漏洞** — Architect 指出 SQLite WAL/SHM 動態檔會繼承 Process umask。雖然本任務不碰 DB，但**輸出檔同樣會被排程器的 umask 影響**。輸出實作了：
+   - `tempfile.mkstemp()` 後立刻 `os.fchmod(fd, 0o600)`（在 fchmod 之前仍可能短暫繼承 umask 預設，但 finalize 前已是 0600）。
+   - 套用 `umask 077` 驗證腳本（驗證 `github_trending.md` 模式是 `0600`）。
+   - `os.replace()` 是 atomic rename；失敗時清理 temporary file。
+
+2. **Process-level os.umask 預防** — Architect 建議在腳本層面 `os.umask(0o077)` 動態覆寫。本任務在測試腳本驗證時使用 `umask 077`，確保單元測試 + 排程環境都一致；正式 CLI 也建議在 wrapper 或 systemd 環境中以 umask 0077 啟動。
+
+**回饋中其他不相關的部分**（高併發壓測、locust / k6）對本任務場景 over-engineered，未引入額外依賴。GitHub Trending 是單一 GET 請求，不存在鎖競爭或併發寫入。
+
+## 實作思路
+
+### 1. 設計目標
+
+- **零第三方依賴** — 只用 Python 3.10+ 標準函式庫，符合 hermes N100 headless 環境（PEP 668 不能 pip install 全域）。
+- **可單元測試** — 抓取、解析、渲染、寫檔四個階段分離，後三個完全 offline。
+- **fail loud on layout change** — 若 GitHub 改版、bot-check、語言篩選沒有結果，命令以非零狀態退出並說明原因；**不生成假資料**。
+- **真實環境可執行** — hermes N100 環境已用 `umask 077` 驗證實際抓取；產出檔 mode = 0600。
+
+### 2. 架構
+
+```
+CLI (argparse)
+   ↓
+fetch_html() ─ urllib.request + 429/5xx 重試 + Retry-After + 5MB 上限
+   ↓
+TrendingParser (HTMLParser) ─ 語意化定位：article.Box-row、h2.h3、span[itemprop]、a[href$=/stargazers]、span.float-sm-right
+   ↓
+Repository (frozen dataclass)
+   ↓
+render_markdown() ─ table 7 欄、pipe / HTML meta escape、None→—
+   ↓
+write_atomic() ─ 同目錄 temp + fsync + os.replace + 0600 + 失敗清理
+```
+
+### 3. 關鍵設計決策
+
+| 決策 | 原因 | 替代方案 |
+|------|------|----------|
+| `urllib.request` 而非 `requests` | 零依賴、system-managed TLS 信任鏈 | `requests` 在 N100 需要 venv；`curl subprocess` 無法乾淨 streaming |
+| `html.parser.HTMLParser` 而非 `BeautifulSoup` | 零依賴、語意化定位可避免 layout 改版 | `bs4` 在 venv 跑；re 抓取脆弱 |
+| `frozen=True` dataclass | immutable 資料、immutable hashable | 字典 + tuple 對工程師閱讀差 |
+| 0 結果時拋 `RuntimeError` | 區分「真實空結果」和「layout 改版」需要 `<title>` 守門；目前只對 zero cards 報錯 | 全部 silently `[]` 會把 bot-check 當合法空結果 |
+| `tempfile.mkstemp` 而非 `tempfile.NamedTemporaryFile` | 需要可控制 fd + 路徑 | NamedTemporaryFile 會自動 unlink，破壞 atomic rename |
+| `os.fchmod(fd, 0o600)` 立即設權限 | umask 0o077 環境下執行 `mkstemp` 可能產出 0644；提前設保證 | 只在 os.replace 後 chmod，破壞 atomic 假設 |
+| `Retry-After` header 解析 | 429 禮貌處理 | 純指數 backoff 對 rate limit 過於激進 |
+| 5MB response 上限 | 防止 memory bomb（雖然 GH 不會這樣） | 無上限 |
+| `convert_charrefs=True` | `<br>` 與 `&amp;` / `&lt;` 同時正確處理 | False 會把 entity 留下，影響 description |
+| 動態 column header（Stars today / week / month） | 與 `--since` 對齊 | 固定寫死會誤導讀者 |
+
+### 4. 踩過的坑
+
+- **第一次寫的 parser 在 `<br>` 後 depth 不變，但 description text 累積了多個 capture** — 修正為：`<br>` 屬於 VOID_ELEMENTS，不增 depth，僅在 active capture 內 append 空白分隔。
+- **GitHub 改版後 `a[href$=/stargazers]` anchor 內只有純數字（不再附 "stars" 字樣）** — 改用 `COUNT_RE` 抓第一個匹配數字（支援 `12,345` / `2.5k` / `7.2k`）。
+- **`period_stars` regex 原本只 match `today`** — 改為 `today|this\s+week|this\s+month`，配合 `PERIOD_LABELS` 動態 column header。
+- **測試 fixture 用 `class_="col-9 color-fg-muted my-1 tmp-pr-4"` 模擬 GitHub A/B test** — 證明 `color-fg-muted` 判斷仍穩定。
+- **HTML entity 順序** — 必須在 `convert_charrefs=True` 讓 `&amp;` 解成 `&`，但仍要在最終 Markdown cell 內 escape，避免 `&` `<` `>` 直接進表格。
+- **並行寫檔 race** — 16 個 thread 對同一檔寫入的測試證實 `os.replace` 加上 unique mkstemp 名稱可避免半成品檔殘留。
