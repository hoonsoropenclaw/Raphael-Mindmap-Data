+# BRIDGE/OS — Product Requirements Document
+
+Status: approved by safe default after the scope-selection prompt returned “use your best judgement and proceed”

+Task: 使用 Playwright 實現跨平台桌面自動化工具
+
+## 1. Product definition
+
+BRIDGE/OS is a local-first Playwright automation deck that runs the same browser workflow on Windows, macOS, and Linux. A user builds a workflow in an offline HTML control surface, validates it, runs it through a loopback-only Node.js service, watches live telemetry, and downloads screenshots or JSON reports.
+
+“Desktop automation” in this product means a desktop-hosted tool for automating browser and WebView-style interfaces. Playwright does not provide a portable API for arbitrary native windows such as Finder, Notepad, or Windows Explorer. Native GUI automation is intentionally out of scope rather than being falsely advertised.
+
+## 2. Reused knowledge
+
+| Existing module | Reused decision |
+|---|---|
+| `playwright_advanced_web_automation` | Register request/console listeners before navigation; prefer robust selectors; structured JSON output; screenshot artifacts |
+| `cross_platform_application_development` | Use platform-neutral paths, explicit platform reporting, and graceful behavior in headless environments |
+| `task_and_workflow_automation` | Decompose workflows into independently verifiable steps; use consistent event envelopes; close resources deterministically |
+| `playwright-skill` | Parameterized target URLs, explicit waits, visible/headless choice, real browser verification |
+| `tdd-workflow` | RED → GREEN → REFACTOR; unit + integration + browser E2E; 80% coverage target |
+| `security-review` | Input allowlists, bounded request bodies, no arbitrary eval/shell, safe errors, local-only service |
+
+## 3. Target users and stories
+
+1. As a QA engineer, I can compose navigation and interaction steps without writing JavaScript.
+2. As an operations user, I can run the same workflow on Windows, macOS, or Linux with `npm start`.
+3. As a developer, I can export/import a stable JSON workflow and invoke it through a documented HTTP API.
+4. As a reviewer, I can inspect step-level timestamps, extracted values, failures, and screenshot artifacts.
+5. As a security-conscious user, I can trust that a workflow cannot execute shell commands or JavaScript evaluation.
+
+## 4. Functional requirements
+
+### 4.1 Workflow model
+
+- Browser engines: `chromium`, `firefox`, `webkit`.
+- Runtime flags: `headless`, viewport width/height, default timeout, optional slow motion.
+- Maximum 50 ordered steps.
+- Supported actions:
+  - `goto`
+  - `click`
+  - `fill`
+  - `press`
+  - `select`
+  - `check`
+  - `uncheck`
+  - `hover`
+  - `waitFor`
+  - `assertText`
+  - `extractText`
+  - `screenshot`
+- Per-step `continueOnError` and optional timeout.
+- JSON import/export and a built-in self-test workflow.
+
+### 4.2 Runner
+
+- Validate and normalize every workflow before launch.
+- Create an isolated browser context for each run.
+- Emit lifecycle and step events without logging filled values.
+- Auto-dismiss browser dialogs and report them.
+- Write `report.json` atomically on both success and failure.
+- Store screenshots beneath `artifacts/<run-id>/` with server-generated safe paths.
+- Close context and browser in `finally`, including cancellation.
+
+### 4.3 Local API
+
+- Bind to loopback by default.
+- `GET /api/health`
+- `POST /api/validate`
+- `POST /api/runs`
+- `GET /api/runs`
+- `GET /api/runs/:id`
+- `GET /api/runs/:id/events` (Server-Sent Events)
+- `POST /api/runs/:id/cancel`
+- `GET /artifacts/:runId/:filename`
+- One active run at a time; bounded in-memory history.

+# BRIDGE/OS
+
+Local-first, cross-platform Playwright browser automation deck.
+
+BRIDGE/OS turns a JSON workflow into a real Playwright run with step telemetry, extracted values, screenshots, and a durable report. The same Node.js project runs on Windows, macOS, and Linux.
+
+Important boundary: Playwright automates browsers and WebView-style interfaces. It is not a portable controller for arbitrary native desktop windows such as Finder, Notepad, or Windows Explorer.
+
+## What is included
+
+- Self-contained automation dashboard: `public/index.html`
+- 12 allowlisted workflow actions
+- Chromium, Firefox, and WebKit engine selection
+- Headless/headed mode, viewport, timeout, and slow-motion controls
+- Step add, duplicate, reorder, delete, JSON import/export
+- Validation API and live Server-Sent Events telemetry
+- Extracted values, screenshots, and atomic `report.json`
+- Loopback-only HTTP service with strict CSP nonce and safe artifact serving
+- Unit, HTTP integration, and real Chromium E2E tests
+- Windows/macOS/Linux CI matrix
+
+## Quick start
+
+Requirements:
+
+- Node.js 20 or newer (Node 22 recommended)
+- Approximately 300–500 MB for one Playwright browser binary
+
+```bash
+npm install
+npm run install:chromium
+npm start
+```
+
+Open:
+
+```text
+http://127.0.0.1:4317
+```
+
+The dashboard starts with a deterministic local demo. Click `Validate`, then `Run`. No external site or credential is required.
+
