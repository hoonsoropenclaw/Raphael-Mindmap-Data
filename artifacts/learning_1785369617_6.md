+## 🎯 設計決策（每個都標原因）
+
+### 1. 純 stdlib、無任何外部相依
+- **原因**：N100 headless 環境的 Python 是系統 `python3`，PEP 668 不允許直接 `pip install`，需要 venv。教學原型要可即跑即驗，純 stdlib = 零安裝摩擦。
+- **代價**：HTTP server 用 `http.server`（低階），實際專案會用 FastAPI / uvicorn。
+
+### 2. 政策模型採「user → roles → (pattern, action)」兩層 + global_deny
+- **原因**：最常見的 RBAC 模式。policy_admin 寫起來直觀（給某人某個 role、給某個 role 某些資源/動作），debug 也容易（看哪個 role 的哪條 rule 命中）。
+- **代價**：沒支援 ABAC（屬性條件如 time-of-day / IP / owner 必須在外部先過濾）。
+
+### 3. Pattern 用 `fnmatch` glob（`*` `?` `[seq]`）
+- **原因**：fnmatch 是 stdlib、無需 re.compile、易讀。
+- **代價**：不是正規表達式語法（如 `doc:\d+:read` 不支援）；大規模政策（>10k rules）應改 compiled regex + trie。
+
+### 4. Pattern 編譯結果走 LRU cache
+- **原因**：`check()` 是 hot path（每個 HTTP 請求都會跑）。fnmatch.fnmatchcase 雖 O(n) 但常被呼叫。
+- **觀察**：smoke 壓測 1000 次，cache hit 0% 是因為每次 resource 都不同（`doc:0:read` 到 `doc:999:read` 全 unique）— 這**是預期行為**，真實流量會大量重複。
+
+### 5. 拒絕優先（deny-by-default + global_deny 最高）
+- **原因**：資安原則「no implicit allow」。沒命中任何 rule = DENY。
+- **代價**：寫 policy 時很容易「忘了給 rule 就 403」，但這正是預期行為。
+
+### 6. Audit log 用 `collections.deque(maxlen=N)`
+- **原因**：固定記憶體、不會 OOM。
+- **代價**：滿了會擠掉舊的。真實環境應送 Kafka / OpenSearch。
+
+### 7. Token 用 base64（**不是 JWT**，**不安全**）
+- **原因**：避免引入 `PyJWT` / `python-jose` 相依。
+- **代價**：任何人都能偽造 `user:admin`。**正式環境必須換 JWT + JWKS**（見下「未實作」）。
+
+### 8. Policy 存在記憶體、不寫 DB
+- **原因**：教學原型。
+- **代價**：restart 就消失。真實環境要寫 Postgres / etcd。
