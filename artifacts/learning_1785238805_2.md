+# Todo API (FastAPI + SQLite + Rate Limit)
+
+簡單的待辦事項 REST API,具備:
+
+- FastAPI 框架
+- SQLite 資料庫 (透過 SQLAlchemy)
+- Rate limiting (slowapi, IP-based)
+- 單元測試 (pytest + httpx)
+
+## 啟動
+
+```bash
+cd todo_api
+python3 -m venv venv
+venv/bin/pip install -r requirements.txt
+venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
+```
+
+開啟 `http://localhost:8000/docs` 查看 Swagger UI。
+
+## API 端點
+
+| 方法 | 路徑 | 說明 |
+|------|------|------|
+| GET | `/todos` | 列出所有 todos |
+| GET | `/todos/{id}` | 取得單一 todo |
+| POST | `/todos` | 新增 todo |
+| PUT | `/todos/{id}` | 更新 todo |
+| DELETE | `/todos/{id}` | 刪除 todo |
+
+## Rate Limit
+
+預設每個 IP 每分鐘最多 30 次 POST 請求。

+def create_todo(db: Session, payload: schemas.TodoCreate) -> models.Todo:
+    todo = models.Todo(
+        title=payload.title,
+        description=payload.description,
+        completed=payload.completed,
+    )
+    db.add(todo)
+    db.commit()
+    db.refresh(todo)
+    return todo
+
+
+def update_todo(
+    db: Session, todo_id: int, payload: schemas.TodoUpdate
+) -> models.Todo | None:
+    todo = db.get(models.Todo, todo_id)
+    if not todo:
+        return None
+    data = payload.model_dump(exclude_unset=True)
+    for key, value in data.items():
+        setattr(todo, key, value)
+    db.commit()
+    db.refresh(todo)
+    return todo
+
+
+def delete_todo(db: Session, todo_id: int) -> bool:
+    todo = db.get(models.Todo, todo_id)
+    if not todo:
+        return False
+    db.delete(todo)
+    db.commit()
+    return True

    實作思路重點
    
    1. 分層架構 (Separation of Concerns)
    - crud.py 純函式、無 HTTP 耦合 → 8 個 unit test 不用跑 server
    - schemas.py (Pydantic) 負責驗證 + 序列化,跟 DB model 解耦
    - main.py 只做 wiring,商業邏輯在 crud
    
    2. App factory pattern
    - create_app() 函式可在測試時注入不同 DB,模組級 app 給正式環境用
    - 但這次踩到坑:在 create_app() 內 @limiter.limit(...) 會在每次呼叫時重複套裝飾器,導致同一個 endpoint 被註冊多次,storage 一次 hit 算 2 次。修正:把 handler 拉到 module level 只裝飾一次,再以 app.add_api_route(...) 註冊路由。
    
    3. slowapi rate limit 三個地雷
    - default_limits 跟 route_limits 用同樣的 key+scope 時會疊加在同一個 storage bucket,導致 limit 數值錯亂 (10/minute 第 6 次就爆)
    - 修正:不設 default_limits,全部由 endpoint 顯式宣告
    - limiter.reset() 在 fixture 與測試後清理,避免跨測試污染
    - TestClient 的 remote address 是 "testclient" (slowapi 內部識別),不用 mock
    
    4. 測試 DB 策略
    - in-memory SQLite (:memory:) 雖然常用,但 SQLAlchemy 不同 engine 的 connection pool 不共享,FastAPI get_db dependency override 後仍可能走別的連線
    - 改用 tempfile.NamedTemporaryFile 創獨立檔案 DB,fixture yield session 後 unlink,簡單可靠
    
    5. 依賴注入 + 測試隔離
    - app.dependency_overrides[get_db] = _override_get_db 把測試 session 注入 endpoint
    - TestClient context manager 確保 lifespan / middleware 正確觸發
    - limiter.reset() 在 fixture 進 / 出都執行一次,避免測試順序敏感
