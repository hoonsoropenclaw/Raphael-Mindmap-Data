+``0022``, which would yield ``0644`` files (world-readable). For a DB that
+may store sensitive content, that is a data-exfiltration hole.
+
+We mitigate at three layers:
+
+1. **Process umask** — `init_db()` calls `os.umask(0o077)` once at startup
+   so any subsequently-created file (including -wal/-shm) inherits 0600.

+   directory and chmod anything that drifted back to a permissive mode.

+* **Bursty traffic** — clients legitimately want to send a quick flurry

+* **Sustained rate limit** — the steady-state cap that protects the
+  service from accidental or malicious overload.
+
+**Why a single in-process limiter?** For the scope of a single-node demo
+API this is the simplest correct design. The bucket state lives in memory,
+gated by a `threading.Lock`. Both the FastAPI request handler (which runs

+# Todo API
+
+A small but production-shaped FastAPI todo service.
+
+## Highlights
+
+- **Persistence**: SQLite, single-connection serialized writer, WAL mode.
+  Main db file and `-wal`/`-shm` sidecars are all created with mode `0600`
+  (CWE-276 mitigation — see `app/db.py`).
+- **Rate limiting**: per-key token bucket with `Retry-After` and
+  `X-RateLimit-*` headers. Keys are picked from `X-API-Key` →
+  `X-Forwarded-For` → peer IP.
+- **Validation**: pydantic v2 with whitespace stripping and length caps.
+- **Lifecycle**: `lifespan` context manager for graceful startup/shutdown.
+- **Concurrency**: `threading.Lock` around the limiter registry so that
+  threaded FastAPI handlers and `asyncio.gather` burst tests see a
+  consistent view.
+- **Configuration**: env vars only (no CLI flags → CWE-214 safe).
+
+## Quick start
+
+```bash
+pip install -r requirements.txt
+python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
+curl http://127.0.0.1:8000/healthz
+curl -X POST http://127.0.0.1:8000/todos \
+  -H "Content-Type: application/json" \
+  -d '{"title": "buy oat milk"}'
+```
