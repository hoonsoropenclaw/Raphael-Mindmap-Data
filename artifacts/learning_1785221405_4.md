+## 3. 關鍵架構決策
+
+### 3.1 為什麼 API + HTML 兩條路?
+
+GitHub **沒有**公開的 trending-list REST endpoint。`/trending` 是 server-side
+rendered HTML,所以選項是:
+
+1. **Search API (`/search/repositories`)** — 結構化 JSON、易 parse、但語意是
+   "最近 X 天新興熱門"而非官方 trending
+2. **HTML scrape (`/trending`)** — 貼近官方定義、但 HTML 結構常變、脆弱
+
+折衷:**API first → HTML fallback**。`fetch_trending()` 內部 try API,失敗或
+使用者明示 `--no-api` 才走 HTML。
+
+### 3.2 為什麼 `convert_charrefs=True` + 手動 normalize class?
+
+`html.parser.HTMLParser(convert_charrefs=True)` 會 **normalizes attribute whitespace** —
+e.g. `class="text-bold"` 變成 `class="t e x t - b o l d"`。
+**這是 silent source of bugs** — substring check `"d-inline-block" in classes`
+會永遠 False,即使 HTML 是對的。
+
+修法(在 `handle_starttag`):
+```python
+classes = "".join((a.get("class", "") or "").split())  # 去所有 whitespace
+```
+
+debug 這 bug 花了 1 個 round (先懷疑是 state machine 邏輯錯,再懷疑 SVG 影響
+`period_text` state,最後才發現是 class 字串)。這是 senior reviewer 點名
+`POSIX compatibility` 之外的另一個常見 **parser-level silent breakage**。
+
