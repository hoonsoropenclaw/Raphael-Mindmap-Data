+## 1. Delivery scope
+
+This workspace contains a complete Vite + React implementation of a reducer-driven operations board called **Signal Desk**. It is intentionally implemented as a small application rather than a static mock so the complex interaction model can be exercised locally.

+## 3. State-management decisions
+
+### Single reducer as the source of truth
+
+The board has enough coordinated transitions that several independent `useState` calls would make state drift likely. `useReducer` owns:
+
+- normalized `cards: Record<string, Card>`
+- lane ordering in `columnOrder: Record<LaneId, string[]>`
+- transient interaction state (`draggedCardId`, `dragOver`)
+- view filters and selected detail card
+- bounded undo/redo history
+
+The reducer only accepts explicit action payloads such as `payload.cardId`, `payload.targetLane`, and `payload.targetIndex`. This avoids the action-shape drift that commonly causes silent selection or drag failures.
+
+### Normalized board data
+
+Cards are stored by ID and lanes store ordered ID arrays. Moving a card therefore updates one card record and two order arrays instead of recursively cloning a nested board tree. `selectVisibleCards` and the `visibleByLane` hook projection derive the rendered view without mutating source data.
+
+### Immutable snapshots
+
+Every business mutation runs through `cloneState()` and `commit()`. History snapshots contain cards, lane order, and the meaningful UI selection, but deliberately exclude the history stack itself and transient drag state. Past/future stacks are capped at 50 entries.
+
+This prevents:
+
+- shallow-reference mutation of the initial state
+- recursive history snapshots
+- undo stacks polluted by drag-over or filter events
+
+### Persistence
+
+Cards, lane order, and filters are saved to `localStorage` under `signal-desk::state-v1` after a 250 ms debounce. On restore, history is reset so an old session cannot undo into an incompatible state. Storage errors are treated as progressive-enhancement failures; the live UI still works.
+
+## 4. Interaction model
+
+- Search is derived from title, description, owner, and tags.
+- Priority and owner filters compose with search.
+- `/` focuses search unless the user is already typing.
+- `Escape` closes the detail panel.
+- `⌘/Ctrl + Z` undoes; `Shift + ⌘/Ctrl + Z` redoes.
+- Native HTML drag-and-drop moves cards between lanes and calculates insertion position from card midpoints.
+- The detail panel edits title, context, priority, and due date.
+- Invalid empty titles expose an error message and `aria-invalid`; saving shows loading then success feedback.
+- Archiving is reversible through undo rather than an unnecessary confirmation modal.
+- List view presents the same derived state without duplicating the data model.
+
+## 5. Visual system
+
+The visual direction is restrained editorial / workbench:
+
+- warm linen paper background rather than a generic white SaaS canvas
+- Playfair Display for editorial hierarchy, DM Sans for UI text, DM Mono for metadata
+- one accent hue (burnt coral), plus muted amber and sage lane signals
+- CSS custom properties for all colours, typography, motion timing, radii, and shadows
