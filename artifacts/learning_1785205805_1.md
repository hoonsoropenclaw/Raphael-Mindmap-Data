+The component is a project command center with task metrics, status filters, search, selection/inspection, task creation, task status transitions, simulated synchronization, toasts, empty state, responsive layout, keyboard focus styling, and reduced-motion support.
+
+## Architecture
+
+### 1. State ownership
+
+A single `useReducer` owns cross-feature state:
+
+- `tasks`: task entities
+- `filter`: status filtering
+- `query`: live text search
+- `selectedId`: inspector selection
+- `isAddOpen`: creation dialog visibility
+- `isSyncing`: asynchronous synchronization state
+- `toast`: transient feedback
+
+Reducer actions make state transitions explicit and auditable. The `advance` action is the central state machine for task progress:
+
+`todo -> active -> done -> todo`
+
+Local form fields remain local to `NewTask` through `useState`; they are not promoted to global state because no sibling consumes them.
+
+### 2. Derived state
+
+`useMemo` derives:
+
+- filtered/searched task results
+- status counts used by the metric strip
+
+This prevents duplicated state and eliminates synchronization bugs between task data, counters, and filters.
+
+### 3. Side effects
+
+Two side-effect boundaries are present:
+
+- Toast auto-dismiss uses an effect with timer cleanup.
+- Sync simulation uses a stable `useCallback`, toggling a disabled/loading state before success feedback.
+
+No visual animation loop is implemented in JavaScript; all micro-interactions are handled by CSS transforms and transitions.
+
+### 4. Component boundaries
+
+- `ProjectCommandCenter`: reducer, derived state, feature orchestration
+- `TaskRow`: task list presentation and event isolation
+- `NewTask`: controlled creation form
+- `Metric` / `Detail`: compact presentation primitives
+
+The boundaries keep feature logic centralized without creating excessive abstraction for a single deliverable.
+
+## UI and CSS decisions
+
+- Warm neutral editorial palette with one orange accent; avoids generic purple/blue dashboard styling.
+- Asymmetric task-board + inspector layout instead of equal card columns.
+- Metrics use divided regions rather than floating generic cards.
+- Responsive breakpoints collapse the inspector below the board and preserve touch-friendly controls.
+- `100dvh` is used for viewport sizing.
+- Focus uses visible `outline`, not shadow-only focus.
+- `prefers-reduced-motion` disables transitions and animation durations.
+- Interactive feedback uses GPU-safe `transform` changes.
+- Loading, empty, selected, modal, disabled, and toast states are represented.
