+    TIMEOUT = 8

+    def get_current(self, city: str) -> WeatherReport:

+# Telegram 天氣機器人 — 實作思路與反思
+
+## 1. 任務
+接收 Telegram 文字訊息 → 解析為城市 → 查天氣 API → 回傳結果給使用者。
+
+## 2. 架構決策
+
+### 2.1 為什麼把 `weather.py` 跟 `bot.py` 拆開？
+- **單一職責**: bot.py 只管 Telegram 協定（更新解析、handler 註冊、reply）；weather.py 只管天氣資料來源
+- **可測試性**: weather.py 用純函式 + Protocol, 任何 handler 測試都可以塞 mock provider, 不必碰 Telegram
+- **可替換**: 未來要加 Yahoo 天氣、氣象署 API, 只要新寫一個實作 `WeatherProvider` 的 class, build_provider() 切換即可
+
+### 2.2 為什麼用 Protocol 而非 ABC？
+- Python 3.12 + duck typing 風格, Protocol 只要結構對就過
+- ABC 強迫繼承、import 順序耦合; Protocol 只要 `from weather import WeatherProvider` 寫 type hint 就好
+- 測試時 mock 直接實作 duck-typed 介面, 不必繼承
+
+### 2.3 為什麼有 Mock provider?
+- **無 API key 也能 demo / 跑測試** — USER 在沒申請 OWM key 的情況下, `python3 bot.py` 還是能跑（TPE / TYO / LON 三個 mock 城市）
+- **測試可控** — mock 回傳固定資料, 測試案例可預期、可重現
+- **生產 fallback** — OWM API 短暫掛掉時, 不會直接 500 給使用者
+
+但明確標記 `source: "mock"`, **絕不**對使用者假裝是 OWM 資料 — 透明度。
+
+### 2.4 錯誤處理統一收口在 WeatherError
+- bot.py handler 只 catch 一個例外, **不必**知道底下是網路掛、404、401 還是 JSON 壞掉
+- 每種錯誤訊息給使用者看都友善（中文 + 動作者建議）
+- 例外鏈 `raise ... from exc` 保留原始 stacktrace 給 log, 但 reply 給使用者的是乾淨中文
+
+### 2.5 為什麼用 `frozen=True` 的 dataclass?
+- WeatherReport 是值物件, 不該被改
+- `frozen` 防呆, hashable 之後可放 cache / set
+
+### 2.6 為什麼 `requests.Session` 而不是裸 requests.get?
+- keep-alive 連線複用, Telegram bot 高頻小查詢省 latency
+- 測試時可以 patch `Session.get`, 不污染全域 requests
+
+## 3. 沒做的事（明確邊界）
+
+### 3.1 沒有持久化
+- 不存使用者偏好、不存查詢歷史
+- 原因: 任務範圍只要「接文字查天氣回傳」, 沒要求個人化
+- 若未來要加: 用 SQLite + repository pattern 抽出去, 不污染 handler
+
+### 3.2 沒做 rate limit
+- OWM free tier = 60 req/min, 一個使用者手動查不會爆
+- 大量濫用才需要 — 那時候再加 token bucket middleware
+
+### 3.3 沒做 inline keyboard / 多城市
+- 任務範圍只要「回傳」, 用 plain text 就夠
+- 之後要加: ReplyKeyboardMarkup + ConversationHandler
+
+### 3.4 沒用 webhook, 用 polling
+- 在 N100 / 容器內跑、用 polling 最簡單, 不需要 HTTPS endpoint
+- 若部署到雲端: 改 webhook, 用 `run_webhook()` 取代 `run_polling()`
+
+### 3.5 沒做國際化（i18n）
+- 訊息直接寫繁中, 不抽 .po 檔
+- 範圍小, 過早抽象比不抽象更糟
+
+## 4. 安全性
