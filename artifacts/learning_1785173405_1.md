+def read_meminfo() -> dict[str, int]:
+    data: dict[str, int] = {}
+    try:
+        for line in Path('/proc/meminfo').read_text().splitlines():
+            key, _, rest = line.partition(':')
+            parts = rest.strip().split()
+            if parts and parts[0].isdigit():
+                data[key] = int(parts[0]) * (1024 if len(parts) > 1 and parts[1] == 'kB' else 1)
+    except (OSError, ValueError):
+        pass
+    return data
+

+def check_resources(report: Report, args: argparse.Namespace) -> None:
+    mem = read_meminfo()
+    total = mem.get('MemTotal', 0)
+    available = mem.get('MemAvailable', mem.get('MemFree', 0))
+    used_pct = (100 * (total - available) / total) if total else None
+    report.metrics['memory_used_percent'] = round(used_pct, 2) if used_pct is not None else None

+        report.findings.append(Finding('memory', 'unknown', 'unable to read /proc/meminfo'))

+# Linux Health Checker — 實作思路與維運說明
+
+## 目標
+
+`linux_health_check.py` 是一個零第三方依賴的 Python 3 維運檢查器，週期性檢查 Linux 主機的記憶體、CPU load、檔案系統用量，以及最近的 error/alert 等級系統日誌；超過閾值時輸出警告，並可選擇 POST 到 webhook。
+
+## 架構
+
+1. 資源檢查：讀取 `/proc/meminfo`，用 `os.getloadavg()` 與 `os.cpu_count()` 將 load 正規化，使用 `shutil.disk_usage()` 檢查指定掛載點。
+2. 日誌檢查：優先呼叫 `journalctl --since ... -p err..alert`；systemd 不可用時降級讀取 `/var/log/syslog` 或 `/var/log/messages`。
+3. 結果模型：`Finding` 保存 check、severity、message、value、threshold；`Report` 保存主機、時間、metrics 與 findings。
+4. 告警：預設 stdout 供 cron/systemd 讀取；`--webhook` 只在存在 warning 時 POST JSON。
+5. 退出碼：0 = 沒有 warning；2 = 有 warning。`unknown` 狀態不會假裝成健康，會被明確輸出。
+
+## 設計決策
+
+- 使用 Python standard library，避免在維運主機安裝額外套件。
+- JSON 模式適合監控代理與日誌收集器；人類可讀模式適合手動執行。
+- 所有外部命令與網路呼叫都有 timeout；journalctl 失敗時有檔案日誌 fallback。
+- 不自行修改系統設定、不刪除日誌、不需要 root 權限（讀取受限日誌時會清楚報告 fallback/unknown）。
+
+## 使用範例
+
+```bash
+python3 linux_health_check.py
+python3 linux_health_check.py --json
+python3 linux_health_check.py --memory 85 --disk-threshold 80 --log-errors 5
+python3 linux_health_check.py --webhook https://example.invalid/health-hook
+```
+
+## 排程建議
+
+每 5 分鐘執行一次，將 stdout/stderr 寫入 journald 或監控系統；不要把 webhook URL（可能含 secret）直接提交到 Git，應由 systemd EnvironmentFile、受限權限的設定檔或 secret manager 注入。
+

+

+- 在無 `journalctl` 的測試環境，應能嘗試 syslog fallback，而不是直接崩潰。
