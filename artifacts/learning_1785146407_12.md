+"""Database layer — a thin SQLite wrapper using the stdlib only.
+
+Design notes
+------------
+* We deliberately avoid SQLAlchemy. A todo API is small enough that the
+  overhead of an ORM doesn't pay off, and using `sqlite3` directly keeps
+  the code path easy to read and easy to test.
+* Connection lifetime is per-request: `get_db()` opens a connection, yields
+  it, and closes it in the `finally`. `check_same_thread=False` lets us
+  share the connection object across the request/response cycle on the
+  same thread, which is the FastAPI dependency-injection pattern.
+* `row_factory = sqlite3.Row` lets us return dict-like rows from the

+def connect(db_path: str = DEFAULT_DB_PATH) -> sqlite3.Connection:
+    """Open a SQLite connection with sane defaults.
+
+    `PARSE_DECLTYPES | PARSE_COLNAMES` makes SQLite return `datetime`
+    objects for columns declared as `TIMESTAMP` instead of raw strings —
+    this is what keeps `created_at` / `updated_at` round-trippable through

+"""Sliding-window in-memory rate limiter.
+
+Why in-memory?
+--------------
+This is a single-process FastAPI app. For a multi-process / multi-host
+deployment you'd back this with Redis — but the dependency is kept inside
+this file behind a single `Limiter` class, so swapping in a Redis backend
+later only requires reimplementing that class, not the call sites.
+
+Algorithm
+---------
+Sliding-window log: we keep every request timestamp for each key within
+the window. When a new request arrives we drop entries older than
+`window_seconds` and compare the remaining count to `max_requests`.
+
+The log-based sliding window is more accurate than a fixed-window counter
+(a fixed window can let through 2× burst at the boundary), and at the
+scale of a todo API the memory cost (one float per request per key) is
+trivial.
+"""
+from __future__ import annotations
+
+import threading
+import time
+from collections import deque
+from dataclasses import dataclass
+from typing import Deque, Dict, Tuple
+
+
+@dataclass
+class LimitDecision:
+    """Outcome of a `check` call."""
+
+    allowed: bool
+    remaining: int
+    retry_after: float  # seconds until the next slot opens, 0.0 if allowed
+
+
+class RateLimiter:
+    """Thread-safe sliding-window log limiter.
+
+    Key format is up to the caller. The router uses
+    `"ip:<remote_addr>"` so different clients have independent budgets.
+    """
+
+    def __init__(self, max_requests: int, window_seconds: float) -> None:
+        if max_requests <= 0:
+            raise ValueError("max_requests must be positive")
+        if window_seconds <= 0:
+            raise ValueError("window_seconds must be positive")
+        self.max_requests = max_requests
+        self.window_seconds = window_seconds
+        self._hits: Dict[str, Deque[float]] = {}
+        self._lock = threading.Lock()
+
+    def _prune(self, key: str, now: float) -> None:
+        bucket = self._hits.get(key)
+        if bucket is None:
+            return
+        cutoff = now - self.window_seconds
+        while bucket and bucket[0] <= cutoff:
+            bucket.popleft()
+        if not bucket:
+            # Free memory for keys that haven't been used recently.
+            self._hits.pop(key, None)
+
+    def check(self, key: str, now: float | None = None) -> LimitDecision:
+        """Decide whether `key` may proceed right now."""
+        if now is None:
+            now = time.monotonic()
+        with self._lock:
+            self._prune(key, now)
+            bucket = self._hits.setdefault(key, deque())
+            if len(bucket) >= self.max_requests:
+                # Retry-after = when the oldest in-window request ages out.
+                retry_after = max(0.0, bucket[0] + self.window_seconds - now)
+                return LimitDecision(False, 0, retry_after)
+            bucket.append(now)

+**為什麼不用 SQLAlchemy?**
+待辦 API 規模太小,ORM 的抽象成本不划算。直接用 `sqlite3` + `Row` 工廠,程式碼可讀性反而更高,而且 `detect_types` + 自訂 adapter/converter 已經能讓 `datetime` 欄位乾淨 round-trip。

+## 三、關鍵決策
+
+### 1. SQLite 連線策略:`autocommit` + 顯式 in_transaction 守衛
+- 預設 `isolation_level=None`(autocommit),每條 SQL 立刻生效
+- `get_conn` context manager 在 exception 路徑上檢查 `conn.in_transaction`,只在真的有 implicit transaction(例如 `executescript`)時才 ROLLBACK
+- **踩坑教訓**:第一次實作直接 `conn.execute("ROLLBACK")`,autocommit 下會 raise `OperationalError: cannot rollback - no transaction is active`——3 個 404/422/delete 測試因此爆掉,改成 `if conn.in_transaction:` 守衛後全綠
+
+### 2. Python 3.12 datetime 適配
+- 3.12 棄用隱式 timestamp converter,改用顯式 `register_adapter` + `register_converter`
+- 自訂 `_adapt_datetime` 強制寫入 ISO-8601 + UTC offset,確保來回不丟 tzinfo
+- 改完後測試輸出從 40 個 deprecation warning → 0 個
+
+### 3. Rate Limiter:Sliding-window log 演算法
+**為什麼不用 fixed-window?**
+fixed-window 在邊界可以 2× burst(例:11:59:59 發 30 個、12:00:00 又發 30 個,總共 60 個/2 秒)。Sliding-window log 更精確,記憶體成本可忽略(每 key 每 request 一個 float)。
+
+**為什麼 in-memory?**
+單進程 FastAPI 應用。Redis 後端只需替換 `RateLimiter` 一個類別,call site 不變。
+
+**Thread-safe**:`threading.Lock` 保護 `_hits` dict;`_prune` 在每次 `check` 開頭跑,自動清掉過期 key,避免記憶體膨脹。
+
+**掛載方式**:`app.include_router(..., dependencies=[Depends(require_rate_limit)])` 在 app 層級注入,**新加 router 預設就會被限流**——不會因為忘記加 Depends 而漏掉。
+
+### 4. 測試隔離三招
+1. **tmp DB per test**:`monkeypatch.setenv("TODO_DB_PATH", tmp_path/test.db)` + reload settings
+2. **Limiter reset**:`reset_limiter` fixture 在每個案例前後清空 in-memory 狀態
+3. **Reload app module**:每個 test 重新 `importlib.reload(config/todos/main)`,避免上一個測試的設定殘留
+
+### 5. Settings 用普通 `@dataclass`(非 frozen)
+踩坑:第一版用 `@dataclass(frozen=True)`,結果測試 fixture 用 `monkeypatch.setattr(settings, "db_path", ...)` 直接爆 `FrozenInstanceError`。改成普通 dataclass 後才能在測試裡換 DB 路徑。
