+# RBAC Flow · Dynamic Permission Editor
+
+Single-page demo: a **React Flow** graph editor for an RBAC model, backed by a **Node.js + Express + WebSocket** server. Every change in any browser tab is broadcast to all other tabs in real time.
+
+## What's in here
+
+```
+rbac-flow-demo/
+├── server/                  # Node.js REST + WebSocket backend
+│   ├── package.json
+│   ├── index.js             # HTTP routes + ws broadcast
+│   ├── store.js             # in-memory + data.json persistence, EventEmitter
+│   └── data.json            # auto-generated on first start
+└── public/
+    └── index.html           # React 18 + React Flow 11 (CDN UMD, no build step)
+```
+
+## Model
+
+| Entity | Example |
+|---|---|
+| Role | Admin / Editor / Viewer (with color) |
+| Permission | `read:document`, `manage:user`, … |
+| Grant | role → permission (edge) |
+| User | Alice / Bob / Cara |
+| Assignment | user → role (edge) |
+
+The graph has three columns (Role / Permission / User). Drag a **user onto a role** to assign; drag a **role onto a permission** to grant. Delete an edge to revoke.
+
+## Run it
+
+```bash
+cd server
+npm install
+npm start
+# → http://localhost:3000
+```
+
+Open the URL in **two browser tabs** — change something in one tab and the other updates within milliseconds.
+
+## Why this layout
+
+- **React Flow via CDN UMD** — no build step, the HTML file is the artifact. Easy to ship / demo.
+- **REST for CRUD** — predictable, testable with curl.
+- **WebSocket for change events** — meets the "real-time permission management" requirement.
+- **Server is the source of truth** — every mutation goes through the store, which then `emit('change')` → broadcast. Clients re-fetch the snapshot on every event. Simple, no client-side merge logic.
+- **JSON file persistence** — fine for demos; swap with Postgres when scaling up.
+
