    確認了：UMD 把所有東西掛在 globalThis.ReactFlow。包含 Background, Controls, MiniMap, Handle, Position, addEdge, applyNodeChanges, applyEdgeChanges, ReactFlow 等。但 useReactFlow / useStore 在 UMD 沒暴露（它們是 hook，要 React Context + zustand store）。
    
    所以原版的兩處錯誤：
    
    1. 第 380 行 import { useReactFlow } from ReactFlow; 假裝成 ES import — Babel 會因為 data-presets="env" 把它當 ES module 解，但 useReactFlow 不在 RF 上。要嘛刪掉（反正我自己寫了 screenToFlowPosition），要嘛用 useStore 或 useViewport 替代。我的方案：我寫的 screenToFlowPosition 讀 DOM viewport.style.transform 已經能算，不依賴 RF hook，那行直接刪。
    2. applyNodeChanges / applyEdgeChanges / addEdge 從 (window.ReactFlow || {}) 解構 — 順序問題：React 程式在 Babel.transform 之後才 root.render，但我在原始碼 top-level 直接解構 window.ReactFlow，執行順序沒問題（UMD 同步載入完後才執行 data-type="module" 區塊）。
    
    但還有第三個隱形 bug：data-type="module" + data-presets="env" — Babel 7 standalone 對 UMD 的支援很容易踩雷，這個組合最容易爆 Unexpected token export 或卡住。最穩的方案是拆成兩個 <script type="text/babel"> 區塊：第一塊放純 JS 拉工具，第二塊放 JSX。
