+## 2. State management — why each primitive was chosen

+### `useReducer` (in `useTasks` hook)

+  action that is trivial to log, test, serialize, or replay.

+  enabling the unit-test layer in `verify/run.mjs §5`.
+
+### Undo/redo via history stack
+- The `history` slice of state holds a `past` array and `future` array of
+  task snapshots.
+- Only mutating actions push to history (`SET_FILTER`/`SET_SEARCH` don't —
+  they're UI state, not domain state).
+- `HISTORY_LIMIT = 50` caps memory growth; older snapshots are dropped.
+- Keyboard shortcuts: `Ctrl+Z` (undo), `Ctrl+Shift+Z` or `Ctrl+Y` (redo).
+
+### `useContext` for cross-cutting concerns
+- `ThemeContext` — exposes `{ theme, toggle }`. Theme is *also* written to
+  `<html data-theme="...">`, so CSS handles the visual update without any
+  React re-render (a small but real perf detail).
+- `ToastContext` — exposes `push(message)`. Imperative-style API for
+  transient feedback (added/deleted/cleared).
+
+### `useEffect` only for side effects
+- localStorage hydration on mount (with fallback to a simulated API call).
+- localStorage persistence on every state change after hydration.
+- Document-level `keydown` listener for the undo/redo shortcuts.
+
+### `useMemo` for derived data
+- The visible task list is derived from `tasks × filter × search`,
+  sorted by completion → priority → recency. Memoized so it only
+  recomputes when one of those three changes.
