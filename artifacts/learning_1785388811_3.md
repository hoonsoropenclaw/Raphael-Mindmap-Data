+
+## 狀態
+- 日期：2026-07-30

+
+## 問題
+人事資料包含身分識別資訊、薪資、績效等敏感欄位。僅隱藏按鈕不足以保護資料；每次讀取與寫入都必須通過集中式授權決策，並產生稽核事件。
+
+## 使用者角色
+1. 系統管理員：管理帳號與角色、看一般資料與 PII；基於職責分離，不可修改薪資。
+2. 人事主管：管理全體人員與薪資、讀稽核紀錄。
+3. 人事專員：新增與更新全體一般/PII 資料，薪資唯讀，不可刪除或授權。
+4. 部門主管：只讀/更新本部門非敏感資料，可看本部門薪資，不可跨部門。
+5. 稽核員：全域唯讀與稽核；PII 遮蔽、不得寫入。
+6. 一般員工：只看/更新自己的非敏感資料；薪資可看自己的，PII 只看自己的。
+
+## 必要功能
+- deny-by-default 集中式 `authorize(subject, action, resource)`。
+- `self / department / all` 資源範圍。
+- 欄位級保護：PII、薪資、一般欄位分開判斷。
+- 角色切換模擬、權限矩陣、人員清單、搜尋與部門篩選。
+- 未授權操作不只隱藏，事件處理器仍須再次拒絕。
+- 編輯與刪除操作產生稽核紀錄；拒絕也記錄。
+- 匯出資料時沿用目前角色的欄位遮蔽與資料範圍。
+- 鍵盤可操作、明確焦點、ARIA 狀態通知、響應式版面。
+
+## 非目標與安全邊界
+- 單檔 HTML 是可執行的安全模型/前端原型，不是生產認證後端。
+- 生產環境必須在 API/資料庫端重跑同一授權決策，使用 HttpOnly/Secure/SameSite session、CSRF 防護、速率限制與 RLS；不得信任前端 role、department 或 record owner。
+- 範例資料全為虛構，不含真實人事資訊。

+## 驗收
+- 六角色 × 核心操作授權矩陣測試全通過。

+- HTML 可由瀏覽器直接載入，無 console error。
+- 角色切換後可見列數、欄位遮蔽及操作按鈕即時更新。

+# 實作規格：RBAC HR Data Guard
+
+## 模組
+1. Policy Engine
+   - 常數：`ROLES`, `ACTIONS`, `POLICIES`
+   - 函式：`authorize(subject, action, resource)`
+   - 規則：未知角色/未知操作/資料不完整一律 deny。
+2. Field Projection
+   - `projectEmployee(subject, record)` 依 `pii.read` / `salary.read` 遮蔽欄位。
+3. HR Repository（示範用記憶體）
+   - 虛構員工資料；所有讀寫入口先授權。
+4. Audit
+   - allow/deny、角色、動作、資源、時間；UI 不提供修改既有事件。
+5. UI
+   - 身分模擬器、摘要卡、人員資料表、權限矩陣、稽核紀錄、編輯對話框。
+6. Export
+   - 僅匯出目前投影後的可見資料，不得繞過欄位遮蔽。
+
+## 威脅模型與控制
+| 威脅 | 控制 |
+|---|---|
+| UI 隱藏但直接呼叫 handler | handler 內再次 `authorize` |
+| 未知角色或 action 造成 fail-open | deny-by-default |
+| 部門主管越權讀其他部門 | resource scope predicate |
+| 一般員工修改角色/薪資 | 欄位白名單 + 獨立 action |
+| 稽核員看到完整 PII | project 層遮蔽 |
+| 匯出繞過畫面遮蔽 | export 使用投影資料 |
