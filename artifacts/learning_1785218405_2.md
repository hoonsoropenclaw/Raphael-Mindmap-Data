+10. Run as a complete Vite application rather than a detached code snippet.

+- TypeScript strict mode.
+- No unbounded history; retain at most 30 snapshots.
+- No mutation of prior reducer states.
+- Semantic landmarks, visible focus, accessible names, and live status messages.
+- CSS-only motion using transform/opacity, with `prefers-reduced-motion` handling.
+- No placeholder URLs, remote images, or runtime API dependency.

+- Aesthetic: industrial editorial control desk.

+## Acceptance scenarios
+
+1. Given a loaded board, when one item moves to another status, then both normalized column arrays update and Undo/Redo restore each state.
+2. Given more than 30 domain mutations, history retains exactly the newest 30 snapshots.
+3. Given multiple selected items, when bulk-moved, all move once and selection clears.

+7. Given the composer, a valid submission creates a visible card and closes the dialog.
+8. Given selected cards, the bulk toolbar moves them to Review; Undo returns them to their prior columns.

+# Flowboard / React Workflow Studio
+
+A self-contained, production-ready React 19 application that demonstrates
+non-trivial state management through a reversible workflow board.
+
+## What it does
+
+- Displays work items across four ordered columns: **Backlog, In progress, Review, Done**.
+- Maintains a normalized domain model (entity dictionary + per-status ordered IDs) inside a `useReducer` store.
+- Supports single-card and bulk status transitions, deletion, creation, search, and priority filtering.
+- Provides a bounded Undo / Redo history capped at **30 snapshots**; older snapshots are discarded.
+- Exposes a complete async load lifecycle with `idle / loading / ready / error` states and a `Retry` action.
+- Surfaces polished `aria-*` semantics, `aria-live` announcements, and a `prefers-reduced-motion` aware motion system.
+
+## Run

+## Architecture decisions
+
+1. **Reducer-first design.** Every domain change passes through `workflowReducer`. Components never own or duplicate board state. This keeps Undo/Redo, bulk operations, and error recovery trivially testable.
+2. **Normalized state.** A `Record<string, WorkItem>` dictionary is paired with `Record<WorkflowStatus, string[]>` column ordering. Selectors are O(n) over visible items, not O(n²) over cards.
+3. **Bounded history.** `HISTORY_LIMIT = 30` is enforced inside the reducer (past + future), satisfying the Senior Architect principle of "no unbounded resource growth."
+4. **Async loader is injectable.** `<WorkflowStudio loadItems={fn} />` lets tests inject deterministic promises and reject sequences. No real network, no placeholder URLs.
+5. **Design system: industrial editorial control desk.** Warm paper, graphite, signal orange. No AI purple/blue, no gradients on copy. Differentiation anchors: numbered vertical queue rails, clipped-corner work tickets, graphite metric console with signal-orange drop shadow.
+6. **Accessibility baked in.** Visible focus rings, `aria-live` announcements, `aria-pressed` and `aria-checked` semantics, semantic landmarks (`<main>`, `<header>`, `<section>`, `<footer>`).
+7. **Performance discipline.** Animations only animate `transform` and `opacity`. `contain: layout style` on the board. Variable font subsets ship per-script (latin, latin-ext, vietnamese, cyrillic, greek).
