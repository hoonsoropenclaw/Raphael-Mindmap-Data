+# sysmon — Linux 系統日誌與資源監控腳本
+
+> 單檔 Python 3.10+ (stdlib only) — 監控系統資源、journal 日誌、自訂日誌檔、systemd 服務，當數值超過閾值時發出分級警告。
+
+---
+
+## 為什麼寫這個
+
+Linux 主機需要一個**輕量、可理解、可嵌入**的監控腳本，能跑在：
+
+- systemd timer 觸發（推薦）
+- crontab 觸發
+- 手動一次性排查
+- CI 環境健康檢查
+
+不需要 Grafana / Prometheus / Node exporter 那一整套，只要「**壞了叫我、印一行可讀訊息**」就夠。
+
+## 特性
+
+| 領域 | 檢查項目 | 預設閾值 (Warn / Crit) |
+|------|---------|----------------------|
+| CPU 負載 | load1 / N_CPU 比率 | 0.7 / 1.5 |
+| 記憶體 | MemAvailable 反向 | 80% / 95% |
+| Swap | 使用率 | 50% / 80% |
+| 磁碟 | 任意路徑（逗號分隔）用量 | 80% / 92% |
+| inode | 同上 | 80% / 92% |
+| Processes | /proc 計數 | 500 / 2000 |
+| Uptime | 提醒週期 | 180 days |
+| Journal | err+ 事件計數（最近 N 分鐘） | 10 / 50 |
+| Journal 黑名單 | regex 命中 = EMERG | 內建: OOM / kernel BUG / I/O error / EXT4 / XFS error |
+| Log 檔 | 自訂檔 + regex（每個檔案獨立） | 看你設定 |
+| Services | systemd unit `is-active` | 期望 = `active`，否則 CRIT |
+
+## 安裝
+
+```bash
+# 1. 複製到任意 PATH 目錄（範例）
+sudo install -m 755 sysmon.py /usr/local/bin/sysmon
+
+# 2. 自動產生預設設定檔（永遠可以重新跑，會覆蓋）
+sudo install -d /etc/sysmon
+python3 sysmon genconf -o /etc/sysmon/sysmon.conf
+sudo chown root:root /etc/sysmon/sysmon.conf
+sudo chmod 644 /etc/sysmon/sysmon.conf
+
+# 3. （可選）狀態目錄 — 給去抖 + JSONL log 用
+sudo install -d /var/lib/sysmon/state
+sudo chown root:root /var/lib/sysmon/state
+sudo chmod 755 /var/lib/sysmon/state
+
+# 4. （推薦）systemd 整合
+sudo install -m 644 sysmon.service /etc/systemd/system/
+sudo install -m 644 sysmon.timer   /etc/systemd/system/
+sudo systemctl daemon-reload
+sudo systemctl enable --now sysmon.timer
+systemctl list-timers sysmon.timer   # 確認下次觸發時間
+```

+## 故障排除
+
+### 1. `journalctl: permission denied`
+
+**症狀**:
+
+```
+[sysmon] journal_config WARN journal|tool=denied
+```
+
+**根因**: 不是 root，沒有讀全域 journal 權限。
+
+**選項**:
+
+| 方案 | 適合情境 |
+|------|---------|
+| `sudo` 跑 sysmon (systemd unit 已是 `User=root`) | server、production |
+| 加 user 到 `systemd-journal` 群組 | 多人共用 server |
+| 接受只能讀自己的 user unit journal | 個人容器、開發機 |
+| 完全跳過 (不通知) | CI 環境、看 log 不重要 |
+
+調整方式（選擇性）:
+
+```bash
+sudo usermod -aG systemd-journal $USER
+# 重新登入後生效
+```
+
+### 2. `dedup.json` 卡住 → 同一個 alert 永遠不再送
+
+**症狀**: 你想清掉 dedup 重新檢查，但發現同一個 CRIT 怎麼跑都不會再印。
+
+**原因**: 這是 by design — dedup 的目的是防止告警風暴，不是「記憶體快取」。300 秒後自動過期。
+
+**立刻強制重新送**:
+
+```bash
+python3 sysmon run --config /etc/sysmon/sysmon.conf --no-dedup
+# 或：刪掉 state 檔（一勞永逸）
+sudo rm ~/.hermes/sysmon_state/dedup.json
+```
+

+
+**症狀**: `~/.hermes/sysmon_state/findings.log.jsonl` 上 GB。

+### 2. 設計決策（為什麼這樣選、不是別樣）
+
+#### a. **stdlib only — 不拉 psutil / 任何第三方**
+
+理由：
+- N100 上 PEP 668 venv 折騰，鎖多小時常常無聊時間
+- 我們只需要 5 個資源指標 → `/proc/meminfo` + `/proc/loadavg` + `os.statvfs` 剛好
+- Python 3.10+ `os.sched_getaffinity` / `pathlib` 都夠用
+- 零依賴 = 零 audit risk = 「上線第一天就信任」
+
+#### b. **INI 設定檔**（不是 YAML、TOML、JSON）
+
+理由：
+- `configparser` 是 stdlib
+- Linux daemon 慣例（systemd、syslog、ntp 都用 INI）
+- 人類直接編輯錯誤率低
+- 程式內建 DEFAULT_CONFIG → 「忘記建設定檔也不會炸」
+
+#### c. **三層分級 (WARN/CRIT/EMERG)**
+
+理由：
+- 二元（OK/not-OK）無法表達「需要看、需要人、需要叫人」三種嚴重度
+- 退出碼 0/1/2/3 → 直接被 systemd、cron、`$?` 識讀
+- EMERG 才觸發 hook = 「我只叫人、別煩我」的最低阻抗原則
+
+#### d. **去抖 (Dedup) 用 JSON file + 記憶體鎖**
+
+理由：
+- 設計目的 = 防止告警風暴，不是「狀態共享」
+- 300 秒後自動過期（不靠 TTL cache eviction）
+- `--no-dedup` 旗標 → 手動跑命令時每次都看見
+- signature 設計：`metric|key1=val1|key2=val2`（如 `disk|path=/`）— 同 disk + 同 path 算同一條
+
+#### e. **state 寫到 `~/.hermes/sysmon_state/`、絕不放 `/tmp`**
+
+理由：(教訓 25) `/tmp` 是 tmpfs、定期清理、cron job 中間檔必放永久路徑。
+
+#### f. **JSONL findings log（append-only）**
+
+理由：
+- 各家 log collector (Vector / Fluent Bit / Promtail) 都能直接讀
+- 時間序列查詢友善
+- 不寫 DB、也寫 CSV、反正 append-only 不會 race
+
+#### g. **journal 黑名單 regex 命中 = EMERG**
+
+理由：
+- 數量門檻（WARN=10 / CRIT=50）是粗抓
+- regex 黑名單才是「已知壞東西」的精確觸發
+- 預設內建：OOM Killer / kernel BUG / I/O error / EXT4 / XFS error
