+# system_monitor.py — Linux 系統健康監控工具
+
+純 Python 3 stdlib 寫成的單行程式，零相依。檢查 CPU / MEM / Disk / Load-average，並掃描 journalctl 與傳統 syslog / auth.log 是否在指定時間窗內出現 OOM、kernel panic、SSH 暴力登入、磁碟 I/O 錯誤。任一項超過閾值就把告警寫到 stdout + 指定的 alerts log 檔。
+
+設計目標：給 cron 或 systemd timer 呼叫，每次跑一次、結束、不留守護行程。
+
+## 安裝
+
+不需要安裝。直接：
+
+```bash
+chmod +x system_monitor.py
+./system_monitor.py --help
+```
+
+## 用法
+
+### 一次完整檢查（預設閾值）
+```bash
+./system_monitor.py --check
+```
+輸出範例（健康）：
+```
+[2026-07-28T07:44:16+00:00] OK — cpu=1.51% mem=8.92% disk=46.83% load1=0.16 ssh_fail=0
+```
+exit code 0。
+
+### 自訂閾值 + 寫入 alerts log
+```bash
+./system_monitor.py --check \
+  --cpu 75 --mem 80 --disk 85 --load 1.5 \
+  --alerts-log /var/log/system_monitor_alerts.log
+```
+當任一項超標，輸出 ALERT 行、append 到 log、exit code 1。
+
+### 純 JSON 輸出（餵給 Prometheus exporter / SIEM）
+```bash
+./system_monitor.py --check --json | jq .
+```
+
+### 模擬告警（測試 alert pipeline，不需真的把系統搞掛）
+```bash
+./system_monitor.py --simulate-alert --alerts-log /tmp/sm_test.log
+```
+exit code 1，會一次觸發全部 8 種告警，驗證你的 alerting hook 走得通。
+
+### 自訂 log 掃描
+```bash
+./system_monitor.py --check \
+  --log-paths /var/log/syslog,/var/log/auth.log,/var/log/kern.log \
+  --log-window 600
+```
+- `journalctl` 可用時優先用它（`--since 600s ago`）
+- 不可用時 fallback 讀檔案尾巴（最後 256 KB），過濾掉時間戳早於 `--log-window` 的行
+
+## 掃描的 log 模式
+
+| 標籤 | 對應 regex（忽略大小寫） |

+- Memory：`/proc/meminfo` 用 `MemAvailable`（kernel 自家算的，Linux 3.14+），比 `MemTotal - MemFree` 精準
+- Disk：`shutil.disk_usage(--disk-path)`，預設監控 `/`，可改成 `/var` 或 `/home`
+- Load：`/proc/loadavg` 拿 1/5/15 分鐘；閾值用 **每核心**（`load_per_core × cores`），這是業界慣例（不直接比絕對值）
+
+**Log**：
+- OOM killer（記憶體爆掉被殺的程式）
+- kernel panic / hardware error / segfault
+- SSH 暴力登入（`failed password` / `invalid user`）——N100 對外 SSH 一定會被掃
+- 磁碟 I/O error（filesystem 要掛的前兆）
+
+### 3. Log 來源優先序：journalctl → fallback 檔案
+**理由**：
+- systemd 主機 journald 是 single source of truth
+- 非 systemd 環境（少數 container / 嵌入式）才讀檔
+- 檔案讀取只 tail **最後 256 KB**——這是 O(1) 記憶體，不會因為 log 暴增炸 RAM
+
+### 4. `derive_alerts` 設計成純函式
+**理由**：
+- 8 條 alert 規則脫離 IO，方便 unit test
+- 同一份邏輯 `--check` 與 `--simulate-alert` 都能用
+- 未來要加新 alert rule，只動 `derive_alerts` + `LOG_PATTERNS`，不用碰 collect / emit
+
+### 5. 三個退出碼（0 / 1 / 2）
+**理由**：
+- 0 = healthy → cron / systemd 視為成功
+- 1 = alerts fired → 可掛 `OnFailure=` / 失敗通知 hook
+- 2 = invocation error → 立刻修（CLI 錯、不會誤報、容易找）
+
+### 6. `--json` 旗標
+**理由**：
+- 人讀要純文字、機器讀要 JSON
+- 不用設計兩個 binary（人版 / 機版），靠 `--json` 一個旗標切換
+- `human_readable=False` 時只寫 alerts log、不重複印 stdout——避免 log 被解析時抓到一行亂碼
