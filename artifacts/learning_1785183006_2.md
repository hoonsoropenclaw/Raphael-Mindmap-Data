+## 架構重點
+
+### 1) Reducer 保持 pure
+`todoReducer` 只接收 `(state, action)`、不讀 `localStorage`、不打 API、不碰 DOM。
+**所有副作用都在 Provider 的 `useEffect` 內**。好處:
+- 可以輕鬆做 `__test__`(jest / vitest 直接 `reducer(state, action)`)
+- 時間旅行除錯(Redux DevTools 之類)直接可用
+- 邏輯集中、未來加 undo/redo 只在 reducer 包一層
+
+### 2) 三個 Context 分層
+```js
+TodoStateContext       // { todos, visible, filter, stats } - 唯讀
+TodoDispatchContext    // dispatch function - 寫入
+TodoActionsContext     // { setFilter } - UI 行為
+```
+
+不是單一 context 的原因:**React context 沒有 selector**,任何 `useContext(MyContext)` 在 value 變動時會 re-render 那顆子樹。拆三層後:
+- `StatsBar` 只訂閱 `StateContext` → 改 filter 會跟著 re-render(因為 `visible` 變了)
+- `AddForm` 只用 `DispatchContext` → 加 todo 時 re-render(這必要),但切 filter **不會** re-render 它
+- `FilterBar` 用 `ActionsContext` → 切 filter re-render 它自己,不會牽動其他子樹
+
+### 3) Lazy initializer + debounce
+```js
+const [todos, dispatch] = useReducer(todoReducer, undefined, loadTodos);
+//                    ^^^  undefined 是「用 lazy init」,loadTodos 只跑一次
+```
