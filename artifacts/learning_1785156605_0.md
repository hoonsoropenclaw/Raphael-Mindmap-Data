+const KEY = 'kanban.board.v1';

+export function usePersistence(state: BoardState): void {
+  const lastSerialized = useRef<string>('');
+
+  useEffect(() => {
+    const serialized = JSON.stringify(state);
+    if (serialized === lastSerialized.current) return;
+    lastSerialized.current = serialized;
+    const handle = setTimeout(() => {
+      try {
+        localStorage.setItem(KEY, serialized);
+      } catch (err) {
+        // Quota errors are non-fatal; surface to console for debugging only.
+        // eslint-disable-next-line no-console
+        console.warn('[kanban] localStorage write failed:', err);
+      }
+    }, DEBOUNCE_MS);
+    return () => clearTimeout(handle);
+  }, [state]);
+}

+## 1. 架構選擇與理由
+
+### 1.1 為什麼不用 Trello clone、要 re-invent
+
+任務規格是「完整 React UI 元件 + 複雜狀態管理」,所以**重點是展現深度** — 不是堆砌 dnd-kit / framer-motion / redux-toolkit 等函式庫。改用以下輕量自製元件:
+
+| 模組 | 函式庫 | 改為自製的理由 |
+|------|--------|---------------|
+| Drag & Drop | `@dnd-kit` 120KB+ | `setDragPayload/readDragPayload` 30 行就能覆蓋 90% 場景,Kanban 不需要 sortable multi-list 抽象 |
+| State | `redux-toolkit` 40KB | `useReducer + 純函式 reducer` 完全足夠,且測試更純 |
+| Persistence | `redux-persist` 14KB | `useEffect + JSON.stringify + 200ms debounce` 4 行 |
+| Animations | `framer-motion` 60KB | CSS `cubic-bezier` + `@keyframes cardEnter` + transition 即可 |
+
+**結論**:產出 209KB/66KB gzip bundle,**沒有任何外部狀態/dnd 函式庫**。一個 reducer + 4 個 React 元件就涵蓋了複雜狀態管理。
+
+### 1.2 模組拆分哲學
+
+採用 **`src/types.ts` = 單一真實來源 (Single Source of Truth)**:
+
+```
+types.ts (58 lines) ─── reducer.ts (255)
+       │                       │
+       └── components/*  ◀─────┤
+                               │
+                            data/seed.ts ◀ (deterministic demo)
+```
+
+- `types.ts` 只放 type + enum,沒有任何函式
+- `reducer.ts` 只放純函式 (`ADD_TASK / UPDATE_TASK / DELETE_TASK / MOVE_TASK / REORDER_IN_COLUMN / HYDRATE / CLEAR_ALL` + `deriveBoard` + `applyFilters` 兩個 selector)
+- **元件不直接操作 state**,全部透過 props 傳遞 callback → reducer dispatch
+
+好處:
+- 改資料 shape 只動 `types.ts` 一個檔
+- 改邏輯只動 `reducer.ts`
+- 改 UI 只動元件
+- 寫單元測試時 `boardReducer(state, action) === ?` 就夠
+
+### 1.3 為什麼 reducer 不用 immer
+
+`immer` 會把 255 行的 reducer 縮短,但會:
+- 多一個 ~16KB 依賴
+- 失去 reducer 看起來像資料遷移腳本的可讀性
+- 增加測試的「為什麼 action 沒生效」除錯時間
+
+手寫 6 個 case 看起來囉嗦,但**每個 transition 都是「先讀、再寫、確保不變性」** — 這正是 useReducer 該有的樣子,而且 6 個 case 全部讀完也不到 60 秒。

+### 1.4 進階狀態設計
+
+挑戰點是「4 欄 × N 卡片 × 任意順序」這個二維狀態。我採取:
+
+- `BoardState = { tasks: Record<TaskId, Task>; columnOrder: Record<ColumnId, TaskId[]> }` — 雙索引模式
+- `tasks` 用 O(1) lookup 拿到 task 物件
