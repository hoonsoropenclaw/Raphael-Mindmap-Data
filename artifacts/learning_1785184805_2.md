+# Signal UI — Implementation Review
+
+## 1. Product direction
+
+This deliverable is a focused workspace overview called **Signal**. The visual direction is editorial-utilitarian: warm off-white surfaces, a restrained coral accent, mono metadata labels, and a serif emphasis word in the hero. The goal is to make a dense work-management surface feel calm rather than dashboard-generic.
+
+## 2. Component architecture
+
+- `App` owns the application state through a single `useReducer` state machine.
+- `WorkCard` is a reusable presentational component receiving `item`, `selected`, and `onToggle` props.
+- Data flow is unidirectional: user events dispatch actions, the reducer produces the next state, and derived board/list output is computed with `useMemo`.
+- Browser persistence is handled through `localStorage` effects, so the work collection survives reloads.
+
+## 3. State model
+
+State fields:
+
+- `items`: work entities displayed in the workspace.
+- `query`: free-text search across title, owner, team, and tags.
+- `status`: active workflow tab filter.
+- `priority`: priority filter.
+- `view`: `board` or `list` presentation mode.
+- `selected`: selected item IDs for bulk actions.
+- `sort`: priority or title ordering.
+- `toast`: transient feedback message.
+
+Reducer actions:
+
+- `query`, `status`, `priority`, `view`, `sort`
+- `toggle`, `clear`, `delete`
+- `add`, `toast`
+
+## 4. Interaction coverage
+
+- Search input filters work in real time.
+- Status tabs filter columns and show live counts.
+- Priority select narrows the visible collection.
+- Board/List toggle changes the presentation without changing data.
+- Card checkboxes support multi-selection.
+- Bulk archive removes selected items and clears selection.
+- New work adds a new item at the top of the collection.
+- Toast feedback confirms mutations and persistence restoration.
+- `/` is visually presented as the search affordance; the input remains keyboard-accessible through standard tab navigation.
+
+## 5. Styling decisions
+
+- CSS variables centralize ink, muted text, border, paper, coral, and green tokens.
+- Layout uses a fixed navigation rail and fluid content area.
+- Cards use low-contrast borders and restrained elevation rather than heavy shadows.
+- CSS-only hover and toast animations keep the dependency surface small.
+- Responsive behavior reduces outer spacing below 1150px while preserving the four-column work board.
