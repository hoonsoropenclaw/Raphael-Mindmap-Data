+"""System metric collectors — read /proc, df, free, journalctl, ps.
+
+All collectors are **read-only**, **side-effect-free**, and return plain
+Python dicts with stable keys. They never raise on a missing metric;
+instead they surface ``None`` or an empty list so the runner can decide
+how to react.
+
+Design rules (see IMPLEMENTATION_DECISIONS.md §3):
+  * Use ``/proc`` directly for CPU/memory/load — no `psutil` dep.
+  * One CLI invocation per command (``df``, ``free``, ``journalctl``).
+  * Each collector is a function that accepts a ``CollectContext`` (a
+    small namespace of config + paths) and returns the metric dict.

+# ---------------------------------------------------------------------------
+# CPU — read /proc/stat twice with a small interval to get a real delta
+# ---------------------------------------------------------------------------
+
+def _read_cpu_stat(proc: Path) -> list[list[int]] | None:
+    try:
+        text = (proc / "stat").read_text()
+    except OSError:
+        return None
+    cpus: list[list[int]] = []
+    for line in text.splitlines():
+        if not line.startswith("cpu"):
+            continue
+        parts = line.split()
+        # tokens after the label are jiffy counters: user nice system idle
+        # iowait irq softirq steal guest guest_nice
+        nums = [int(x) for x in parts[1:]]
+        cpus.append(nums)
+    return cpus
+

+def collect_cpu(ctx: CollectContext, interval: float = 0.5) -> dict[str, Any]:

+    snapshot is meaningless for % utilization.
+    """

+    if b is None:

+"""Persistent throttling state — avoid alert storms.
+
+We persist a small JSON file at ``cfg.state_file`` keyed by
+``"<alert_key>:<level>"`` with the timestamp of the last *fired* alert.
+
+Logic per tick:
+  1. Each alert has key+level.
+  2. We *fire* only if (now - last_fired) >= cooldown_seconds, OR if
+     the level *escalated* (warning → critical) for the same key.
+  3. On recovery (level goes back to None) we reset the cooldown so
+     the next time it crosses warn we fire immediately.
+
+Why persistence: a daemon that restarts shouldn't immediately re-alert
+on a problem that's been going on for hours.
+
+See IMPLEMENTATION_DECISIONS.md §5 for the throttling design rationale.
+"""
+

+
+import json
+import os
+import tempfile
+import time
+from pathlib import Path
+from typing import Any
+
+LEVEL_RANK = {"ok": 0, "warning": 1, "critical": 2}
+
+

+    """Throttling state store. Thread-unsafe by design — single writer."""
+
+    def __init__(self, path: str | Path):
+        self.path = Path(path)
+        self._data: dict[str, Any] = {"last_fired": {}, "recovered": set()}
+        self._loaded = False
+
+    # ---- IO ---------------------------------------------------------------
+
+    def load(self) -> None:
+        if not self.path.exists():
+            self._data = {"last_fired": {}, "recovered": set()}
+            self._loaded = True
+            return
+        try:
+            text = self.path.read_text()
+            raw = json.loads(text)
+            self._data = {
+                "last_fired": dict(raw.get("last_fired", {})),
+                # sets come back as lists in JSON
+                "recovered": set(raw.get("recovered", [])),
+            }
+        except (json.JSONDecodeError, OSError) as exc:
+            # corrupt state file shouldn't kill the daemon — log + start fresh
+            print(f"[sysmon.state] WARNING: failed to load state from {self.path}: {exc}; starting fresh")

+        self._loaded = True

+# sysmon
+
+A lightweight, dependency-free Linux system monitor + alert daemon.
+Pure Python 3.10+ standard library — no pip installs, no `psutil`, no
+third-party runtime requirements. Designed for N100 / homelab / edge
+boxes where adding deps just to watch `/proc` is overkill.
+
+## What it watches
+
+| Metric | Source | Threshold keys |
+|--------|--------|----------------|
+| Aggregate CPU % | `/proc/stat` (two-sample delta) | `cpu_pct` |
+| Memory used % / swap used % | `/proc/meminfo` | `memory_pct`, `swap_pct` |
+| 1-min load / core | `/proc/loadavg`, `/proc/cpuinfo` | `load_per_core` |
+| Per-mount disk % | `df -PB1` | `disk_pct` |
+| Recent journal errors | `journalctl -p err` (or `tail -500` fallback) | `journal_errors` |
+| Top processes (context only) | `ps -eo pid,user,pcpu,pmem,comm` | — |
+
+## What it does when a threshold crosses
+
+1. **Logs** to `/var/log/sysmon.log` (JSON Lines, append-only)
+2. **Prints** a single-line alert to stdout (so `journalctl` picks it
+   up when run under systemd)
+3. **Writes** to the system log via `logger -t sysmon`
+4. **POSTs** JSON to `webhook_url` (if configured)
+5. **Throttles** — never alerts the same `(metric, level)` more than
+   once per `cooldown_seconds`. Persistence survives daemon restarts.
+
+## Quick start
+
+```bash
+# 1. install (root)
+sudo ./install.sh --with-systemd
+sudo systemctl enable --now sysmon.service
+
+# 2. or run it locally without installing
+./bin/sysmon --once                # one tick, exit
+./bin/sysmon --daemon              # foreground (Ctrl-C to stop)
+
+# 3. or smoke test your config
+./bin/sysmon --check --config /etc/sysmon/sysmon.yaml
+echo $?    # 0 = healthy, 1 = alerts firing
+```
+
+## CLI
+
+```
+sysmon [OPTIONS]

+      --print-config        print merged config as JSON and exit

+# sysmon — Implementation Decisions
+
+**Status:** v0.1.0 (shipped)
+**Date:** 2026-07-28
+**Author:** 赫米斯 (autonomous build session)
+
+This document records the key design decisions made while building sysmon,
+the alternatives we rejected, and the trade-offs the user should be
+aware of. Read it before changing the architecture.
+
+---
+
+## 1. Scope
+
+**Goal:** Watch Linux system health (CPU/memory/load/disk/journal
+errors) and fire structured alerts when configurable thresholds are
+crossed.
+
+**Non-goals (explicit):**
+- Cross-host aggregation / fleet monitoring
+- Custom alert routing rules (severity → team mapping)
+- Long-term metric storage / dashboards
+- Anomaly detection (ML-based)
+- Process-kill actions / auto-remediation
+
+This tool emits alerts. Where they go is the user's problem (log file,
+stdout, syslog, webhook). What to do with them is also the user's
+problem. Anything beyond that is a separate tool.
+
+---
+
+## 2. Pure stdlib (no `psutil`, no `requests`)
+
+**Decision:** Build on Python 3.10+ stdlib only.
+
+**Rationale:**
+- The N100 target is a homelab box; adding `psutil` for "read
+  `/proc/stat` twice and compute a delta" is overkill.
+- One less moving piece means fewer CVEs, fewer `pip install` steps in
+  the install script, faster cold start.
+- `/proc` + `df -PB1` + `journalctl -p err` covers all six metrics we
+  need in < 1ms per tick.
+
+**Rejected:**
+- `psutil` — works but adds a dependency for marginal convenience.
+- Reading `top` output — fragile, not designed for machine parsing.
+- A pure-C agent (e.g. `node_exporter`) — heavier, harder to ship
+  config for, and `node_exporter` already exists if the user wants it.
+
+**Trade-off:** CPU measurement is two-sample-delta (sleeps
+`interval=0.5s` between samples). That's a hard floor on tick latency
+for the CPU collector. Acceptable for a 30s default interval.
+
+---
+
+## 3. Module layout
+
+```
+lib/sysmon/
+  __init__.py        — public version + symbol re-exports
+  collectors.py      — read /proc, df, free, journalctl, ps
+  config.py          — load YAML/JSON config, defaults dataclass
+  thresholds.py      — pure function: snapshot + Config → list[alert]
+  state.py           — persistent throttling state, atomic writes
+  alerter.py         — multi-channel dispatch (log, stdout, syslog, webhook)
+  runner.py          — main loop, signal handling, CLI
+```
+
+Each module has **one** responsibility. `thresholds.py` is pure (no I/O)
+so it's trivially unit-testable. `alerter.py` knows about the world
+(files, network, syslog) but not about which metric fires when. This
+separation is what lets us reuse `Alerter` from the `--test-alert`
+flag without involving the daemon loop.
+
