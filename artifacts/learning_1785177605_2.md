+"""Per-key token-bucket rate limiter.
+
+Each caller key (typically ``X-API-Key`` header, falling back to client IP)
+gets its own bucket. A bucket has:
+
+* ``capacity`` — maximum tokens (initial burst allowed)
+* ``refill_per_sec`` — tokens added back per second of real time
+
+We keep a single ``threading.Lock`` because the bucket dict is mutated by both
+the request hot path *and* the GC sweep that evicts stale keys. Per-key state
+could be locked finer, but at our scale the global mutex is faster and simpler.

+
+* A fixed window allows 2x the intended rate across the window boundary. Token
+  bucket caps the long-run rate at ``refill_per_sec`` and still allows bursts

+# Todo API
+
+A small but production-shaped FastAPI todo service.
+
+* **Persistence**: SQLite (single connection, WAL mode, file mode 0600)
+* **Rate limiting**: per-key token bucket with `Retry-After` and `X-RateLimit-*`
+  response headers
+* **Validation**: pydantic v2 with whitespace and length checks
+* **Lifecycle**: `lifespan` context manager for graceful startup / shutdown
+
+## Quick start
+
+```bash
+# 1. install dependencies (already present in this repo's pyenv)
+pip install -r requirements.txt
+
+# 2. run
+python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
+
+# 3. try it
+curl http://127.0.0.1:8000/healthz
+curl -X POST http://127.0.0.1:8000/todos \
+  -H "Content-Type: application/json" \
+  -d '{"title": "buy oat milk"}'
+```
+
+## Configuration
+
+All settings come from `TODO_*` environment variables; nothing is exposed as
+a CLI flag (avoids CWE-214 — secrets leaking into `ps aux`).
+
+| Variable | Default | Purpose |
+|----------|---------|---------|
+| `TODO_DB_PATH` | `./data/todo.sqlite` | SQLite file location |
+| `TODO_RATE_LIMIT_CAPACITY` | `20` | Token bucket size (initial burst) |
+| `TODO_RATE_LIMIT_REFILL_PER_SEC` | `5.0` | Sustained request rate per key |
+| `TODO_DEFAULT_LIST_LIMIT` | `50` | Default pagination page size |
+| `TODO_MAX_LIST_LIMIT` | `200` | Cap on `?limit=` |
+
+Out of the box: capacity 20, refill 5/sec → each key may burst 20 requests
+and is sustained at 5 req/s.
+
+## Rate-limit keys
+
+For each request we pick a key in this order:
+
+1. `X-API-Key` header (treated as opaque identifier)
+2. First hop in `X-Forwarded-For`
+3. Direct peer IP
+
+Header-derived keys can be spoofed; this is **only a rate limit**, not
+authentication. Add a real auth layer in front of the service when needed.
+
+## Endpoints
+
+| Method | Path | Notes |
+|--------|------|-------|
+| GET | `/healthz` | **Never** rate-limited (k8s liveness-friendly) |
+| GET | `/todos?limit=N&offset=M&completed=true/false` | Paginated list |
+| POST | `/todos` | Create; 422 on blank / too-long title |
+| GET | `/todos/{id}` | 404 if missing |
+| PATCH | `/todos/{id}` | Partial update; `updated_at` always bumps |
+| PUT | `/todos/{id}` | Full replace; missing `completed` resets to `false` |
+| DELETE | `/todos/{id}` | 204 on success, 404 if missing |
+
+Every `/todos*` call carries `X-RateLimit-Limit`,
+`X-RateLimit-Remaining`, `X-RateLimit-Refill-Per-Sec`; denied calls also
+carry `Retry-After`.

-## 2. 設計取捨說明
-
-### 2.1 為什麼 mini-YAML 而不是要求裝 PyYAML
-
-Production 部署最痛的事是「裝不起來」。我寫了一個**極小 YAML 子集解析器**（只支援 2 空格縮排、list 用 `- `、基本 scalar），覆蓋 `config.yaml.example` 內所有語法。如果系統有 PyYAML 就用 PyYAML（更 robust），沒有就用 fallback。零 pip 依賴即可跑。
-
-### 2.2 為什麼 disk 路徑預設空 = 全掃 `/proc/mounts`
-
-預設掃描所有 real filesystem mount（過濾 tmpfs/devtmpfs/overlay/proc 等 22 種虛擬 FS），同時跳過非 `/dev/*` 開頭的偽裝條目。這比要求使用者列舉 `/`、`/data`、`/var` 更不容易漏。**但仍可透過 `disks.paths` 顯式指定**——例如只想監控 `/`。
-
-### 2.3 為什麼 cooldown 在 state 裡而不在記憶體
-
-跨 daemon 重啟必須保留 cooldown：daemon 重啟期間告警已發過，重啟後不應再 fire。State 落盤是必要設計。
-
-### 2.4 為什麼 `tempfile.mkstemp` 而不是 `Path.write_text` + rename
-
-`write_text` 再 `rename` 在寫大 state 時若 SIGKILL 砸下，可能寫到一半留半檔。`mkstemp` 是 `O_CREAT|O_EXCL` 原子建立，再 chmod + rename，**任何時刻目錄裡只有「舊 state」或「新 state」二擇一**。
-
-### 2.5 為什麼 `single_instance_lock` 失敗時 `sys.exit(0)` 而非 1
-
-任務說「自動化檢查」，通常由 cron 或 systemd 啟動。第二個實例的職責是「讓第一個繼續做事」，exit 0 讓 systemd 不會誤判為失敗。
-
-### 2.6 為什麼 `lock` 失敗時 fallback 到 `/tmp/...`
-
-讓開發者在本機（無 sudo）也能跑 smoke test。Production 部署是 root 跑，仍會用 `/var/run/linux-monitor.lock`。
