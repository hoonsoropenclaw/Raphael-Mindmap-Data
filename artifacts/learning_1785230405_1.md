+# Telegram Weather Bot (stdlib-only)
+
+A minimal Telegram bot that fetches current weather for any city name a user
+sends. **Zero third-party dependencies** — pure Python 3.10+ stdlib
+(`urllib`, `signal`, `dataclasses`, `json`, `re`, `logging`).
+
+## Features
+
+- 🌍 City name → weather (via free public `wttr.in` API, no key required)
+- 🛡 Three-layer defense:
+  1. **Allowlist** — optional `TELEGRAM_ALLOWED_USERS` env var
+  2. **Per-user rate limit** — 10 requests / 60s sliding window
+  3. **City-name sanitization** — length + charset regex, HTML-escaped output
+- 🔁 Long-polling with exponential backoff (1s → 30s cap, ±jitter)
+- 🛑 Graceful shutdown on SIGINT / SIGTERM
+- 🧪 `--dry-run` mode for testing without a real Telegram token
+- 📦 Single file (`telegram_weather_bot.py`) — easy to read, audit, ship
+
+## Quick start
+
+```bash
+# 1. Create a bot with @BotFather on Telegram, copy the token
+# 2. Export env vars
+export TELEGRAM_BOT_TOKEN="123456:ABC-DEF..."
+export TELEGRAM_ALLOWED_USERS="111111111,222222222"   # optional
+
+# 3. Run
+python3 telegram_weather_bot.py
+
+# 4. Open Telegram, message your bot:  Taipei
+```
+
+## Usage
+
+| User input | Bot response |
+|------------|--------------|
+| `Taipei` | current weather for Taipei |
+| `Tokyo` | current weather for Tokyo |
+| `New York` | current weather for New York |
+| `/help` or `/start` | usage message |
+| empty / non-text | usage message |
+| disallowed characters | `❌ invalid input` |
+| over rate limit | `⏳ too many requests — please wait 60s` |
+| user not in allowlist | silently ignored |
+
+## Configuration
+
+| Env var | Required | Default | Purpose |
+|---------|----------|---------|---------|
+| `TELEGRAM_BOT_TOKEN` | yes (unless `--dry-run`) | — | Bot token from @BotFather |
+| `TELEGRAM_ALLOWED_USERS` | no | allow all | comma-separated Telegram user IDs |
+
+## CLI flags
+
+```
+--dry-run    log actions but don't contact Telegram or wttr.in
+--verbose    debug logging
+```
