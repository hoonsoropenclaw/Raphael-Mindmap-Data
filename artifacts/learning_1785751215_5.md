+# PRD：Playwright 動態 API 逆向工程爬蟲
+
+## 1. 背景
+
+傳統 HTML 爬蟲只能取得 SSR／hydrated DOM，無法可靠回答「資料真正來自哪個動態 API、請求參數與回應 schema 是什麼」。本工具使用 Playwright 觀察瀏覽器實際網路流量，在合法授權的目標上建立可重現的 API interface map。
+
+指定的 `architect_feedback.md` 不存在，因此本 PRD 不虛構架構意見；改採以下已檢索且可重用的舊微技能：
+
+- Headless Browser Verification：Chromium headless + `--no-sandbox`／`--disable-dev-shm-usage`。
+- Browser Console：使用 Playwright page API 觀察瀏覽器執行後狀態。
+- Data Export and Schema-Driven Extraction：JSON 匯出與 schema 推導。
+- Playwright Cross-Browser Automation：使用官方 Playwright browser/context 模型。
+- 舊 Hermes Spider：沿用 `request/response` 攔截、HAR/API parser 的成功結構，補足安全與完整性缺口。
+
+## 2. 目標
+
+1. 擷取由 page load、click、scroll 觸發的 XHR/fetch/JSON/GraphQL 請求。
+2. 產出經過敏感資料遮罩的原始 trace。
+3. 將重複實例 URL 正規化為 endpoint pattern 並聚合統計。
+4. 推導 request/response JSON schema，辨識 GraphQL operation。
+5. 產出 JSON inventory、Markdown 報告與單檔 HTML dashboard。
+6. 用本機受控動態 API 測試站重播驗證，不以外站偶發結果代替 E2E 證據。
+
+## 3. 非目標
+
+- 不繞過 CAPTCHA、WAF、登入、付費牆或網站授權。
+- 不竊取／輸出 cookies、Authorization、token、password、API key。
+- 不自動重放 POST/PUT/PATCH/DELETE；避免造成資料異動。
+- 不宣稱單次 trace 等於完整 API 契約。
+- 不建立常駐服務或修改 Hermes 系統設定。
+
+## 4. 使用者故事
+
+- 作為開發者，我可輸入 URL、等待 selector、click selector，得到動態 API 清單。
+- 作為資料工程師，我可讀 `api_inventory.json` 取得 endpoint、參數、schema 與樣本。
+- 作為安全審查者，我可確認報告不含認證資料與敏感 payload。
+- 作為維護者，我可用本機 demo 一鍵驗證 capture → infer → report 全鏈。
+
+## 5. 功能需求
+
+### FR-1 網路擷取
+
+- 監聽 `request`、`response`、`requestfailed`。
+- API 候選條件：resource type 為 `xhr/fetch`，或 content-type 含 JSON/GraphQL，或 URL path 命中 `/api/`、`/graphql`。
+- navigation 採 `domcontentloaded` + 明確 selector/action wait，避免 `networkidle` 在長輪詢站點永久等待。
+
+### FR-2 互動觸發
+
+- 支援 0..N 個 `--click`，依輸入順序執行。
+- 支援 `--scroll-count` 與 `--wait-selector`。
+- 不提供任意 JavaScript eval CLI，縮小攻擊面。
+
+### FR-3 安全遮罩
+
+- Header：Authorization、Cookie、Set-Cookie、X-API-Key 等值替換為 `[REDACTED]`。
+- URL query：token/password/secret/api_key/session 等值替換。
+- JSON/form body：遞迴依 key 遮罩。
+- response body 有大小上限並記錄 truncation。
+- target 僅接受 `http/https`。
+- output 預設必須位於目前工作目錄；外部路徑需明確 opt-in。
+
+### FR-4 逆向推導
+
+- URL path 中 numeric id、UUID、長 hex id 正規化為 `{id}`。
+- REST 與 GraphQL 分類。
+- GraphQL 擷取 `operationName`、operation type/name。
+- JSON schema 支援 object、array、null、boolean、integer、number、string 與 union。
+- 聚合 call count、status distribution、query parameter names、request/response schema。
+
+### FR-5 交付格式
+
+每次 run 產出：
+
+- `api_trace.json`：遮罩後逐次證據。
+- `api_inventory.json`：聚合 endpoint inventory。
+- `report.md`：TRACE/evidence 摘要。
+- `report.html`：完整單檔 dashboard，不依賴 CDN。

+## 2. 核心資料流
+
+```text
+URL + actions
+  -> Playwright Chromium page
+  -> request/response/requestfailed observers
+  -> API candidate classifier
+  -> bounded body capture
+  -> recursive sanitizer
+  -> endpoint normalization + GraphQL analysis
+  -> schema inference + endpoint aggregation
+  -> trace.json + inventory.json + report.md + report.html
+```
+
+## 3. 公開 Python 介面

+8. scroll N 次，每次等待。
+9. 額外 settle wait，finalize response body。
+10. 先 sanitize，再寫磁碟。
