+# PRD：GraphQL API Gateway
+
+---
+date: 2026-07-29
+topic: GraphQL API 閘道器與前後端請求效率
+status: approved-by-explicit-task
+---
+
+## 1. 問題
+
+前端若直接組合使用者、訂單與商品 REST 資源，常見流程是：先取使用者、再取訂單、再逐項取商品。這會造成：
+
+1. 瀏覽器與後端之間多次往返（over-fetching / under-fetching）。
+2. 巢狀關聯形成 N+1 請求。
+3. 相同資源在同一請求或短時間內重複取得。
+4. 前端耦合多個後端端點與錯誤格式。
+5. GraphQL 的彈性若無限制，反過來會形成深度查詢、別名洪水與昂貴操作風險。
+
+## 2. 目標
+
+建立可執行的 GraphQL Backend-for-Frontend/API Gateway，聚合 mock REST 後端並提供：
+
+- 一個 GraphQL 請求取得完整 dashboard。
+- 每請求 DataLoader batching/deduplication，消除 N+1。
+- 跨請求有界 TTL entity cache。
+- 相同 Query 的短期完整 response cache，且按 session 隔離。
+- Query depth、alias、field count、body size 與 rate limit 防護。
+- request ID、health、readiness、JSON metrics。
+- 可直接使用的 HTML demo、真實 HTTP smoke test 與 benchmark。
+
+## 3. 使用者旅程
+
+### Journey A：前端 dashboard
+
+身為前端工程師，我只送出一次 GraphQL Query，就能取得登入使用者、訂單、訂單項目與商品資訊，不必知道後端 REST 拆分方式。
+
+### Journey B：避免 N+1
+
+身為後端工程師，我能看到多個訂單項目的商品查詢被 DataLoader 合併成一次批次 upstream 呼叫。
+
+### Journey C：重複讀取
+
+身為平台工程師，我能看到相同 query 第二次回應命中 response cache，upstream 呼叫數不增加。
+
+### Journey D：濫用防護
+
+身為維運者，我能確認過深查詢、過多 aliases、過多欄位、超大 body 與過高請求速率會被拒絕。
+
+## 4. 功能需求
+
+| ID | 需求 | 驗收方式 |
+|---|---|---|
+| F-01 | `POST /graphql` 聚合 User/Order/Product | HTTP integration test |
+| F-02 | `dashboard` 使用 `x-user-id` session | 無 header → GraphQL `UNAUTHENTICATED` |
+| F-03 | User/Product 使用每請求 DataLoader | 同 request 重複 ID 只載入一次 |
+| F-04 | DataLoader miss 批次呼叫 upstream | 多商品 ID → 1 次 `/products?ids=` |
+| F-05 | 有界 TTL entity cache | expiry/eviction unit tests |
+| F-06 | Query response cache | 第二次相同 Query upstream delta = 0 |
+| F-07 | Cache session isolation | u1 與 u2 不共享 private result |
+| F-08 | Query 成本限制 | depth/alias/field tests |
+| F-09 | Observability | `/healthz`, `/readyz`, `/metrics` |
+| F-10 | Demo 與 benchmark | `demo.html`, `npm run benchmark` |
+
+## 5. 非功能需求
+
+- Node.js 22+。
+- 所有設定集中在 config，環境變數可覆寫且啟動時驗證。
+- 無硬編碼密鑰；demo 身份只使用非機密 `x-user-id`。
+- CORS 明確 origin；demo 預設 localhost。
+- 錯誤不回傳 stack trace。
+- 所有 cache 有 TTL 與容量上限。
+- DataLoader 必須每請求建立，禁止全域共用。
+- 測試覆蓋率門檻：lines/functions/statements ≥ 80%，branches ≥ 75%。
+
+## 6. 效能驗收指標
+
+基準資料：3 筆訂單、6 筆 item、4 個 unique products，mock upstream 每次固定延遲。

+
+## 1. 架構決策
+
+| 決策 | 選擇 | 理由 |
+|---|---|---|
+| 結構 | feature-first | gateway/loaders/cache/limits 可獨立測試與替換 |
+| GraphQL runtime | GraphQL Yoga 5 + GraphQL.js | Fetch API、plugin 生態、Node HTTP 易整合 |
+| N+1 | DataLoader（per request） | 官方 GraphQL.js 推薦；批次 + request-scoped memoization |
+| entity cache | 自製 bounded TTL LRU + single-flight | 可測、可觀測、避免 cache stampede |
+| response cache | Yoga response-cache plugin | operation+variables+session 結果快取與 mutation invalidation seam |
+| upstream | REST adapter over native `fetch` | 無 axios 依賴；timeout 與 HTTP contract 明確 |
+| auth seam | `x-user-id` → context viewer | demo 可驗證 session isolation；production 可換 JWT |
+| realtime | 不需要 | 本任務是讀取效率，不增加 WebSocket 複雜度 |
+| errors | GraphQL errors + extension code + requestId | 前端一致處理；不暴露 stack |
+
+## 2. 請求流程
+
+```text
+Browser
+  │ POST /graphql (1 request, x-user-id)
+  ▼
+HTTP guard ─ body limit / CORS / rate limit / request ID
+  ▼
+GraphQL parse + validate ─ depth / aliases / total fields
+  ▼
+Response cache (query + variables + session)
+  │ miss
+  ▼
+Resolvers
+  ├─ OrderService.listByUser() ─────────────► REST /orders
+  ├─ userLoader.load() ─ batched ───────────► REST /users?ids=...
+  └─ productLoader.load() ─ batched ────────► REST /products?ids=...
+          │
+          └─ bounded TTL entity cache + per-key single-flight
+```
+
+## 3. 模組與契約
+
+### `src/config.js`
+
+- `loadConfig(env)`：解析、型別轉換、範圍驗證。
+- 所有設定支援環境變數與建構參數覆寫。
+- 無效值立即 throw，fail fast。
+
+### `src/cache/ttl-lru-cache.js`
+
+```js
+new TtlLruCache({ maxEntries, ttlMs, clock })
+cache.get(key)
+cache.set(key, value, ttlOverrideMs?)
+cache.getOrLoad(key, loader)
+cache.getMany(keys, batchLoader)
+cache.invalidate(keyOrPredicate)
+cache.snapshot()
+```
+
+保證：
+- LRU eviction。
+- expired entry 不回傳。
+- 相同 key concurrent miss 只執行一次 loader。
+- `getMany` 按 input keys 原順序輸出，missing key 回 `null`。
+
+### `src/upstream/mock-upstream.js`
+
+- 獨立 Node HTTP server。
+- `GET /users?ids=u1,u2`
+- `GET /products?ids=p1,p2`
+- `GET /orders?userId=u1&limit=10`
+- `GET /stats`, `POST /reset`
+- 固定可配置延遲與 call counters。

+export function useBoundedJsonParser({ maxBodyBytes }) {
+  if (!Number.isInteger(maxBodyBytes) || maxBodyBytes < 1) {
+    throw new Error('maxBodyBytes must be a positive integer');
+  }
+  return {
+    onRequestParse({ request, setRequestParser }) {
+      if (request.method !== 'POST' || !isJsonRequest(request)) return;
+      setRequestParser((incomingRequest) => parseBoundedJson(incomingRequest, maxBodyBytes));
+    },
+  };
+}
+
+export async function parseBoundedJson(request, maxBodyBytes) {
+  if (request.body == null) {
+    throw httpError('POST body is required.', 'BAD_REQUEST', 400);
+  }
+
+  const reader = request.body.getReader();
+  const chunks = [];
+  let total = 0;
+  try {
+    while (true) {
+      const { done, value } = await reader.read();
+      if (done) break;
+      total += value.byteLength;
+      if (total > maxBodyBytes) {
+        await reader.cancel('payload too large');
+        throw httpError(
+          `GraphQL request body exceeds ${maxBodyBytes} bytes.`,
+          'PAYLOAD_TOO_LARGE',
+          413,
+        );
+      }
+      chunks.push(value);
+    }
+  } finally {
+    reader.releaseLock();
+  }
+
+  const bytes = new Uint8Array(total);
+  let offset = 0;
+  for (const chunk of chunks) {
+    bytes.set(chunk, offset);
+    offset += chunk.byteLength;
+  }
+
+  let parsed;
+  try {
+    parsed = JSON.parse(new TextDecoder('utf-8', { fatal: true }).decode(bytes));
+  } catch {
+    throw httpError('POST body contains invalid JSON.', 'BAD_REQUEST', 400);
+  }
+  if (parsed == null || typeof parsed !== 'object' || Array.isArray(parsed)) {
+    throw httpError('POST body must be a JSON object.', 'BAD_REQUEST', 400);
+  }
+  return parsed;
+}
