+# Telegram Weather Bot
+
+A small, dependency-free Telegram bot. It listens for plain-text locations
+(`Taipei`, `東京`, `/weather New York`) and replies with the current weather
+from [wttr.in](https://wttr.in). Everything is written against the Python
+standard library so there is no `pip install` step.
+
+## Features
+
+- Long polling against the Telegram Bot API (`getUpdates` + `sendMessage`).
+- Text location parsing plus `/start` and `/help` commands.
+- Optional numeric allowlist (`TELEGRAM_ALLOWED_USERS`).
+- Per-user cooldown (`USER_COOLDOWN_SECONDS`, default `3`).
+- Private, atomic, resumeable offset state file (`bot_state.json`, mode `0600`).
+- `fcntl.flock`-based single-instance lock (`telegram_weather_bot.lock`).
+- `SIGINT` / `SIGTERM` graceful shutdown.
+- wttr.in JSON endpoint with local Chinese translation table for common
+  weather conditions.
+- Direct Unicode emoji (no surrogate escapes that can break f-strings).
+- Secrets read only from environment variables; never from CLI arguments or
+  source files.
+
+## Requirements
+
+- Python 3.10 or newer.
+- A Telegram bot token from [@BotFather](https://t.me/BotFather).
+- Outbound network access to `api.telegram.org` and `wttr.in`.
+

+# Implementation Notes & Senior Architect Review
+
+## Goal
+
+Build a Telegram bot that accepts a plain-text location, calls a weather
+API, and replies with a concise current-conditions report.
+
+## 1. Architecture
+
+The bot is split into two files that have separate responsibilities and
+separate test surfaces:
+
+| File | Responsibility | Lines |
+|---|---|---:|
+| `weather_api.py` | wttr.in client + JSON parser + i18n table + CLI | 99 |
+| `telegram_bot.py` | Telegram transport, allowlist, rate limiter, state, lock, polling loop, signals | 234 |
+| `test_weather_bot.py` | 27 offline tests covering both modules and the polling loop | – |
+
+The weather module is independently runnable (`python3 weather_api.py
+Taipei`); the bot module is independently testable. There is no shared
+mutable state between them beyond the function call into `fetch_weather`.
+
+## 2. Standard library only
+
+`urllib.request`, `urllib.error`, `urllib.parse`, `json`, `fcntl`, `signal`,
+`threading.Event`, `tempfile`, `os`, `time`, `dataclasses`, `pathlib`,
+`logging`. The task is a small three-endpoint pipeline
+(`getMe` + `getUpdates` + `sendMessage` plus one `wttr.in` request) and a
+framework would add dependency surface area without enabling new behavior.
+The user memory notes from Cycle 538 already converged on this choice.
+
+## 3. Long polling over webhooks
+
+`getUpdates` with `offset = update_id + 1` and `timeout = 30` works on a
+headless machine without a public HTTPS endpoint, certificate, or reverse
+proxy. The polling response itself is wrapped in
+`urlopen(..., timeout = poll_seconds + 10)` so a slow Telegram server cannot
+silently kill the request.
+
+## 4. wttr.in `format=j1` and a local i18n table
+
+wttr.in's `lang=zh` query parameter only affects the human-readable
+one-liner (`format=3`). The JSON data fields stay in English. To keep the
+JSON path simple, the bot requests `format=j1` and translates the
+`weatherDesc[0].value` field with a small client-side dictionary. Unknown
+conditions are passed through verbatim (e.g. `Smoky haze` is kept), which is
+the documented design.
+
+## 5. Three-layer input safety
+
+| Layer | Mechanism | Where |
+|---|---|---|
+| 1 | Allowlist (`TELEGRAM_ALLOWED_USERS`) | `telegram_bot.process_update` |
+| 2 | Per-user cooldown (`USER_COOLDOWN_SECONDS`) | `telegram_bot.RateLimiter` |
+| 3 | Location sanitisation (length, content, lone-surrogate stripping) | `weather_api.sanitize_location` |
+
+External error responses are logged server-side; Telegram users only see a
+generic `⚠️ 天氣服務暫時無法使用，請稍後再試。` message, never the raw HTTP
+status or upstream response body.
+
+## 6. Persistence and single-instance
+
+`StateStore` writes `{"offset": N}` atomically:
+
+1. `tempfile.mkstemp(dir=state.parent, prefix=".<name>.", suffix=".tmp")`
+2. `os.fchmod(fd, 0o600)` + `os.fsync`
+3. `os.replace(temp, path)` + `os.chmod(path, 0o600)`
+
+`acquire_lock` opens `BOT_LOCK_FILE`, chmods it `0600`, then takes a
+non-blocking `fcntl.flock`. A second instance raises `LockUnavailable`,
+which `main()` surfaces as exit code `2`.
+
+## 7. Graceful shutdown
+
+`SIGINT` and `SIGTERM` set a `threading.Event`. The polling loop checks the
+event after each `getUpdates` and breaks. A long-poll request that is
+already in flight is allowed to complete naturally before the loop exits.
+The lock is released by the `with acquire_lock(...)` context manager.
