+# Signal Desk — 實作思路與交付審查
+
+## 1. Senior Architect 回饋吸收
+
+已先讀取 `/home/hoonsoropenclaw/.hermes/architect_feedback.md`。本輪採用其中可泛化的兩個原則：
+
+1. 邊界分離：把純狀態邏輯放在 `workflow.ts`，React 僅負責事件轉譯與呈現。
+2. 無網路測試：reducer 與 DOM 行為測試均不依賴遠端 API，確保快速、穩定、可重現。
+
+回饋中的 long-polling/webhook 與快取建議屬 Weather Bot 專案，不硬套到本 React UI。
+
+## 2. 架構
+
+```text
+src/
+├── workflow.ts       純型別、資料、reducer、selector
+├── workflow.test.ts  狀態不變量與歷史測試
+├── App.tsx            UI 組合、鍵盤事件、dispatch 邊界
+├── App.test.tsx       使用者可見行為整合測試
+├── styles.css         industrial-editorial 設計系統
+└── main.tsx           React 掛載點
+```
+
+核心選擇是 `useReducer` 而非多個散落的 `useState`。原因是 selection、task mutations、activity、history、future 彼此有交易一致性：一次批次移動必須同時更新 tasks、清空 selectedIds、寫 activity、推入 history 並清空 future。集中 reducer 可讓這些改動成為單一原子轉移。
+
+## 3. 狀態模型
+
+- Domain：tasks
+- View state：filters、sort、density、activeId、selectedIds
+- Audit state：activity
+- Reversible state：history、future
+- Derived state：visibleTasks、各 status counts、activeTask、allVisibleSelected
+
+`history`/`future` 只保存 task + activity 快照，不保存搜尋、詳情開關等暫態 UI，避免 Undo 意外改變使用者目前視角。歷史限制 20 步，防止長時間操作造成無界記憶成長。
+
+No-op 操作回傳原 state reference，不建立虛假歷史。例如無選取時 bulk-move、重複指派同一人、移到目前狀態。
+
+## 4. 互動設計
+
+- 搜尋涵蓋 ID、標題、摘要與 tags。
+- 篩選變動清空選取，避免把已不可見項目誤做批次操作。
+- 批次工具列只在 selection 非空時出現。
+- Inspector 以 dialog 語意呈現，支援 Esc 與遮罩關閉。
+- Undo/Redo 同時支援按鈕與 Ctrl/Cmd+Z；Shift 組合走 Redo。
+- `/` 聚焦搜尋；表單輸入中不攔截。
+- reduced-motion 使用者不承受 drawer 動畫。
+
+## 5. 視覺方向

+- 美學：Industrial Editorial Control Desk
+- DFII：14（Impact 5 + Fit 4 + Feasibility 4 + Performance 4 - Consistency Risk 3）
+- 字體：Archivo Black 作刊頭、IBM Plex Mono 作操作資訊、Noto Sans TC 作中文內文。
+- 色彩：暖紙色為主、酸性萊姆表示 active、橘色表示 urgency、鈷藍表示 progress/action。
