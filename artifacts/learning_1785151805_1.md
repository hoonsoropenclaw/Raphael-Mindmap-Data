+# GitHub Trending Scraper — 實作思路
+
+## 任務
+> 寫一個腳本，抓取 GitHub Trending repositories，輸出成 markdown 表格。
+
+結果檔：`./github_trending.py` (12.6 KB, 373 行, 純 stdlib + requests + bs4)
+
+## 設計決策
+
+### 1. 資料源選擇：HTML 為主，API 為備
+- **主：GitHub Trending 頁** (`https://github.com/trending[/{lang}][?since=...]`)
+  - 優點：免 API token、秒級 fetch、欄位最完整（含 **期間內星數** `stars today/week/month`）
+  - 缺點：HTML 結構可能會改 (但 GitHub 過去 3 年很穩，class `Box-row` 一直保留)
+- **備：GitHub Search API**
+  - 觸發條件：使用者送 `--use-api` 或 HTML 抓取失敗時自動 fallback
+  - 缺點：API 沒有「trending」概念,只能用 `created:>X` + `sort=stars` 近似,且**沒有 star_in_period 欄位** (所以欄位會失真)
+  - 需要 `GH_TOKEN` 環境變數
+
+### 2. 解析策略：多 selector 向後相容
+GitHub 不是只一套 class,我對**每個欄位**都準備備援 selector:
+- repo 名稱: `h2 a` → `h1 a` → 第一個 `href=/owner/repo` 的 a
+- 描述: `p.col-9` → 第一個 `p`
+- 語言: `[itemprop='programmingLanguage']`
+- 總星數: `a[href*=stargazers]` 內文字
+- Fork 數: `a[href*=forks]` 或 `a[href*=network/members]`
+- **期間內星數: `span.float-sm-right` 含文字 "N stars today/this week/this month"**
+
+每列獨立 try/except,單列失敗不影響整體清單。
+
+### 3. 期間內星數的 regex 坑 (踩過)
+GitHub 頁面在 3 個模式顯示的文字不一樣:
+- `daily` → `1,166 stars today`
+- `weekly` → `6,991 stars this week`  
+- `monthly` → `13,743 stars this month`
+
+第一版 regex 只 match `stars today` → weekly/monthly 全部歸零。修正:`(today|this\s+week|this\s+month)`。
+
+### 4. CLI 設計
+```
+--since {daily,weekly,monthly}   預設 daily
+--language LANG                  預設空 (全部)
+--output {markdown,json,PATH}    
+        | 純字串 "markdown"/"json" → stdout
+        | 含 .md/.json 副檔名 → 寫檔
+--use-api                        強制走 API fallback
+```
+
+訊息分流:[INFO]/[WARN]/[ERROR] 全部往 **stderr**,純資料往 **stdout** → 可直接 pipe 給 `jq` / `python3 -m json.tool`。
+
+### 5. 輸出格式
+**Markdown**:
+```
+| # | Repository | Description | Language | ⭐ Today | Total ⭐ | Forks |
+```
+- 數字欄位右對齊 (`---:`)
+- 缺描述顯示 `_(no description)_`
+- 缺語言顯示 `—`
+- 數字用千分位 `1,166`
+
+**JSON**: `dataclasses.asdict()` 序列化,UTF-8,indent=2。
