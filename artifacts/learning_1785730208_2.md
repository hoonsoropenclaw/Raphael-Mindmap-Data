+# PRD：DocuForge OCR
+
+## 1. 問題
+行政與知識工作者需要把 PDF、掃描圖片、DOCX 與純文字文件中的資料轉成可搜尋、可校對、可匯出的結構化報告；文件可能只有圖片層，且不能上傳第三方雲端。
+
+## 2. 目標
+1. 本機處理單檔或多檔。
+2. PDF 有可靠文字層時直接擷取，否則自動使用 Tesseract OCR。
+3. 解析台灣常見欄位並附信心值。
+4. 產出 HTML、JSON、CSV 報告。
+5. 同一核心同時提供 CLI 與本機桌面 Web UI。
+6. 部分文件失敗時仍產出其他文件結果與明確錯誤。
+
+## 3. 非目標
+- 不做雲端同步、外部 LLM 分類、資料庫或帳號系統。
+- 不承諾手寫字、複雜表格或極低品質掃描件百分之百正確。
+- 不在伺服器持久保存上傳原檔。
+
+## 4. 使用者流程
+1. 執行 `./start_app.sh`，瀏覽器開啟 localhost UI。
+2. 拖放或選取文件，選 OCR 語言與最大 OCR 頁數。
+3. 啟動處理，看到逐檔狀態、擷取方式、欄位與原文。
+4. 下載 HTML/JSON/CSV 報告，人工校對低信心欄位。
+5. 自動化場景改用 `python3 app.py process ...`。
+
+## 5. 支援格式
+- PDF
+- PNG、JPG/JPEG、TIFF/TIF、BMP、WebP
+- DOCX
+- TXT、MD、CSV
+
+## 6. 功能需求
+- FR-1 驗證副檔名、檔案存在性、大小與批次上限。
+- FR-2 PDF 逐頁判斷文字層，不以整份文件單一布林值決定。
+- FR-3 影像前處理包含 EXIF 旋轉、灰階、自動對比與合理放大。
+- FR-4 OCR 回傳文字與平均有效 token confidence，不依賴 Tesseract 臨時輸出檔。
+- FR-5 提取 document_number、roc_date、iso_date、amount_ntd、email、phone、tax_id、subject、contact_person、address、organization。
+- FR-6 每個欄位含 value、confidence、source。
+- FR-7 批次處理保留 input 順序，逐檔隔離錯誤。
+- FR-8 報告 HTML/JSON/CSV 原子寫入；HTML 內容 escape。
+- FR-9 API 僅綁 localhost，允許 multipart 多檔上傳與報告下載。
+- FR-10 UI 支援 drag/drop、鍵盤操作、進度、空狀態、錯誤狀態、responsive。
+
+## 7. 非功能需求
+- Privacy：無網路 API、無上傳持久化。
+- Reliability：失敗可觀測，沒有 bare exception swallow。
+- Security：檔名 sanitize、下載 allowlist、body size 上限、HTML escape。
+- Performance：文字 PDF 不 OCR；OCR 限頁；本機多檔順序處理避免 N100 CPU 過載。
+- Accessibility：semantic HTML、label、focus-visible、reduced-motion。
+
+## 8. 驗收準則

+- API health、upload、report download 實測成功。
+- UI 桌面與 320px viewport 無水平 overflow，console 0 error。

+# 技術規格

+## 架構
+
+`UI / CLI → Application Service → Extractors → Field Parser → Reporters`

+- `models.py`：不可變 DTO 與序列化契約。
+- `extractors.py`：格式路由、PDF 逐頁策略、影像 OCR、DOCX/文字擷取。
+- `fields.py`：純函式 regex 欄位解析與正規化。
+- `reports.py`：HTML/JSON/CSV renderer + atomic writer。
+- `service.py`：單檔/批次 orchestration、部分失敗、report bundle。
+- `server.py`：stdlib ThreadingHTTPServer、multipart 邊界、靜態 UI、下載 allowlist。
+- `cli.py`：`process` 與 `serve` 子命令。
+- `web_output.html`：無 CDN，local-first responsive UI。

+## 依賴決策
+- PyMuPDF：PDF 文字層與頁面 rasterization。
+- Pillow：圖片開啟與前處理。

+- python-docx：DOCX 結構化文字擷取。
+- stdlib：HTTP、CLI、CSV、JSON、multipart、tempfile。
+
+## 限制
+- 單檔預設上限 25 MiB；API 總 body 60 MiB；批次最多 20 檔。
+- PDF OCR 預設最多 8 頁；超過頁保留跳過警告。
+- server 只接受 loopback host。
+- report ID 使用 UUID，download endpoint 只讀內存 allowlist 內的輸出路徑。

+DocuForge 是一個 local-first 的文件自動化工作台：把 PDF、掃描圖片、DOCX、TXT/MD/CSV 的文字與常見行政欄位，轉成可校對的 HTML、JSON、CSV 報告。
+
+## 核心特性
+
+- PDF 逐頁文字層優先；文字不足的頁面才啟動 Tesseract。
+- 支援繁中、簡中、英文 OCR；預設 `chi_tra+eng`。
+- 支援文件編號、民國日期、西元日期、金額、Email、電話、統編、主旨、聯絡人、地址、機關/組織。
+- 每個欄位保留 `value`、`normalized`、`confidence`、`source`。
+- 單一檔案失敗不會中止整批；報告會保留錯誤。
+- localhost Web UI + CLI 共用同一個 service layer。
+- 不需 API key、不把文件送到外部服務。
+
+## 環境
+
+已在目標主機驗證：
+
+- Python 3.12.3
+- Tesseract 5.3.4
+- Tesseract languages: `chi_sim`, `chi_tra`, `eng`, `osd`
+- PyMuPDF 1.26.7
+- Pillow 12.2.0
+- python-docx 1.2.0
+- reportlab 4.0.7（本工具不依賴它）
+

+

+```
+
+再從另一台允許的桌面瀏覽器透過 SSH port forwarding 使用；程式本身仍只 bind loopback。
+
+UI 支援：
+
+1. 拖放或選取多個文件。
+2. 選 OCR 語言與 PDF OCR 頁數上限。
+3. 點擊「開始提取並生成報告」。
+4. 查看欄位、標準值、信心值與逐頁原文。
+5. 下載 HTML / JSON / CSV。
+6. 「載入示範結果」可在沒有文件時驗證 UI 互動。
+

+## 1. 來源
+
+本工作區原本沒有本輪 `architect_feedback.md`。依任務要求檢索了鄰近 learning project 的架構回饋與已完成 OCR 成品，採用其中可泛化的原則：
+
+- 文字提取與 OCR fallback 分層，不把所有文件直接送 OCR。
+- 模組責任分離：extractor、field parser、reporter、transport 各自可測試。
+- typed result + partial failure，批次不因單檔錯誤中止。
+- 本機 local-first，不把文件送第三方服務。
+- 使用可注入 OCR function，讓離線 unit test 不需要每次真的啟動 Tesseract。
+- UI 與 CLI 共用 service layer，避免兩套邏輯漂移。
+- server 啟用 address reuse，但 E2E 測試動態取得 free port，避免被既有程序污染。
+- responsive UI 不用 `overflow-x: clip` 掩蓋問題；以 `min-width: 0` 讓 grid item 真正可收縮。

+web_output.html / app.py CLI

+
+### 通過項目

+- 每個欄位輸出 `value`、`normalized`、`confidence`、`source`。
