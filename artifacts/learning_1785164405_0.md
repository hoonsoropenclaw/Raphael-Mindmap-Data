+# Operations Command Center — Implementation Notes
+
+## 目標
+
+建立一個可直接執行的 React UI 元件，展示複雜但可追蹤的營運工作佇列狀態管理，以及獨立 CSS 視覺系統。
+
+## 架構決策
+
+- `src/main.jsx`：唯一 React entry point，使用 `StrictMode`。
+- `src/OperationsCommandCenter.jsx`：互動元件與狀態邏輯。
+- `src/styles.css`：所有視覺樣式、responsive breakpoint、motion 與 accessibility 規則。
+- `simulateRefresh()`：模擬外部資料邊界；未來可直接替換成 `fetch` / query client，不需改 UI action contract。
+
+## 狀態模型
+
+採用 `useReducer` 而不是多個彼此耦合的 `useState`：
+
+- `items`：工作項目資料。
+- `query` / `status` / `sort`：列表視圖狀態。
+- `selected`：批次操作的選取集合。
+- `activeId`：右側詳情抽屜。
+- `isRefreshing` / `error`：非同步資料生命週期。
+
+Action contract：`query`、`status`、`sort`、`toggle`、`toggleAll`、`open`、`close`、`refresh-start`、`refresh-success`、`refresh-error`、`clear-selection`。
+
+這讓所有狀態轉移集中在 reducer，後續可以無 UI 測試 reducer；同時沿用 Senior Architect 回饋中的邊界分離原則：資料同步邊界與呈現層分開。
+
+## 互動與狀態覆蓋
+
+- 搜尋：依 ID、標題、負責團隊與 tag 過濾。
+- 篩選：All / In progress / Review / Blocked / Done。
+- 排序：Priority / Progress。
+- 選取：單筆與全選。
+- 批次操作：Mark done、Assign to me，以 toast 回饋並清除選取。
+- 詳情抽屜：點擊工作名稱或更多按鈕開啟，可標記完成。
+- Refresh：展示 loading label、非同步更新與成功 toast。
+- Empty：無符合結果時顯示空狀態。
+- Error：reducer 支援錯誤狀態與 retry UI。
+- Reduced motion：CSS `prefers-reduced-motion` 會降低動畫。
+- Keyboard/accessibility：可見 focus ring、aria-label、aria-live 狀態通知。
+
+## 視覺方向
