    設計重點
    
    為什麼選 React Flow + Babel Standalone 單檔:
    - 不需 build step,純單檔 HTML 可在任何瀏覽器直接打開
    - React Flow UMD 版本(@11.11.4)內建 Handle、Position、MarkerType 等必要元件
    - Babel Standalone 解析 JSX → 適合一次性 demo / 部署到任何靜態主機
    
    為什麼用極簡自製 Store(useSyncExternalStore + actions):
    - 不依賴 Redux/Zustand,單檔自包含
    - actions 自動包裝成 setState,內部調用 __store.getState() 拿最新狀態避免 stale closure
    - 已修正的 race condition:setNodes([...cur.nodes]) 永遠建立新 array reference,確保 React 重渲染
    
    為什麼 engine 是「單節點逐步推進」而非「批次並行」:
    - 簡化狀態追蹤(每 tick 只看 1 個 running 節點)
    - 視覺化效果好:使用者可清楚看到執行中節點發光 + 活躍邊脈動
    - join 節點仍正確等待所有 incoming 完成(BPMN 規範)
    
    過程中的 bug 修正(真實試誤記錄)
    
    1. JS 字串內真實換行:JSX 中 cond: 'leave_days > 3 → 主任秘書核准\nleave_days ≤ 3 → 單位主管核准' 在原始碼被換行,造成 Babel parser 報 Unterminated string constant。修正:把所有 cond 字串內的真實換行改為 \n(regex 全替換)。
    
    2. nodes.find is not a function:原 executeNext 透過 setNodeStatus(id, status) callback 呼叫 cur.setNodes(patch),但 setNodes 的 closure 內呼叫 __store.getState() 時拿到的是 wrapped state(含 actions functions),nodes 變成物件而非 array。修正:把 executeNext 改成 in-place 修改 cur.nodes 元素,EngineLoop 再用 setNodes([...cur.nodes]) 觸發重渲染。
    
    3. Sidebar 滾動導致 role-card 點不到:左側 sidebar 累積 4 個 role card + 4 個 template card + 15 個 palette item,總高度超過 viewport。Playwright click 預設會 scroll_into_view 但 sidebar 自身有 overflow-y:auto。修正:驗收腳本改用 scroll_into_view_if_needed(timeout=2000) + click(force=True)。
    
    4. MyEmpty handler 未提供:某些 path 上節點 status 變更後 React Flow 內部 applyNodeChanges 短暫傳 undefined 給 selector。修正:isActiveEdge/computeFlowStats/getStartNodes/getOutgoing 都加 Array.isArray() 防禦性檢查,回傳安全預設值。
