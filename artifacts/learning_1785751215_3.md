+從手機 Telegram 送訊息 → 自動操控桌面/瀏覽器執行工作。

+### 1.2 三層分離（最重要的設計決策）
+
+```
+┌──────────────────────────────────────────────────────────┐
+│  Telegram Layer                                           │
+│  ├─ RealTelegramListener (python-telegram-bot 21.x)      │
+│  └─ MockTelegramListener (測試用，直接 .inject())        │

+└──────────────────────────────────────────────────────────┘
+                            │ ActionSpec
+                            ▼
+┌──────────────────────────────────────────────────────────┐
+│  RPA Layer                                                │
+│  ├─ MockRPAExecutor (純記憶體、不碰外部)                 │
+│  └─ RealRPAExecutor (Playwright + xdotool)                │
+└──────────────────────────────────────────────────────────┘

+**為什麼要分離**：

+- 未來加 retry / queue / logging 都在 Dispatcher 層加，不會污染其他層
+
+### 1.3 共用資料合約（`schemas.py`）
+
+| 物件 | 用途 | 跨層時誰產生、誰消費 |
+|------|------|---------------------|
+| `TelegramCommand` | 從 Telegram 來的原始命令 | TG listener 生 → Dispatcher 收 |
+| `ActionSpec` | 統一的 RPA 動作規格 | Dispatcher 生 → Executor 收 |
+| `ActionResult` | 統一執行結果 | Executor 生 → Dispatcher 收 → TG 回覆 |
