+# System Health Monitor — 設計計畫
+
+## 目標
+Linux 系統日誌 + 資源監控腳本,閾值超標自動警告。
+
+## 4 大監控軸
+
+### 1. 資源 (Resource)
+- CPU: `/proc/stat` 計算短期 busy% (非 psutil,避免相依)
+- Memory: `/proc/meminfo` → MemAvailable/MemTotal → 使用率
+- Disk: 每個 mount point 使用率 + inode 使用率 (shutil.disk_usage)
+- Load avg: `/proc/loadavg` vs CPU 核心數 (`os.cpu_count()`)
+- Uptime: `/proc/uptime`
+
+### 2. journalctl 掃描
+- `--since "5 min ago"` (可調) → priority `emerg..err`
+- 三個單元都掃: kernel, system-wide, `-u` 全部 user unit
+- 分類計數: priority × unit
+
+### 3. syslog 傳統檔掃描 (fallback)
+- `/var/log/syslog`, `/var/log/auth.log`, `/var/log/kern.log`
+- `grep -E` 最近 N 分鐘的 ERROR/FATAL/CRITICAL/Authentication failure
+
+### 4. systemd 服務健康
+- `systemctl --failed --no-pager`
+- journalctl `_PID=1` Failed message 統計
+
+## 閾值 (CLI 可調, 預設合理值)
+
+| 指標 | 預設 | 行為 |
+|------|------|------|
+| CPU% > | 90 | warn |
+| Memory% > | 90 | warn |
+| Disk% > | 85 | warn (個別 mount) |
+| Inode% > | 85 | warn |
+| Load1 / cores > | 2.0 | warn |
+| err log count > | 5 (per 5 min) | warn |
+| any failed service | — | critical |
+
+## 告警輸出 (3 管道)
+
+1. **`alerts.log`** 本地檔,JSON-per-line (後續 cron/dashboard 可撈)
+2. **`logger -p user.alert`** 進 syslog (跨進程可監聽)
+3. **stdout** 彩色 + 等級 (人類讀)
+
+## 執行模式
+
+- `--once` 跑一次,exit code 反映最嚴重等級 (0=ok, 1=warn, 2=critical)
+- `--watch <seconds>` 背景循環,daemon-style
+- `--json` 純 JSON 輸出 (給其他工具)
+
+## 安全性 / 防呆
+
+- **零外部相依**: 只用 Python stdlib + journalctl/logger 系統命令
+- **絕不 rm / 寫系統檔**: 只讀 /proc, /var/log*, 只寫專案目錄 + syslog
+- **降級模式**: journalctl 失敗 → fallback 到 syslog 檔掃描
+- **timeout**: 每個 subprocess 包 10s timeout,避免卡住
+- **rate-limit**: 同樣 alert 5 分鐘內不重發
+
+## 驗證
+
+1. 跑 `--once` 看 4 軸都抓到
+2. 用 stress-ng 或單純塞爆 /var/log 測告警
+3. 看 alerts.log 寫入、syslog 看到 message
+4. `--json` 解析 OK

+# sysmon.py — Linux 系統日誌 + 資源監控腳本
+
+## 概述
+
+單一 Python 3 stdlib 腳本,監控 Linux 主機的 4 個面向,
+閾值超標時自動發出多管道告警。
+
+零外部相依(只用 stdlib + journalctl/logger 系統命令)。
+
+## 4 個監控軸
+
+1. **資源** (resources)
+   - CPU busy% (`/proc/stat` 兩次取樣)
+   - Memory 使用率 (`/proc/meminfo` → MemAvailable/MemTotal)
+   - 磁碟使用率 + inode 使用率 (`shutil.disk_usage` + `os.statvfs`)
+   - Load avg / CPU 核心數比值
+   - Uptime
+
+2. **journalctl** (emerg..err 等級)
+   - 解析 JSON 輸出
+   - 統計 priority 分布 + 噪音最大的 unit
+   - 採樣前 3 條訊息
+   - emerg/alert 任一出現 → critical
+
+3. **syslog 傳統檔掃描** (fallback 通道)
+   - `/var/log/syslog`、`/var/log/auth.log`、`/var/log/kern.log`、`/var/log/messages`
+   - 模式比對:EMERG / FATAL / CRITICAL / ERROR / authentication failure / segfault
+   - journalctl 不可用時仍能跑
+
+4. **systemd --failed 服務健康**
+   - 任何 failed service → critical
+
+## 告警輸出 (3 管道)
+
+| 管道 | 用途 |
+|------|------|
+| `alerts.log` | 本機 JSON-lines,給 cron/dashboard 後續處理 |
+| `logger -p user.{warning,crit}` | 進系統 syslog,跨進程可監聽 |
+| stdout | 彩色 + 等級,人類讀 |
+
+## Rate-Limit
+
+同一個 `check:severity` 告警在 **5 分鐘冷卻期** 內只發一次。
+狀態存在 `.sysmon_ratelimit.json`(跨 process 持久)。
+
+> 注意:同一個 alert 的訊息可能改變(例如 err count 增加),
+> rate-limit 依 *鍵* 而非 *訊息內容*,所以計數上升仍會在冷卻後發出。
+> 若想每次都發,把 cooldown 改成 0。
+
+## 閾值 (CLI 可調)
+
+| 參數 | 預設 | 說明 |
+|------|------|------|
+| `--cpu-warn` | 90 | CPU busy% |
+| `--mem-warn` | 90 | Memory% |
+| `--disk-warn` | 85 | 磁碟使用率% |
+| `--inode-warn` | 85 | inode 使用率% |
+| `--load-warn` | 2.0 | load1 / cpu_cores |
+| `--journal-err-warn` | 5 | journalctl err+ 條數 / window |
+| `--syslog-err-warn` | 10 | syslog 檔 error 模式條數 / window |
+| `--log-window` | 5 | 日誌回看分鐘數 |
