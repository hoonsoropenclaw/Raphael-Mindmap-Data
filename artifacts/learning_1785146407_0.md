+# fetch_trending
+
+Automated script that scrapes [GitHub Trending](https://github.com/trending) and
+emits a Markdown table of repositories ranked by stars-gained in a chosen period
+(daily / weekly / monthly).
+
+## Why HTML and not the REST API?
+
+The official REST `GET /search/repositories` *can* approximate trending with a
+`created:>` + stars-range query, but it cannot reproduce GitHub's own
+"trending" weighting (which factors in relative star growth and velocity vs a
+repo's own baseline). The Trending page is the single source of truth humans
+see, so we scrape it. Cost: one HTTP GET per (range, language).
+
+## Install
+
+```bash
+python3 -m venv .venv
+.venv/bin/pip install -r requirements.txt
+```
+
+Tested on Python 3.12 with `requests==2.34.2` and `beautifulsoup4==4.15.0`.
+
+## Usage
+
+```bash
+# daily trending → stdout
+.venv/bin/python fetch_trending.py
+
+# weekly, Python-only, top 10, save to file + dump JSON
+.venv/bin/python fetch_trending.py --since weekly --language python --top 10 \
+    --output trending_python_weekly.md --json trending_python_weekly.json
+
+# monthly, restricted to English-spoken repos
+.venv/bin/python fetch_trending.py --since monthly --spoken-language en
+```
+
+### Flags
+
+| Flag | Purpose | Default |
+|---|---|---|
+| `--since {daily,weekly,monthly}` | Trending range | `daily` |
+| `--language LANG` | Primary language filter (e.g. `python`, `go`) | `""` (all) |
+| `--spoken-language LANG` | UI-spoken-language filter (e.g. `en`) | `""` (all) |
+| `--top N` | Cap rows, 1-100 | `25` |
+| `--output PATH` | Write Markdown to PATH | stdout |
+| `--json PATH` | Also dump structured JSON for downstream tools | — |
+| `--timeout SEC` | HTTP timeout | `20` |
+| `--user-agent UA` | Override User-Agent | sensible default |
+| `--quiet` | Suppress stderr progress | noisy |
+| `--debug` | Verbose HTTP / parse diagnostics | off |
+
+### Exit codes
+
+| Code | Meaning |
+|---|---|
+| `0` | Success (zero or more rows) |
+| `1` | Network / non-2xx HTTP |
+| `2` | Parse failure (DOM drift) |
+| `3` | Invalid CLI args (argparse also exits `2`) |

+## 3. 實作思路 (Design Walkthrough)
+
+### 3.1 為什麼 HTML scrape 而不是 REST API?
+
+GitHub 沒有公開的 "trending" API。`GET /search/repositories` 雖然能模擬
+(`created:>` + stars 區間查詢),但無法重現 GitHub 自己的 trending 加權
+(計算「相對本基線的成長速率」)。Trending 頁是 GitHub 對人類顯示的唯一真相。
+一個 HTTP GET per (range, language) 成本極低,因此選 scrape。
+
+### 3.2 頁面 DOM 結構 (實測於 2026-07-27)
+
+- 頁面: `https://github.com/trending` (預設 daily)
+- 每張 repo 卡片 = `<article class="Box-row">`
+- 卡片裡:
+  - `<h2>` 包含 owner/repo,以 " / " 分隔
+  - `<p class="col-9">` = description
+  - `<span itemprop="programmingLanguage">` = 語言
+  - `<a href$="/stargazers">` 顯示文字 = 總星數
+  - 卡片尾部 "X stars today / this week / this month" = 當期星增
