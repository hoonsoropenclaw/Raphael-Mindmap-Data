+"""In-memory per-client rate limiter middleware.
+
+Design
+------
+- We use a simple **fixed-window** counter keyed by client IP. Fixed
+  window is cheap, easy to reason about, and accurate enough for a small
+  demo API. A token bucket would be smoother under bursts but adds
+  complexity we don't need here.
+- Storage is an in-process ``dict[str, dict[str, int]]`` mapping
+  ``client_key -> {"window_start": epoch_s, "count": n}``. Keys are
+  evicted lazily when a new request lands and the window for that key
+  has expired — we don't run a background sweeper.
+- The client key is the remote IP. The ``X-Forwarded-For`` header is
+  honoured if present, but only the **leftmost** entry is trusted; in a
+  production deployment you'd reverse-proxy terminate and trust a
+  known proxy chain. For a local service this is fine.
+- The middleware is a plain callable (not a class) so it can be wired
+  with ``app.middleware("http")`` and is trivial to swap in tests by
+  monkey-patching ``app.rate_limit.check_rate_limit``.
+
+Configuration
+-------------

+attributes, which are set in :func:`app.main.create_app`. Tests

+
+> 本文件是「極限超頻模式」下,赫米斯如何在沒有使用者確認的情況下,
+> 從 zero 拉到一個可執行的 FastAPI 待辦事項 API 的完整思路紀錄。
+> 寫成 markdown 給下一次同類任務當 checklist / 反思材料。
+
+## 1. 任務拆解
+
+| 模組 | 職責 | 檔案 |
+| ---- | ---- | ---- |
+| ORM 模型 | `Todo` 資料表 schema | `app/models.py` |
+| 資料庫 | SQLite engine + session lifecycle + 可注入 factory | `app/database.py` |
+| Schema 驗證 | Pydantic v2 請求/回應模型 | `app/schemas.py` |
+| CRUD | 與 DB 直接對話的純函式 | `app/crud.py` |
+| Rate limit | 固定窗口 + per-IP + 執行緒安全 | `app/rate_limit.py` |
+| App | FastAPI 路由組合 + lifespan | `app/main.py` |
+| 測試 | pytest + TestClient + per-test 乾淨環境 | `tests/{test_api,test_crud,test_rate_limit}.py` + `conftest.py` |
+
+## 2. 關鍵設計決策
+
+### 2.1 同步 SQLAlchemy 而非 async
+
+**為什麼:** 本任務量級是 SQLite + 單機 demo。`async_sessionmaker` 對 SQLite 沒實質好處,
+而且根據 trial-and-error 教訓 37(Cycle 539, 2026-07-26),**`async def` endpoint 內用同步
+sessionmaker + `.query()` 會在 100 個 concurrent requests 觸發 deadlock**。
+FastAPI 會把 sync route 自動丟到 threadpool 跑、表現等價 async。
+選同步 = 沒 deadlock 風險、語法更簡單、除錯容易。
+
+**實作:** `sessionmaker(autocommit=False, autoflush=False, expire_on_commit=False)` —
+`expire_on_commit=False` 是標配(若 commit 後還要讀 attribute,不會拋 `DetachedInstanceError`)。
+
+### 2.2 SQLite `check_same_thread=False` + FK 強制開啟
+
+**為什麼:** FastAPI 用 sync session 會在 worker thread 跑,SQLite 預設不允許跨執行緒。
+FK 預設是關的、若未來加關聯表會踩雷。我寫在 `database.py` 內的 `connect` event listener
+中,只在 dialect 是 `sqlite` 時掛上去、不會影響其他 db。
+
+### 2.3 Rate limit = 固定窗口而非 token bucket
+
+**為什麼:** 簡單、可預測、易測試。固定窗口的「邊界 2x 突發」問題對 demo API 不影響。
+演算法:
+- `dict[client_key, {window_start: epoch_monotonic, count: int}]`
+- 每次請求:lazy evict 過期的 bucket、若當前 bucket 滿就 429、否則 count++
+- `Retry-After` 永遠 `>= 1`,避免客戶端無限 retry loop
+- 加 `threading.Lock` 保護共享 bucket — 教訓 37 順帶提醒的並發安全
+
+**client key 解析:** `X-Forwarded-For` 第一個 hop → `request.client.host` → `"test-client"`。
+在 ASGI TestClient 環境 `client` 是 `None`,所以測試預設都打到同一 bucket。
+真要分桶,測試自己加 `X-Forwarded-For` header 即可(`test_blocks_independent_per_client` 驗證)。
+
+### 2.4 Rate limit 排除 `/docs` 等
+
+**為什麼:** OpenAPI docs 頁面會發出數十個內部 sub-request(inline favicon、schema 預取)。
+若把 docs 也納入限流,使用者還在瀏覽 API 就被自己 429 掉會非常惱人。
+白名單: `/`、`/docs`、`/redoc`、`/openapi.json`、`/health`。
+
+### 2.5 模組化 create_app factory
+
+**為什麼:** `app = create_app()` 模組層級的 singleton 讓 `uvicorn app.main:app` 可用;
+但測試若共用同一個 limiter,桶會互相汙染 → 把 limiter 變成 per-app 屬性、`create_app(rate_limiter=...)` 注入。
+**驗證:** `TestRateLimitBlocks::test_blocks_independent_per_client` 證明不同 IP 不互相影響。
+
+### 2.6 依賴注入覆寫
+
+**為什麼:** 測試需要 in-memory DB,而 `create_app` 內部已經綁 `get_db` 到 module-level engine。

+
