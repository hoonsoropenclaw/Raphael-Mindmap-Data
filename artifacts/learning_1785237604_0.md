+## 實作決策與預設值
+
+### 監控的 5 個 check（純 stdlib）
+
+| # | Check | 偵測方式 | 預設 WARN | 預設 CRIT |
+|---|-------|----------|-----------|-----------|
+| 1 | CPU load | `os.getloadavg()[1] / nproc` (5-min 平均) | ratio ≥ 0.85 | ratio ≥ 1.50 |
+| 2 | Memory free | `/proc/meminfo` MemAvailable / MemTotal | < 10% | < 5% |
+| 3 | Disk used% | `shutil.disk_usage(/).used / .total` | ≥ 85% | ≥ 95% |
+| 4 | Journal err 件數 | `journalctl -p err --since "-5m"` 計行 | ≥ 10 (5m) | ≥ 50 (5m) |
+| 5 | SSH auth fail | `journalctl -u sshd ... Failed password` 或 `/var/log/auth.log` | ≥ 20 (5m) | ≥ 100 (5m) |
+
+全部閾值可用 env var 覆寫（`SYSMON_CPU_WARN`、`SYSMON_DISK_CRIT` 等共 11 個）。
+
+### 為什麼這樣選
+
+- **純 stdlib** — 不依賴 `psutil`：容器 / minimal image 也能跑、不需要 pip install
+- **5 個 check 涵蓋最常見生產失效類型**：CPU 過載、OOM、磁碟滿、systemd 服務崩潰、SSH 暴力破解
+- **journal 容忍降級**：journald 在容器裡常拿不到 (`Function not implemented`)，我把它判成 SKIP 不影響 overall exit，而不是當錯誤 raise
+- **SKIP 不影響 overall level** — 沒裝 SSH 不應該誤報；這也是實際跑時出現的場景（N100 沒 sshd unit）
+
+### 警告方式（為什麼這樣選）
+
+- **寫到 `/tmp/sysmon-watchdog.log`** — 每跑一次 append 一行 JSON
+- **超過 WARN/CRITICAL 時另外寫 `/tmp/sysmon-watchdog.err`** — 限制長度 4KB（避免 cron 一天塞出 47 段 telegram 訊息，**吸收 `devops:cron-job-health-monitor` skill 類型 P 的教訓**）
+- **exit code**：`0=OK`、`1=WARN`、`2=CRITICAL` —— 給 cron / systemd 判斷用
+- **沒有 telegram / webhook / email 推送** —— 訊息裡 injection「寫入 ____」欄位是空白的，**不主動選一個 channel**。如果未來要推送，建議用 hermes cron job 的 `last_error` / `last_status` 機制（已在 `devops:cron-job-health-monitor` SKILL.md 內）
+
+### 為什麼不加 `/usr/bin:/usr/sbin` 以外的東西
+
+- 不動 `/etc/crontab` —— 不需 sudo、user-local-only
+- 不自動 `systemctl enable` —— 不搶 systemd ground truth
+- 不寫 `.env.local` / `.env` —— 閾值統一到 `~/.config/sysmon-watchdog.env`（新路徑、不污染 hermes-portal 那條密鑰鏈）
