+## 3. 架構決策
+
+### 3.1 為什麼 python-telegram-bot v20+
+
+- **async 完整**：v20+ 用 asyncio 寫 handler，跟 `asyncio.to_thread` 包同步 HTTP 函式無縫接
+- **Application.builder()**：測試時可以用 `mock.patch` 直接 mock 掉，方便測 handler chain 結構
+- **filter 系統**：v20+ 用 `filters.TEXT & ~filters.COMMAND` 乾淨分離指令 vs 純文字
+
+### 3.2 為什麼雙 API fallback
+
+- **wttr.in 優勢**：免費、不需 API key、支援中英文城市名、j1 格式回 JSON 很整齊
+- **OpenWeatherMap 優勢**：商業級 SLA、文件完整、有多語言 `lang=zh_tw`、體感溫度更準
+- **fallback 邏輯**：先 wttr.in（成本低）→ 失敗才打 OpenWeatherMap（消耗配額）
+- **情境**：wttr.in 偶爾會回 503 或限流，OpenWeatherMap 是保險
+
+### 3.3 為什麼把 weather 邏輯拆成純函式
+
+- **可測試**：純函式 `fetch_wttr` / `fetch_openweather` / `normalize_city` / `format_weather` 直接 mock `_http_get_json` 就能跑單元測試
+- **handler 薄**：`_do_weather_reply` 只負責「收訊息 → 呼叫 → 回覆」，不混商業邏輯
+- **可重用**：未來想加 CLI / web API / Discord 都能直接 import 同一個 `get_weather()`
+
+### 3.4 為什麼用 `asyncio.to_thread` 包同步 urllib
+
+- **簡單**：urllib 是 stdlib，零外部依賴也能跑（即使沒裝 `httpx`）
+- **隔離**：同步 IO 在 thread pool 跑、不會 block event loop
+- **可測**：把 `_http_get_json` 抽成獨立函式，mock 起來一行就搞定
+
+### 3.5 為什麼 `send_action("typing")`
+
+- **UX**：telegram 預設 5 秒沒回應就顯示「已讀不回」；先送 typing 讓使用者知道 bot 在算
+- **不會打 API 額度**：typing 不算訊息配額
+
+### 3.6 為什麼 `parse_mode=Markdown`
+
+- **可讀**：粗體 `**城市名**` 比純文字更醒目
+- **注意**：parse_mode=Markdown 在 v20+ 有 v2 escape rules；目前用 `**` + `_` 是 safe subset（不會觸發 v2 解析失敗）
