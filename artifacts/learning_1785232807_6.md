+# Agent Implementation Notes — GitHub Trending Scraper
+
+> 工程紀錄：本次任務「抓 GitHub Trending repos 並輸出 markdown 表格」的
+> 實作思路、決策、踩坑、驗證。給 Senior Architect review 用。

+## 1. 任務定義
+
+寫一個自動化腳本：
+- 抓 `https://github.com/trending` 的 repository 清單
+- 解析欄位（repo 名 / 描述 / 語言 / stars / forks / 期間 stars）
+- 輸出成 Markdown 表格
+
+## 2. 關鍵技術決策
+
+### 2.1 不依賴任何第三方套件（stdlib-only）
+
+**選擇**：`urllib.request` + `re` + `html.parser`（標準庫）。
+
+**原因**：
+- GitHub Trending 沒有官方 REST API，唯一公開管道就是 HTML scraping
+- 零依賴 = 任何主機、CI、cron、Docker image 都不用 `pip install`
+- BeautifulSoup 雖然好讀，但部署成本多一步、會跟舊版 lxml 衝突
+- stdlib `html.parser` 處理 `<a>` 內文去 tag 已足夠
+
+**取捨**：regex 解析 HTML 對 GitHub 改版較脆弱。緩解方式：
+1. 每個 regex 都附 fallback（欄位找不到 → 0 或空字串，不 abort）
+2. 註解清楚說明 selector 位置，未來改版只需動 `_ARTICLE_RE` 等 regex
+
+### 2.2 不需 GitHub API token
+
+GitHub Trending 頁面是公開的，curl 帶一般瀏覽器 UA 即可拿到完整 HTML。
+所以腳本不該誤設計成需要 `GITHUB_TOKEN` — 反而增加操作摩擦。
+
+### 2.3 CLI 設計：argparse + 多輸出
+
+```
+python3 github_trending.py                       # daily, stdout
+python3 github_trending.py --since weekly        # 切時間窗
+python3 github_trending.py --language python     # 切語言
+python3 github_trending.py --output file.md      # 寫檔
+python3 github_trending.py --json                # 改輸出格式
+python3 github_trending.py --limit 10            # 截斷
+```
+
+**為什麼這樣設計**：從「人工臨時跑」到「cron 排程餵下游 pipeline」都要能 cover。
+`--json` 模式可以串其他工具（Notion sync、Slack bot、daily briefing），Markdown 模式可以直接 commit 到 repo 當報表。
+
+### 2.4 Markdown 表格欄位排序
+
+```
+# | Repository | Description | Language | ⭐ Total | 🍴 Forks | 🔥 Stars (period)
+```
+
