+# ---------------------------------------------------------------------------
+# Token bucket primitive
+# ---------------------------------------------------------------------------
+
+@dataclass
+class TokenBucket:
+    """Classic token bucket — refills `rate` tokens per second, capacity caps burst."""
+
+    rate: float
+    capacity: float
+    tokens: float = field(init=False)
+    last_refill: float = field(init=False)
+
+    def __post_init__(self) -> None:
+        self.tokens = self.capacity
+        self.last_refill = time.monotonic()
+
+    def _refill(self, now: float) -> None:
+        elapsed = now - self.last_refill
+        if elapsed > 0:
+            self.tokens = min(self.capacity, self.tokens + elapsed * self.rate)
+            self.last_refill = now
+
+    def try_consume(self, cost: float = 1.0, now: float | None = None) -> bool:
+        now = now if now is not None else time.monotonic()
+        self._refill(now)
+        if self.tokens >= cost:
+            self.tokens -= cost
+            return True
+        return False
+
+    def retry_after(self, cost: float = 1.0, now: float | None = None) -> float:

+        self._refill(now)
+        if self.tokens >= cost:
+            return 0.0
+        deficit = cost - self.tokens
+        return deficit / self.rate if self.rate > 0 else float("inf")

+## Rate limiting
+
+Three independent per-IP token buckets:
+
+| Rule     | Rate (tok/s) | Capacity | Use                        |
+|----------|--------------|----------|----------------------------|
+| `read`   | 20           | 40       | GET endpoints              |
+| `write`  | 3            | 10       | POST/PUT/PATCH/DELETE item |
+| `bulk`   | 1            | 3        | DELETE /todos (whole table) |
+
+429 responses carry `Retry-After: <seconds>` per RFC 6585.
+
+## Design decisions (from Senior Architect feedback)
+
+1. **Bucket init is explicit, not lazy** — no `defaultdict` that would let a write burst sneak through under read defaults.
+2. **`asyncio.Lock` guards bucket creation + consumption** — tested under `asyncio.gather`.
+3. **`TodoUpdate` (PATCH) rejects `null`** — sending `{"completed": null}` is 422, never writes `None` to a `nullable=False` DB column.
+4. **X-Forwarded-For takes the first IP in the chain** — `split(',')[0].strip()`.
+5. **Pragma listener is at module level** — `_set_sqlite_pragmas(dbapi_connection, connection_record)` does not close over any factory.
+6. **TTL sweep evicts idle buckets** — bounded memory; periodic background task.

+## 3. Key architectural decisions
+
+### 3.1 Why `create_app()` factory instead of module-level `app`?
+
+A single module-level `app = FastAPI()` works for `uvicorn app.main:app`, but it's hostile to testing:
+
+- **Engine sharing across tests** — every test would share the same SQLite handle, and you'd have to manually drop/recreate tables between tests.
+- **Limiter state leaks across tests** — buckets from a previous test would still be in the dict.
+- **Lifespan runs at import time** — you'd have to manually trigger lifespan or skip the rate-limit setup.
+
+`create_app(database_url, *, limiter=None)` returns a **fresh** app per call. Every `TestClient` gets its own engine + limiter + session factory. Tests are independent and parallel-safe.
+
+Module-level `app` is kept for `uvicorn app.main:app` convenience, but production code is encouraged to use the factory (the README documents this).
