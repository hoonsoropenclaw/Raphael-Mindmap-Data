+from collections import defaultdict, deque
+from threading import Lock
+import time
+
+
+class RateLimiter:
+    """In-memory fixed-window limiter keyed by client identifier."""
+
+    def __init__(self, max_requests: int, window_seconds: int):
+        if max_requests < 1 or window_seconds < 1:
+            raise ValueError("max_requests and window_seconds must be positive")
+        self.max_requests = max_requests
+        self.window_seconds = window_seconds
+        self._requests: dict[str, deque[float]] = defaultdict(deque)
+        self._lock = Lock()
+
+    def check(self, key: str, now: float | None = None) -> tuple[bool, int]:
+        current = time.monotonic() if now is None else now
+        with self._lock:
+            timestamps = self._requests[key]
+            cutoff = current - self.window_seconds
+            while timestamps and timestamps[0] <= cutoff:
+                timestamps.popleft()
+            if len(timestamps) >= self.max_requests:
+                retry_after = max(1, int(timestamps[0] + self.window_seconds - current + 0.999))
+                return False, retry_after
+            timestamps.append(current)
+            return True, 0

+# Todo FastAPI API
+
+A small, self-contained Todo REST API using FastAPI, SQLAlchemy, and SQLite.
+
+## Features
+
+- CRUD endpoints for todo items
+- SQLite persistence
+- Input validation with Pydantic
+- Thread-safe in-memory per-client rate limiting
+- Health check endpoint excluded from rate limiting
+- Unit and API integration tests
+- OpenAPI documentation at `/docs`
+
+## Run locally
+
+```bash
+python3 -m uvicorn app.main:app --reload
+```
+
+The default database is created at `data/todos.db`. For tests, each test fixture uses a temporary SQLite database.
+
+## API
+
+- `GET /health`
+- `POST /todos` with `{"title": "Buy milk", "description": "Optional"}`
+- `GET /todos?skip=0&limit=100`
+- `GET /todos/{id}`
+- `PATCH /todos/{id}` with any of `title`, `description`, or `completed`
+- `DELETE /todos/{id}`
+
+The default limit is 60 requests per 60 seconds per client IP. A rejected request returns HTTP 429 and a `Retry-After` header. The limiter is intentionally in-memory for this simple single-process example; a multi-worker deployment should replace it with a shared store such as Redis.
+
+## Test
+
+```bash
+python3 -m pytest
+python3 -m pytest --cov=app --cov-report=term-missing
+```
+
+## Design notes
+
+- The API uses synchronous FastAPI route handlers with synchronous SQLAlchemy sessions. This avoids mixing `async def` endpoints with blocking database calls for a CRUD workload.
+- `check_same_thread=False` is set for SQLite because FastAPI can execute synchronous handlers in worker threads.
+- Repository methods own short-lived sessions and commit explicitly.
+- Rate-limiter state is protected by a lock, so concurrent requests cannot race while checking and recording a client window.

+The available feedback was for a different Linux monitoring project, but its reusable principles were applied where relevant:
+
+- Keep sensitive configuration out of CLI arguments. This Todo API has no secret-bearing CLI arguments and accepts only a database URL through Python configuration.
+- Protect mutable shared state. The in-memory rate limiter uses a `threading.Lock` around request-window updates.
+- Prefer atomic, explicit state transitions. Database writes use short-lived repository sessions with explicit commit and refresh.
+- Avoid duplicate-instance race conditions in shared state. The limiter's check-and-record operation is one locked critical section.
+- Track state at the correct granularity. Rate-limit windows are keyed per client IP, rather than globally throttling all clients.
+
+The log-cursor and single-instance-lock recommendations are specific to continuous log-monitoring processes and are not applicable to this request-scoped API. For a multi-process deployment, the in-memory limiter should be replaced by a shared external store.
+
+## Implementation rationale
+
+1. Sync FastAPI routes + sync SQLAlchemy were selected for simple CRUD and SQLite. This avoids blocking the event loop by accidentally combining `async def` routes with synchronous database calls.
+2. SQLite is initialized through SQLAlchemy metadata, and tests use independent temporary database files for isolation.
+3. Pydantic models enforce title and description bounds before repository operations.
+4. A middleware applies rate limiting to all API routes except `/health`, returns HTTP 429, and includes `Retry-After`.
+5. Tests cover health, CRUD, pagination, validation, not-found behavior, limiter isolation/expiry, and HTTP 429 behavior.
