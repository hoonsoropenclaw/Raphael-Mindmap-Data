+## 1. 實作思路（L3 抽象層）
+
+### 1.1 為什麼純 stdlib
+
+- N100 環境是 PEP 668 managed、安裝第三方套件要 venv/uv
+- 監控工具是長期 daemon 性質、依賴越小越好
+- Python 3.10+ stdlib 已具備：subprocess、urllib、json、dataclasses、signal、pathlib — 完全足夠
+- **只有 PyYAML 是選配依賴**（讀設定檔用），缺它會 raise ConfigError、不會讓工具 crash

+### 1.2 為什麼模組化（5 個檔案 + 1 個主程式）
+
+| 模組 | 職責 | 可獨立使用 |
+|------|------|-----------|
+| `config_loader.py` | YAML 載入 + 預設值 + `~/` 展開 | CLI: `python3 config_loader.py` |

+| `journal_reader.py` | journalctl + 檔案增量讀取 + 門檻判定 | CLI: `python3 journal_reader.py demo` |
+| `alert_dispatcher.py` | log + JSONL + webhook 三 channel | CLI: `python3 alert_dispatcher.py` |

+**好處**：
+- 任何模組失敗只影響一塊、其餘能跑
+- 單元測試可以 mock 任何一層

+2. **JSONL events** (`~/.hermes/logs/system-monitor/events.jsonl`) — 給 hermes cron watchdog / session_search 撈（結構化、可解析）
+3. **Webhook**（選配、需 `SM_WEBHOOK_URL` env）— Slack / Discord / Line Notify 都吃 JSON POST
+
+### 1.4 為什麼加冷卻機制
+
+- cron 每 5 分鐘跑 → 同個 CPU crit 會在 5 分鐘內連發 60 條 alert

+### 2.1 CPU 採樣不引進 psutil
+
+- psutil 是第三方、N100 預設沒裝

+
