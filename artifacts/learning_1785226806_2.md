+# GitHub Trending Scraper — 實作思路
+
+## 1. 任務目標
+
+撰寫一支自動化腳本，抓取 GitHub Trending 頁面
+（`https://github.com/trending`），把當下的 trending repositories
+整理成 Markdown 表格，輸出到檔案或 stdout。
+
+## 2. 設計決策
+
+### 2.1 為什麼不用 headless browser / Scrapling？
+
+GitHub Trending 是**完全公開**、**server-side rendered** 的頁面，
+HTML 內含完整資料；不需要登入、不觸發 rate limit、
+也不跑 JavaScript 動態載入內容。換言之：
+
+- **curl + regex** 就足夠（trial-and-error: scrapling 不必）
+- 用 Playwright / Scrapling 只會**浪費資源**、引入不必要的 headless
+  維運負擔（trial-and-error: `browser-automation.md`）。
+
+> 反例（不要做）：scrapling `Fetcher.configure()` 不回傳實例、
+> 直接 `Fetcher()` 才是正確用法（trial-and-error:
+> `scrapling-api-usage-20260629.md`）——但這個專案用不到 scrapling。
+
+### 2.2 為什麼 `urllib` 不用 `requests`？
+
+`urllib` 是 Python 標準庫、零依賴。這個任務只是下載一個 HTML、
+解析、輸出表格，**不需要** session、cookies、retry 等進階功能。
+依賴 `requests` 會帶來 PEP 668 + venv 的麻煩（trial-and-error:
+`stdlib-production-tool-pattern.md`）。
+
+### 2.3 為什麼 regex 不用 BeautifulSoup？
+
+GitHub Trending 的 article 結構穩定（單一 pattern：`<article
+class="Box-row">`），共 5 個抓取欄位。BeautifulSoup 會多 ~10 倍行數、
+多一個依賴。當前規模下 regex **更易讀、更易維護**。
+
+> 若未來 GitHub 改版（例如改成 React SPA）導致 SSR HTML 消失，
+> 才需要切換到 BeautifulSoup 或 headless browser。
+
+### 2.4 設計穩健的 selector
+
+HTML class 名稱 GitHub 會改版（見實測：`pr-4` 變 `tmp-pr-4`）。
+**不能 hardcode 完整 class 字串**，要用**穩定的 class prefix
+pattern**：
+
+| 欄位 | Selector 設計 | 為什麼這樣 |
+|------|--------------|----------|
+| repo path | `<h2 class="h3 lh-condensed">` 內 `href="/owner/repo"` | `<h2>` 是語意穩定的 container |
+| description | `<p class="col-9 ... color-fg-muted ...">` | 用 class prefix 而非完整 class，吸收 trailing utility class 改名 |
+| language | `<span itemprop="programmingLanguage">` | microdata 屬性是 schema.org 標準，比 class 穩定 |
+| stars today | `(\d+,?\d*) stars (today|this week|this month)` | 同樣字串支援 daily/weekly/monthly 三種模式 |
+| total stars | `href="/.../stargazers"` link 內 svg 後第一個數字 | 跟著 stargazer link 走，不會抓到 fork 數 |
+
+### 2.5 Markdown 表格的安全性
+

+`_md_cell()` 必須把這兩個字元過濾掉：
+
+```python
+text = text.replace("|", "\\|").replace("\n", " ")

+

+> 用 `evil|owner` 等對抗式輸入驗證轉義正確。
+
