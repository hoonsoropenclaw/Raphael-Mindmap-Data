+## 給之後接手的人看的架構筆記
+
+1. **單一職責**：`bot.py` 只負責 Telegram 對接、`weather.py` 只負責 API 對接。
+   兩者**不直接 import 對方** — bot 透過 `weather.query(city)` 呼叫。
+   這樣 `weather.py` 可以沒 Telegram 環境也跑得起來（測試全是這樣跑的）。
+
+2. **錯誤收斂**：所有可預期的失敗（城市空 / 401 / 404 / 429 / 5xx / timeout / 網路錯 / JSON 壞）都收成 `weather.WeatherError`。
+   bot 只 `try/except WeatherError`，沒預期到的錯誤用 `logger.exception` 救下來、給使用者友善訊息。
+
+3. **不寫死 token**：`config.py` 從 `.env` 或環境變數讀，**沒用就 raise**。
+   `bot.build_app()` 啟動時就檢查，跟生活裡所有「跑到一半才發現少了 key」相反。
+
+4. **測試用 monkeypatch**：`patch("weather.requests.get", ...)` 攔截所有 HTTP 呼叫。
+   不需要真的網路、也不需要真的 Telegram 帳號。
