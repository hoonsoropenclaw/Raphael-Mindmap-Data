Pseudo-streaming loop

每 BOT_PROGRESS_TICK 秒 editMessageText 一次，直到 task 完成。

async def transcribe_with_progress(voice_bytes, *, progress_cb):
    task = asyncio.create_task(self.transcribe(voice_bytes))
    while not task.done():
        await asyncio.sleep(SETTINGS.progress_tick_seconds)
        await progress_cb(elapsed, done=False)
    return await task

Hard timeout

asyncio.wait_for 包住整個呼叫；超過 25s 一律取消，給使用者清楚的錯誤訊息。

return await asyncio.wait_for(
    _call(),
    timeout=SETTINGS.whisper_timeout_seconds + 5.0,
)

誠實對照：server-side vs pseudo-streaming

OpenAI 目前 不公開 Whisper 的 SSE 串流端點。下方是兩種實作的對照。

特性Server-side streamingPseudo-streaming (本 bot)
使用者體感「即時」✓ 真正 partial text△ 進度動畫 + 耗時更新
實作複雜度高 (SSE / WebSocket)低 (輪詢 + editMessageText)
API 配額可能更高 (per-chunk)與一次性呼叫相同
對 OpenAI 依賴需等官方支援立即可用
錯誤恢復需設計 partial-failure與原本相同
