+# PRD — Kinetic Interface Kit
+
+## 1. Problem
+Next.js applications often accumulate one-off animations with inconsistent timing, poor reduced-motion support, unnecessary React renders, and weak keyboard semantics. The deliverable must provide a small reusable system rather than a single animated landing page.
+
+## 2. Users
+- Next.js developers who need composable client-side motion primitives.
+- Product designers who need a live reference for timing, hierarchy, and interaction feedback.
+- Keyboard, touch, and reduced-motion users who must receive equivalent state feedback.
+
+## 3. Reused knowledge
+- `nextjs_project_setup`: App Router, TypeScript, metadata, global CSS.
+- `frontend_theme_and_animation_management`: `useReducedMotion`, low viewport threshold, GPU-safe properties.
+- `frontend-dev/references/motion-recipes.md`: Reveal, stagger, MotionValue-driven magnetic/tilt, shared layout.
+- Historical Motion Foundry project `learning_1785720608_1`: verified Next.js + Framer Motion baseline.
+
+## 4. Historical constraints applied
+- Use npm `framer-motion`; do not depend on a broken React-less UMD bundle.
+- Never make content permanently invisible if IntersectionObserver does not fire.
+- Avoid CSS transition conflicts with animation-engine-owned transforms.
+- Use transform/opacity/filter/clip-path only for continuous animation.
+- Disable cursor-driven effects for touch/coarse pointers.
+- Respect `prefers-reduced-motion` in both React and standalone HTML.
+
+## 5. Functional requirements
+### Must
+1. Next.js 16 App Router project using React 19, TypeScript, and Framer Motion.
+2. Public component exports for: `MotionProvider`, `Reveal`, `Stagger`, `StaggerItem`, `Pressable`, `Magnetic`, `Tilt`, `MorphCard`, `AnimatedNumber`, `MotionTabs`, `ToastRegion`, `MotionSwitch`.
+3. Central motion tokens for springs, easings, durations, and distances.
+4. Every pointer-driven primitive avoids state updates on pointer move.
+5. A live showcase covering feedback, continuity, state, progress, and disclosure.
+6. Full keyboard semantics: buttons, tabs with arrow keys, switch, dialog close/Escape.
+7. Reduced-motion and coarse-pointer fallbacks.
+8. A complete self-contained `web_output.html` with no runtime CDN dependency.
+9. Automated structural/API tests, TypeScript checking, production build, and browser E2E.
+
+### Should
+- Polymorphic `Reveal` element support.
+- Configurable direction, delay, distance, and viewport behavior.
+- Configurable button type and native button props for `Pressable`.
+- Accessible toast status messages with deterministic dismissal.
+
+## 6. Visual direction
+- Aesthetic: Industrial editorial / kinetic notation.
+- Palette: warm paper, carbon ink, safety orange, signal green.
+- Signature anchor: a vertical motion timeline crossing the asymmetric layout.
+- No glass cards, neon glow, gradient headline, oversized centered hero, or generic 3-column SaaS cards.
+- DFII estimate: Impact 4 + Fit 5 + Feasibility 5 + Performance 5 − Risk 2 = 17.

+- Browser console: zero uncaught errors.
+- Browser interactions: press feedback, tabs keyboard/click switching, switch state, toast appearance/dismissal, morph dialog open/close.
+- `web_output.html`: HTTP 200 via local static server and all equivalent interactions pass.
