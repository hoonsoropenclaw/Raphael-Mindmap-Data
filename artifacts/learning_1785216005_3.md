+# Telegram Weather Bot
+
+零第三方依賴的 Telegram 天氣查詢機器人，使用 Telegram Bot API 長輪詢接收文字，透過 Open-Meteo 的 geocoding + forecast API 查詢目前天氣，再回傳繁體中文結果。
+
+## 功能
+
+- 直接輸入城市名稱：`台北市`、`Tokyo`、`New York`
+- 支援 `/start`、`/help`、`/weather <城市>`
+- Open-Meteo 不需要天氣 API key
+- Telegram long polling，不需要公開網域或 webhook 憑證
+- 可選 `TELEGRAM_ALLOWED_USERS` allowlist
+- 每位使用者 cooldown rate limit
+- Telegram/Open-Meteo response size 上限，避免無限制讀取
+- bounded retry：429、5xx、網路暫時錯誤才重試
+- `SIGINT`/`SIGTERM` graceful shutdown
+- 所有測試不需要 Telegram token，也不需要網路
+
+## 檔案
+
+- `telegram_weather_bot.py`：Telegram API client、更新處理、long polling、allowlist、rate limit
+- `weather_api.py`：Open-Meteo client、地理編碼、天氣資料轉換與中文輸出；也可獨立當 CLI
+- `test_weather_bot.py`：stdlib `unittest` 離線測試
+- `.env.example`：設定範例，不含任何 secret
+- `IMPLEMENTATION_NOTES.md`：架構決策、限制與驗證紀錄
+
+## 啟動
+

+python3 telegram_weather_bot.py

+# 實作思路與交付審查
+
+## 1. 任務目標
+
+建立一個能接收 Telegram 文字訊息、查詢天氣 API 並回傳結果的可執行 bot。實作採 Python 3.12 標準函式庫，不引入 `requests`、`aiohttp` 或 `python-telegram-bot`，降低安裝、維護與部署成本。
+
+## 2. Senior Architect 回饋吸收狀況
+
+啟動時先檢查目前專案目錄，沒有可讀的專案內架構建議檔。既有 `/home/hoonsoropenclaw/.hermes/architect_feedback.md` 可讀內容包含本輪 Telegram Weather Bot 的前次交付報告；另有 `/home/hoonsoropenclaw/.hermes/review_queue.md`。已吸收其中的原則：
+
+- 使用 Open-Meteo，避免額外天氣 API token。
+- geocoding 與 forecast 兩階段分離。
+- Telegram handlers 與 weather service 分離，service 可離線測試。
+- bounded response read，防止無限制 HTTP body 造成記憶體風險。
+- 明確 User-Agent。
+- allowlist、rate limit 與 long polling absolute offset。
+- 送出回覆失敗時 rollback reservation，避免重送 update 被錯誤判定為 cooldown。
+
+本次沒有複製前次報告中的第三方 `aiohttp` 依賴，因為本專案可由 `urllib` 完成，並與目前 stdlib-first 生產工具規範一致。
+
+## 3. 架構
+
+```text
+Telegram update
+      │
+      ▼
+telegram_weather_bot.py
+  ├─ BotConfig：環境變數、token 格式、timeout
+  ├─ TelegramClient：getUpdates/sendMessage、HTTPS、bounded read、retry
+  ├─ CooldownLimiter：每使用者 cooldown、thread-safe、rollback
+  └─ WeatherBot：allowlist、指令解析、offset、graceful shutdown
+      │
+      ▼
+weather_api.py
+  ├─ sanitize_query：Unicode normalize、控制字元清理、長度限制
+  ├─ Open-Meteo geocoding：城市 → latitude/longitude
+  ├─ Open-Meteo forecast：座標 → current weather
+  └─ WeatherReport：WMO code → 繁體中文與 emoji
+```
+
+## 4. 關鍵決策與理由
+
+### 4.1 Open-Meteo
+
+Open-Meteo 的 geocoding 與 forecast endpoint 不需要 API key；避免把另一組 secret 帶進 bot。API 回傳的 WMO weather code 由本地字典轉繁中，因為免費 API 的 `language` 參數不保證修改 JSON 欄位。
+
+### 4.2 Long polling
+
+本機或 headless 主機不需要公開 HTTPS endpoint，因此使用 `getUpdates` long polling。每筆更新都使用 `offset = update_id + 1` 的絕對游標，不使用 `offset += 1`，避免批次更新或非連續 update ID 導致重複處理。
+
+### 4.3 防護層
+
+1. Allowlist：設定 `TELEGRAM_ALLOWED_USERS` 後，未授權 user ID 直接忽略。
+2. Rate limit：每個 user 使用獨立 cooldown，避免單一使用者打爆免費 API。
+3. Input sanitization：城市名稱做 NFKC normalization、去除控制字元、限制 80 字元。
+4. HTTP bounded read：Telegram 與 Open-Meteo 都限制最大 response body。
