+# OCR Quest — Godot 2D Game OCR System
+
+A runnable Godot 4.3 desktop prototype demonstrating an in-game OCR pipeline for 2D game frames.
+
+## What is included
+
+- Dark game HUD with a live-frame preview panel.
+- OCR pipeline state machine: capture → preprocessing → OCR → vision validation.
+- Signal-based progress updates so the game loop remains responsive.
+- Throttled frame processing and bounded, deterministic demo output.
+- Keyboard controls: F12 / Space to scan, Escape to reset.
+- The `OCRQuest` scene runs without external assets or network access.
+
+## Run
+
+```bash
+godot --path . --editor
+# Or run headlessly for a smoke check:
+godot --headless --path . --quit-after 2
+```
+
+The current environment has Godot 4.3, Tesseract 5.3.4, and FFmpeg 6.1.1. The demo deliberately uses a local simulated OCR provider so it is executable without downloading language models. To connect real OCR, replace `ocr_engine.gd`'s `process_frame()` provider call with a subprocess bridge to Tesseract or a native GD extension; keep the same signals and bounded processing contract.
+
+## Architecture
+
+`main.gd` owns the game HUD, input, and frame cadence. `ocr_engine.gd` owns the OCR pipeline and emits typed progress/completion/failure signals. This separation follows the reusable OCR, video-rendering, and Godot optimization patterns: preprocessing is explicit, work is throttled, and the render loop does not block on external work.
