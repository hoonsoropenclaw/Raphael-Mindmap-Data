    🧠 實作思路
    ────────────────────────────────────
    
    1.  不用 API / 不用 token — /trending 是公開 SSR HTML，不需要 GitHub API key、不需要 OAuth、不計 rate limit（雖然 GitHub 對 bot 不友善，但 trending 頁是公開快取層）。換來的好處：能在任何環境、任何 IP 跑，包含 N100 迷你機、CI、容器。
    
    2.  lxml → bs4 html parser — requests + BeautifulSoup 是這個案例最合適的組合：trending 頁的每個 repo 是一個獨立 <article class="Box-row"> 區塊，結構穩定。re.search 兜底解出語言色碼與區間增量。
    
    3.  欄位設計：
        - # 排名 / Repository（帶連結）/ Language / Stars (Δ) 區間增量 / Total ★ / Forks / Description
        - 區間增量 (Stars (Δ)) 是 trending 頁最有價值的資訊（這是「為什麼現在火」），不是用 total 代替
        - 用 +1,166 顯式標示「過去 24h 新增」的語意，避免讀者把 total 跟 delta 混淆
    
    4.  雙輸出格式：
        - markdown 表格（給人看的日報用）— 帶 snapshot 時間戳、span、language 篩選條件 metadata
        - JSON（給程式接的 pipeline 用）— 完整結構化資料
    
    5.  陷阱處理：
        - parse_count() 把 '1,234' / '12.3k' / '1.2m' / '850' 都正確轉 int，避免小寫 k 漏掉
        - description 內的 | 會破壞 markdown 表格 → 自動轉義成 \|
        - 沒有 description 的 repo 用 (no description) 標示，不留空 cell（GitHub trending 有時就是有 repo 沒填）
        - language span 用 style="background-color:#xxx" 的 attribute 抓色碼，不用 sibling span（trending 頁會重排結構）
    
    ────────────────────────────────────
    ⚠️ 兩個誠實的限制
