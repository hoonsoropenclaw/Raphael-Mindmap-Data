任務

集成 Telegram Bot API 與 OpenAI Whisper API，實現「語音訊息自動轉錄 + 自動回覆」。 使用者從 Telegram 傳 voice / video_note / audio / audio 文件 → bot 下載 → Whisper 轉錄 → 自動回傳文字。

async-native (asyncio + httpx) provider abstraction (易測試) 指數 backoff retry dry-run (零 API 成本 demo) 雙模式 (bot 自動回覆 + CLI 單檔)

系統架構

① Telegram Update
long-polling 收到 voice / video_note / audio / document 訊息
② Telegram getFile + 下載
用 httpx.AsyncClient 串流到 tempfile,超 25MB 拒絕
③ Whisper API
multipart/upload 送 OpenAI,retry 3 次,指數 backoff
④ Telegram sendMessage
reply_to_message_id 引用原訊息,chunk_text 切長訊息
核心服務層
TranscriptionService — orchestrate ③ & ④,hold history(list[TranscriptionResult])
Provider 抽象
HttpWhisperProvider / HttpTelegramProvider — 真實打 API;
MockWhisperProvider / MockTelegramProvider — 測試用,不發任何 HTTP

如何使用

A. Dry-run (零 API 成本,測流程)

# 雙模式 CLI — bot 模式 & 單檔轉錄模式
python3 whisper_telegram_bot.py transcribe ./my-recording.ogg --dry-run --language zh

# Bot 模式 dry-run (會啟 long-polling,但任何上傳都會回假轉錄)
python3 whisper_telegram_bot.py bot --dry-run

# 跑完整 demo (含 tests)
bash run_demo.sh

B. Live 模式 (需要真的 key)

export TELEGRAM_BOT_TOKEN="123456:ABC..."      # @BotFather 拿
export OPENAI_API_KEY="sk-..."                 # platform.openai.com
export TELEGRAM_CHAT_ID="987654321"             # CLI 模式需要 (bot 模式不用)
export WHISPER_LANGUAGE="zh"                   # 選填

# Bot 模式 — 長駐,等使用者傳語音
python3 whisper_telegram_bot.py bot

# CLI 模式 — 給一個音訊立刻轉
python3 whisper_telegram_bot.py transcribe recording.m4a --language zh

C. 跑 unit tests

python3 -m unittest tests.test_whisper_telegram -v
