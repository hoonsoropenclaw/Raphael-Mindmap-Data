+## 狀態設計
+
+狀態存於 `useReducer`，shape：
+
+```js
+{
+  todos: [{ id, text, completed, priority, createdAt }],
+  filter: 'all' | 'active' | 'completed',
+  search: string,
+  sortBy: 'created' | 'priority' | 'alpha',
+  selectedIds: Set<string>,
+  history: Array<{ prevTodos, prevSelected }>   // 上限 10
+}
+```
+
+**為什麼選 useReducer 而不是 useState**：
+- state 有 5 個 slice、衍生 selector 3 個
+- 批次動作（bulk toggle/remove）需要同時清掉 selection——多 slice 同步
+- 13 個 action 各自有副作用（push history / drop from set），集中到 reducer 比散在 handler 易測試
+
+**為什麼用 Set 存 selectedIds**：O(1) lookup，且 `selectedIds.size` 直接拿 selectedCount，避免每次 O(n)。
+
+**Undo 設計**：每次 mutation action（ADD/TOGGLE/EDIT/REMOVE/SET_PRIORITY/BULK_TOGGLE/BULK_REMOVE/CLEAR_COMPLETED）push 一筆到 history。UNDO 從 stack 頂 pop，把 todos + selectedIds 都還原。LIMIT=10 避免 memory leak。
