+# GitHub Trending → Markdown
+
+A zero-dependency Python 3 automation script that fetches GitHub Trending repositories and emits a GitHub-flavored Markdown table.
+
+## Quick start
+
+```bash
+# Daily Trending to stdout
+python3 github_trending.py
+
+# Weekly Python Trending to a file
+python3 github_trending.py \
+  --language python \
+  --since weekly \
+  --limit 20 \
+  --output trending-python-weekly.md
+
+# Use a 10-minute cache for repeated scheduled runs
+python3 github_trending.py \
+  --cache-ttl 600 \
+  --output trending.md
+
+# Fully offline replay/debug
+python3 github_trending.py \
+  --input-html tests/fixtures/trending.html \
+  --output fixture-output.md
+```
+
+## CLI options
+
+| Option | Purpose | Default |
+|---|---|---|
+| `--language`, `-l` | Programming-language filter | all |
+| `--since`, `-s` | `daily`, `weekly`, or `monthly` | `daily` |
+| `--spoken-language` | Spoken-language code | none |
+| `--limit`, `-n` | Maximum rows | `25` |
+| `--output`, `-o` | Output file or `-` for stdout | `-` |
+| `--input-html` | Parse a local HTML fixture instead of network | none |
+| `--timeout` | Network timeout in seconds | `15` |
+| `--retries` | Bounded retries for 429/5xx/timeouts | `2` |
+| `--cache-ttl` | Cache lifetime in seconds; `0` disables | `0` |
+| `--cache-dir` | Override cache directory | XDG cache |
+| `--refresh` | Force an upstream refresh | off |
+| `--title` | Custom Markdown title | generated |
+| `--quiet`, `-q` | Suppress success diagnostics | off |
+
+## Automation examples
+
+Cron writes directly to a durable file; no long-running process is needed:
+
+```cron
+17 * * * * cd /absolute/path/to/project && /usr/bin/python3 github_trending.py --cache-ttl 600 --output trending.md >> cron.log 2>&1
+```
+
+GitHub Actions example:
+
+```yaml
+- name: Generate Trending report
+  run: python3 github_trending.py --since weekly --output trending.md
+```
+
+## Architecture
+
+```text
+build_trending_url()   validates filters and creates source URL
+fetch_html()           urllib transport, bounded retries, gzip and size guards
+get_trending_html()    optional cache boundary
+TrendingHTMLParser     stdlib streaming parser with schema-drift detection
+render_markdown()      pure presentation function
+atomic_write_*()       unique tempfile + fsync + os.replace
+main()                 argparse orchestration and exit status
+```
+
+The parser deliberately handles nested SVGs and HTML void elements. GitHub places icons inside numeric links; ending capture at the first nested closing tag would incorrectly produce zero stars. Similarly, counting `<img>` or `<br>` as normal nested elements would prevent an `<article>` from closing.

+
+## Delivery status
+
+- Project: `learning_1785164405_6`
+- Status: delivered and locally verified
+- Runtime: Python 3.12 standard library only
+- External service: public `https://github.com/trending` HTML endpoint
+- Credential requirement: none
+
+## 1. Senior Architect feedback absorbed
+
+The available feedback in `/home/hoonsoropenclaw/.hermes/architect_feedback.md` praised four patterns in an earlier automation tool and identified two deployment risks. This implementation deliberately carries those patterns forward:
+
+| Feedback | Applied here |
+|---|---|
+| stdlib-first | `urllib.request`, `html.parser`, `tempfile`; no pip dependency |
+| separate API client from transport/orchestration | URL builder, HTTP fetcher, cache, parser, renderer, atomic writer, and CLI are separate functions/classes |
+| mock external boundaries | 26 deterministic unit tests; HTTP opener, sleep function, clock, and fetcher are injectable |
+| avoid upstream abuse | optional `--cache-ttl`, bounded retries, `Retry-After` support, explicit User-Agent |
+| long-running loops do not suit serverless | this is a short-lived batch command; cron/GitHub Actions invoke one run and exit |
+| protect production behavior | bounded response size, HTML content-type validation, schema-drift failure, atomic output |
+
+## 2. Architecture and reasoning
+
+### 2.1 Why HTML scraping
+
+GitHub has no documented public REST endpoint for the Trending page. The stable, public source is the Trending HTML page. Because HTML is less stable than an API contract, the implementation treats parsing failure as a first-class operational failure rather than returning an empty report.
+
+### 2.2 Module boundaries
+
+Even though the deliverable is one executable script, the code is internally split by responsibility:
+
+1. `build_trending_url()` validates period/language inputs and URL-encodes filters.
+2. `fetch_html()` owns HTTP, timeout, gzip, response-size guard, retry policy, and content-type verification.
+3. `get_trending_html()` owns the optional cache; it never parses HTML.
+4. `TrendingHTMLParser` transforms HTML into immutable `Repository` records.
+5. `parse_trending_html()` performs structural/schema-drift checks.
+6. `render_markdown()` is a pure presentation function.
+7. `atomic_write_bytes()` owns durable/concurrency-safe filesystem replacement.
+8. `main()` only orchestrates CLI arguments, boundaries, diagnostics, and exit codes.
+
+This boundary design keeps external I/O mockable while avoiding an unnecessarily large package for a single-purpose CLI.
+
+### 2.3 Parser correctness details
+
+Two details are easy to get wrong in GitHub's current HTML:
+
+- Stars/forks text occurs after nested SVG elements. A parser that stops capture at the first `</svg>` silently records `0`.
+- `<img>`, `<br>`, `<meta>`, and other void elements do not have closing tags. A depth parser that increments for them never reaches the expected article depth, swallowing following records.
+
+The parser therefore has:
+
+- separate article depth and capture depth;
