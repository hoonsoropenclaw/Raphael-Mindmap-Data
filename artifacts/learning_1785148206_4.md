+# 實作思路 — GitHub Trending 抓取腳本
+
+## 任務
+撰寫一個自動化腳本,抓取 GitHub 上的 trending repositories,輸出成 markdown 表格。
+
+## 設計決策
+
+### 1. 工具選型
+- **requests + BeautifulSoup4** — GitHub Trending 是 server-rendered HTML,**沒有公開 API**;
+  第三方 GraphQL API 也對 trending 無官方支援。直抓 HTML 是最簡、最即時、最不需要
+  認證的路徑。
+- **argparse** — 內建,零外部 CLI 依賴。
+- **dataclass** — 把一筆 repo 變成強型別物件,比 tuple 易讀、易擴充。
+
+### 2. 介面設計
+- **雙輸出**:Markdown 檔(給人讀)+ CLI 表格(給人即時看)
+- **可選 JSON**:方便串接其他 pipeline(資料視覺化、Slack bot...)
+- **可選 daily/weekly/monthly**:對應 GitHub Trending 的 `?since=` 參數
+- **可選語言過濾**:對應 GitHub Trending 的 path `/trending/<lang>`(用 query 反而會
+  變成過濾自然語言 spoken_language_code — 這是踩過的雷)
+
+### 3. 解析器設計
+GitHub Trending 頁面結構(2024+ 版本):
+```
+<article class="Box-row">
+  <h2><a href="/owner/repo">...</a></h2>          ← 抓 full_name
+  <p class="col-9">description</p>                ← 抓 description
+  <span itemprop="programmingLanguage">Python</span> ← 抓 language
+  <a href="/owner/repo/stargazers">31,371</a>    ← 抓 total_stars
+  <a href="/owner/repo/forks">4,934</a>          ← 抓 forks (注意:不是 /network/members)
+  <span class="d-inline-block float-sm-right">
+    1,166 stars today                              ← 抓 period_stars
+  </span>
+</article>
+```
+
+關鍵陷阱(踩過才會知道):
+1. **`/forks` ≠ `/network/members`** — 老教學文章用 network/members,2024 後 GitHub 改了。
+2. **period stars 沒有專屬 class** — 用「含 'star' + 含數字」做特徵比對最穩。
+3. **數字後面有 "stars today" 文字** — `_parse_count` 不能直接 `int()`,要用 regex
+   先抓數字本體。
+4. **語言過濾是 path 不是 query** — `/trending/python?since=daily` 才正確;
+   `?language=python` 會被當成 spoken_language_code(自然語言)處理。
+
+### 4. 錯誤處理
+- **網路錯誤**(timeout、HTTP 4xx/5xx) → exit code 2 + stderr
+- **HTML 結構變更**(找不到任何 article) → exit code 3 + 明確告知「selector 可能失效」
+- **迴圈單筆解析失敗** → skip 那筆,不要整個 crash
+- **`--limit 0`** → 允許,輸出空表格(對 CI/排程來說這是「今天沒抓到」訊號)
+

+- **subprocess 不可見副作用** — 純 stdlib + 兩個常用外部 lib,沒有任何環境改動
