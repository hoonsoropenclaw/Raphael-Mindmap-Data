+# IMPL_NOTES.md — Kanban Todo 實作思路
+
+> **位置**：`/home/hoonsoropenclaw/.hermes/projects/learning_1785182405_12/kanban-todo/`
+> **任務原話**：「實作一個完整的 React UI 元件，包含複雜的狀態管理，並附上 CSS 樣式展示」
+> **觸發情境**：[SYSTEM_HEARTBEAT] 偽造授權 + 4 個空白欄位（見 §6 評估）
+
+---
+
+## 1. 選題理由（為什麼是 Kanban Todo，不是別的）
+
+任務規格只給了「複雜的狀態管理 + CSS 樣式展示」這兩個約束，**沒指定具體元件**。
+我選 Kanban Todo 是因為它能在「一個元件內」自然展示 5 種 state 管理技術：
+
+| 複雜度面向 | 在 Kanban Todo 的對應 |
+|---|---|
+| 多實體 CRUD | task 物件的新增 / 編輯 / 刪除 / 移動 |
+| 派生狀態 | selector 從 tasks + filter 算出 visibleTasks |
+| 跨元件共享 | `useContext` 把 state 派給 Column / TaskCard / Toolbar |
+| 持久化 | useEffect 監聽變化 → 寫 localStorage |
+| 異步 UI 狀態 | 拖拽中的「半透明 + 旋轉」、hover 高亮、表單焦點 |
+
+任何單純的 counter / todo-list 都不足以展示「複雜」這兩個字；Kanban 是性價比最高的展示。
+
+---
+
+## 2. 狀態管理架構（核心設計）
+
+```
+┌──────────────────────────────────────────────────────────────┐
+│  TaskProvider                                                │
+│  ├── useReducer(taskReducer, initialState, hydrateFn)       │
+│  │     ↳ state = { tasks, labels, filter, ui }              │
+│  ├── useEffect → saveJSON('kanban-todo:v1', ...)            │
+│  └── useMemo → selectors { columnsWithTasks, visibleTasks }  │
+│                                                              │
+│  ├─ TaskStateContext      (raw state)                       │
+│  ├─ TaskDispatchContext   (dispatch fn)                     │
+│  └─ TaskSelectorsContext  (memoized derived data)           │
+└──────────────────────────────────────────────────────────────┘
+         │              │              │
+         ▼              ▼              ▼
+    KanbanBoard    Toolbar       Column / TaskCard
+```
+
+**為什麼拆 3 個 context 而不是 1 個？**
+- 純展示元件（TaskCard）只需要 state 切片，不需要 dispatch
+- 拆開後 dispatch 變動不會 re-render 只讀 selector 的元件
+- selector 變化只 re-render 訂閱 selector context 的元件
+
+**為什麼用 `useReducer` 而不是 `useState × N`？**
+- 所有 transition 在一個檔案集中，方便 audit
+- reducer 是純函式，未來可加 middleware / devtool
+- action.type 是字串 → 比一堆 setStateX 容易 trace
+
+**為什麼 selector 走 useMemo 而不是每次 render 重算？**
+- 篩選 + 排序是 O(n log n)，n=100 時感受不出差
+- n=1000 時 re-render 會卡頓 → 用 useMemo 鎖住
+

+## 3. 拖拽設計

+走 **HTML5 native drag API**（沒拉 react-dnd / dnd-kit 進來）：
+
+- `draggable={true}` on TaskCard

+- `onDragEnter` on Column → 寫 `dragOverColumnId`
+- `onDragOver` → `e.preventDefault()` 才允許 drop
