+## 1. 實作選擇（為什麼這樣做）
+
+### 1.1 任務核心拆解
+1. **接收 Telegram 文字訊息** → 需要 Telegram Bot API client
+2. **呼叫天氣 API** → 需要氣象資料來源
+3. **回傳結果** → 把資料格式化後回 Telegram

+### 1.2 技術選型
+| 需求 | 選擇 | 理由 |
+|------|------|------|
+| Telegram client | **`python-telegram-bot` v21+** | 官方維護、文件齊全、async API、`Application.builder()` 簡潔 |
+| 天氣 API | **Open-Meteo** | **完全免費、不需 API key、不需註冊**；支援 current + daily forecast；全球城市（lat/lon） |
+| HTTP client | `urllib.request`（stdlib） + `requests`（optional） | `urllib` 給 Open-Meteo 用（stdlib 已足夠）、`requests` 給相容性 |
+| 城市資料庫 | 內建 `CITY_DB: Dict[str, (lat, lon, en_name)]` | 不依賴外部 geocoding API、零額外成本、72 個城市（中英對照） |

+### 1.3 不做的事（明確取捨）
+- ❌ **不支援任意城市自動 geocoding**：因 Open-Meteo 本身不提供 geocoding，且引入 Google Geocoding API 需 token。改採「內建 72 城市表」+「找不到就列可用範例」的 UX。

+- ❌ **不做持久化（DB / cache）**：純無狀態服務、無敏感資料，符合最小可用原則。
