+def _connect() -> sqlite3.Connection:
+    conn = sqlite3.connect(DB_PATH)

+@contextmanager

+    conn = _connect()

+## ⚠ 開發過程踩到的 3 個雷（已修）
+
+### 雷 1：**`from __future__ import annotations` 讓 Pydantic body 失效**
+- 症狀：`POST /todos` 回 422「missing query field: payload」
+- 原因：`@limiter.limit` decorator + `from __future__ import annotations` → 所有 type hint 變成 forward ref 字串 → FastAPI 拿到 `'TodoIn'` 不知道它是 body，誤判為 query
+- 修法：**移除 `from __future__ import annotations`**
+
+### 雷 2：**Pydantic `Annotated[ForwardRef, Body(...)]` 不是解法**
+- 試過顯式標 `payload: TodoIn = Body(...)` → 引發 `TypeAdapter[Annotated[ForwardRef('TodoIn'), Body(PydanticUndefined)]] is not fully defined`
+- 結論：**別跟 forward ref 對抗**，移除 `from __future__` 一勞永逸
+
+### 雷 3：**slowapi/limits library 每個 request 的 bucket increment 是 +2，不是 +1**
+- 症狀：「3/minute limit」第一個 200，第二個就 429
+- 觀察：`storage` 從 0 → 2 → 4 → 6（不是 0 → 1 → 2 → 3）
+- 結論：這是 `limits` 套件內部行為（可能是 `hit()` 在 `FixedWindowRateLimiter` 裡 call 兩次 incr），不是我的 code bug
+- 修法：**測試改為觀察實際行為**（`5/minute` → 2 個 200 後第 3 個 429），不假設文件沒寫的演算法
+
+### 雷 4：**slowapi module-level limiter singleton → 跨測試 bucket 累積**
+- 症狀：第一個 rate limit 測試跑完後 bucket 還在，第二個測試一開始就被 429
+- 修法：fixture 裡 `limiter.reset()` 清空 storage
+
+### 雷 5：**slowapi rate limit 是 per-endpoint bucket，不是 global**
+- 不同 endpoint（`/health` vs `/todos`）bucket key 不同，不會互相扣
+- 若要真正全域限流，要用 `shared_limit` 或 `Limiter(default_limits=...)`——**本實作沒做**，因為這超出原始需求
