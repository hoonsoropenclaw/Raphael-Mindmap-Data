+---
+
+## 1. 設計決策 (Why)
+
+### 1.1 為什麼不用 GitHub REST API
+- GitHub **沒有官方 trending endpoint**(GitHub 從未公開過 trending 資料的 API)。
+- 即便用 Search API 模擬(`created:>... stars:>100`),也只能近似、不是真實 trending 排序。
+- **正解**:直接抓 `https://github.com/trending` HTML 解析。
+- 風險:HTML 結構變動時會壞 → 用「找不到 Box-row → 退出碼 2」當作早期警示。
+
+### 1.2 為什麼抓 daily / weekly / monthly 三種 URL
+- GitHub Trending 預設 daily。URL 加 `?since=weekly|monthly` 切換。
+- 額外支援 `?language=python` 與 `?spoken_language=en` 兩種獨立篩選(orthogonal dimensions)。
+- 不用 Selenium / Playwright:GitHub Trending 是純 server-rendered HTML,curl + BS4 即可。
+
+### 1.3 為什麼用 dataclass + 模組化函式
+- `TrendingRepo` 與 `FetchResult` 用 `@dataclass`:型別清楚、欄位 immutable 易於單元測試。
+- 函式拆成 `build_trending_url` / `fetch_html` / `parse_trending` / `render_markdown` 四個獨立 I/O 邊界。
+  - 之後若想加 JSON 輸出、加 SQLite cache、加 GitHub Actions cron,只需替換其中一個 function,不會動到其他層。
+
+---
+
+## 2. HTML 解析要點 (How)
+
+### 2.1 鎖定的 selector
+GitHub Trending 每個 repo 都是 `<article class="Box-row">`,從這層開始:
+
+| 欄位 | Selector | 備註 |
+|------|----------|------|
+| repo name | `h2 > a` 文字 | 但內含空白(見下) |
+| repo URL | `h2 > a[href]` | `/owner/repo` 開頭,需補 `https://github.com` |
+| description | `p.col-9` | 可能不存在 → 留空字串 |
+| language | `span[itemprop="programmingLanguage"]` | 可能為空字串 |
+| stars total | footer 內 `a[href$="/stargazers"]` 或 `a[href$="/stars"]` | 兩個都相容(防 GitHub 改字) |
+| forks | footer 內 `a[href$="/forks"]` | |
+| stars today/week/month | `span.float-right` 或 `span.d-inline-block.float-sm-right` | 兩種 class 都要 fallback |
+
+### 2.2 處理 h2 內的「假空白」
+`<h2>` 內文長這樣:`permissionlesstech /\n bitchat`(換行 + 縮排會被 BS4 當作空白)。
+我用 regex `\s+/\s*` 標準化為單一 `/`,得到 `permissionlesstech/bitchat`。
+
+### 2.3 處理 markdown 表格破壞者
+description 內可能含 `|`、換行、`\r`。`_md_escape()` 把 `|` 變 `\|`、換行變空白,確保表格不炸。
+
+---
+
+## 3. 防禦性設計
+
+### 3.1 網路層(對應 bash-defensive-patterns skill 精神)
+- 預設 3 次指數退避(`2^attempt`,上限 8s)。
+- User-Agent 預設為 Chrome 124,避免被 GitHub 當 bot 擋。
+- 失敗訊息寫 stderr(不污染 stdout 表格輸出),這樣 `--output` 寫檔時 log 不會混進 markdown。
+
+### 3.2 CLI 驗證
+- `--since` 用 `choices=("daily","weekly","monthly")` → argparse 自動擋非法值(exit 2)。
+- `--limit <= 0` 手動擋(exit 3)。
+- 退出碼語意化:0=成功 / 1=網路失敗用盡 / 2=解析錯誤 / 3=CLI 用法錯。
+
+### 3.3 早期警示
+找不到任何 `<article class="Box-row">` → `raise ValueError` → exit 2。
+**理由**:GitHub 改版通常一次換掉 class 名稱,與其 silently 輸出空表格,不如明確失敗讓 cron job 警報觸發。
