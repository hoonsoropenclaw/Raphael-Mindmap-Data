+# IMPLEMENTATION_NOTES — Telegram 天氣機器人
+
+日期：2026-07-27
+專案：learning_1785157806_2
+
+## 1. 需求
+
+建立可執行的 Telegram 機器人：
+
+1. 透過 Telegram Bot API long polling 接收文字訊息。
+2. 將一般文字視為城市／地點名稱。
+3. 呼叫 wttr.in 免費天氣 API。
+4. 將目前天氣格式化後回傳 Telegram。
+5. 不依賴第三方 Python 套件。
+
+## 2. 吸收的 Senior Architect 回饋
+
+已讀取並套用既有 `ARCHITECTURE_NOTES.md`：
+
+- 採 stdlib-first：使用 `urllib.request`、`json`、`dataclass`，避免為三個簡單端點引入大型框架。
+- 天氣模組與 Telegram glue 分離，讓 `wttr_weather.py` 可獨立用於 CLI、cron 或其他 bot。
+- 採 long polling，適合沒有公網 HTTPS endpoint 的 headless 主機。
+- 保留三層防護：user allowlist、每位使用者 rate limit、Unicode surrogate sanitization。
+- 所有 emoji 使用 UTF-8 literal，避免 lone-surrogate `UnicodeEncodeError`。
+- wttr.in JSON 的天氣描述自行用 weather code 對照中文，不誤認為 `lang=zh` 會翻譯 JSON 欄位。
+- 對缺失 API 欄位 fail loud，回傳 `BAD_JSON`，不以晴天等預設值掩蓋上游格式變更。
+
+## 3. 架構
+
+```text
+Telegram user
+    │ text message
+    ▼
+telegram_bot.py
+    ├─ allowlist
+    ├─ per-user cooldown
+    ├─ command routing
+    └─ Telegram sendMessage
+          │
+          ▼
+wttr_weather.py
+    ├─ input sanitization
+    ├─ wttr.in JSON request
+    ├─ typed parsing
+    ├─ weather-code → 中文／emoji
+    └─ one-line / detailed formatting
+```
+
+### 模組職責
+
+- `telegram_bot.py`：Telegram Bot API、long polling、指令路由、graceful shutdown。
+- `wttr_weather.py`：天氣 API、資料解析、錯誤分類、文字格式化。
+- `run.sh`：載入 `.env`、執行 bot、unit/smoke/check 模式。
+- `test_unit.py`：13 個無網路 mock-based tests。
+- `test_smoke.py`：4 個真實 wttr.in 網路測試。
+
+## 4. 支援行為
+
+- `<城市>`：單行目前天氣。
+- `/detail <城市>`：完整天氣資訊。
+- `/start`、`/help`：操作說明。
+- SIGINT/SIGTERM：停止 polling，確認最後 offset 後正常退出。
+
+## 5. 錯誤與安全設計
+
+- 空城市：回 `EMPTY_INPUT`。
+- HTTP 404：回 `NOT_FOUND`。
+- timeout、DNS、連線錯誤：回 `NETWORK`。
+- 無效 JSON 或必要欄位缺失：回 `BAD_JSON`。
+- Telegram 回覆上限：截斷至 4000 字以避開 4096 字限制。
+- `TELEGRAM_ALLOWED_USERS` 未設定時會警告 bot 為公開模式。
+- Telegram token 僅由環境變數讀取，不寫入程式碼或文件。
