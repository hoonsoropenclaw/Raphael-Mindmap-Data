+# WASM Graphics Engine — Implementation Spec
+
+## Goal
+Build a directly-openable browser artifact demonstrating a high-throughput graphics engine whose particle simulation runs in WebAssembly and whose rendering runs on WebGL2.
+
+## Architecture
+1. `engine.wat`: WebAssembly SIMD-free scalar particle update kernel with linear memory shared with JavaScript.
+2. `app.js`: WebGL2 instanced point renderer, engine lifecycle, adaptive particle count, interactions and HUD.
+3. `styles.css`: responsive dark technical UI.
+4. `build.mjs`: compile WAT to WASM and inline WASM/JS/CSS into standalone `index.html`.
+5. `test.mjs`: instantiate compiled WASM in Node, verify ABI, memory writes, integration, wrapping and finite outputs.
+
+## ABI
+- Exported memory: `memory`
+- `init(count, seed)` initializes packed particle records.
+- `step(count, dt, time, pointerX, pointerY, attract)` updates records in place.
+- `stride()` returns 24 bytes.
+- Record: `x, y, vx, vy, phase, size` as six little-endian `f32` values.
+
+## Rendering path
+- JavaScript creates one static quad-free point geometry.
+- WebGL2 reads particle positions/sizes directly from a typed view of WASM linear memory.
+- One `drawArrays(POINTS)` call renders all particles.
+- Fragment shader draws soft additive circular sprites.
+
+## Verification
+- Compile WAT successfully.
+- Node ABI/invariant test passes.
+- Generated `index.html` contains embedded WASM and no external runtime dependencies.
+- Browser smoke test verifies WebAssembly instantiation, WebGL2 renderer and animation-frame progression.
+
+## Risk / rollback
+All files are newly created in this task directory. Rollback is removal of these new files; no pre-existing project source is modified.

+# IMPLEMENTATION_REPORT.md
+
+## 交付摘要
+完成一個可直接以瀏覽器開啟的 WebAssembly 圖形渲染引擎展示：WebAssembly 負責 75,000 粒子的物理狀態更新，WebGL2 負責 GPU 點精靈渲染，最終產物封裝成無外部依賴的單一 `index.html`。
+
+## 實作思路
+
+### 1. 計算層：WebAssembly
+- 以 WAT 實作 `init` 與 `step`。
+- 每個粒子使用 24 bytes：`x/y/vx/vy/phase/size` 六個 `f32`。
+- JavaScript 與 WASM 共用 linear memory，不逐粒子建立 JS 物件。
+- 單次 `step` 在 WASM 內批次更新吸引力、旋轉場、阻尼與邊界 wrapping。
+
+### 2. 渲染層：WebGL2
+- 用單一 interleaved GPU buffer 上傳 WASM 記憶體區段。
+- 每幀只呼叫一次 `drawArrays(gl.POINTS)`。
+- Vertex shader 處理尺寸脈動與 aspect correction。
+- Fragment shader 產生 cyan/violet additive soft particles。
+
+### 3. 交付層：單檔 HTML
+- `build.mjs` 使用 `wabt` 將 `engine.wat` 編譯成 `engine.wasm`。
+- 將 WASM 轉為 Base64，連同 CSS、JavaScript 內嵌到 `index.html`。
+- 成品可由 `file://` 直接開啟，不需要 HTTP server、不需要安裝依賴、不需要再次編譯。
+
+### 4. 操作與觀測
+- Pointer move/down：彎曲粒子場。
+- RESEED：重新初始化粒子分布。
+- PAUSE/RESUME：暫停或恢復 simulation/render loop。
+- HUD：顯示粒子數、FPS、單幀 simulation + upload + draw 成本。
+
+## 除錯過程
+
+### 問題 1：瀏覽器只顯示 UI，畫布空白
+- Node 端 WASM 測試已通過，但真實瀏覽器 smoke test 顯示：`window.__engine=false`、FPS 為 `—`、canvas 保持預設 300×150。
+- 根因：`app.js` 使用 top-level `await`，但 build 產出的內嵌 script 是普通 `<script>`，不是 module script，因此程式在 parse 階段停止。
+- 修正：build template 改為 `<script type="module">`。
