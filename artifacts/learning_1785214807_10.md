+
+Why slowapi: it speaks FastAPI natively, supports per-route limits via
+``@limiter.limit(...)``, and falls back to in-memory storage so the test
+suite doesn't need Redis. The limiter instance is module-level so
+``main.py`` can import it for ``app.state.limiter`` (slowapi's protocol).
+
+Why per-IP key: rate-limit by ``get_remote_address`` is the simplest sane
+default. Production should swap in a ``key_func`` that pulls an
+authenticated user id; for a starter API the IP key is enough to stop
+trivial abuse.
+"""
+
+from __future__ import annotations
+
+from fastapi import Request
+from slowapi import Limiter
+from slowapi.util import get_remote_address
+
+
+def _build_limiter(default_limit: str, storage_uri: str) -> Limiter:
+    """Construct a Limiter with the given defaults.
+
+    ``headers_enabled=True`` makes slowapi emit ``X-RateLimit-*`` headers
+    so clients can self-throttle. ``strategy=fixed-window`` is the cheapest
+    and works fine at the throughput a SQLite-backed toy API can serve.
+    """
+
+    return Limiter(
+        key_func=get_remote_address,
+        default_limits=[default_limit],
+        storage_uri=storage_uri,
+        strategy="fixed-window",
+        headers_enabled=True,
+    )
+

+### 1. 為什麼不用 slowapi，改自己寫 thin wrapper over `limits`
+
+`slowapi` 看似方便但有兩個坑：
+
+- **`@limiter.limit` 強制 `request: Request` 在 handler 簽名**。當 handler 同時有 Pydantic body 參數時，FastAPI 會把 body 誤判為 query — 跑出 `422 {"loc":["query","payload"]}`。第一輪測試就撞到。
+- **`SlowAPIMiddleware` 假設每個 endpoint 有 `__name__`**。從依賴函式（dependency）呼叫時，拿到的是 `Request` 物件（沒 `__name__`），跑出 `AttributeError: 'Request' object has no attribute '__name__'`。
+
+繞過方案：直接用 `limits.aio.storage.MemoryStorage` + `limits.aio.strategies.FixedWindowRateLimiter`，寫一個 60 行的 `RateLimiter` class + `RateLimited` exception + FastAPI 依賴 `_rate_limit_post(request)`。整個 codebase 不再依賴 slowapi，可少裝一個套件、行為也變得可預測。
+
+### 2. 為什麼用 AsyncClient + ASGITransport 而非 TestClient
+
+`httpx.AsyncClient` + `ASGITransport(app=app)`：
+- 跟 handler async 行為一致（`TestClient` 是 sync 包裝，對 async DB session 可能會有 race）
+- 不綁 TCP port，CI/沙盒友善
+- 跟 `pytest-asyncio` (`asyncio_mode=auto`) 整合乾淨
+
+### 3. CRUD 服務層獨立（不直接從路由呼叫 ORM）
+
+`app/crud.py` 接收 `AsyncSession`，所有函式都可單元測試（不依賴 HTTP）。路由只剩「依賴注入 + Pydantic 轉換 + HTTP status 決策」。
+
+### 4. Rate limit 策略
+
+- 全域預設 `60/minute`（從 `TODO_RATE_LIMIT` env）
+- `POST /todos` 額外加 `30/minute`（從 `POST_LIMIT` 常數）— 防 bulk-create 濫用
+- key 用 IP（loopback 折成單一 bucket 避免測試跨 `127.0.0.1`/`::1` 分散）
+- 失敗時回 `429` + `Retry-After: <秒數>`
+
+### 5. 測試隔離策略
+
+`conftest.py` 的 `_reset_rate_limiter` 是 `autouse` async fixture，每個 test 開始前 `await limiter.storage.reset()`。`app` fixture 用 function scope，每個測試拿新的 `init_engine` + 新 lifespan + 新 `MemoryStorage`。
+
+Rate limit 測試用 `monkeypatch` 替 `limiter.route_limits["POST /todos"]` 成 `"2/minute"`，跑 3 次 POST 驗證 `[201, 201, 429]` 序列。這比跑滿 30 次再驗 429 穩定且快。
