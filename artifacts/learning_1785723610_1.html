Next.js 13 — Server / Client 元件探索

這個 web_output.html 是 /app/page.tsx (Server Component) + /app/live-board.tsx (Client Component) + /api/sync + /api/messages 完整邏輯的單檔可執行版。SSR 流程已被預先執行 (見下方種子訊息), 點開這頁時 Client Component 立刻 hydrate,訂閱 SSE。

⚙️ 模式: 瀏覽器直連 (mock event bus) 已連線
ℹ️ 偵測到目前不是開在本機 3030 port,沒辦法接真實 SSE 後端;此頁已改用 LocalStorage 內的 broadcast, 同一瀏覽器多開分頁就能看到即時同步。實作的 Next.js 13 程式碼在專案根目錄,跑 npm run dev 就會有真實 SSE。

訊息面板

已連線 SSR 時間: —

    本示範展示的關鍵概念 (Next.js 13 App Router)

    • Server Component (本檔 server 端 mirror,page.tsx) — 在伺服器端 fetch 資料,直接內嵌進 RSC payload,首屏不必等 JS 載完就能看到內容
    • 'use client' 邊界 — LiveBoard 內所有 useState / useEffect / EventSource 都不會污染 server bundle
    • Route Handler — /api/sync 建立 SSE 串流, /api/messages 接受 POST 寫入
    • props.serialization — Server→Client 傳遞的物件必須可序列化 (這裡是純 JSON 友好結構)
    • streaming — 客戶端用 EventSource 持續接收新訊息,server-side store 經由 subscribers 廣播
    • optimistic UI — 送出訊息時先在 client 顯示標記 optimistic,server 回應後再以正式訊息取代

    對應的專案檔

    • app/layout.tsx — Root layout (Server Component)
    • app/page.tsx — 首頁 (Server Component),呼叫 listMessages() 取得 SSR 資料
    • app/live-board.tsx — Client Component (對應本檔下方腳本)
    • app/api/sync/route.ts — SSE GET Route Handler
    • app/api/messages/route.ts — POST / GET Route Handler
    • app/lib/store.ts — 跨 route 共用的 in-memory store
    SSR payload 來自 /api/messages · 即時推送來自 /api/sync (SSE)
