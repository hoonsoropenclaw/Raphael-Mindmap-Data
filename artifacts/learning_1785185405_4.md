+## 設計取捨

+### 取捨 1：Bash + Python 內嵌 vs 全 Python？
+**選 Bash + Python 內嵌**。原因：
+- Bash 適合 `/proc` 系統呼叫、process control、watch 模式 loop
+- Python 適合 regex multi-pattern（awk/grep 痛苦）
+- 兩者用 heredoc 內嵌，零外部 .py 部署，單檔交付
+
+### 取捨 2：等級策略 — 單一閾值 vs warning + critical 兩段？
+**選兩段 × 指標 multiplier**：
+- warning = 達閾值
+- critical = warning × 倍率（CPU 1.20, MEM 1.15, DISK 1.10, LOAD 1.50, PROCS 1.30）
+- 各 metric 容忍度不同：磁碟 I/O 慢爬升可晚點報警、load 突爆要早點警示
+
+### 取捨 3：dry-run 真的要完全不寫嗎？
+**是**。 `--dry-run` 連 `/tmp/sysmon` 都不建——驗證 CI、debug 用。
+
+### 取捨 4：Webhook 怎麼做？
+**Stub**：寫到 `$LOG_DIR/webhook.log`，真實部署時把 `fire_webhook()` 內 stub 換成 `curl -X POST "$WEBHOOK_URL" -d "$payload"`。
+理由：監控鏈不該帶 webhook server 假設；stub 讓所有部署都先跑得起來。
