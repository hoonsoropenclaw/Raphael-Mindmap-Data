+# linux-monitor
+
+A self-contained Linux system log + resource monitor with webhook alerting.
+Zero pip dependencies (Python 3.8+ stdlib only).
+
+## What it does
+
+1. Polls CPU%, memory%, swap%, load-per-CPU, disk usage on a fixed interval.
+2. Tails configured log files with **byte-offset + inode cursors** so logrotate
+   is handled automatically and lines are never missed or double-counted.
+3. When a metric exceeds its threshold (or a log pattern fires within its
+   window), emits a webhook alert — but with a per-key cooldown so you don't
+   get alert storms.
+4. Runs as a single instance (fcntl.flock); duplicate starts exit cleanly.
+
+## Security design (absorbed from prior review)
+
+- **Webhook URL & token are read from environment variables**, never CLI args.
+  This avoids leaking secrets via `ps aux` / `/proc/<pid>/cmdline`.
+- **State files are written mode 0600**, owned by the service account.
+- **Systemd hardening** (`ProtectSystem=strict`, `NoNewPrivileges`,
+  `MemoryDenyWriteExecute`, etc.) in the provided unit file.
+- **Config file mode is checked** at load time; a warning is logged if the
+  config is world- or group-readable.
+
+## Layout
+
+```
+linux-monitor/
+├── linux_monitor.py          # main daemon
+├── config.yaml.example       # config template (no secrets)
+├── systemd/
+│   └── linux-monitor.service # hardened systemd unit
+├── tests/
+│   └── test_smoke.sh         # quick functional checks
+└── README.md
+```
+
+## Quick start
+
+```bash
+# 1. Drop the script somewhere on PATH
+sudo install -m 0755 linux_monitor.py /usr/local/bin/linux_monitor.py
+
+# 2. Create config + state dirs
+sudo install -d -m 0750 -o root -g root /etc/linux-monitor /var/lib/linux-monitor
+
+# 3. Edit config to taste
+sudo cp config.yaml.example /etc/linux-monitor/config.yaml
+sudo chmod 0640 /etc/linux-monitor/config.yaml
+
+# 4. Set webhook secrets via env file (mode 0600!)
+sudo tee /etc/linux-monitor/webhook.env > /dev/null <<'EOF'
+MONITOR_WEBHOOK_URL=https://hooks.slack.com/services/TXXX/BXXX/secret-token
+MONITOR_WEBHOOK_TOKEN=
+EOF
+sudo chmod 0600 /etc/linux-monitor/webhook.env
+
+# 5. Run once for sanity
+sudo linux_monitor.py --config /etc/linux-monitor/config.yaml --once
+
+# 6. Install as service
+sudo cp systemd/linux-monitor.service /etc/systemd/system/
+sudo systemctl daemon-reload
+sudo systemctl enable --now linux-monitor.service
+
+# 7. Watch logs
+journalctl -u linux-monitor -f
+```

+### 2.1 為什麼 mini-YAML 而不是要求裝 PyYAML
+

+
+### 2.2 為什麼 disk 路徑預設空 = 全掃 `/proc/mounts`
+
+預設掃描所有 real filesystem mount（過濾 tmpfs/devtmpfs/overlay/proc 等 22 種虛擬 FS），同時跳過非 `/dev/*` 開頭的偽裝條目。這比要求使用者列舉 `/`、`/data`、`/var` 更不容易漏。**但仍可透過 `disks.paths` 顯式指定**——例如只想監控 `/`。

+### 2.3 為什麼 cooldown 在 state 裡而不在記憶體
+
+跨 daemon 重啟必須保留 cooldown：daemon 重啟期間告警已發過，重啟後不應再 fire。State 落盤是必要設計。
+
+### 2.4 為什麼 `tempfile.mkstemp` 而不是 `Path.write_text` + rename
+
+`write_text` 再 `rename` 在寫大 state 時若 SIGKILL 砸下，可能寫到一半留半檔。`mkstemp` 是 `O_CREAT|O_EXCL` 原子建立，再 chmod + rename，**任何時刻目錄裡只有「舊 state」或「新 state」二擇一**。
+
+### 2.5 為什麼 `single_instance_lock` 失敗時 `sys.exit(0)` 而非 1
+
+任務說「自動化檢查」，通常由 cron 或 systemd 啟動。第二個實例的職責是「讓第一個繼續做事」，exit 0 讓 systemd 不會誤判為失敗。
+
+### 2.6 為什麼 `lock` 失敗時 fallback 到 `/tmp/...`
+
+讓開發者在本機（無 sudo）也能跑 smoke test。Production 部署是 root 跑，仍會用 `/var/run/linux-monitor.lock`。
