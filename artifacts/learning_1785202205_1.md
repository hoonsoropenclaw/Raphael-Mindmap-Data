+# sysmon — Linux 系統日誌與資源維運監控
+
+`sysmon.py` 是一個零外部依賴、可由 cron 或 systemd timer 執行的 Linux 監控腳本。
+它每次收集資源與日誌快照，將結果轉成一致的 finding schema；超過閾值時輸出 WARN/ALERT，並以 state transition + cooldown 避免告警風暴。
+
+## 功能
+
+- CPU 使用率：`/proc/stat` 兩次 delta 取樣
+- Load average：`load1 / logical CPU` 正規化
+- Memory：使用 Linux `MemAvailable` 語義，不把 page cache 誤判為不可用記憶體
+- Swap、disk、inode：stdlib `statvfs`
+- 系統日誌：優先 `journalctl`；不可用時 fallback 到設定的文字 log 檔
+- 日誌分類：error-like、authentication failure、kernel/OOM/panic signatures
+- `/var/log` 目錄總大小檢查
+- `fcntl.flock` 單例鎖，避免 cron 與 watch 重疊
+- state JSON 原子寫入：temporary file → flush/fsync → `os.replace`，state/lock `0600`、父目錄 `0700`
+- transition notification：首次異常、升降級、恢復與 cooldown 到期 reminder

+## 告警與狀態
+
+每個 finding 有固定欄位：`key`、`level`、`value`、`threshold`、`detail`、`source`、`samples`。
+
+| Exit code | 意義 |
+|---:|---|
+| `0` | 沒有 WARN/ALERT/ERROR finding |
+| `1` | 至少一個 WARN |
+| `2` | 至少一個 ALERT 或 monitor 內部錯誤 |
+| `3` | 已有另一個 instance 持有 lock |
+| `4` | CLI/config 錯誤 |
+| `130` | 收到 SIGINT/SIGTERM |
+
+state 會保存每個 finding 的目前 level 與 `last_emitted_at`：
+
+- `OK → WARN/ALERT/ERROR`：發一次 transition
+- `WARN ↔ ALERT`：發一次升降級 transition
+- 壞狀態持續且仍在 cooldown：不重複通知
+- 壞狀態持續且 cooldown 到期：發一次 reminder
+- `WARN/ALERT/ERROR → OK`：發一次 recovery transition
+
+stdout 每次都會完整列報告；去重只作用於 transition/外部通知，不會隱藏目前狀態。

+          |

+## 4. 重要實作決策
+
+### 4.1 資源
+
+- CPU 用 `/proc/stat` 兩次累積 ticks 差值；idle 包含 iowait，並將結果限制在 0–100%。
+- memory 不用簡單 `free/total`；採 `MemAvailable`，避免 cache 導致誤報。
+- swap disabled 時記為 0/OK，而不是錯誤。
+- disk/inode 使用 `os.statvfs`，避免解析 locale 或 mount path 空白造成 `df` parser 問題。
+- 預設只檢查 `/`，`mounts=["auto"]` 才掃 `/proc/self/mounts`，並排除 pseudo filesystem。
+
+### 4.2 日誌
+
+- 優先執行 bounded `journalctl --since ... --lines N --output short-iso`，不限制 priority，確保 auth failure 等低 priority 訊號也能被分類。
+- journal 不可用時，逐一讀設定中的文字檔尾端，單檔與總行數都有限制。
+- 分開計算 error-like、authentication failure、kernel/OOM/panic signatures。
