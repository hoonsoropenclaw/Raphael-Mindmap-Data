    1. stdlib-only（urllib + re + argparse + html.unescape）— 跟 2026-07-28 同任務前作保持一致風格；避免引入 requests / beautifulsoup4 等外部相依，部署零摩擦（Hermes 環境無 pip 套件管理即可跑）
    2. CLI 參數化（--since / --language / --top / --output / --user-agent / --json）— 比上次新增了 --json 開關（debug 用）與 --top N（控制輸出量）
    3. 雙端輸出（stdout 永遠印 + --output 額外寫檔）— 兩個介面不互斥，pipe 友善
    4. graceful empty filter — 沒有匹配 repo 時不 crash，改印 No repositories found for filter: ... 訊息並 exit 0
    5. Dataclass TrendingRepo — 7 個欄位結構化（rank / name / url / description / language / stars_total / forks / stars_period），日後易擴充
    6. URL 組合器 build_trending_url(since, language) — 自動處理 trending[/<lang>]?since=<since> 的 ? vs &
    
    踩到的坑（debug 紀錄）
    
    坑 #1：stars_total 跟 forks 一開始抓出來都是 0
    - 原因：regex 寫成 <svg[^>]*></svg>（期待 self-closed svg），但實際 GitHub HTML 給的是 <svg aria-label="star" ... viewBox="..." ...>，整個 svg 標籤跨多行還包含內嵌 <path>
    - 解法：把 [^<]<svg[^>]></svg> 改成 [^>]>\s<svg.*?</svg> —— lazy quantifier 配 re.S 讓 svg 內容完整吃掉，再抓後面第一個純數字 token
    - 結果：15/15 repo 的 stars_total / forks 都正確（bitchat ⭐32,857、strix ⭐45,143、imgui ⭐75,292）
    
    坑 #2：pipe escape 在中文 description
    - GitHub trending 有些中文 description 內含 |（如 xbtlin/ai-berkshire：「巴菲特·芒格·段永平·李錄四大師方法論 + 多Agent並行研究。| AI-era Berkshire...」）
    - 解法：_esc_md() 自動把 | 換成 \|，印出來不破壞 markdown table 結構
