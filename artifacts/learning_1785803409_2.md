### 教訓 1：Reveal 動畫要 progressive enhancement，不能依賴 JS
**問題**：初版用 `.reveal { opacity: 0 }` + IntersectionObserver 加 `.in`。結果**瀏覽器 headless render + 截圖瞬間 IO 還沒 fire**，整個 main 區塊顯示為黑屏。
**根因**：把「內容可見性」綁死在 JS 執行結果上。
**修法**：CSS 預設可見、JS 只加額外的 fade-up 動畫。**降級行為 = 完整可見、不是黑屏**。
**L3 規則**：任何 `opacity: 0` 的初始樣式，必須有「JS 失敗時的 fallback 路徑」保證內容可見。

### 教訓 2：Single-file demo 用 Tailwind Play CDN 是合理選擇
**情境**：54KB 設計系統樣板，必須 single-file（交付契約）。
**取捨**：
- 優：CDN 一行載入、零 build step、開盒即用
- 劣：Tailwind Play CDN 在 file:// 協定下載入略慢、headless 截圖容易抓到「CDN 還沒 compile」的瞬間
**L3 規則**：single-file demo 用 Play CDN 可接受、但 reveal 動畫必須等 CDN 載完再啟動（不能依賴 IO 在初始 viewport 馬上 fire）。

### 教訓 3：Token-first 設計讓 theme 切換接近零成本
**情境**：dark / light 兩套 theme，原本以為要寫兩套 CSS class。
**實作**：所有顏色/blur/border/shadow 都用 `var(--xxx)` 引用，theme 切換只需改 `<html data-theme="...">` 一個 attribute。整個 theme 切換 < 0.4s transition。
**L3 規則**：設計 token 優先 → component 樣式全部用 `var()` → theme 切換是 0 成本。
