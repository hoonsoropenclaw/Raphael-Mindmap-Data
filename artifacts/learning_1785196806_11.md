+# TaskTracker — React UI Component
+
+A complete React component demonstrating complex state management, custom CSS,
+and production-ready patterns. No external state libraries, no UI framework.
+
+## Files
+
+| File              | Purpose                                                            |
+|-------------------|--------------------------------------------------------------------|
+| `TaskTracker.jsx` | The component (default export). Single file, ~24 KB.               |
+| `TaskTracker.css` | Companion stylesheet with CSS custom properties (light + dark).   |
+| `demo.html`       | Standalone preview using React 18 UMD + Babel-standalone (no build). |
+| `verify.sh`       | Compiles the JSX with Babel and runs an automated render smoke test. |
+
+## Architecture decisions
+
+1. **`useReducer` as single source of truth.** State is `{ tasks, filter, selectedId, editing }`. Every state mutation goes through a pure reducer with named actions (`create`, `update`, `delete`, `setStatus`, `cycleStatus`, `select`, `setEditing`, `setFilter`, `resetFilter`, `clearAll`, `reseed`, `hydrate`).
+2. **Derived state via `useMemo`.** Filtered, sorted, and selected views are computed from `state.tasks` + `state.filter`. Never stored separately — no risk of divergence.
+3. **Stable handlers via `useCallback`.** Every dispatch handler is wrapped so it has a stable identity across renders.
+4. **Local persistence via `useEffect` + `localStorage`.** Saves the full state tree on every change (150 ms debounced). Re-hydrates on mount. Transient flags like `editing` are intentionally excluded.
+5. **Defensive feature detection.** `window.confirm` is checked before being called (graceful in headless test environments).
+6. **JSDoc-typed but plain JS.** Works without TypeScript; IDEs still get intellisense.
