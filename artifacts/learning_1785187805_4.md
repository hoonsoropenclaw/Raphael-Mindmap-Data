+# 實作思路與交付審查
+
+## 任務解讀
+
+核心需求是「Telegram 收到文字 → 將文字視為地點 → 呼叫天氣 API → 回覆天氣」。原始訊息的「讀取」與「寫入」欄位沒有路徑，因此沒有猜測不存在的 Senior Architect 文件；實際盤點工作目錄後，只有 `local.log` 與 `nohup.out`。本檔作為缺失交付路徑的明確替代。
+
+## 架構
+
+1. `weather.py`
+   - 使用 Open-Meteo Geocoding API 將地點轉成經緯度。
+   - 使用 Open-Meteo Forecast API 讀取 current weather。
+   - 將 WMO weather code 翻成繁體中文。
+   - 定義 `WeatherError`，只把適合給終端使用者看的錯誤傳出去。
+
+2. `telegram_bot.py`
+   - 直接使用 Telegram Bot HTTP API，不引入第三方套件。
+   - long polling 適合沒有公開 HTTPS endpoint 的 CLI/headless 環境。
+   - offset 使用 `update_id + 1`，避免重複處理訊息。
+   - 支援純文字、`/weather 地點`、`/start`、`/help`。
+   - 選填 `TELEGRAM_ALLOWED_USERS` allowlist。
+   - 每位使用者 3 秒冷卻，避免濫用外部 API。
+   - SIGINT/SIGTERM 設定停止旗標，讓 polling loop 可正常結束。
+
+3. `run.sh`
+   - `set -euo pipefail`，從腳本所在目錄啟動，避免 cwd 差異。
+
+## 選型理由
+
+- Open-Meteo 不需要 weather API key，減少一組秘密與供應商設定。
+- Telegram token 僅由環境變數讀取，不硬編碼、不記錄到 log。
+- Python 標準函式庫足以處理此三端點流程；避免 `requests` 與大型 bot framework 的依賴及升級成本。
+- 天氣模組與 Telegram transport 分離，便於獨立測試及未來替換 API。
+
