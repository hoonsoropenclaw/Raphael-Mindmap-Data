+# PRD — Adaptive Form Studio
+
+- Date: 2026-08-03
+- Status: Implementing
+- Task: 基於 Next.js 開發動態表單生成器，支援基於用戶輸入的 UI/UX 動態調整
+
+## 1. Product goal
+
+建立可直接執行的 Next.js 16 動態表單生成器。表單設計者可建立、編輯、排序與條件顯示欄位；填表者的回答會即時改變欄位可見性、資訊密度、字級與引導文案。
+
+## 2. Primary users
+
+1. 表單設計者：快速配置資料蒐集流程，不寫程式。
+2. 填表者：只看到當下需要的欄位，介面依熟悉度與閱讀需求調整。
+
+## 3. Must-have requirements
+
+- Next.js 16 App Router + React 19 + TypeScript。
+- 8 種以上欄位類型：text、email、tel、number、textarea、select、radio、checkbox、date、rating。
+- 欄位 CRUD、複製、上下排序、必填、說明、placeholder、選項。
+- 以另一欄回答作為顯示條件（equals / notEquals / answered）。
+- `experience` 與 `readability` UX signal：回答後自動切換 compact/comfortable 與 normal/large scale。
+- 即時預覽、可見欄位計數、完成度、驗證錯誤與成功畫面。
+- Auto / Comfortable / Compact 密度覆寫；3 種色彩主題。
+- localStorage 自動草稿、JSON 匯入/匯出、重設範例。
+- 手機、平板、桌面響應式；鍵盤與 ARIA 基本可及性。
+- 完整離線單檔 `web_output.html` 與真正可 build 的 Next.js 專案共用同一核心元件。
+
+## 4. Dynamic UX rules
+
+| Input signal | Answer | UI effect |
+|---|---|---|
+| experience | first-time | comfortable density + step guidance |
+| experience | frequent | compact density + reduced guidance |
+| readability | large | larger control/text scale |
+| field condition | matches | reveal dependent field |
+| field condition | not matched | hide dependent field |
+| validation | error | summary + field-level message + focus first invalid field |
+
+Manual density setting overrides only the density rule; readability remains answer-driven.
+
+## 5. Non-goals
+
+- Backend database, authentication, external API submission, collaborative editing.
+- Production deployment.
+- Drag-and-drop library; deterministic up/down controls are chosen for keyboard reliability.
+
+## 6. Acceptance criteria
+
+1. `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run build:html` all pass.
+2. Desktop and 390px mobile viewport have no horizontal overflow.
+3. Adding a field updates builder and preview.
+4. Selecting email/phone reveals only the matching conditional field.
+5. Selecting frequent changes adaptive density; selecting large changes scale.
+6. Submit empty form shows validation; valid form shows success.
+7. Reload restores schema draft.
+8. `web_output.html` contains inlined CSS/JS and runs through HTTP without external assets.
+9. Browser console contains no uncaught errors.

+## State strategy
+
+- Schema and respondent answers remain separate.
+- All schema updates are immutable.
+- Field IDs are stable and unique.
+- Draft schema persists under versioned localStorage key.
+- Derived UI state is never persisted; it is recomputed from schema, answers and viewport.
+
+## Rule evaluation order
+
+1. Resolve field visibility from conditions.
+2. Validate only visible fields.
+3. Read `experience` and `readability` signal answers.
+4. Respect explicit density override, otherwise derive density.
+5. Calculate progress from visible fields only.
+6. Render one guidance message through an `aria-live` region.
+
+## Risk controls
+
+- Every button declares `type="button"` unless it is the respondent submit action.
+- Mobile layout uses CSS grid collapse and wrapping toolbar; no fixed panel widths.
+- No default-hidden IntersectionObserver content.
+- No CDN runtime dependencies in final HTML.
+- File import is JSON schema-validated before replacing state.
+- Browser APIs are guarded for SSR.
