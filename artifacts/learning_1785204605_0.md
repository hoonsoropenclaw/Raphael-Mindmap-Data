+### 4.1 資源收集：純 /proc、不依賴 psutil
+
+| 指標 | 來源 | 算法 |
+|------|------|------|
+| CPU% | `/proc/stat` 兩次取樣（間隔 0.1s） | `(d_total - d_idle) / d_total`，idle = idle + iowait |
+| 記憶體% | `/proc/meminfo` | `1 - MemAvailable / MemTotal` |
+| Load | `/proc/loadavg` | 直接讀，每 CPU 正規化（load1 / cpu_cores）|
+| 磁碟用量 | `shutil.disk_usage("/")` | used / total |
+| 磁碟 throughput | `/proc/diskstats` 兩次取樣差 | delta_sectors × 512 / elapsed（KB/s）|

+
+### 4.2 日誌掃描：journalctl 優先、syslog/dmesg 退路
+
+**訊號源優先序**：
+1. `journalctl --priority=0..3 --output=json`（取結構化 `PRIORITY` 數字）
+2. `/var/log/syslog` 或 `/var/log/messages`（fallback，僅 mtime 最近 60s 才掃）
+3. `dmesg --level=err,crit,emerg,alert`
+
+**噪音過濾**（必要）：
+- `Failed to set up standard output: No such file or directory` — background slice 啟動時的合法 stdout 失敗訊息，journal 會把 service 標記 err 但其實無害
+- `Closed ...slice`、`Reached target Shutdown`、`Starting Session N of User`
+

+### 4.3 閾值評估：純函式，無 I/O
+
+`evaluate_thresholds(metrics, events, cfg) → list[Alert]` 不讀任何檔案、不寫任何檔案。**這是測試套件的核心可測表面**。

+```
+cpu_percent ≥ cpu_crit → cpu_crit
+cpu_percent ≥ cpu_warn → cpu_warn
+mem_percent similar
+load1 / cpu_cores ≥ load_per_cpu_crit → load_crit
+disk_percent ≥ disk_crit → disk_crit
+events 含 critical/emergency → log_crit
+events ≥ 10 個 error → log_warn
+```
+
+### 4.4 告警節流：cooldown seconds
+
+每個 alert 有 `key`（如 `cpu_warn`），同 key 距離上次發出 < `cooldown_seconds`（預設 300s）則略過。**這是防止 N 秒一個 cycle 把 log 灌爆的關鍵**。
