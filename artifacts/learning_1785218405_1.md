+## 架構決策

+### 1. 資料來源 = Open-Meteo（不需 API key）
+- `geocoding-api.open-meteo.com/v1/search` 做城市名 → lat/lon 解析

+- 為什麼不選 OpenWeatherMap / WeatherAPI：要付費 token，多一層 secrets 管理成本
+
+### 2. 兩段式查詢（geocode → forecast）
+- geocode 失敗 → 直接回「找不到城市」，不浪費 forecast 配額
+- forecast 失敗 → 回「請稍後再試」，區隔清楚兩種錯誤

+### 4. 單例 service
+- `_service = WeatherService()` 在 module-level 建一次

+- handler 是 short-lived coroutine，無 thread-safety 問題
+- 為什麼不用 dependency injection：對 100 LOC 的 bot 是 overkill；DI 適合大型 app
+
+### 5. aiohttp over requests
+- `aiohttp.ClientSession` 原生 async，與 `python-telegram-bot` 的 asyncio 完美整合

+- 空字串 → 「請輸入城市名稱」三種錯誤都不 raise，永遠回字串
