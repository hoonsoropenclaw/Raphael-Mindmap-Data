+"""Sliding-window in-memory rate limiter.
+
+Implementation: a deque per client (key) holds timestamps of recent requests.
+On each request we drop entries older than `window_seconds`, then check whether
+`max_requests` is exceeded. This is precise (not the cheaper but bursty
+fixed-window alternative) and avoids any external dependency.
+
+Limitations:
+  - In-memory only; for multi-process deploys, swap to Redis.
+  - Key by client IP from X-Forwarded-For first (so it works behind a proxy)
+    then falls back to the direct client.
+"""
+from __future__ import annotations
+
+import asyncio
+import time
+from collections import deque
+from typing import Deque, Dict, Tuple
+
+from fastapi import HTTPException, Request, status
+
+
+class SlidingWindowRateLimiter:
+    """Thread/async-safe sliding window limiter."""
+
+    def __init__(self, max_requests: int = 10, window_seconds: float = 60.0) -> None:
+        if max_requests <= 0:
+            raise ValueError("max_requests must be positive")
+        if window_seconds <= 0:
+            raise ValueError("window_seconds must be positive")
+        self.max_requests = max_requests
+        self.window_seconds = window_seconds
+        self._buckets: Dict[str, Deque[float]] = {}
+        self._lock = asyncio.Lock()
+
+    async def check(self, key: str) -> Tuple[bool, int]:
+        """Check whether `key` may make a request now.
+
+        Returns (allowed, remaining_in_window). When not allowed, the caller
+        should raise 429.
+        """
+        now = time.monotonic()
+        cutoff = now - self.window_seconds
+        async with self._lock:
+            bucket = self._buckets.get(key)
+            if bucket is None:
+                bucket = deque()
+                self._buckets[key] = bucket
+
+            # Drop expired entries.
+            while bucket and bucket[0] <= cutoff:
+                bucket.popleft()
+
+            if len(bucket) >= self.max_requests:
+                return False, 0
+
+            bucket.append(now)
+            return True, self.max_requests - len(bucket)
+
+    async def reset(self, key: Optional[str] = None) -> None:
+        """Clear state. Tests use this between cases."""
+        async with self._lock:
+            if key is None:
+                self._buckets.clear()
+            else:
+                self._buckets.pop(key, None)
+
+
+def client_key(request: Request) -> str:
+    """Resolve the rate-limit key. Prefer X-Forwarded-For (left-most public IP),
+    fall back to client.host. Tests can monkey-patch the limiter instead."""
+    fwd = request.headers.get("x-forwarded-for")
+    if fwd:
+        # First entry is the original client per RFC 7239 convention.
+        return fwd.split(",")[0].strip()
+    return request.client.host if request.client else "unknown"

+
+A small FastAPI service that exposes CRUD over a SQLite-backed todo list, with
+sliding-window rate limiting and a full pytest suite.
+
+## Run
+
+    pip install -r requirements.txt

+
+## Endpoints
+
+| Method | Path                | Purpose                          |
+|--------|---------------------|----------------------------------|
+| GET    | /health             | Liveness probe                   |
+| GET    | /todos              | List todos (filter, paginate)    |
+| POST   | /todos              | Create a todo                    |
+| GET    | /todos/{id}         | Fetch one                        |
+| PUT    | /todos/{id}         | Partial update                   |
+| DELETE | /todos/{id}         | Remove (returns 204)             |

+
+By default: **10 requests per 60 seconds** per client IP (X-Forwarded-For wins
+over the socket address when present). Exceeding the limit returns
+`429 Too Many Requests` with a `Retry-After` header. The limiter is held in
+`app.state.limiter` — tests inject their own with tighter windows.
+
+## Tests
+
+    pytest                  # all tests
+    pytest tests/test_api.py -v
+    pytest --cov=todo_api   # with coverage (pytest-cov is in requirements)

+DB per test — no uvicorn process needed.

+# PROGRESS — Todo API 實作思路
+
+## 任務
+Python FastAPI 待辦事項 API，含 SQLite + rate limit + pytest 單元測試。
+
+## 最終成果
+- **32 個測試全綠**（1.97s），**96% line coverage**
+- `pytest --cov=todo_api` 顯示：models 100% / database 93% / rate_limiter 98% / main 97%
+- 真實 uvicorn server smoke test 全路由 200/201/204/404/422 正確
+- Swagger UI `/docs`、OpenAPI `/openapi.json` 都可存取
+
+## 架構決策與理由
+
+### 1. 三層分離：`models / database / rate_limiter / main`
+不是把 SQL、驗證、路由全塞 `main.py`。理由：
+- **測試粒度可控**：`tests/test_rate_limiter_unit.py` 可以單測 limiter 不掛 HTTP；`tests/test_api.py` 透過 TestClient 跑端到端。
+- **換實作成本低**：例如想把 SQLite 換 Postgres，只要改 `database.py`，route 0 改動。
+
+### 2. Repository pattern（`TodoRepository`）
+所有 SQL 集中在一個 class，route 只呼叫語意方法（`create / get / list_all / update / delete`）。好處：
+- **白名單更新欄位**：`update()` 用 `allowed = {"title","description","completed"}`，杜絕 SQL 注入點（即便我們用 parameterized query 已經安全，加這層是 defense in depth）。
+- **時間戳管理**：`_utcnow_iso()` 統一 ISO 8601 UTC，二次寫入的 `updated_at` 自動推進。
+
+### 3. Sliding window rate limiter（in-memory deque）
+選 sliding window 而不是 fixed window，理由：
+- **不會在 window 邊界雙倍 burst**：fixed window 在 t=59s 打 10 個、t=61s 又打 10 個，實際 20 個/2s；sliding window 用 deque 嚴格算「過去 N 秒內」，杜絕此漏洞。
+- **不引入外部依賴**：純 Python `collections.deque`，不需 Redis。
+- **async-safe**：用 `asyncio.Lock` 包住 bucket 寫入，多個 async request 並行也不會壞。
+- **key by client IP，X-Forwarded-For 優先**：實戰部署在 reverse proxy 後方時，正確拿原始 client 而不是 proxy IP。
+
+明確限制（已寫入文件）：**in-memory only**，多 process 部署需換 Redis。對單機 demo 夠用。
+
+### 4. App factory（`create_app(db_path, limiter, rate_limit_enabled)`）
+不是直接 `app = FastAPI()`。理由：
+- **測試隔離**：每個 test 用不同 `db_path`（tempfile）+ 嚴格 limiter（3/1s 加速測試），互不污染。
+- **`rate_limit_enabled=False` 開關**：讓極限壓測或內部呼叫可以 bypass。
+- **模組層級 `app = create_app()`**：兼顧「給 uvicorn `todo_api.main:app` 用」，不用兩份程式碼。
+
+### 5. Pydantic v2 schemas
+`TodoBase / TodoCreate / TodoUpdate(partial) / Todo / ErrorResponse`：
+- `Field(min_length=1, max_length=200)` 讓空 title 在 422 階段就被擋，不會打到 DB。
+- `TodoUpdate` 全部 Optional → partial update。空 payload 路由層顯式 raise 400（避免靜默 no-op）。
+- `from_attributes=True`：跟 `dict` row 對接。
+
+### 6. 測試設計
+- **per-test 全新 SQLite**（`tempfile.mkstemp` + function scope fixture）：零交叉污染，pytest 平行跑也安全。
+- **TestClient 不用真 uvicorn**：FastAPI 內建，async-friendly，速度快。
+- **`asyncio_mode = auto`**：async 測試不用每個都 `@pytest.mark.asyncio`。
+- **每個 route 一個 happy + 至少一個 sad path**：404、422、400、429 都覆蓋。
+- **limiter 用 `time.sleep(1.1)` 驗 window recovery**：證明時間窗真的會過期。
+
+## Bug 與修正（debug 紀錄）
+
+1. **204 No Content 不能有 response body**
+   - 起初 `@app.delete(..., status_code=204)` 直接 `return None` → FastAPI 啟動時 assert 失敗
+   - 修正：加 `response_class=Response` + `return Response(status_code=204)`，明確空 body
+
+2. **rate limit 沒生效**
+   - 起初 `/health` 沒掛 `Depends(rate_limit_dep)`，以為是 lifespan 沒注入；實際是 endpoint 沒保護
+   - 修正：health 加上 dep，所有端點一致
