+# MY_NOTES.md — Telegram 天氣小幫手 實作思路
+
+**作者**：赫米斯（工程獺）  
+**日期**：2026-07-28  
+**任務**：寫一個 Telegram 機器人，接收文字 → 查天氣 API → 回傳
+
+---
+
+## 1. 技術選型 — 為什麼這樣選
+
+### 1.1 Bot 框架：`python-telegram-bot` v20+
+- **為什麼不選 Telebot / 其他**：`python-telegram-bot` 社群最大、文件最齊、async 設計乾淨
+- **v20+ 用 asyncio**：跟 httpx 完美搭，未來要加非同步任務（cron 推播、cache 預載）很自然
+- **不用 webhook、改 polling**：polling 對個人小 bot 簡單到不行，不用搞 SSL / ngrok
+
+### 1.2 天氣 API：**Open-Meteo**（不是 OpenWeatherMap）
+- **決定性優勢**：**免 API key、免註冊、馬上能用**
+- 對比 OpenWeatherMap：要註冊、要等 key、免費層有 60 calls/min 限制
+- 對比中央氣象局：要註冊 + 只能查台灣
+- Open-Meteo 全球覆蓋 + 免費 + 兩段式 API（geocoding + forecast）剛好符合需求
+
+### 1.3 HTTP client：`httpx`（不是 requests）
+- 跟 `python-telegram-bot` v20+ 同樣 async-native
+- 比 requests 現代（type hints、原生 HTTP/2）
+- requests 也能用，但混 sync/async 會很亂
+
+### 1.4 環境變數：`python-dotenv`
+- 主流選擇，沒什麼好說的
+- TG token 放 `.env`（gitignored），正式環境用 export 環境變數即可
+
+---
+
+## 2. 架構設計 — 為什麼這樣拆
+
+### 2.1 兩層分離：`weather.py` 純函式 + `bot.py` Telegram 邏輯
+
+```
+[ Telegram User ]
+       ↓
+[ bot.py ]  ← Telegram 邏輯、Markdown 格式、typing indicator
+       ↓ 呼叫
+[ weather.py ]  ← 純函式、可獨立 CLI 測試、可換框架重用
+       ↓ 呼叫
+[ Open-Meteo API ]
+```
+
+**好處**：
+- `weather.py` 沒有 Telegram 依賴，可以 `python weather.py 台北` 直接測
+- 未來想加 Discord bot / LINE bot / cron 推播，只要複製 `weather.py` 邏輯
+- 寫 unit test 不用 mock Telegram
+
+### 2.2 錯誤處理的層次
+
+`weather.py` 定義兩個 exception：
+- `CityNotFoundError` — 找不到城市（**使用者輸入問題**）
+- `WeatherAPIError` — API 掛了（**系統問題**）
+
+`bot.py` 分别處理：
+- `CityNotFoundError` → 友善提示「找不到，請試英文」
+- `WeatherAPIError` → 友善提示「服務暫時有問題」
+- 任何其他 Exception → 最後防線，避免 bot 崩
+
+還有 `error_handler` 全域錯誤註冊：`add_error_handler` 確保單一 update 失敗不會讓 bot 整個死掉。
+

+- 不可變 — 寫起來安全，不用擔心被竄改
