+# Telegram Weather Bot
+
+A minimal Telegram bot that accepts a city name as text and replies with
+the current weather. Free public APIs only — **no API keys required** for
+the weather service. You only need a Telegram bot token (free, from
+@BotFather).
+
+## Features
+
+- 🌐 Chinese / English / mixed city names ("臺北", "Tokyo", "天氣 高雄")
+- 🔁 Two weather providers with automatic fallback
+  - **Open-Meteo** (primary): structured JSON, no key
+  - **wttr.in** (fallback): fuzzy matching, no key
+- 🪶 Zero-token dry-run mode for local testing
+- 🛡️ Graceful errors (unknown city, API down, bad input)
+
+## Setup
+
+```bash
+# 1. Install deps
+pip install -r requirements.txt
+
+# 2. Configure token
+cp .env.example .env
+# edit .env and set TELEGRAM_BOT_TOKEN=<your token from @BotFather>
+
+# 3. Run
+python bot.py
+```
+
+If `TELEGRAM_BOT_TOKEN` is empty, the bot runs in **dry-run mode**:
+it tests the weather pipeline against sample cities and prints what
+*would* be sent to Telegram. This lets you verify the integration
+without a token.
+
+## File layout
+
+```
+bot.py              # Telegram handlers + entry point
+weather.py          # Weather API client (Open-Meteo + wttr.in fallback)
+requirements.txt    # python-telegram-bot 22.x, httpx, python-dotenv
+.env.example        # copy to .env and fill in TELEGRAM_BOT_TOKEN
+notes.md            # implementation notes (architecture decisions)
+```
+
+## Commands
+
+| Command       | Behaviour                                |
+|---------------|------------------------------------------|
+| `/start`      | Greeting + usage example                 |
+| `/help`       | Full help                                |
+| any text      | Treated as a city name (with prefix OK)  |
+
+## Architecture notes
+
+See `notes.md` for the design rationale (provider choice, async design,
+error handling, dry-run mode).
