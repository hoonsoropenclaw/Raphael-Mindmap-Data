+## 設計決策（為什麼這樣寫）
+
+### 1. 為什麼用 watchdog（不是自己 polling）
+- `watchdog.observers.Observer` 內建 background thread + 跨平台原生 API（inotify/FSEvents/ReadDirectoryChangesW）
+- 自己 polling 不可能 beat 核心 API；且 polling 會在 idle 浪費 CPU
+- polling 只在極特殊情況才用（網路磁碟）
+
+### 2. 為什麼要 200ms 去抖
+- watchdog 對「一次寫入」會噴出多個事件（created → modified → modified → modified）
+- 沒去抖 → 規則引擎對同一 logical 事件跑 5 次 → 重複備份、重複 log
+- 200ms 是實測甜蜜點：太短會漏合併、太長會讓使用者覺得「lag」
+
+### 3. 為什麼 FSEvent 是 dataclass、不是 dict
+- dataclass 提供型別保護（IDE / mypy），否則訂閱者要寫 `ev["event_type"]` 沒 hint
+- `to_dict()` 在跨越 HTTP/WS 邊界時序列化
+- ring buffer 內部仍用 dataclass（效能更好），對外才序列化
+
+### 4. 為什麼規則是宣告式（Rule dataclass）不是 callback

+- 未來改成讀 YAML/JSON 配置不需改引擎
+- callback 永遠是 hard-coded、不可熱插拔
