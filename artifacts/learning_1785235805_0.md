+|------|------|------|

+## 2. 設計決策
+
+### 為什麼 Python 而不是 Bash？
+- **/proc 解析需要小心**（欄位順序、cmd 含空格用 `)` 切），Python 有 `dataclass` + 型別守護
+- **cooldown 狀態檔原子寫入**比 Bash 暫存檔安全
+- **stdlib only**：不引入 psutil / pyyaml 等依賴，部署只需 Python 3.10+
+- **可測試**：dataclass 結構讓 unit test 容易加（後續可擴充）
+
+### 為什麼不用 psutil？
+- `pip install psutil` 需要 root 或 venv，CI 上常見 friction
+- 採集的指標其實很有限（CPU%、Mem%、Disk%、Load、Top N），/proc 已經夠
+- 換來的好處：單檔可執行、丟到任何 Linux 都能跑
+
+### 為什麼自己寫 mini-YAML parser？
+- 避免 pyyaml 相依
+- 設定檔需求很簡單（key: value + 巢狀縮排 + list-of-dicts）
+- 解析器只 ~80 行，邊界案例（list-of-dicts、inline comment）可控
+- 若使用者要進階語法，可自行換成真 YAML 並把 `load_config` 的 parser 換掉
+
+### 為什麼要 cooldown？
+- 沒 cooldown 的話：cron 每分鐘跑 → CPU 高就每分鐘炸 webhook 60 次/hr
+- cooldown 把「同 key」壓成 30 分鐘一次
+- webhook 數量 = (實際故障數量)，不是 (故障持續時間 × 採集頻率)
+
+### 為什麼 lock file 不用 PID 而是 flock？
+- PID 可能被回收（程序死掉、kernel 分配新 PID）
+- flock 是 OS 級資源，文件還在 = lock 還在 = 別人拿不到
+- flock 在 `__exit__` 時自動釋放（即使程序 crash），比 PID file 健壯
+
