+| **Search REST API** `search/repositories?q=pushed:>7d&sort=stars` | 結構化 JSON、易解析、無 HTML 維護成本 | 60 req/h（未登入）、沒 `stars_this_period` 欄位 |
+| **HTML scrape** github.com/trending | 真實「今日星星數」欄位 | DOM 結構會變、要靠 HTMLParser 不是 regex |
+
+**結論**：兩條都實作，**API 優先**（省 API 配額時還能用），**失敗自動 fallback HTML**（拿真實 period stars）。

+
+### 2.3 HTMLParser 而非 regex
+
+**前次（v1.0）** 用 regex 暴力抓 `<article class="Box-row">`：
+- 缺點：DOM 結構一變就壞、`<span>` 嵌套時數字會錯抓
+- v1.0 對應的 `learning_1785183604_0` 真實抓取時還過得了，但**對未來 GitHub 改版不穩**
+
+**本版（v1.1）** 改用 `html.parser.HTMLParser`：
+- 優點：狀態機驅動、`handle_starttag`/`handle_endtag` 自動維護 DOM 邊界
+- 容錯：每個欄位獨立 try，缺欄位不影響其他欄位
+- `_extract_period_stars()` 仍用 regex 二次掃描（因為「X stars today」這段文字跨多個 element 邊界，在 parser 內抓很囉嗦）
