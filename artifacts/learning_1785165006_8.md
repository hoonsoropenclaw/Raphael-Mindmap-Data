+
+### 1. 工具選型
+
+| 選擇 | 理由 |
+|---|---|
+| `python-telegram-bot` v22（async）| 用戶已安裝、API 友善、PTB 官方目前主力維護版本 |
+| `requests` | 不需要再加新依賴 |

+| 兩個公開免 key API（wttr.in + Open-Meteo） | **不需任何付費金鑰就能 demo**，對「無金鑰環境」或初次部署零摩擦 |
+
+### 2. 為什麼兩個天氣 API？
+
+- **wttr.in**：JSON 模式一次回溫度 / 濕度 / 風向 / 體感。但**偶爾 rate-limit**（公開服務無 SLA）。
+- **Open-Meteo**：需先 geocoding（`name=City → lat/lon`），再拿 current weather。也是免 key。
+
+預期部署環境：「毫無金鑰、隨時可能連不穩」。**fallback pattern** 比單一 API 更穩，故採用兩個。
+
+### 3. 流程分工
+
+```
+cmd handlers  ── /start /help /about ──→ 文字
+text handler  ── 非指令文字 ──→ fetch_weather()
+fetch_weather ── try wttr.in → except → try Open-Meteo → except RuntimeError
+                      │
+                      ▼
+                WeatherReport dataclass
+                      │
+                      ▼
+                format_telegram() → Markdown
+                      │
+                      ▼
+                update.message.reply_text()
+```
+
+### 4. 容錯設計
+
+- **`_sanitize_city(city)`**：先把使用者輸入做白名單過濾（中文/英文/數字/空格/逗號/連字號），避免 URL injection。
+- **`_safe_float`/`_safe_int`**：API 回的溫度/濕度可能是空字串或 None，永遠 try/except。
+- **Top-level guard**：沒 `TELEGRAM_BOT_TOKEN` 時 `raise SystemExit(...)`，比讓 bot 開啟後才報錯友善。
+- **`on_error` callback**：Telegram 框架內任何未捕例外都不會炸 process，全部 log。
+- **長訊息切段**：`Telegram` 上限 4096 字元，保險只送 3800。
+- **`send_action(ChatAction.TYPING)`**：通知使用者「在查了」，降低等待感。
+- **空字串 / 超長輸入**：早期 return，提示使用者。
