+## 核心設計決策
+
+### 1. 零第三方依賴（純 Python 標準庫）
+
+**為什麼**：
+- Telegram Bot API = HTTPS + JSON，標準庫 `urllib.request` 完全夠用
+- 同環境是 PEP 668，除非建 venv 否則 `pip install` 會被擋
+- 沒依賴 = 沒供應鏈攻擊面、沒版本衝突、部署最簡單
+- 改裝 httpx / aiohttp / aiogram 很容易：HTTP 集中在 `http_json()` 一處
+
+**權衡**：犧牲的是「快速套用別人的 bot 框架」。但寫一個 ~380 行 bot 完全可控。
+
+### 2. 天氣 API 選 Open-Meteo，不選 OpenWeatherMap
+
+**為什麼**：
+- OpenWeatherMap 強制要 API key，要註冊、要管理 key
+- Open-Meteo 免 key、免註冊、CORS 開放、文件清楚
+- 唯讀服務，不會被當攻擊媒介
+- 中文 / 英文 / 日文都能查（geocoding）
+
+### 3. Long polling，不開 webhook
+
+**為什麼**：
+- Webhook 需要 HTTPS endpoint + 公開 domain + 防火牆打洞
+- Long polling `getUpdates` 跑在出方向連線，N100 headless 環境最簡單
+- 多人對話規模不大，polling 完全夠用
+
+**長輪詢參數**：
+- `timeout=30` — Telegram 最多 30 秒無更新就回空 list，client 再 loop
+- `allowed_updates=["message"]` — 只收 message，不收其他事件，省 bandwidth
+- 重試用指數退避（3s → 6s → 12s → 24s → 48s，封頂 60s）
+
+### 4. Token 走環境變數，不寫檔
+
+**為什麼**：
+- `.env.example` 是 template（無真實值）
+- `.gitignore` 阻擋 `.env` 進版控
+- 程式只讀 `os.environ["TELEGRAM_BOT_TOKEN"]` — 沒 fallback，**沒 token 就是 2 退出**
+- 不在 log 印 token（前綴比對 `123456:` 後面用 `***` 蓋掉也行，但目前完全沒印）
+
+### 5. 安全 / 健壯性

+- 訊息長度上限：使用者輸入 `MAX_USER_TEXT=200`，bot 輸出 `MAX_TEXT_LEN=4096`（Telegram 限制）
