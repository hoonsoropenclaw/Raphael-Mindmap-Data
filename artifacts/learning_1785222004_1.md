+"""業務 ID 生成 - 短字串 ID (Base32 8 字, 夠 ~1e9 不撞)."""
+from __future__ import annotations
+
+import secrets
+
+
+def generate_todo_id() -> str:
+    """生成 8-char Base32 URL-safe ID.
+
+    為什麼不用 DB auto-increment:
+    - ID 會出現在 URL 路徑上, 短一點友善
+    - 避免 enumeration attack (連續編號可被列舉)
+    - Base32 (A-Z 2-7) 共 32^8 ≈ 1.1e12, 生日攻擊到 1e6 個才 ~2.7e-6 機率撞
+    """
+    # secrets.token_hex(5) -> 10 hex chars; 為了 base32 我用 randbits
+    alphabet = "ABCDEFGHIJKLMNOPQRSTUVWXYZ234567"
+    n = secrets.randbits(40)  # 40 bits = ~1.1e12
+    out = []
+    for _ in range(8):
+        out.append(alphabet[n & 0x1F])
+        n >>= 5
+    return "".join(out)

+## API
+
+| Method | Path | 說明 |
+|--------|------|------|

+| GET | `/todos/{id}` | 查單筆 |

+## Rate Limit
+

+# Todo API — 實作紀錄

+## 設計決策 (為什麼這樣寫)
+
+### 1. **Sync 而非 Async** (最關鍵)
+
+**做法**: 所有 endpoint 宣告 `def`（不是 `async def`），sessionmaker 是 sync 版。
+
+**依據**:
+- `trial-and-error/references/by-category/fastapi-sync-vs-async-pattern-20260727.md` 教訓 38
+- `trial-and-error/references/by-category/fastapi-async-session-pitfalls.md` 教訓 37 列出 3 個 async pitfall：stale read / async-vs-sync deadlock / `expire_on_commit` 漏設
+- Quote API (`/home/hoonsoropenclaw/permanent-projects/quote-api/`) 用 sync 模式已跑 72 tests 通過 production
+- 這個 Todo API 沒有任何外部 I/O 等候，不需要 async 的高並發優勢
+
+**避坑**: 若改 async，每條 endpoint 都得加 `await db.execute()`；混用 sync sessionmaker + async endpoint 會 deadlock。
+
+### 2. **Rate limit 設計**
+
+**做法**:
+- 套件: `slowapi`（FastAPI 生態最常用）
+- Key: `request.client.host` (ASGI scope)，**不在 app 層 parse `X-Forwarded-For`**
+- 預設: 60/min/IP，從 `RATE_LIMIT` env 覆寫
+- 自訂 429 handler 附 `Retry-After` header（RFC 7231 §7.1.3）
+
+**依據**: SOP `fastapi-sync-vs-async-pattern-20260727.md` If→Then #2 — Uvicorn proxy headers 才應該 trust；app-level parsing 會成為攻擊面。
+
+**避坑**: 若部署在 reverse proxy 後，應在 uvicorn `--proxy-headers --forwarded-allow-ips=<trusted-CIDR>` 設定，**不要**在 app 層偷看 header。
+
+### 3. **SQLite 預設 + 環境變數覆寫**
+
+**做法**:
+- 預設路徑 `./data/todos.db`，父目錄自動 mkdir
+- `DATABASE_URL` env 優先（任意 SQLAlchemy URL，可換 Postgres）
+
+**SOP 對齊**:
+- `sqlite3` 的 `check_same_thread=False`（FastAPI thread pool 用）
+- 未做 `chmod 0700` 父目錄（依 If→Then #3 — 父目錄已存在 broad mode 時 fail closed，不要 chmod 整個 `/tmp` 既存目錄；這個專案的 `data/` 是新建子目錄，可以在工廠時 chmod 0700；目前 `mkdir(parents=True, exist_ok=True)` 之後**未設權限**，留 hook 給 production 強化）
+
+### 4. **業務 ID 用 Base32 隨機短字串**
+
+**做法**: 8 字 `A-Z 2-7` random，secrets.randbits(40)。
+
+**為什麼不用 auto-increment**:
+- 對外 URL 路徑友善（`/todos/AASV25PE` 比 `/todos/47` 短）
+- 防 enumeration attack（連續編號可列舉整個資料表）
+- 生日攻擊到 1e6 個 ID 才 ~2.7e-6 機率撞，10^12 個空間對「個人用」夠用
+
+**錯誤處理**: 若 MySQL 層撞 ID，retry 3 次；3 次都撞（不可能）回 503。
+
+### 5. **Strict bool 驗證**
+
+**問題**: Pydantic v2 預設會把 `"yes"`/`"true"`/`"1"` coerce 成 `True`，測試 `test_invalid_completed_type_rejected` 一開始誤回 200。
+
+**修復**: 用 `StrictBool | None` 強制 strict mode，`"yes"` 會被 422 拒絕。
+
+### 6. **PATCH 為 partial update + 空 body 是 noop**
+
+**做法**: 用 `payload.model_dump(exclude_unset=True)` 拿有送進來的欄位；空 `{}` 直接回原狀態（不視為 400）。
+
+**意義**: 前端能做 partial render (form 改一個欄位不重送全部)，減少耦合。
