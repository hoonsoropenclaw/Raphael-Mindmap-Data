# xlsx_recon — Excel 合併與加總對帳工具

把一個資料夾（含子資料夾）內的多個 Excel 活頁簿合併成一張明細表，
並用**加總等式**驗證合併結果沒有重複計算或漏算。

## 為什麼需要這個工具

合併報表最常見、也最難察覺的錯誤是「小計列被當成明細列一起加總」，
結果報表上的數字是正確值的兩倍。這種錯誤**不會讓程式出錯、不會讓檔案打不開**，
只是數字 quietly 錯了——沒有等式就沒有任何東西能發現它。

本工具的核心保證：

```
全表總計 = Σ 分組合計 = Σ 明細值
```

這三個數字由**同一個函式**回算（`xlsx_recon/engine.py` 的 `reconcile()`），
並且逐一與「來源檔自己宣告的小計」交叉核對。

## 需求

- Python 3.10 以上（3.12 已實測）
- `openpyxl`（唯一的第三方相依）

```bash
pip install openpyxl
```

## 安裝與執行

不需要安裝，把 `xlsx_recon/` 資料夾放在專案根目錄即可：

```bash
# 預覽對帳結果，不寫任何檔案
python -m xlsx_recon --input ./我的資料夾 --report-only

# 真的合併並寫出輸出
python -m xlsx_recon --input ./我的資料夾 --out-dir ./輸出

# 機器可讀的 JSON
python -m xlsx_recon --input ./我的資料夾 --report-only --json
```

## 結束碼

| 碼 | 意義 |
|---|---|
| `0` | 全部等式成立，且沒有來源檔處理失敗 |
| `1` | 有等式不成立或來源檔處理失敗（詳見輸出與 `issues.csv`） |
| `2` | 找不到任何可處理的 Excel 檔，或輸入路徑不存在 |

## 參數

| 參數 | 說明 |
|---|---|
| `--input PATH` | **必填**。輸入資料夾，會遞迴子資料夾 |
| `--out-dir PATH` | 輸出目錄。不給就不寫檔案 |
| `--dry-run` | 只預覽不合併 |
| `--report-only` | 只輸出對帳報告到 stdout |
| `--json` | 以 JSON 輸出報告 |
| `--no-recursive` | 不遞迴子資料夾 |

## 輸出檔案（給了 `--out-dir` 時）

| 檔案 | 內容 |
|---|---|
| `merged.xlsx` | 合併後的明細表（含來源檔／工作表／來源列／分組鍵） |
| `summary.csv` | 分組合計 + 全表總計 |
| `issues.csv` | 問題清單：來源檔失敗、被排除的列、小計核對結果 |
| `merge_summary.json` | 機器回算的對帳結果（其他文件一律引用這份） |

## 支援的欄位寫法

工具會把各種表頭寫法對映到五個正規欄位：

| 正規欄位 | 可接受的表頭寫法（部分） |
|---|---|
| 日期 | 日期 / date / 交易日期 / 時間 / occurred_at |
| 類別 | 類別 / category / 項目 / 分類 / 科目 / type |
| 說明 | 說明 / description / 備註 / remark / 摘要 / memo |
| 單號 | 單號 / id / 編號 / 流水號 / no / number / ticket |
| 金額 | 金額 / amount / 數額 / 價額 / 金額(元) / 金額（元） |

無法對映的欄位會被記錄（`unmapped_columns`），不會被靜默丟棄。
全形英數字元、全形括號、千分位、貨幣前綴（`NT$`）、括號負數（`(500)`）
都會被正確處理。

## 金額解析的失敗分類

無法解析時，該列**不進加總母體**，並且記錄明確原因：

| 原因 | 意義 |
|---|---|
| `unparseable` | 有內容但認不出來（例如「待補」） |
| `empty` | 空值 |
| `percent` | 百分比值——語意與金額不同，不進加總 |

## 小計列的兩層偵測

1. **標籤層**：整格文字命中 `小計 / 合計 / 總計 / 累計 / subtotal / total / sum` 等寫法。
2. **結構層（安全網）**：金額欄有值、這一列**只有一個非空文字格**、
   且該格看起來像彙總標籤。

第二層是必要的，因為標籤清單**不可能完整**——來源檔可能寫「本段彙總」
「本期彙總款項」。清單漏接時，該列會被當成明細，報表金額靜默變兩倍。
而清單式偵測**結構上無法自我驗證**（漏了就是漏了，沒有任何東西會紅）。

兩層偵測到的小計列都會被**獨立驗證**：它宣稱的值必須等於
「自上一個小計列之後的明細和」，否則判定為被誤判的明細列並亮紅。

## 本工具**不**做什麼（not_covered）

誠實揭露，這些都沒有驗證：

- 不檢查跨檔案的單號是否重複
- 不驗證日期欄位的格式合法性（只當不透明字串使用）
- 不驗證同一檔內的單號唯一性
- 不驗證來源檔的金額本身對不對（只驗證「合併後的加總等式成立」）

## 檔案結構

```
xlsx_recon/
├── __init__.py
├── __main__.py       # python -m xlsx_recon 的進入點
├── cli.py            # 命令列介面與結束碼
├── engine.py         # 合併 + 對帳引擎（加總等式在這裡）
└── normalize.py      # 欄位對映、金額解析、小計偵測
checks/
└── check_delivery.py # 交付閘門：自足性 / 乾淨度 / 相依完整性
tools/
├── make_test_data.py # 產生測試資料集
└── build_records.py  # 建置交付集合並產生權威摘要
tests/
└── test_xlsx_recon.py
```

## 執行測試

```bash
python -m pytest tests/ -q
```

測試資料會在測試執行時自動產生（不需要預先準備）。
