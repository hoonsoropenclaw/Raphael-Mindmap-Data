+            raw = response.read()

+# Telegram Weather Bot
+
+A small long-polling Telegram bot that accepts a city name as text, queries wttr.in, and replies with current weather. It uses only Python 3 standard-library modules.
+
+## Run
+
+1. Create a bot with BotFather and obtain its token.
+2. Export the token in the shell (do not commit it):
+
+```bash
+export TELEGRAM_BOT_TOKEN='your-token-from-botfather'
+# Optional hardening: only these numeric Telegram user IDs may use the bot.
+export TELEGRAM_ALLOWED_USERS='123456789,987654321'
+python3 telegram_weather_bot.py
+```
+
+Send `/start` or `/help`, then send a city such as `台北`, `Tokyo`, or `London`.
+
+## Design
+
+- Long polling avoids requiring a public HTTPS endpoint.
+- `offset = update_id + 1` prevents Telegram from redelivering updates.
+- Every network call has a timeout.
+- Expected network/API/input errors become user-safe messages and are logged.
+- Optional user allowlist and input length validation reduce abuse.
+- SIGINT/SIGTERM stop the polling loop cleanly.
+
+## Test
+
+```bash
+python3 -m unittest -v test_telegram_weather_bot.py
+python3 -m py_compile telegram_weather_bot.py
+```
+
+## Notes
+
+wttr.in's JSON response may contain English condition descriptions even with `lang=zh`; the bot preserves the provider's description while presenting labels in Traditional Chinese. For production use, consider adding a persistent rate limiter and a service manager such as systemd.

+Implementation review notes
+
+Architecture
+- Chose Python standard library only: urllib handles Telegram and wttr.in HTTP calls, avoiding unnecessary third-party runtime dependencies.
+- Separated weather parsing (`fetch_weather`) from Telegram routing (`handle_update`) so weather behavior can be tested without network access.
+- Used Telegram long polling because it does not require a public HTTPS endpoint.
+
+Reliability and safety
+- All outbound HTTP requests have bounded timeouts.
+- Polling retries transient BotError failures after a short delay.
+- Telegram update offsets are advanced using the absolute update_id + 1 rule.
+- Input is normalized and limited to 100 characters.
+- Optional TELEGRAM_ALLOWED_USERS allowlist is available for private deployments.
+- SIGINT and SIGTERM set a shutdown flag so the process exits without abruptly terminating the loop.
+- Secrets are provided through TELEGRAM_BOT_TOKEN and excluded from git.
+
+Verification
+- Unit tests use a fake weather HTTP function, so they do not need credentials or network access.
+- Syntax compilation and unit tests should be run before deployment.
+
+Known scope limits
+- wttr.in is a free third-party dependency and can rate-limit or change response fields.
+- The rate limiter is intentionally not included in this minimal version; use a persistent or distributed limiter if exposed publicly at scale.
