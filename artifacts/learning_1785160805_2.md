    🧠 實作思路
    
    為什麼 HTML scrape 而非 API
    GitHub 沒有官方 Trending REST/GraphQL API。/search/repositories 雖然能拿 repo,但沒有「trending」這個時間過濾維度(必須先知道「過去 24h 的 created 截止時間」才能查)。HTML 頁面 https://github.com/trending?since=daily&language=python 是唯一可靠的單一來源。
    
    解析策略
    1. 用正則 <article class="Box-row">.*?</article> 把 25 個 repo 區塊粗切(這層 anchor 在 GitHub HTML 五年沒變過)
    2. 區塊內改用 BeautifulSoup(html.parser),因為內部屬性順序亂、正則難維護
    3. 每個欄位用「穩定錨點」定位:
       - name/url → <h2> 內第一個 <a>
       - description → <p class="col-9 ...">
       - language → [itemprop="programmingLanguage"]
       - language_color → sibling <span class="repo-language-color" style="background-color: #XXX">(踩坑修正:原以為色碼在 class 名,實際在 inline style)
       - stars → <a href="/.../stargazers"> 內文字
       - 期間 stars → <span class="float-sm-right"> 內 "1,234 stars today"
       - forks → <a href="/.../forks|/network/members">
       - contributors → "Built by" 區(本次 trending 沒有,正常)
    
    支援參數
    - --since daily/weekly/monthly(預設 daily)
    - --language python/go/rust/...
    - --top N(只取前 N)
    - --output FILE(寫檔)
    - --json(純 JSON 輸出,適合管線接 zsh/jq)
    
    魯棒性細節
    - _parse_count() 處理 GitHub 的 1,234 跟 12.3k / 1.2m 三種格式
    - description 裡的 | escape 成 \|,newline 變空白,超過 120 字截斷 → 不會破壞 Markdown 表格
    - User-Agent 設為 Chrome 124,GitHub 不會回精簡 HTML 給 bot
    - 失敗時 sys.exit(1) + stderr 報錯
