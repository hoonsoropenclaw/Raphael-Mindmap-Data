+"""In-memory sliding-window rate limiter for FastAPI.
+
+Why a custom in-memory limiter?
+-------------------------------
+For a learning-grade todo API we want a *visible*, *testable* rate limit
+without pulling in `slowapi` / `limits` / Redis. The design is:
+
+* Map ``(client_key, window_key)`` -> list of request timestamps.
+* On each request, drop timestamps older than the window, then either
+  accept the new request (append timestamp) or reject with 429.
+* Cleanup: a background thread prunes empty buckets every ``cleanup_interval``
+  seconds so memory doesn't grow unbounded.
+
+Trade-offs:
+  * In-memory means per-process counters; multiple uvicorn workers would each
+    have their own bucket. That's acceptable for a single-process dev server.
+  * Not atomic across processes; we use a module-level ``threading.Lock`` to
+    keep it thread-safe within a single process.
+"""
+from __future__ import annotations
+
+import threading
+import time
+from collections import deque
+from typing import Callable, Deque, Dict, Tuple
+
+from fastapi import Request
+from fastapi.responses import JSONResponse
+from starlette.middleware.base import BaseHTTPMiddleware
+
+
+class SlidingWindowRateLimiter(BaseHTTPMiddleware):
+    """Sliding-window rate limiter as ASGI middleware.
+
+    Parameters
+    ----------
+    app:
+        The ASGI application.
+    limit:
+        Maximum number of requests allowed within ``window_seconds``.
+    window_seconds:
+        Length of the sliding window in seconds.
+    key_func:
+        Optional callable that takes a ``Request`` and returns the client key
+        used to bucket requests. Defaults to ``request.client.host``.
+    cleanup_interval:
+        How often the background sweep removes empty buckets.
+    """
+
+    def __init__(
+        self,
+        app,
+        *,
+        limit: int = 60,
+        window_seconds: float = 60.0,
+        key_func: Callable[[Request], str] | None = None,
+        cleanup_interval: float = 60.0,
+    ) -> None:

+        self.limit = limit
+        self.window = float(window_seconds)
+        self.key_func = key_func or (lambda r: r.client.host if r.client else "anonymous")
+        self._buckets: Dict[Tuple[str, int], Deque[float]] = {}
+        self._lock = threading.Lock()
+        self._cleanup_interval = cleanup_interval

+    if completed is None:
+        rows = conn.execute(
+            "SELECT id, title, completed, created_at, updated_at "

+        ).fetchall()
+    else:
+        rows = conn.execute(
+            "SELECT id, title, completed, created_at, updated_at "
+            "FROM todos WHERE completed = ? ORDER BY id ASC",
+            (1 if completed else 0,),
+        ).fetchall()
+    return [_row_to_dict(r) for r in rows]
+
+

+    row = conn.execute(
+        "SELECT id, title, completed, created_at, updated_at FROM todos WHERE id = ?",
+        (todo_id,),
+    ).fetchone()
+    return _row_to_dict(row) if row else None
+

+## 3. 設計決策(為什麼這樣寫)
+
+### 3.1 App factory pattern
+`create_app(db_path, rate_limit, rate_window)` 取代模組層級常數。
+- **測試友善** — 每個 test fixture 拿自己的 in-memory/temp-file DB
+- **設定可注入** — 不靠 monkey-patch,直接傳參數
+- **零全域狀態** — module-level `app = create_app()` 留給 uvicorn 入口,但測試永遠用 factory
+
+### 3.2 連線管理:每個 request 一條新連線
+`sqlite3` 預設 `check_same_thread=True`,而 FastAPI 的 sync dependency 在 thread pool 跑。
+每次 request 開新連線、結束關閉,徹底避開「objects created in thread X can only be used in thread X」這個經典地雷。
+**Trade-off**:不能跨 request 共用連線池——但對 todo API 量級完全夠用,程式碼也單純很多。
+
+### 3.3 Schema 設計
+- `id INTEGER PRIMARY KEY AUTOINCREMENT`
+- `title TEXT NOT NULL CHECK(length(title) <= 200)` — DB 層擋掉超長輸入,pydantic 層再擋一次(double belt)
+- `completed INTEGER NOT NULL DEFAULT 0 CHECK(completed IN (0,1))` — 用 INTEGER 而非 BOOLEAN(更 portable)
+- `created_at / updated_at` 預設 `datetime('now')`,trigger 自動維護 `updated_at`
+- 兩個 index:`completed`、`created_at` —— 列表查詢兩種常見排序都有覆蓋
+
+### 3.4 Sliding-window rate limiter(自己寫,沒用 slowapi)
+- 用 `deque[float]` 存時間戳,每次 request:
+  1. 砍掉視窗外的舊時間戳
+  2. 數量 < limit → append,放行
+  3. 數量 >= limit → 回 429 + `Retry-After`
+- `threading.Lock` 保護 bucket map(同一行程式內 thread-safe)
+- 背景 cleanup 機制:每 60 秒掃一次、刪空 bucket → 記憶體不會無限成長
+- 對每個回應加 `X-RateLimit-Limit / Remaining / Window` header,讓 client 可以自我節流
+- 為什麼不直接用 `slowapi`?**學習目的**:寫一次才能真正理解 sliding window 跟 fixed window 差在哪、memory bucket 怎麼清,而不是裝套件 `app.add_middleware(SlowAPIMiddleware...)` 就交差了事
+- **已知 trade-off**:in-memory → 多 uvicorn worker 各自計數;production 規模要換 Redis,但對單機 dev / demo 完美
+
+### 3.5 Pydantic v2 + ConfigDict
+- `TodoBase / TodoCreate / TodoUpdate / TodoOut` 分清楚「in vs out」,response model 只暴露 ORM 想暴露的欄位
+- `TodoUpdate` 用 `Optional[T] = None` 表 PATCH 語意(欄位不傳 = 不更新)
+
+### 3.6 Lifespan(不用 deprecated 的 on_event)
+FastAPI 0.110+ 把 `@app.on_event("startup")` 標 deprecated。
+改用 `@asynccontextmanager` lifespan pattern — 順便清掉測試輸出裡所有的 deprecation warning。
