+## 🎯 為什麼這樣設計（架構決策）
+
+### 1. 為什麼用「自帶 vulnerable app」而不是打外部網路
+**原本最通用版本** = 拿公開 vulnerable 站台（如 `httpbin.org`、DVWA、OWASP Juice Shop）當 fixture。
+**為什麼換成自帶**：
+- 外部站台會壞、會改 API、會 rate-limit IP（hoonsoropenclaw 的 N100 已驗證過這個雷）
+- 公開 vulnerable 站台**本身就是武器化**，不該鼓勵
+- 自帶 server 雖然是 stdlib 拼出來的，但**確定性 + 可離線 + 可重複 + 不外洩**
+- 測試攻擊向量時，能明確知道「這個 endpoint 預期回什麼」
+
+### 2. 為什麼 vulnerable 而不是 secure-by-default
+框架目的是**測試 detection 能力**，不是測保護能力。
+- 微技能 #7 §3.2 的 `detect_injection` 函數就是這個 pattern — 「給一段輸入、判斷是不是 injection」
+- 對應到測試上：「VulnerableApp 故意脆弱 → framework 測『能不能偵測到該偵測的東西』」
+- Production 修補由 owner 負責；framework 只負責 surface the issue
+
+### 3. 為什麼 Playwright + requests/httpx 兩種 client
+對應微技能 #3 的「multi-layer defense」概念：
+- **HTTP client**（`urllib` / `httpx`）— 純 protocol 層測試（auth/JWT/SQLi/輸入驗證）
+- **Playwright browser** — DOM 層測試（XSS 真的會在瀏覽器執行）
+- 兩個層都測 → 任何一層被繞過都能被抓到
+
+### 4. 為什麼 rate limit 預設 100 而不是 5

+改成「寬鬆預設 + 環境變數可覆寫」：

def call(method, path, body=None, headers=None):
    data = json.dumps(body).encode() if body is not None else None
    req = urllib.request.Request(base+path, data=data, method=method,
        headers={'Content-Type':'application/json', **(headers or {})})
    try:
        r = urllib.request.urlopen(req, timeout=5)
        return r.status, json.loads(r.read() or b'{}')
    except urllib.error.HTTPError as e:
        return e.code, json.loads(e.read() or b'{}')
