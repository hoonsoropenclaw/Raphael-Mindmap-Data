+// uses Playwright device emulation instead of a fixed viewport. We run the
+// same three demo pages through iPhone 13, iPad, and a desktop reference
+// viewport, capturing screenshots and comparing against a separate set of
+// baselines (baselines/responsive--<device>--<page>.png). The visual diff
+// threshold is identical to run-visual-regression.cjs.
+//
+// Why a separate suite?
+//   - run-visual-regression focuses on cross-ENGINE consistency (chromium vs
+//     firefox vs webkit at the same viewport).
+//   - run-responsive focuses on cross-DEVICE consistency within ONE engine
+//     (chromium) — it surfaces CSS reflow / responsive bugs that don't show
+//     up at a single 1280x800 viewport.
+//   - Mixing them would either bloat the visual baseline matrix (3 engines x

+# Playwright Cross-Browser Lab — README
+
+End-to-end cross-browser + visual regression + responsive testing for a static
+HTML surface (3 demo pages). Pure Node.js + Playwright. No CI required — runs
+on any machine with the three Playwright browser engines pre-installed.
+
+## What it covers
+
+3 separate test suites, all orchestrated by `tests/run-all.cjs`:
+
+| Suite                     | Matrix                              | Cases | Tooling |
+| ------------------------- | ----------------------------------- | ----- | ------- |
+| Cross-browser functional  | chromium × firefox × webkit (1280×800) | 3 pages × 3 engines = 9 | Playwright locators + assertions |
+| Visual regression         | same — 3 engines × 3 pages               | 9     | pixelmatch + pngjs (threshold 0.18, fail if diff > 2%) |
+| Responsive (multi-device) | desktop-1280 + iPad (gen 5) + iPhone 13 | 3 devices × 3 pages = 9 | Playwright `devices[]` + pixelmatch |
+
+**Total: 27 cases, runs in ~17s on the N100 headless box.**
+
+## Quick start
+
+```bash
+# 1. install node deps (one-time; assumes playwright browsers are already
+#    in ~/.cache/ms-playwright/ — `npx playwright install` if not)
+npm install
+
+# 2. run the full matrix (3 suites + dashboard HTML report)
+node tests/run-all.cjs
+
+# 3. individual suites
+node tests/run-cross-browser.cjs
+node tests/run-visual-regression.cjs
+node tests/run-responsive.cjs
+
+# 4. refresh baselines after a UI change
+node tests/run-visual-regression.cjs --update
+node tests/run-responsive.cjs     --update
+# or both at once
+npm run baseline
+```
+
+Outputs:
+
+- `reports/functional.json` / `visual.json` / `responsive.json` / `summary.json` — raw per-case results
+- `reports/screenshots/<browser>--<page>.png` — every current run's screenshot
+- `reports/diffs/<browser>--<page>.diff.png` — pixelmatch diff overlay (red = mismatch)
+- `reports/dashboard.html` — interactive HTML report with KPIs, per-case tables, screenshot gallery
+- `../web_output.html` — mirror of the dashboard at the workdir root (for the `web_output.html` deliverable contract)

+## 設計決策紀錄
+
+### 為什麼 responsive 套件只用 chromium（不跑 3 個瀏覽器）？
+
+原想過 `chromium + firefox + webkit` × `desktop + ipad + iphone-13` = 27 case 的 matrix，但實務上：
+
+1. **firefox mobile 渲染跟真實 Android Chrome 差太多**（不是「真實 mobile firefox」使用者場景，diff 訊號會是 engine 差異不是 RWD 差異）
+2. **webkit mobile 才是真實 iOS Safari**（但 Playwright 的 webkit-mobile 跟 macOS Safari-on-iOS-Simulator 渲染仍有差異）
+3. RWD 測試目的是驗「同一頁面在不同 viewport 下行為正確」——只要 Chromium 的 RWD 是對的，跨瀏覽器的 RWD 通常也對（因為 RWD 是 CSS media query 行為，瀏覽器差異在這層很薄）
+
+所以：responsive 套件用 chromium 一個 engine × 3 個 device，fail 訊號純淨指向 CSS。
+
+### 為什麼把 responsive 拆成獨立 suite、不併進 visual regression？
+
+兩個原因：
+
+1. **Fail 訊號會混**：`run-visual-regression` 跑 3 engines 同一 viewport，比的是「同一頁面在 chrome vs firefox vs safari 渲染差異」。如果把它擴成 3 engines × 3 viewports = 27 baseline，單一失敗無法分辨「engine bug」還是「viewport bug」。
+2. **Baseline 命名空間獨立**：`<browser>--<page>.png` vs `responsive--<device>--<page>.png`，互不污染。
+
+### 為什麼不直接用 Playwright 內建 `toHaveScreenshot()` 而要 pixelmatch？
+
+- Playwright 內建 snapshot 適合「baseline 鎖住、無腦回歸」場景，但對「調 threshold」沒那麼彈性（要寫 expect options）
+- pixelmatch 對 1-pixel 級差異的 threshold (YIQ color distance 0.18) 可調、能直接看 raw 差異 pixel 數跟 ratio、還能輸出視覺化 diff overlay
+- 對「教學 + demo + 實務」三個場景都更友善——dashboard 可以同時秀「基線截圖 + 差異遮罩 + 差異比例」三個視角
