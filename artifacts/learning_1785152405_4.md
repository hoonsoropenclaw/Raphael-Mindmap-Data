+## 2. 關鍵設計決策
+
+### 2.1 Finding 統一 schema（為什麼這是值得的）
+
+`resource_checker.Finding` 跟 `log_scanner.Finding` 用同一個 shape：
+`{severity, source, message, value, threshold, timestamp}`。
+
+→ alerter **不用分支判斷來源**就能處理所有資源/日誌/認證告警。
+→ 主程式 `run_once()` 把 `r_snap.findings + l_snap.findings` 直接 `sum`。
+→ 加第四個 module（比如 `process_checker`）不用動 alerter.py。
+
+這個決定在 L2 是「省了 if/else」；在 L3 是「讓監控可以組合化擴充」。
+
+### 2.2 監控自己不能變死角
+
+`run_once()` 用 try/except 包住 module 呼叫；任一炸了，產生一個

+→ `exit code 3` 而不是 `exit 1`：cron / systemd timer 可以分別觀測到
+「完全沒抓到資料」vs「有 warn」。
+→ 自身 crash 算 warn 而不是 crit：避免一個 module bug 觸發 alert 風暴
