+# GitHub Trending Markdown Exporter
+
+A dependency-free Python utility that fetches GitHub's public Trending page and writes a Markdown repository table.
+
+## Requirements
+
+- Python 3.10+
+- Network access to `github.com`
+- No third-party packages
+- No GitHub token
+
+## Usage
+
+```bash
+# Daily, all languages; writes trending.md
+python3 github_trending.py
+
+# Weekly Python repositories, maximum 10 rows
+python3 github_trending.py \
+  --language Python \
+  --since weekly \
+  --limit 10 \
+  --output python-weekly.md
+
+# Print Markdown to stdout
+python3 github_trending.py --limit 5 --output -
+```
+
+Options:
+
+```text
+--language NAME
+--since daily|weekly|monthly
+--limit 1..100
+--output PATH|-
+--timeout SECONDS
+--retries 0..5
+```
+
+## Reliability design
+
+- Semantic `HTMLParser` instead of a fixed regex or brittle visual selector.
+- HTML void elements (`img`, `br`, etc.) do not corrupt repository-card depth.
+- Transient HTTP `429` and `5xx` failures use bounded exponential retries.
+- Empty/unrecognized GitHub responses fail non-zero rather than produce a blank report.
+- Output uses a unique sibling temporary file, `fsync`, and `os.replace`.
+- A non-blocking `fcntl.flock` prevents overlapping automation runs from writing the same output.
+- The lock file remains beside the report as `.trending.md.lock`; it contains no secret data.
+
+## Verification
+
+```bash
+python3 -m py_compile github_trending.py test_github_trending.py
+python3 -m unittest -v test_github_trending.py
+python3 github_trending.py --limit 5 --output trending.md
+```
+
+## Cron example
+
+```cron
+15 9 * * * cd /absolute/path/to/project && /usr/bin/python3 github_trending.py --since daily --output trending.md >> trending.log 2>&1
+```
+
+GitHub Trending is an HTML page, not a versioned JSON API. If GitHub changes its markup, the command intentionally exits with an explicit parser error and leaves the previous successful Markdown output untouched.

+## 3. Architecture
+
+### 3.1 Upstream source
+
+GitHub Trending has no stable public JSON API. The script reads the public HTML endpoint:
+
+```text
+https://github.com/trending[/{language}]?since={daily|weekly|monthly}
+```
+
+It uses `urllib.request`, a descriptive User-Agent, a bounded timeout, and retries only transient failures (`429`, `500`, `502`, `503`, `504`, and temporary network errors). Permanent HTTP errors fail immediately.
+
+No GitHub token is accepted or required.
+
+### 3.2 Parser
+
+`TrendingHTMLParser` extends Python’s standard-library `HTMLParser`. It recognizes repository cards by the semantic `article.Box-row` boundary and extracts:
+
+- repository path and URL
+- description
+- programming language
+- total stars
+- forks
+- stars gained during the selected period
+
+A `VOID_ELEMENTS` set makes `img`, `br`, `meta`, and other HTML void tags depth-neutral. Without this, an unclosed `img` can shift parser depth and merge or lose later cards. The regression fixture contains `<br>` and `<img>` in the first card followed by a second card, proving the parser closes both records correctly.
+
+If no recognizable repository card exists, parsing fails with a `TrendingError`. It does not fabricate rows or silently replace a good report with an empty one.
+
+### 3.3 Markdown rendering
+
+The generated table has the following columns:
+
+```text
+Rank | Repository | Description | Language | Stars | Forks | Stars gained
+```
+
+Table cells normalize newlines and escape Markdown pipe characters. Missing optional values are rendered as an em dash. Repository names are clickable GitHub links.
+
