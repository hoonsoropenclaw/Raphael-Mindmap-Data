+/**
+ * useUndoableReducer
+ * --------------------------------------------------
+ * 把一個純 reducer 包成有 undo / redo 能力的 hook。
+ *
+ * 設計重點：
+ *  - history 是 stack<T>，每個 T 都是「完整 state 快照」。
+ *  - 一個 action 只產一個 history entry（不是 delta）；
+ *    避免「undo 半步」這種使用者會困惑的行為。
+ *  - SET_FILTER 之類的「UI-only state」可以選擇性跳過 undo
+ *    （filter 進 history = undo 回去會覺得 bug）。
+ *  - 容量上限 = MAX_HISTORY；超過時丟最舊的（FIFO）。
+ *  - undo/redo 都用 reducer 而非直接 mutate history stack，
+ *    確保 React 重新渲染並對齊 dispatch 順序。
+ */
+
+export interface UndoableConfig<S, A> {
+  /** 哪些 action 該被記進 history（predicate 模式） */
+  shouldRecord?: (action: A) => boolean;
+  /** history 上限 */
+  capacity?: number;
+  /** 把 S 中需要排除 history 的欄位在 snapshot 時 strip 掉 */
+  scrubHistory?: (s: S) => S;
+}
+
+interface History<S> {
+  past: S[];
+  future: S[];
+}
+
+type UndoableAction<S, A> =
+  | { kind: 'dispatch'; action: A }
+  | { kind: 'undo' }
+  | { kind: 'redo' }
+  | { kind: 'reset'; next: S };
+
+export function useUndoableReducer<S, A>(
+  reducer: (state: S, action: A) => S,
+  initial: S,
+  config: UndoableConfig<S, A> = {},
+) {
+  const {
+    shouldRecord = () => true,
+    capacity = 50,
+    scrubHistory = (s) => s,
+  } = config;
+
+  // 我們自己的「meta-reducer」：包裝使用者的 reducer，加上 history 管理。
+  const metaReducer = useCallback(
+    (
+      state: { current: S; history: History<S> },
+      action: UndoableAction<S, A>,
+    ): { current: S; history: History<S> } => {
+      switch (action.kind) {
+        case 'dispatch': {
+          const next = reducer(state.current, action.action);
+          if (next === state.current) {
+            // reducer 選擇 noop（例如非法 move）→ 不進 history
+            return state;
+          }
+          if (!shouldRecord(action.action)) {
+            return { current: next, history: state.history };
+          }
+          const past = [...state.history.past, scrubHistory(state.current)];
+          if (past.length > capacity) past.shift();
+          return { current: next, history: { past, future: [] } };
+        }
+        case 'undo': {

+# Kanban Board — React + TS + Vite
+
+一個「複雜狀態管理」的 React UI 元件 demo。
+
+## 功能
+
+- **多欄看板** — 4 個欄位（待辦 / 進行中 / 審核 / 完成），欄位配色用 CSS custom property 驅動
+- **任務 CRUD** — 新增 / 編輯 / 刪除（modal editor，含 a11y 鍵盤操作）
+- **拖拽** — HTML5 Drag-and-Drop API，支援欄間移動、欄內重排、上下插入（用 dataset `dropZone` 區分前後）
+- **鍵盤操作** — `←/→` 移到隔壁欄、`Esc` 關 modal、`Ctrl+Z` undo、`Ctrl+Shift+Z` (或 `Ctrl+Y`) redo
+- **搜尋 + 標籤篩選** — 即時搜尋（標題/描述/標籤）、tag chip 切換單一 tag 過濾
+- **Undo / Redo** — 全域 history stack（80 步），每個 action 進 1 個 snapshot；UI-only 的 `SET_FILTER` 不進 history（避免「undo 回去變成篩選怪怪的」）
+- **LocalStorage 持久化** — versioned payload `{ __persist: { version, savedAt }, data: state }`，壞掉自動 fallback 到 seed
+- **Dark / Light 主題** — 用 CSS custom properties，data-theme 切換；偏好存 localStorage
+- **無障礙** — ARIA roles / labels、`aria-pressed`、`role="dialog"` modal、`:focus-visible`、尊重 `prefers-reduced-motion`
+

+## 2. 架構決策

+### 2.1 State 管理：純 reducer + wrapper hook
+
+**為什麼不用 Redux / Zustand / Recoil？**
+
+- 為了 demo「複雜狀態管理」的可控性，自己刻 reducer + hook 比叫 library 更能看到設計 trade-off
+- 任務範圍小（單一 feature 頁），library 的 middleware/devtools/store overhead 是 over-engineering
+- 自製 hook 還能精準控制 `shouldRecord`、`scrubHistory`——這是 Redux 預設做不到的
+
+**核心抽象**：`useUndoableReducer<S, A>(reducer, initial, config)`
+
+```
+              ┌─────────────────────────────────────┐
+              │  metaReducer (history-aware)        │
+              │  ─ past / future stack              │
+              │  ─ shouldRecord predicate            │
+              │  ─ capacity FIFO eviction            │
+              └──────────────┬──────────────────────┘
+                             │ dispatch(action)
+                             ▼
+              ┌─────────────────────────────────────┐
+              │  userReducer (pure)                 │
+              │  boardReducer(state, action) → S'   │
+              └─────────────────────────────────────┘
+```
+
+### 2.2 State shape：dictionary + sequence 分離
+
+```ts
+BoardState {
+  tasks: Record<TaskId, Task>      // O(1) lookup by id
+  order: Record<ColumnId, TaskId[]> // 每欄的序列順序
+  filter: { query, tag }            // UI-only
+}
+```
+
+**為什麼不直接 `tasks: Task[]`？**
+
+- 拖拽「移到第 N 欄、第 M 位」需要 `O(1)` 找到 task by id + `O(N)` 改 column + `O(N)` 改 order，三件事各自高效
