+"""
+visual_diff.py — Pillow-powered visual regression engine.
+
+Adapted from the visual_regression_with_pillow micro-skill
+(skills/visual_regression_with_pillow.md).
+
+Provides a single compare_images() function that returns diff statistics and
+optionally writes a heatmap-style diff PNG to disk.
+"""
+from __future__ import annotations
+
+import os
+from pathlib import Path
+from typing import Optional, Dict, Any
+
+from PIL import Image, ImageChops
+
+
+def compare_images(
+    baseline_path: str | os.PathLike,
+    current_path: str | os.PathLike,
+    diff_path: Optional[str | os.PathLike] = None,
+    threshold: int = 32,
+) -> Dict[str, Any]:
+    """
+    Compare two PNGs pixel-by-pixel and (optionally) write a diff heatmap.
+
+    Parameters
+    ----------
+    baseline_path : path to the reference (golden) screenshot
+    current_path  : path to the freshly captured screenshot
+    diff_path     : where to write the heatmap PNG (None → skip)
+    threshold     : 0..255 — a pixel is "different" when the max channel delta
+                    exceeds this value. Higher = more tolerant.
+
+    Returns
+    -------
+    dict with keys:
+        - diffPixels   (int)    number of pixels that exceed the threshold
+        - totalPixels  (int)    baseline width × height
+        - ratio        (float)  diffPixels / totalPixels
+        - passed       (bool)   True if ratio < 0.001 (0.1 %)
+        - diffImage    (str|None) path to heatmap PNG if any diff exists
+        - width, height (int)
+    """
+    baseline = Image.open(baseline_path).convert("RGBA")
+    current = Image.open(current_path).convert("RGBA")
+
+    # Sizes must match — Playwright pins the viewport per device so this is
+    # almost always true, but guard anyway (the upstream micro-skill's
+    # #1 common-error is "image sizes don't match").
+    if baseline.size != current.size:
+        current = current.resize(baseline.size, Image.LANCZOS)
+
+    diff = ImageChops.difference(baseline, current)
+
+    # Per-channel max into a single grayscale "did anything change?" map.
+    r, g, b, a = diff.split()
+    channel_max = ImageChops.lighter(
+        ImageChops.lighter(r, g),
+        ImageChops.lighter(b, a),
+    )
+
+    # Count pixels above the threshold.
+    pixels = sum(1 for px in channel_max.getdata() if px > threshold)
+
+    total = baseline.width * baseline.height
+    ratio = (pixels / total) if total else 0.0

+# Cross-Browser Visual Regression Suite
+
+A self-contained Playwright + Tailwind CSS harness that captures, baselines, and
+pixel-diffs UI snapshots across **Chromium, Firefox, WebKit** and their mobile
+emulations. One Python project, zero node toolchain required.
+
+## Why this exists
+
+- **CI gate for visual bugs.** Every PR should answer: did the pixels change
+  in a way a human would notice?
+- **Cross-browser matrix by default.** Five device projects (Desktop
+  Chrome/Firefox/Safari, Pixel 5, iPhone 13) — same DOM, different paint.
+- **Pixel-accurate diffs.** Pillow `ImageChops` aggregates per-channel deltas
+  into a heatmap, surfaced in a self-contained HTML report.
+
+## Architecture
+
+```
+web_output.html              ← the Tailwind subject under test
+framework/
+  __init__.py
+  device_matrix.py           ← 5-project viewport + UA matrix
+  visual_diff.py             ← Pillow compare_images() (micro-skill refactor)
+  run_suite.py               ← orchestrator: capture → diff → report
+screenshots/
+  baseline/   current/   diff/
+report/
+  results.json               ← machine-readable per-device stats
+  index.html                 ← self-contained Tailwind report
+run_framework.sh             ← convenience CLI wrapper
+```
+
+The two core modules are direct refactors of the project's existing micro-skills:
+

+## Quickstart
+
+```bash
+# 1) Capture a fresh set of golden screenshots
+./run_framework.sh baseline
+
+# 2) After any change, diff against the baselines and write a report
+./run_framework.sh verify
+
+# 3) Open the report
+xdg-open report/index.html    # or just inspect the file
+```

+## Key design decisions
+
+1. **Animations are frozen before capture** (`page.add_style_tag` with
+   `animation: none !important`). Without this, anti-aliased motion in
+   `gradient` / `float-slow` / `pulse-soft` keyframes produces 1–2 % pixel
+   diffs between two captures of the same DOM, drowning out real regressions.
+2. **Sync API, not pytest-playwright.** The harness needs to run from a
+   single `python3 framework/run_suite.py` invocation so it composes cleanly
+   with cron, CI, and ad-hoc shell pipelines.
+3. **Self-contained HTML report.** Every screenshot is base64-inlined, so the
+   report is one file you can email, paste in Slack, or attach to a PR.
+4. **Diffs land in a heatmap PNG** (red overlay, 4× amplified alpha) so a
+   human can see *where* the change happened, not just *that* it happened.
