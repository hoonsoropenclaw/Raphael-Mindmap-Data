+- `--period`：`daily`、`weekly`、`monthly`

+- `--output`：輸出路徑；未指定時寫到 stdout
+- `--timeout`：HTTP timeout 秒數，預設 15
+- `--retries`：可重試錯誤的重試次數，預設 2
+
+## 注意

+# Senior Architect Review — GitHub Trending Markdown Exporter
+
+## 1. 實作思路
+
+- GitHub 目前沒有官方 Trending API，因此直接讀取公開的 `https://github.com/trending` HTML。
+- 使用 Python 3 標準函式庫完成：`urllib.request` 負責 HTTP、`html.parser.HTMLParser` 負責結構解析、`argparse` 負責 CLI。
+- 不使用脆弱的單一大型 regex 解析 HTML；改用 repository card（`article.Box-row`）作為狀態邊界，分別擷取 repository、description、language、stars、forks 與期間新增 stars。
+- HTTP 層加入 timeout、有限次數 exponential backoff，以及只對 429／5xx 類暫時性錯誤重試。
+- 輸出 Markdown 前處理 HTML entities、空白與 pipe 字元，避免描述內容破壞 Markdown table。
+- 若 GitHub HTML 結構改變而抓不到 repository card，明確以 exit code 1 失敗，不靜默輸出空資料。
+
+## 2. 架構決策
+
+1. Standard-library first：此工具本質只需一個 HTTP GET 與 HTML state parser，加入 requests／BeautifulSoup 會增加部署與供應鏈成本，收益有限。
+2. Parser 與 renderer 分離：`fetch_html`、`parse_repositories`、`render_markdown` 各自只有一種責任，方便未來替換來源或輸出格式。
+3. Repository dataclass 作為中間模型：避免 HTML 細節滲入 Markdown 輸出層。
+4. CLI 可組合性：預設寫 stdout；指定 `--output` 才寫檔，適合 cron、pipe 與 GitHub Actions。
+5. 防誤判：repository link 排除 `sponsors`、`topics`、`collections`、`marketplace` 等 GitHub 導航 namespace。本輪真實執行曾抓到 `sponsors/opengeos`，已透過此規則修正並重測。
