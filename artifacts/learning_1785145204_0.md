+# sysmon.py — 交付文件
+
+## 任務
+撰寫一個自動化檢查 Linux 系統日誌與資源的維運腳本，並在超過閾值時發出警告。
+
+## 設計思路
+
+### 1. 監控範圍（三層）
+| 層 | 項目 | 來源 |
+|---|---|---|
+| **資源** | CPU 使用率 | `/proc/stat` 兩次取樣差 |
+| | Load Average | `/proc/loadavg`（轉 per-CPU） |
+| | RAM / Swap | `/proc/meminfo` |
+| | Disk / inode | `shutil.disk_usage` + `df -i` |
+| | 殭屍行程 | 掃 `/proc/*/stat` 找 `state=Z` |
+| **日誌** | journal priority 0..3 訊息數 | `journalctl --since=... --priority=0..3` |
+| | 關鍵字命中 | regex 掃 OOM / Segfault / Auth fail / Kernel panic / Disk full |
+| **狀態** | Journal 蒐集失敗偵測 | journalctl 非 0 退出時降級為 WARN（不偽造數字） |
+
+### 2. 為什麼不用 `psutil` / `distroinfo`
+- **零外部依賴**：systemd 環境本來就一定有 `/proc` + `journalctl`，stdlib + 兩個 coreutil 就夠
+- 安裝成本 = 0，cron / systemd timer / Docker image 都好帶
+
+### 3. 分級與退出碼
+- 三級：`OK` / `WARN` / `CRIT`（rank 0/1/2）
+- exit code 對應 0/1/2 → 直接餵 cron / Nagios / Prometheus node-exporter textfile collector
+- 嚴重度對應 `severity_rank` 取最大值決定整體狀態
+
+### 4. 閾值設計哲學
+- **預設偏保守**：CPU 80/95、RAM 85/95、Disk 85/95（業界常用）
+- **可被 CLI 完全覆寫**：每個閾值都有 `--xxx-warn` `--xxx-crit`，避免 hard-code 卡死
+- **Load 用 per-CPU**：跟 CPU 數量解耦（4 核 vs 64 核比較才公平）
+
+### 5. 告警去重（冷卻）
+- 同樣的檢查項在 `--cooldown` 秒內（預設 300s）第二次觸發 → 自動降級成 OK、附 `(冷卻中 Xs)`
+- 狀態寫到 `--state` 檔（預設 `~/.cache/sysmon.state`），原子寫入（tmp + rename）
+- 用 `apply_cooldown()` 包，**集中在一個地方**，好測試
+
+### 6. 已知陷阱（修過的）
+- ❌ `journalctl --since=1h` **不接受** → 補 `_normalize_since()` 轉成 `1 hour ago`
+- ❌ 關鍵字 regex 跑在 journalctl 自己的 stderr 上 → 結果是「`journalctl-error:Failed to parse...`」誤報 OOM 之類的關鍵字。修正：journalctl 失敗時把 hits 標成 `journalctl-error:` 前綴、輸出階段才區分
+- ❌ 早期設計把 `journalctl 不存在` 當關鍵字命中 → 改成 return `(0, [])` 直接略過
+
