+## 任務定位
+
+撰寫一個自動化檢查 Linux 系統日誌與資源的維運腳本，並在超過閾值時發出警告。

+## 設計核心原則
+
+### 1. 零第三方依賴
+
+- 純 bash + `awk` + `grep` + `df --output` + `/proc/*` + python3（算浮點 + 多行 JSON 處理）
+- **不安裝** psutil / yq / jq / PyYAML
+- 理由：container / embedded / 最小化 Server 環境跑不起來第三方；維運 script 改一支就壞整組
+
+### 2. ENV 變數覆寫優先於設定檔（重要修正點）
+
+第一版用 `${VAR:-default}` 模式，但踩到關鍵 bug：`source defaults.env` 會把 ENV 已經 export 的同名變數**覆蓋回 defaults.env 的值**。這違反「ENV 為主 → 設定檔為 fallback → 主腳本後備」的契約。
+
+修正流程（在 source 前用 assoc array 備份 ENV、source 後還原）：
+
+```
+1. declare -A OVERRIDES，把所有可覆寫變數存起來
+2. source defaults.env
+3. for var in OVERRIDES: 還原有設定的值
+```
+
+### 3. 6 個 check × 3 級嚴重度 + cooldown stamp 防 log bomb
+
+- `WARN` (severity=1) / `ALERT` (2) / `CRITICAL` (3) — exit code 直接回報 max severity
+- cooldown 機制：寫 stamp 到 `$SYSMON_STATE_DIR/stamp.<sanitized-key>`，內容是 unix timestamp
+- 預設 30 分鐘內同 `(cat, target, level)` 只 emit 一次
+
+### 4. 並發鎖 + 10 分鐘 stale 自動清
+
+- 防 cron 重疊（雖然 `*/5` 不太可能，但 timer race condition 真實存在）
+- 超過 `STALE_LOCK_MINUTES` 的鎖自動覆蓋、避免上次 crash 卡死
+
+### 5. 顯式 sanitize key（避免 path 不一致 bug）
+
+第一版踩到：`sanitize_for_filename` 在 `in_cooldown` 內隱式呼叫，但 caller 寫 stamp 時又用「未 sanitize」的 key → 兩邊 path 不一致 → cooldown 永遠 miss。
+
+最終設計：單一入口 `stamp_path_for <...args>`，內部一次性 sanitize，所有 caller 都用這個路徑。**architect_feedback #1 精神：explicit > implicit**（不要 defaultdict lazy init、不要在 caller 看不到的地方 sanitize）。
+
+### 6. Journal scan 預設 opt-in
+
+太多系統都有「正常」err-level（cron job 失敗、kernel module 載入錯誤）；預設開會誤觸 → 設 `ENABLE_JOURNAL_SCAN=true` 才掃。
