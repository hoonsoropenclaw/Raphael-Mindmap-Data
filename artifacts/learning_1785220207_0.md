+# Telegram Weather Bot
+
+純 Python 3 標準庫 Telegram 天氣機器人。收到城市文字後，依序呼叫 Open-Meteo Geocoding 與 Forecast API，再以繁體中文回覆即時天氣。Open-Meteo 不需要 API key。
+
+## 功能
+
+- Telegram Bot API long-polling，不需要公網網域或 HTTPS webhook
+- 支援純城市文字與 `/weather <城市>`
+- `/start`、`/help` 使用說明
+- Open-Meteo：城市定位 + 即時溫度、體感、濕度、降水、風速
+- 可選 Telegram user ID allowlist
+- 每位使用者 process-local cooldown rate limit
+- HTTP timeout、重試、1 MB 回應上限、HTTPS 強制
+- Telegram token 只讀環境變數，錯誤訊息不輸出 API URL/token
+- SIGINT / SIGTERM graceful shutdown
+- 零第三方 Python 套件
+
+## 需求
+
+- Python 3.11+（本機已用 Python 3.12 驗證）
+- 由 Telegram `@BotFather` 建立的 bot token
+
+## 啟動
+
+本專案刻意不自動 `source .env`，避免 `.env` 內任意變數變成 shell/Python import 控制面。請在程序管理器或目前 shell 提供環境變數：
+
+```bash
+cd /home/hoonsoropenclaw/.hermes/projects/learning_1785220207_0
+export TELEGRAM_BOT_TOKEN='<BotFather 提供的 token>'
+export TELEGRAM_ALLOWED_USERS='<你的數字 Telegram user ID>'
+./run.sh
+```
+
+`TELEGRAM_ALLOWED_USERS` 可用逗號分隔多個 ID，例如 `123,456`。若留空，機器人允許所有 Telegram 使用者並在 stderr 顯示警告。
+
+## 不連 Telegram 的 Weather API 檢查
+
+```bash
+./run.sh --check '台北市'
+```
+
+## 測試
+
+```bash
+python3 -m unittest -v
+python3 -m compileall -q weather.py telegram_bot.py test_weather_bot.py
+```
+
+離線測試使用 fake HTTP response，不需要 Telegram token，也不消耗外部 API 配額。

+## 環境變數
+
+| 名稱 | 必填 | 預設 | 說明 |
+|---|---:|---:|---|
+| `TELEGRAM_BOT_TOKEN` | 是 | — | Telegram bot token；只從環境讀取 |

+## 3. 關鍵架構決策
+
+### 3.1 純 stdlib 的取捨
+- 優點：沒有 `pip install`，無 supply chain；無 aiohttp/tornado/httpx 依賴；能跑在 Python 3.11+ 任何最小環境
+- 缺點：long-polling 期間 timeout > 30 會觸發 urllib.read 的閒置 timeout；目前用 `timeout = poll_timeout + 5` 緩解
+- 評估：對 5–30 req/min 的天氣查詢量級（每 user 3s cooldown），`urllib` 足夠
+
+### 3.2 allowlist 是建議不是強制
+- 沒設 `TELEGRAM_ALLOWED_USERS` 時仍啟動，但 `stderr` 印 `WARNING: 目前允許所有 Telegram 使用者`
+- 對 N100 個人 bot 場景：先能跑起來、警告使用者記得補，優於直接 crash
+
+### 3.3 sendMessage 失敗時回滾 rate-limit reservation
+- `CooldownLimiter.rollback(user_id, reservation)` 比較**傳入的 reservation timestamp** 與目前 bucket
+- 只有相等才刪除 → 若 A 失敗後 B 已經 reserve 過（更新時間戳），A 的 rollback 就不會誤刪 B
+- 測試 `test_send_failure_rolls_back_reservation_for_redelivery` 確認：sendMessage 失敗 → reservation 回滾 → 同一 Telegram update 重新送達時仍可被處理
+- 同時 `process_updates` 在 sendMessage 失敗時**不前移 offset**，讓 Telegram redeliver；這樣結合 at-least-once + 冷卻保護，攻擊者無從利用失敗重試洪水消耗 token bucket
+
+### 3.4 WMO code 表 = 模組級常數
+- 28 個天氣代碼中翻放在 `weather.py` 模組頂部，方便之後抽成 `i18n` 多語系 JSON

+
+### 3.5 location name 去重
