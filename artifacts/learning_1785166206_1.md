+# IMPLEMENTATION_NOTES — Telegram 天氣 Bot
+
+## 一句話總結
+
+Telegram bot,使用者傳城市名 → 透過 Open-Meteo 公開 API 查天氣 → 回傳當前天氣 + 今日高低溫 + 降雨。
+整套程式 `python-telegram-bot` v20 async + `httpx.AsyncClient`,**免 API key、免申請**,拿到 bot token 就能跑。
+
+---
+
+## 1. 技術選型與取捨
+
+| 面向 | 選擇 | 為什麼 |
+|------|------|--------|
+| Telegram SDK | `python-telegram-bot` v20+ | 官方推薦、社群最大、有 async API |
+| 天氣資料源 | **Open-Meteo** | 免 API key、限額寬鬆、可商用;OpenWeatherMap 要註冊拿 key 會卡住首次使用 |
+| HTTP client | `httpx.AsyncClient` | 連線池、原生 async、context manager 乾淨關閉 |
+| Python | 3.12 (PEP 668,所以走 venv) | 主機已有 |
+| 城市翻譯 | 內建 dict 別名表 | Open-Meteo 對繁中命中率 ≈ 0,改用 `language=en` + 別名表繞過 |
+
+**關鍵決策細節**:
+
+- **Open-Meteo 對非拉丁字元命中率極差** — `language=zh` + `name=台北` 不會命中任何東西。實測 `name=Taipei&language=en` 完美回台灣的台北。解法:內建一份 25+ 個繁中 → 英文別名 dict(`weather.py` 的 `CITY_ALIASES`),對沒命中的輸入 fallback 走原名(這樣「Tokyo」「London」直接打也能命中)。
+- **不用 ConversationHandler** — 使用者只要打一次城市名就完成查詢,沒有對話狀態。CommandHandler + MessageHandler 兩個就 cover。
+- **輸出用純文字不用 Markdown** — Telegram Markdown 對 `*` `_` `` ` `` 等敏感,出錯時訊息顯示會亂掉。純文字最穩。
+- **共用 `httpx.AsyncClient`** — 透過 `application.bot_data` 注入,跨 handler 複用,避免每次 query 都重連。
+
+## 2. 架構
+
+```
+使用者傳訊息
+   │
+   ▼
+bot.py: text_handler
+   ├─ 丟 typing action
+   ├─ weather.geocode_city(city_name)   ← Open-Meteo geocoding API
+   │     └─ 試別名 → 試原名 → 都失敗拋 GeocodingNotFound
+   ├─ weather.fetch_current_weather(lat, lon, tz)   ← Open-Meteo forecast API
+   ├─ weather.format_weather_report(location, weather)  ← 純文字組裝
+   └─ reply_text(report)
+       └─ 任何例外都被 catch,回「⚠️ 查天氣失敗:...」給使用者,bot 不會 crash
+```
+
+### 2.1 模組職責
+
+- **`config.py`** (32 行) — `Settings` dataclass + `load_settings()` 從 env 讀 token,缺 token 直接 raise
+- **`weather.py`** (243 行) — 純天氣邏輯,沒有 Telegram 依賴,獨立可測
+- **`bot.py`** (199 行) — Telegram 組裝層:handlers、ApplicationBuilder、error_handler、post_init/post_shutdown
+- **`smoke_test.py`** (49 行) — 不需 Telegram 帳號,直接打 Open-Meteo 驗證
+
+### 2.2 為什麼這樣拆?
+
+`weather.py` 完全沒 import `telegram.*`,所以能寫 smoke test 不碰 Telegram。
+開發者在 CI 或本機沒 token 也能跑 `make smoke` 驗整條 pipeline。
+
+## 3. 錯誤處理策略
+
+- **token 缺失** — `load_settings()` 直接 raise RuntimeError,訊息明確告訴使用者怎麼設定
+- **城市找不到** — `GeocodingNotFound` (WeatherError 子類),handler 轉成「🔍 找不到城市...」
+- **Open-Meteo 連線失敗** — `WeatherError`,handler 轉成「⚠️ 查天氣失敗:...」
+- **未知例外** — `text_handler` 的最後 `except Exception` 兜底,log `logger.exception(...)`,使用者看到「發生未預期的錯誤」
+- **全域 error_handler** — `app.add_error_handler` 處理 PTB 內部丟出但沒被 handler 接住的錯誤,確保 bot 不會因為一個壞訊息就整個 polling loop 死掉
+- **typing action 失敗** — `send_action("typing")` 包在 try/except,失敗不影響主流程
