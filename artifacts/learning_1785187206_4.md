+# syshealth_monitor
+
+Linux 系統日誌與資源監控腳本 — 純 Python 3 stdlib,零外部依賴。
+
+## 功能
+
+- **資源監控**:CPU、Memory、Disk、Load Average(讀取 /proc,不需要 psutil)
+- **日誌掃描**:journalctl (systemd) + /var/log fallback,統計近 N 分鐘的嚴重訊息數
+- **閾值警告**:雙層級(warning + critical),超標時輸出彩色人類報告 + 可寫入 alert log
+- **退出碼語意化**:`0` = OK,`1` = WARNING,`2` = CRITICAL
+- **JSON 模式**:`--json` 給 Prometheus / healthcheck / 其他監控系統直接吃
+- **守勢編程**:每條 IO 都有 try/except,跑不起來的檢查會回 SKIPPED 不會讓整支死掉
+
+## 快速開始
+
+```bash
+chmod +x syshealth_monitor.py
+./syshealth_monitor.py                    # 預設閾值,人類可讀輸出
+./syshealth_monitor.py --json             # JSON 輸出
+./syshealth_monitor.py --cpu-warn 70      # 客製 CPU 閾值
+./syshealth_monitor.py --alert-log /var/log/health.alert
+```
+
+## 預設閾值
+
+| 指標 | 預設 warning | 預設 critical |
+|------|--------------|---------------|
+| CPU 使用率 | 80% | 90% |
+| Memory 使用率 | 85% | 95% |
+| Disk 使用率 | 90% | 95% |
+| Load / CPU (1min) | 1.5 | 2.25 |
+| 系統日誌錯誤數 / 5min | 25 | 50 |
+
+所有閾值都可以 CLI flag 或環境變數覆寫(見 `--help`)。
+
+## 退出碼
+
+`syshealth_monitor` 結束時回傳 `0 / 1 / 2`,適合搭配 cron、systemd timer、容器 healthcheck:
+
+```bash
+# Dockerfile HEALTHCHECK 範例
+HEALTHCHECK --interval=5m --timeout=10s --retries=3 \
+  CMD python3 /usr/local/bin/syshealth_monitor --json --no-color || exit 1
+```
+

+## 實作思路
+
+### 1. 設計目標
+- **零外部依賴**:用 Python 3 stdlib + `/proc/*` 直讀,任何 Linux 都能跑(不需要 pip install psutil)
+- **可觀測性優先**:同時支援人類可讀報告 + JSON 輸出 + alert log 寫入
+- **雙層級閾值**:warning + critical,退出碼語意化(0/1/2),可直接餵 docker HEALTHCHECK 或 systemd NotifyState
+
+### 2. 監控面設計(五大檢查項)
+
+| 檢查項 | 資料源 | 演算法 |
+|--------|--------|--------|
+| CPU 使用率 | `/proc/stat` 雙取樣 | Δtotal/Δidle,需要 0.5s 取樣間隔 |
+| 記憶體 | `/proc/meminfo` | (Total - Available) / Total |
+| 磁碟 | `os.statvfs` | (Blocks - Free) / Blocks |
+| Load Average | `/proc/loadavg` + CPU 核心數 | load1 / cpu_count(看 per-cpu,不是絕對值) |
+| 系統日誌 | `journalctl` + `/var/log/*` | 嚴重等級關鍵字計數(crit/error/fail) |
+
+每個檢查項獨立成 `check_xxx()` 函式,回傳 `CheckResult` dataclass,**易於擴充**(未來加 swap/IO/network/Failed systemd unit 都只要寫一個函式)
+
+### 3. 錯誤容忍策略
+- `/proc/*` 不存在 → 回 SKIPPED 不 crash
+- `journalctl` 不在(沒 systemd) → 自動走 /var/log
+- alert log 路徑無寫權 → stderr 寫一行警告,主流程繼續
+- KeyboardInterrupt → 退出碼 130(標準慣例)
+- 任何未預期例外 → 退出碼 1 + stderr 印錯誤
+
+### 4. 日誌掃描口徑(踩過的坑)
+**第一版設計缺陷**:用 `/var/log/*` 檔案內文全文 grep crit/error 關鍵字,結果遇到 syslog 累積到 25k+ 歷史錯誤就全算進來。
+
+**修正**:加入 `mtime` 視窗判定 — 只有「在 `now - since_minutes` 之後被寫入」的檔案才算「近期」,太舊的檔案視為歷史,但仍列入 `files_scanned` 供診斷。
+
+**已知後續限制**:syslog 檔案如果持續被 rotate 寫入新訊息,mtime 永遠在視窗內,目前用「cron 每 5 分鐘跑」自然收斂這個問題。完整 streaming line-aware 解析需要 inotify + tail-following,超出本任務範圍。
+
+### 5. 退出碼用途
+- `0` OK → cron 用 `||` 就能判斷觸發通知
+- `1` WARNING → 進入 PagerDuty/Telegram 的 medium severity
+- `2` CRITICAL → 直接呼叫 + 自動 restart 候選
+
+JSON 模式可被 prometheus textfile collector 讀取,或送進 ELK / Loki。
+
+### 6. 可被擴充的方向(沒做、未來可加)

+- systemd unit Failed 偵測(`systemctl list-units --failed`)
+- 網卡流量 / connection count
+- Disk SMART / RAID state
+- 容器/Docker 健康檢查整合
