+# sysmonitor 實作思路 — Senior Architect Review
+
+> 任務：撰寫一個自動化檢查 Linux 系統日誌與資源的維運腳本，
+>      並在超過閾值時發出警告。
+
+---
+
+## 1. 設計取捨（為什麼這樣做）
+
+### 1.1 純 Python stdlib，零第三方依賴
+- **理由**：PEP 668 環境（system Python 不能 `pip install`），
+  任何 monitor 腳本都應該在裸 Python 環境能跑。
+- **副作用**：放棄 psutil、requests、PyYAML；改寫：
+  - `/proc/stat`、`/proc/meminfo`、`/proc/loadavg`、`/proc/mounts` 直讀
+  - `os.statvfs` 拿 inode
+  - `subprocess.run(["curl", ...])` 取代 requests
+  - 極簡 YAML parser fallback（只支援本工具需要的 subset）
+
+### 1.2 三層輸出（console + log file + webhook）
+- **console**：ANSI color 區分 severity，給人讀。
+- **reports/*.log**：純文字可 grep、給 log 收集器讀。
+- **reports/*.json**：machine-readable，可餵 ELK / Grafana / Prometheus。
+- **webhook**：選填；用 curl 走 stdin 帶 payload（避免 command-line 暴露 secret）。
+- **為什麼不寫 syslog**：syslog 是「對外廣播」應該由使用者明確啟用；先預留 `--section` 但不主動寫。
+
+### 1.3 兩階段閾值（warn / crit）
+- 符合人類直覺（綠/黃/紅）。
+- `crit` 同時也通過 `warn`，實作時直接比大小：
+  ```
+  if value >= crit: sev = "crit"
+  elif value >= warn: sev = "warn"
+  ```
+- **不選**三階段（info/warn/crit）— 太多 alert noise。
+
+### 1.4 Alert dedup / cooldown
+- **場景**：syslog 一秒可能噴出 100 條 `Failed password`，一秒鐘 alert 100 次反而是雜訊。
+- **解法**：每個 `rule::logfile` 在 `cooldown_sec` 內只發一次（預設 300s）。
+- **特例**：OOM killer / kernel panic 設 `cooldown_sec: 0`（不冷卻），每次都報。
+
+### 1.5 增量日誌掃描（state.json）
+- **不每次從頭掃**：N100 機器上 auth.log 可能 50MB+，重複掃很浪費。
+- **機制**：把每個 log 檔讀到的 byte offset 存到 `.log_state.json`，下次接續。
+- **rotate 偵測**：若當前 size < 上次 offset → 檔案被 rotate 了，從頭讀。
+
+### 1.6 兩種模式：單次 vs watch
+- **單次**（預設）：給 cron / systemd timer 用。
+- **--watch N**：給人類臨時監控。
+- **不提供 daemon 模式**：systemd 已經是更好的 daemon 方案，不要重造輪子。
+
