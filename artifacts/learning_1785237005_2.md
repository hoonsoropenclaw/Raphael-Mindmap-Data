+# Iteration Log — Linux 系統日誌與資源監控腳本
+
+## 任務
+自動化檢查 Linux 系統日誌與資源的維運腳本，並在超過閾值時發出警告。
+
+## 交付物
+- `monitor.py`（單檔、約 20 KB、純 Python 3 stdlib + psutil）
+
+## 設計決策
+
+### 為什麼選 Python 而不是 shell
+- 需要 JSON 輸出（給下游消費）→ Python 原生
+- 日誌 regex 處理 + rotation 容忍（.gz）→ Python `gzip` 內建
+- 結構化設定檔載入 → `json.loads` 比 shell 解析器穩
+- exit code、testable、stderr 警告容易做對
+- shell 在 gzip rotated log + boundary case 容易出錯
+
+### 為什麼用 psutil 而不是純 /proc
+- 環境已裝 psutil 7.2.2（驗證過）
+- 跨相容性（boot_time 在 macOS / Linux / Windows 行為不同）
+- 負擔最小（一個被廣泛使用的 lib）
+
+### 模組切分（單檔內部）
+1. **`collect_resources()`** — 一次性採集 CPU/RAM/Swap/Disk/Load/ProcessCount
+2. **`scan_logs()`** — 遍歷 `log_scan_paths`、自動處理 `.gz`、檔案過大時只掃尾段
+3. **`evaluate()`** — 純函式，把 snapshot + findings 對照 thresholds 產生 alerts
+4. **`render_report()`** — 組裝成 `Report` dataclass
+5. **`format_human()`** — 給人讀
+6. **`write_json_report()`** — 給機器讀
+7. **`write_syslog_line()`** — 給 syslog 收集器
+
+### 嚴重等級設計
+- `ok` / `warn` / `crit` 三層
+- `crit` 觸發條件：超過閾值的 105%~110%、或日誌錯誤 ≥ 10 條
+- exit code：`ok=0 / warn=1 / crit=2`（3 留給「設定錯誤 / 缺 psutil」）
+
+### 預設掃描日誌
+- `/var/log/syslog`（Debian/Ubuntu）
+- `/var/log/messages`（RHEL/CentOS）
+- `/var/log/auth.log`（Debian/Ubuntu SSH 登入）
+- `/var/log/secure`（RHEL/CentOS 對應）
+- `/var/log/kern.log`（核心 panic / OOM）
+
+### 預設關鍵字
+- error：`error|err|fail|failed|failure|panic|oom|segfault|denied`
+- warn：`warn|warning|deprecated|retry|timeout`
+
+### 旋轉日誌處理
+- 主檔 + `.1` rotated file 都會掃
+- `.gz` 自動用 `gzip.open('rt')`
+- 檔案 > 50 MB 時只掃尾段（最後 50 MB）避免 OOM
+- 沒讀取權限（journald-only 場景）→ 靜默跳過、不算 fail
+
+### Dry-run 設計
+- `--dry-run` → 不寫 JSON、不送 syslog
+- 預設行為 → 寫 JSON 到 `/tmp/monitor_report.json` + 送 syslog
+- 兩個行為可獨立關：`--no-syslog` / `--dry-run` / `--json-only` 互不衝突
+
+### Alarm sink 設計
+- **stdout**（人讀）：給互動查詢
+- **JSON 檔**（machine）：給外部 dashboard / Prometheus exporter
+- **syslog**（via `logger`）：給現有的 log 收集器（journald / rsyslog）
+
+### 為什麼不做「長期 daemon 模式」
+- 沒需求且增加複雜度（signal handling、graceful shutdown）
+- 用 `--interval N` 已經能在一個 process 內每隔 N 秒跑一次
+- 長期推薦用 systemd timer / cron 包 `python3 monitor.py --once`（最簡潔、最乾淨）
+
+## 使用方式
+
+### 一次性檢查（給 cron / systemd timer）
+```bash
+python3 monitor.py --once --json-output /var/log/monitor_report.json
+# exit code 0/1/2 可直接拿給 cron 通知
+```
