+# GitHub Trending Markdown Exporter
+
+A dependency-free Python 3 script that fetches GitHub Trending and emits a Markdown table.
+
+## Usage
+
+```bash
+python3 github_trending.py
+python3 github_trending.py --language python --period weekly --limit 10
+python3 github_trending.py --spoken-language zh --output trending.md
+```
+
+Options:
+
+- `--language`: programming language slug (for example `python`, `rust`)
+- `--period`: `daily`, `weekly`, or `monthly`
+- `--spoken-language`: ISO spoken-language code
+- `--limit`: 1–100 (default 25)
+- `--output`: write to a file; otherwise print to stdout
+- `--timeout`: HTTP timeout in seconds
+
+## Validation
+
+```bash
+python3 -m unittest -v
+python3 github_trending.py --language python --period daily --limit 5 --output trending.md
+```
+
+The scraper deliberately fails with a non-zero exit code if GitHub changes the Trending HTML structure, rather than silently producing an empty report.

+# Implementation Notes
+
+## Approach
+
+1. Fetch the public GitHub Trending HTML endpoint with a descriptive User-Agent.
+2. Parse each `article.Box-row` using narrowly scoped patterns matching repository path, description, language, stars, forks, and period-specific stars.
+3. Normalize HTML entities and whitespace, escape Markdown table delimiters, and render a deterministic table.
+4. Expose language, period, spoken-language, limit, timeout, and output path through `argparse`.
+5. Use Python standard library only, with bounded exponential retry and explicit errors when the upstream layout is unrecognized.
+
+## Design decisions
+
+- No GitHub token: Trending is a public HTML page and the GitHub REST API has no equivalent Trending endpoint.
+- No third-party parser dependency: deployment remains a single-file script on any Python 3.10+ host.
+- Loud structural failure: an empty parse returns exit code 1, preventing automation from publishing a misleading empty table.
+- Testable separation: fetching, parsing, rendering, URL construction, and CLI orchestration are independent functions.
+
+## Verification plan
+
+- Unit tests cover extraction, URL construction, Markdown escaping, table rendering, and changed/empty HTML behavior.
+- A live smoke test writes a real Markdown report and verifies it contains repository rows.
+- Python bytecode compilation catches syntax errors.
