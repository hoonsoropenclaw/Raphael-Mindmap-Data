+# Telegram 天氣機器人
+
+## 功能
+
+- 使用 Telegram long polling 接收文字訊息。
+- 使用免費 wttr.in JSON API 查詢城市天氣。
+- `/start`、`/help` 顯示使用說明；其他文字直接視為城市名稱。
+- 純 Python standard library，沒有第三方依賴。
+- 可用 `TELEGRAM_ALLOWED_USERS` 建立 user ID allowlist。
+- 支援 SIGINT/SIGTERM 優雅停止，並以 update_id + 1 正確推進 offset。
+
+## 設定與執行
+
+```bash
+export TELEGRAM_BOT_TOKEN='從 BotFather 取得的 token'
+# 可選：export TELEGRAM_ALLOWED_USERS='123456789,987654321'
+python3 telegram_weather_bot.py
+```
+
+請勿把 token 寫入程式碼、提交 Git 或貼到聊天記錄。
+
+## 使用方式
+
+在 Telegram 傳送 `台北`、`Tokyo` 或 `New York`。機器人會回傳目前天氣、溫度、體感、濕度與風速。
+
+## 注意
+
+本實作選 long polling，適合沒有公開 HTTPS 網域的主機。wttr.in 是外部免費服務，可能限流；程式會記錄錯誤並在 polling 失敗後延遲重試。

+# 實作思路與交付審查
+
+## 架構
+
+本次採用三個清楚的責任邊界：
+
+1. `http_json()`：集中處理 urllib HTTP、JSON 解碼、timeout 與可預期的網路錯誤。
+2. `weather()`：只負責呼叫 wttr.in、解析資料並產生中文回覆；它不依賴 Telegram，因此可獨立測試或改接其他入口。
+3. `TelegramBot`：只負責 Telegram API、long polling、訊息路由與回覆。
+
+## 關鍵決策
+
+- 使用 Python standard library，不引入 `requests` 或 Telegram framework；這個「文字 → 天氣 API → 回覆」流程不需要額外依賴。
+- 使用 long polling，避免 webhook 所需的公開 HTTPS endpoint。
+- 使用 `offset = update_id + 1`，避免重複處理更新。
+- token 從 `TELEGRAM_BOT_TOKEN` 讀取，不寫入原始碼。
+- 使用 allowlist（可選）降低未授權使用；輸入限制城市名稱最多 100 字。
+- 捕捉 SIGINT/SIGTERM，讓服務可被 systemd、Docker 或終端機正常停止。
+
+## 風險與限制
+
+- wttr.in 是免費外部服務，可能暫時不可用或限流；錯誤會轉成使用者可讀訊息，polling 會延遲 3 秒重試。
+- allowlist 是應用層保護，不取代 Telegram token 保密與主機安全。
+- 目前使用記憶體內狀態，重啟後 offset 會從 0 開始；Telegram 會重新提供 pending updates，正常情況下不會遺失訊息，但高流量場景應改用持久化 offset。
+
+## 驗收項目
+
+- Python 編譯檢查：`python3 -m py_compile telegram_weather_bot.py`
+- 靜態 import 檢查：只使用標準庫。
+- 離線行為測試：mock HTTP，驗證天氣解析、指令回覆、allowlist 與 offset。
+- 線上 smoke test：只有設定有效 `TELEGRAM_BOT_TOKEN` 後才執行 Telegram API / wttr.in 呼叫，避免把秘密寫入測試。
