+# Linux Monitor
+
+`monitor.py` is a dependency-free, cron/systemd-friendly health check for:
+
+- aggregate CPU utilization (two `/proc/stat` samples)
+- memory utilization based on `MemAvailable`
+- filesystem utilization
+- normalized one-minute load (`load1 / CPU count`)
+- systemd journal error entries in a configurable time window
+
+## Usage
+
+```bash
+python3 monitor.py --dry-run
+python3 monitor.py
+python3 monitor.py --log-file /var/log/linux-monitor.jsonl
+```
+
+Exit status is automation-friendly:
+
+- `0`: no alert
+- `1`: warning or unavailable metric
+- `2`: critical alert or fatal configuration/runtime error
+
+The script uses a thread pool for independent I/O probes, invokes `journalctl` with an argument list (never a shell), applies a 10-second subprocess timeout, distinguishes unavailable probes from a real zero count, and sets process `umask(077)` before creating output files. The small scalar YAML format avoids third-party dependencies; edit `thresholds.yaml` to tune values.
+

+# Review Queue — Linux Monitor

+## 實作審查
+
+### 目標
+建立一個不依賴第三方套件、可由 cron 或 systemd 執行的 Linux 維運檢查腳本，檢查 CPU、記憶體、磁碟、load average 與 systemd journal 錯誤，並以 exit code 與 JSON 輸出告警。
+
+### 架構思路
+1. 使用 Python standard library，避免部署時引入依賴。
+2. 以 `Metric` 與 `Alert` dataclass 將「讀值」和「判斷閾值」分離，方便未來接 webhook、Prometheus 或其他後端。
+3. 五個獨立 probe 透過 `ThreadPoolExecutor` 並發執行；單一 probe 失敗會轉為明確的 `error` metric，不會讓其他檢查結果消失。
+4. CPU 使用 `/proc/stat` 兩次取樣差分，避免瞬間值失真；記憶體使用 `MemAvailable`，比單純 `free` 更適合判定實際壓力；load 以 CPU 數正規化。
+5. `journalctl` 使用 argv list 呼叫、禁止 shell 展開，並設 10 秒 timeout；journalctl 不存在、失敗或 timeout 與「錯誤數為 0」明確區分。
+6. 閾值放在 `thresholds.yaml`，腳本使用小型 scalar parser，保持零第三方依賴。
+7. 告警等級：WARN / ERROR → exit 1；CRITICAL 或致命設定錯誤 → exit 2；正常 → exit 0。
+8. 啟動時設定 `umask(077)`，寫入 JSONL 後再強制 `chmod(0600)`，連既有 log 檔也不會維持過寬權限。
+
