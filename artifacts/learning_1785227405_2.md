+# syswatch
+
+> Linux 系統日誌與資源監控腳本 — 純 Python 3.10+ stdlib、零第三方依賴、5 分鐘裝好。
+
+`syswatch` 是一個輕量級維運工具，做四件事：
+
+1. **資源監控** — CPU% / 記憶體% / 根磁碟% / inode% / Load Average (per-CPU)
+2. **日誌掃描** — 優先讀 `journalctl`、沒有 systemd 時 fallback 追蹤檔案 (offset 持久化)
+3. **閾值告警** — 連續 2 次超標 → WARNING；連續 5 次超標 → CRITICAL (去抖動)
+4. **多通道輸出** — 終端彩色報告 + JSONL 持久化 log + 可選 webhook (Slack/Discord/通用)
+
+## 安裝
+
+```bash
+# 1. 系統安裝（推薦，要 root）
+sudo ./install.sh
+
+# 2. 立刻跑一次
+syswatch --once -c /etc/syswatch/config.yaml
+
+# 3. 持續跑（debug 用）
+syswatch --watch --interval 30
+
+# 4. 解除安裝
+sudo ./install.sh --uninstall
+```
+
+`install.sh` 會做：
+- 複製 `monitor.py` 到 `/etc/syswatch/`
+- 複製 `config.example.yaml` 為 `/etc/syswatch/config.yaml`
+- 建立 `/usr/local/bin/syswatch` wrapper
+- 註冊 `syswatch.service` + `syswatch.timer` (每 60 秒跑一次，OnBootSec=30s 開機後 30 秒第一次)
+
+## 不裝、直接跑
+
+```bash
+python3 monitor.py --once
+python3 monitor.py --watch --interval 60 -c config.example.yaml
+python3 monitor.py --check-config -c config.example.yaml
+python3 monitor.py --dry-run --once                          # 不寫 state
+python3 monitor.py --trigger-test cpu_percent --once         # debug：強制觸發
+```

+## 設計重點
+
+### 1. 純 stdlib
+- `subprocess` 跑 `journalctl` (timeout 5s 防爆)
+- `urllib.request` POST webhook
+- `pathlib` + `json` + `argparse` + `signal` + `dataclasses` + `collections.deque`
+
+### 2. 三層環境兼容
+- systemd 主機 → 用 `journalctl --since "60 seconds ago" -p warning --no-pager`
+- 容器 / 沒 systemd → 追蹤檔案 (`extra_log_files` in config) + `state/last_log_pos.json` 紀錄 byte offset
+- 都沒有 → `cpu/mem/disk/load` 仍可監控（資源監控完全不依賴 systemd）
+
+### 3. 去抖動 (De-bounce)
+- 同一 metric 連續 N 次超過閾值才升級（避免 spike 噪音）
+- WARNING: 連續 2 次
+- CRITICAL: 連續 5 次
+- 同級重複告警遵守 `alert_cooldown_sec` (預設 5 分鐘)
+
+### 4. State 持久化
+- `state.json` 用 atomic rename (`.tmp` → `real`) 寫入，避免半寫狀態
+- 還原時帶回 metric history → 跨重啟不會丟失 de-bounce continuity
+- scans.jsonl / alerts.jsonl 是 append-only machine-readable log
+
+### 5. 退出碼語意
+- `0` = 全部正常
+- `1` = 有 WARNING
+- `2` = 有 CRITICAL  (systemd OnFailure= 會觸發)
+- `3` = 環境/設定錯誤

+### 2.3 去抖動（De-bounce）
+連續 2 次超標 → WARNING；連續 5 次超標 + value ≥ crit_threshold → CRITICAL。

+### 2.4 State 持久化

+- 驗證：跑 6 次 trigger 不同 metric，state.json 顯示 history 真的累積

+### 2.5 退出碼語意（systemd-friendly）
+- `0` = 全部正常
