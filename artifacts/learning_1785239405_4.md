+#!/usr/bin/env bash
+# sysmonitor.sh — Linux system log + resource monitor with threshold alerts.
+#
+# Checks:
+#   1. CPU usage (instantaneous, sampled twice 1s apart for a meaningful delta)
+#   2. Memory usage
+#   3. Disk usage per mount point
+#   4. Load average (1-min) normalized per CPU
+#   5. journald error/priority<=3 line count since last run
+#   6. journald OOM kill events since last run
+#
+# Emits alerts to stderr + structured log file + optional webhook.
+# Designed for cron: idempotent, exits 0 on success even when warnings fire.
+#
+# Exit codes:
+#   0 = success (warnings may have fired; check stderr)
+#   1 = configuration / dependency error
+#   2 = critical threshold breached (still also emits alerts normally)
+#
+# Usage:
+#   sysmonitor.sh [--once] [--dry-run] [--config FILE] [--no-webhook]
+#
+# Modes:
+#   (default)   One full pass; designed for cron every 1-5 min
+#   --once      Same as default; explicit one-shot
+#   --loop SEC  Loop with sleep between passes (foreground; for testing)
+#   --dry-run   Print what would be done, never call webhook / write state
+#   --no-webhook Override WEBHOOK_URL from config
+
+set -Eeuo pipefail
+IFS=$'\n\t'
+
+# ---------- Paths & defaults ----------
+SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)"
+SCRIPT_NAME="$(basename -- "${BASH_SOURCE[0]}")"
+DEFAULT_CONFIG="${SCRIPT_DIR}/sysmonitor.conf"
+
+CONFIG_FILE="${DEFAULT_CONFIG}"
+DRY_RUN=false
+NO_WEBHOOK=false
+LOOP_SEC=0
+
+# ---------- Argument parsing ----------
+usage() {
+    cat <<EOF
+Usage: ${SCRIPT_NAME} [OPTIONS]
+
+Options:
+    --once            Run one monitoring pass and exit (default).
+    --loop SEC        Loop, sleeping SEC seconds between passes (foreground).
+    --dry-run         Print actions without side effects (no webhook, no state write).
+    --config FILE     Path to config file (default: ${DEFAULT_CONFIG}).
+    --no-webhook      Override config: suppress webhook delivery for this run.
+    -h, --help        Show this help and exit.
+
+Cron example:
+    */5 * * * * ${SCRIPT_DIR}/${SCRIPT_NAME} --once >> /var/log/sysmonitor.cron.log 2>&1
+EOF
+}
+
+while [[ $# -gt 0 ]]; do
+    case "$1" in
+        --once)            shift ;;
+        --loop)            LOOP_SEC="${2:-0}"; shift 2 ;;
+        --dry-run)         DRY_RUN=true; shift ;;
+        --config)          CONFIG_FILE="${2:-}"; shift 2 ;;
+        --no-webhook)      NO_WEBHOOK=true; shift ;;
+        -h|--help)         usage 0 ;;
+        *)                 printf 'ERROR: unknown option: %s\n' "$1" >&2; usage 1 ;;
+    esac
+done
+
+# ---------- Load config ----------
+if [[ ! -r "${CONFIG_FILE}" ]]; then
+    printf 'ERROR: config file not readable: %s\n' "${CONFIG_FILE}" >&2
+    exit 1
+fi

+## 監控項目
+| Check | 來源 | 計算方式 |
+|---|---|---|
+| CPU 使用率 | `/proc/stat` | 兩次 1s 採樣，計算 busy / total 比例 |
+| Memory 使用率 | `/proc/meminfo` | `(MemTotal - MemAvailable) / MemTotal` |
+| Disk 使用率 | `df -P` | 每個 mount 點（可用 `DISK_MOUNTS` 限定） |
+| Load average | `/proc/loadavg` | `load1 / nproc`（per-core 正規化） |
+| journald 錯誤數 | `journalctl -p err` | 自上次成功執行以來的 error/crit/alert/emerg 行數 |
+| journald OOM 事件 | `journalctl \| grep` | "Out of memory" / "oom-kill" / "Killed process" |

+## 嚴重程度分級
+- **0 = OK** — 在閾值以下，不觸發 alert
+- **1 = WARN** — 超過 `*_WARN` 閾值
+- **2 = CRIT** — 超過 `*_CRIT` 閾值

+整體（process exit code）：

+- `2` = 至少一個 check 達到 crit

+知道系統活了）。State 檔存 `last_alert_ts` 跟 `last_alert_level`。

+`--dry-run` 不寫 state、不送 webhook、不寫 log 檔，只把「會做什麼」

+## Bash 陷阱與設計選擇
+
+### 1. `IFS=$' \t\n'` 而非 `$'\n\t'`
+原本抄 defensive pattern 用 `IFS=$'\n\t'`（newline + tab only），結果
+`read -r user1 nice1 ...` 對 `/proc/stat` 的輸出完全無法按空白切開，
+整個 CPU 採樣解析失敗（`syntax error in expression`）。改成標準
+`IFS=$' \t\n'`（空白 + tab + newline），所有 array 跟 read 都正常。
+
+### 2. `usage()` 必須有 `exit`
+原本 heredoc 之後忘了寫 `exit "${1:-0}"`，結果 `--help` 時 `usage` 函式
+return 但 while loop 沒消耗掉 `--help` 這個 argv，無限重印 usage，
+產生 30+ MB 輸出。已修。
+
+### 3. `set -Eeuo pipefail` + `$(exit 1)` 會立刻中斷腳本
+bash 5.2 在 `set -e` 模式下，`x="$(exit 1)"` 會因為命令替換的 exit code
+非零而觸發立即終止。測試腳本原本寫 `out="$(...); rc=$?"` 在負面測試
+（如「壞 config 應該 exit 1」）會被這個機制搞壞。解法：包成 helper
+`run_capture`，內部用 `_out="$(...)" || _rc=$?` 顯式吸收失敗。
+**（這個現象在 bash 4.x 不一定出現——只在 5.x 才穩定觸發）**
