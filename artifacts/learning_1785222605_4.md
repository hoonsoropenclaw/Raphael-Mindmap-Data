+# OUTPUT — GitHub Trending 抓取器實作思路
+
+## 1. 任務目標
+寫一個自動化腳本，從 GitHub Trending 抓熱門 repos，輸出成 Markdown 表格。
+
+不需要 GitHub API token，直接抓 `https://github.com/trending` 公開頁面解析 HTML。
+
+## 2. 技術選型
+| 項目 | 選擇 | 原因 |
+|------|------|------|
+| 語言 | Python 3.12 | 環境已有 requests + bs4，不用裝新套件 |
+| HTTP | `requests` | 標準做法，設定 timeout 與錯誤處理簡單 |
+| HTML parser | `BeautifulSoup4` (html.parser) | 不用 lxml，html.parser 已足夠、不需 C 編譯相依 |
+| 輸出 | Markdown 表格 | GitHub README 原生支援、CLI 易讀、可直接 paste |
+
+**為什麼不用 GitHub REST API？**
+- API 需要 token，多一層 secret 管理
+- Trending 是 GitHub 公開頁面，`view-source` 即可拿，無 rate limit 顧慮
+- API 的 `/search/repositories` 雖可模擬 trending，但 sort 邏輯跟 Trending 不一樣，會失真
+
+## 3. 程式架構（單檔、4 個函式）
+
+```
+main()
+  ├─ fetch_trending(since, language)    → str HTML
+  │    └─ requests + 自訂 UA（GitHub 對裸 curl 會擋）
+  ├─ parse_repos(html)                  → List[dict]
+  │    └─ BeautifulSoup 解析 <article.Box-row>
+  │       ├─ 抓 h2 裡的 a[href^=/] → repo 名 + URL
+  │       ├─ 抓 p.col-9 → description
+  │       ├─ 抓 [itemprop="programmingLanguage"] → language
+  │       └─ _parse_count() × 2 → stars / forks
+  └─ render_markdown(repos, since, language) → str Markdown
+       └─ pipe table，| / newline 在 desc 都 escape
+```
+
+CLI 參數用 `argparse`：
+- `--since {daily, weekly, monthly}`（預設 daily）
+- `--language / -l`（可選，常見語言 slug 已在 `LANGUAGE_SLUGS` map）
+- `--top N`（預設 25，GitHub 一頁最多 25）
+- `--output / -o`（不指定就印 stdout）
+- `--timeout`（預設 30 秒）
+
+## 4. 實作過程踩到的坑
+
+### 坑 1：stars 欄位一直是 0
+**原因**：`_parse_count` 的 `href_pattern` 把 `/stargazers` 拼成 `/stargzers`（少了 `a`），所以 selector 完全抓不到。
+
+**修正**：直接 hardcode `"/stargazers"`（其餘 kind 才用 `f"/{kind}s"` 規則）。
+
+**驗證**：修完後 bitchat = 32,643 stars、imgui = 75,265 stars — 數字合理。
+
+### 坑 2：`datetime.utcnow()` DeprecationWarning
+**原因**：Python 3.12 把 `datetime.utcnow()` 標 deprecated，要求改用 timezone-aware 的 `datetime.now(timezone.utc)`。
+
+**修正**：`from datetime import datetime, timezone`，呼叫改成 `datetime.now(timezone.utc)`。
+
+### 坑 3：GitHub Trending 沒有 "stars today" 欄位
+**觀察**：舊版 GitHub Trending 頁每個 repo 旁邊會顯示 "1,234 stars today"（當日新增），但 GitHub 在 2024 年改版後**把這個欄位拿掉了**，頁面上只顯示 repo 的**累計 stars**。
+
+**決策**：就抓累計 stars 並老實標在文件/docstring 裡 — 這是 GitHub 端的限制，不是爬蟲 bug。沒去硬模擬「stars today」是誠實的做法。
+
+### 坑 4：daily 頁只有 15 個 repos
+**觀察**：今天抓 daily 只有 15 個，weekly/monthly 都有 25 個滿頁。
+
+**原因**：這是 GitHub 端的資料量問題，不是爬蟲問題。Trending 算法每天不保證滿 25 個。
+
+**驗證**：直接看頁面 HTML 就是 15 個 `<article.Box-row>`，沒被擋。
