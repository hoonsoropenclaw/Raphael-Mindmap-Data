+"""
+SQLAlchemy engine + session factory.
+
+Design choice: sync pattern (sessionmaker + def), per
+trial-and-error fastapi-sync-vs-async-pattern-20260727:
+- avoids 3 async pitfall categories (stale read / deadlock / expire_on_commit)
+- production-proven in Quote API (72 tests, 2026-07-27)
+- this service has no concurrent I/O waiting inside requests
+
+Dependency injection via yield Depends(get_db) — the session is closed
+after the request finishes, even on exception.
+"""
+from __future__ import annotations
+
+from typing import Iterator
+
+from sqlalchemy import create_engine
+from sqlalchemy.orm import DeclarativeBase, Session, sessionmaker
+
+from app.config import get_settings
+
+
+class Base(DeclarativeBase):
+    """SQLAlchemy 2.0 declarative base for all ORM models."""
+
+
+def _make_engine(url: str):
+    """Build the engine with SQLite-friendly settings.
+
+    For SQLite (file or in-memory test DB) we need check_same_thread=False
+    so FastAPI's threadpool can share the connection across requests.
+    For other DBs (Postgres in prod), normal pool settings.
+    """
+    if url.startswith("sqlite"):
+        return create_engine(
+            url,
+            connect_args={"check_same_thread": False},
+            pool_pre_ping=True,
+        )
+    return create_engine(url, pool_pre_ping=True, pool_size=5, max_overflow=10)
+
+
+settings = get_settings()
+engine = _make_engine(settings.database_url)
+SessionLocal = sessionmaker(
+    bind=engine,
+    autoflush=False,
+    autocommit=False,
+    expire_on_commit=False,  # safe default even for sync; mirrors async SOP lesson
+)
+
+
+def init_db() -> None:
+    """Create all tables. Idempotent — safe to call on every startup."""
+    # Import models so they register on Base.metadata before create_all.
+    from app import models  # noqa: F401
+
+    Base.metadata.create_all(bind=engine)
+
+
+def get_db() -> Iterator[Session]:
+    """FastAPI dependency: yield a session, close it on request end.
+
+    Using sync generator here is intentional — pair with `def` endpoints
+    (not `async def`) to avoid the event-loop deadlock trap.
+    """
+    db = SessionLocal()
+    try:
+        yield db
+    finally:
+        db.close()

+"""Rate limiting setup using slowapi.
+
+We rate-limit per remote IP on all /todos routes. slowapi ships with a
+Limiter object you attach to FastAPI via app.state.limiter + a custom
+exception handler, and decorate routes with @limiter.limit("N/minute").
+
+Why slowapi over a custom middleware: the integration with FastAPI's
+Request object is clean (the @limiter.limit decorator needs `request: Request`
+as a parameter) and it's the de-facto choice for FastAPI rate limiting.
+"""
+from __future__ import annotations
+
+from slowapi import Limiter
+from slowapi.errors import RateLimitExceeded
+from slowapi.util import get_remote_address
+from starlette.requests import Request
+from starlette.responses import JSONResponse
+
+from app.config import get_settings
+
+_settings = get_settings()
+
+# Per-IP limiter; storage is in-memory (suitable for single-process dev /
+# tests). For multi-process prod, swap storage_uri to redis://...
+limiter = Limiter(
+    key_func=get_remote_address,
+    default_limits=[f"{_settings.rate_limit_per_minute}/minute"],

+        headers={"Retry-After": str(getattr(exc, "retry_after", 60))},
+    )

+# Todo API
+
+A minimal FastAPI todo service with SQLite + per-IP rate limiting.
+
+## Quick start
+
+```bash
+python3 -m venv .venv
+source .venv/bin/activate
+pip install -r requirements.txt
+
+# Run the server
+python -m uvicorn app.main:app --reload
+
+# Open docs
+open http://127.0.0.1:8000/docs
+```
+

+
+```bash
+source .venv/bin/activate

+17 tests cover happy-path CRUD, validation (422), 404s, filtering,

+|---|---|---|

+## API surface
+
+| Method | Path | Description |
+|---|---|---|
+| GET | `/health` | Liveness probe |
+| POST | `/todos` | Create a todo |
+| GET | `/todos` | List with `?completed=`, `?priority_min=`, `?limit=`, `?offset=` |
+| GET | `/todos/{id}` | Fetch one |
+| PATCH | `/todos/{id}` | Partial update |
+| DELETE | `/todos/{id}` | Delete (204) |
+
+## Design notes
+
+- **Sync SQLAlchemy, not async.** Per `trial-and-error/references/by-category/fastapi-sync-vs-async-pattern-20260727.md` — async adds 3 pitfall categories (stale read, deadlock, `expire_on_commit`) with no benefit for a CRUD service like this.
+- **SQLite by default**, but the engine factory supports any SQLAlchemy URL. Switch `TODO_DATABASE_URL` to Postgres in prod.
+- **slowapi for rate limiting.** Per-IP via `get_remote_address`, enforced by `SlowAPIMiddleware` (which reads `app.state.limiter.default_limits`). 429 returns JSON + `Retry-After`.
+- **Tests use StaticPool** so an in-memory SQLite shares state across sessions in a single test.
+
+See `IMPLEMENTATION_NOTES.md` for the full design rationale, decisions, and tradeoffs.

+# Todo API — Implementation Notes
+
+**Task**: Build a small FastAPI todo service with SQLite + rate limiting + unit tests.
+**Date**: 2026-07-28
+**Location**: `learning_1785196806_14/todo-api/`
+**Final state**: 17/17 tests passing, server boots cleanly, smoke test (POST/GET/PATCH/DELETE) works end-to-end with `X-RateLimit-*` headers in the response.
+
+---
+
+## 1. Architectural decisions
+
+### 1.1 Sync SQLAlchemy (not async) — the headline decision
+
+This is the single most important choice. Before writing a line of code I read two trial-and-error references:
+
+- `fastapi-sync-vs-async-pattern-20260727.md` — Cycle 549 (2026-07-27) decision analysis
+- `fastapi-async-session-pitfalls.md` — the 3 async pitfall categories
+
+**Decision: sync `sessionmaker` + `def` endpoints.**
+
+The 3 async pitfall categories I'd otherwise be walking into:
+
+| # | Pitfall | What would happen here |
+|---|---------|------------------------|
+| 1 | Stale read | `yield Depends(get_db)` returns the same `AsyncSession` for the whole request — identity map caches. If a request reads a todo, then mutates it, the second read returns the old object. Avoidable with `await db.refresh()`, but easy to forget. |
+| 2 | Async/sync deadlock | `async def` endpoint + sync `sessionmaker` = blocks the event loop. 100 concurrent users freeze the server. Confirmed in GitHub FastAPI Discussion #6628. |
+| 3 | `expire_on_commit=False` | After `await db.commit()`, lazy-loaded relationships (`todo.user.posts`) raise `DetachedInstanceError`. Standard fix is one config flag, but it's another "must remember" item. |
+
+**Evidence the sync path works**: `permanent-projects/quote-api/` has 72 tests passing on the same pattern. This is a battle-tested template.
+
+**When async would be the right call**: this service has no concurrent I/O waiting inside requests (no external API calls, no long polling). The async benefit is "many concurrent external calls inside one request" — we don't have that. Therefore: sync wins on simplicity, sync wins on safety, sync wins on this service's shape.
+
+### 1.2 Rate limiting with `slowapi` + `SlowAPIMiddleware`
+
+Tried first without the middleware. The first test run showed that `default_limits=[100/minute]` was a no-op because **nothing was reading it**. `slowapi` only enforces `default_limits` when you install `SlowAPIMiddleware` OR put `@limiter.limit("...")` on each route.
+
+Chose the middleware path because:
+- One place to set the policy (not per-route)
+- Same default applies to all routes consistently
+- Swapping limiters in tests is a one-line `app.state.limiter = test_limiter`
+
+**Key learning**: `Limiter._default_limits` is a list of `LimitGroup` objects, not raw strings. You cannot mutate it post-construction. The only ways to change limits at runtime are: (a) new Limiter instance + swap `app.state.limiter`, or (b) per-route `@limiter.limit()` decorator.
+
+### 1.3 SQLite for the default DB
+
+- Zero infra to run the project (no Postgres install)
+- Production switch is one env var: `TODO_DATABASE_URL=postgresql+psycopg2://...`
+- The engine factory in `app/db.py` is polymorphic: SQLite gets `check_same_thread=False`, other DBs get a connection pool.
+
+### 1.4 Test isolation: `StaticPool` + dependency override
+
+**First design** I considered was `:memory:` SQLite + `app.dependency_overrides[get_db]`. The trap: `:memory:` SQLite gives **each connection its own database**, so different sessions in the same test see different data. The fix is `StaticPool` (keeps one connection alive for the test's lifetime). This is documented in the async pitfall reference, even though we're sync — same root cause.
+
+**Autouse fixture `reset_rate_limiter`**: slowapi's `Limiter` is process-global. Without reset, tests run in order, the storage accumulates, and the 7th test in a session gets a 429 it shouldn't. Reset is cheap.
+
