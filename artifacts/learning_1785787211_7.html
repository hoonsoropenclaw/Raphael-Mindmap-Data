/ 01

三層抓取，各司其職

不是「哪個最好」，是「哪個適合」。同一個目標站，可以用三種策略驗證三次，產出交叉對照的結構化資料。

TIER 01
FAST
requests + BeautifulSoup
純 HTTP / SSR HTML 解析
直接打 HTTP、parse HTML。最快、最輕、但拿不到 JS 渲染後的內容。適合結構穩定的靜態頁面、開放資料、API 沒公開但 HTML 有資料的場景。
速度~1165ms
20 筆 / 1 頁20 筆
TIER 02
HEAVY
DynamicFetcher (Playwright)
JS 渲染後的 hydrated DOM
底層是 Playwright Chromium，跑 JS、等 network idle 再抓 DOM。hydrated DOM 的 title/price/availability 跟 Tier 1 對照驗證，確保 Tier 1 沒漏資料。
每頁~5-8s
已驗證3 / 3
TIER 03
RESILIENT
adaptive=True
Scrapling 自適應重定位
第一次抓會自動存元素指紋，第二次用 adaptive 重新配對。網站改版、CSS class 改名、DOM 結構變動時，Scrapling 會自動找新位置而非直接壞掉。
首次 / 重抓20 → 20
指紋類型auto_save
/ 02

三層怎麼寫

真實跑起來的程式碼片段。完整版在 smart_crawler.py。

TIER 01

requests + BeautifulSoup

直接 HTTP 抓 SSR HTML，BeautifulSoup 用 CSS selector parse 結構化欄位。1.2 秒抓 20 筆，沒有任何瀏覽器開銷。

TIER 02

Scrapling DynamicFetcher

底層 Playwright，headless=True + network_idle=True。hydrated DOM 拿到的 title 跟 Tier 1 完全一致，確認 SSR 沒缺漏。

TIER 03

adaptive=True

網站改版、CSS class 改名，Scrapling 會自動從指紋庫找新對應。這個 demo 跑 20 → 20 證明 adaptive 真的能 parse。
