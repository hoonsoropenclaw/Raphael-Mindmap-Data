+#!/usr/bin/env bash
+# linux_health_monitor.sh — pure-bash Linux system log + resource monitor.
+#
+# Reads /proc-style and df-style snapshots, applies configurable thresholds,
+# prints a JSON report on stdout, and forwards the same payload to a
+# pluggable notifier. Designed for cron / systemd timer / on-demand use.
+#
+# All inputs are env-overridable so the same script is unit-testable without
+# touching a real host.
+#
+# Exit codes:
+#   0 = all metrics within thresholds (status OK)
+#   1 = one or more soft targets (status DEGRADED)
+#   2 = one or more hard thresholds breached (status WARNING)
+#   3 = invalid configuration / missing input file
+set -Eeuo pipefail
+shopt -s lastpipe

+# linux_health_monitor — IMPL_NOTES
+
+## Scope
+
+A self-contained Bash + Python 3 (stdlib only) monitoring script that
+checks four Linux operational signals and emits a structured report
+plus a pluggable notification when thresholds are breached.
+
+| Signal           | Source                           | Default thresholds (warn / degrade) |
+|------------------|----------------------------------|--------------------------------------|
+| CPU load (1 min) | `/proc/loadavg` vs `nproc`       | 80% / 60% of CPU count               |
+| Memory used      | `/proc/meminfo` (MemAvailable)   | 85% / 75%                            |
+| Disk used        | `df -P /` (overridable)          | 90% / 80%                            |
+| Log error rate   | configurable log file, last 60 m  | 10 errors / 2 errors                 |
+
+## Architecture
+
+- `linux_health_monitor.sh` (≈220 lines) — driver, config, threshold eval, JSON report.
+  - All inputs are environment variables so the same binary runs unit tests
+    and production without code branches.
+  - `set -Eeuo pipefail` + `shopt -s lastpipe` to keep defensive Bash.
+  - `parse_int` rejects non-numeric thresholds up front (exit 3 = config error).
+- `tests/test_linux_health_monitor.py` — three red-green TDD cases driving the
+  script with stub `/proc/meminfo`, `/proc/loadavg`, log file and `df` output.
+  Tests are fully hermetic; they never read the real host.
+
+## Threshold semantics
+
+Two severity tiers per metric:
+
+- `DEGRADED` (soft) → `exit 1`
+- `WARNING` (hard) → `exit 2`
+- none → `exit 0`
+
+Exit code 3 is reserved for configuration / file-access errors so a
+cron supervisor can distinguish "system is bad" from "monitor itself
+is broken."
+
+## Notification modes
+
+`NOTIFY_MODE` selects the sink:
+
+- `stdout` (default) — JSON to stdout, optional human summary when
+  `OUTPUT_FORMAT=text`.
+- `log` — append-only JSON line to `NOTIFY_LOG_FILE` (default
+  `/var/log/linux_health_monitor.log`).
+- `none` — silent except for the exit code, useful when piped to a
+  higher-level agent that only inspects the return code.
