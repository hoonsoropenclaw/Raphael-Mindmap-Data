+"""SlowAPI rate-limiter setup.
+
+We key on the remote IP address (X-Forwarded-For aware) so per-client
+quotas work even when behind a reverse proxy. Defaults to in-memory storage,
+which is fine for a single-process dev/test deployment.
+"""
+from __future__ import annotations
+
+from fastapi import Request
+from slowapi import Limiter
+from slowapi.util import get_remote_address
+
+
+def _client_key(request: Request) -> str:
+    """X-Forwarded-For first hop, else peer address."""
+    xff = request.headers.get("x-forwarded-for")
+    if xff:

+    )
+    session.add(todo)

+# Implementation Notes — Todo API
+
+## Stack & rationale
+
+- **FastAPI** for routing + dependency injection + auto-generated OpenAPI.
+- **SQLModel** = SQLAlchemy 2.x + Pydantic v2. Single source of truth for
+  the ORM model and the request/response schemas, less duplication than
+  keeping `Base` + `BaseModel` side-by-side.
+- **SlowAPI** for per-IP rate limiting. Chosen over a custom middleware
+  because it plugs into FastAPI's request lifecycle cleanly and ships
+  with a tested in-memory backend.
+- **SQLite** + SQLAlchemy `StaticPool` for tests so a single in-memory
+  database is shared between the lifespan hook (`init_db`), the dependency
+  override (`get_session`), and direct service-layer tests.
+
+## File layout
+
+```
+app/
+  __init__.py
+  config.py        # env-var driven Settings
+  database.py      # engine + get_session + init_db
+  models.py        # Todo / TodoCreate / TodoRead / TodoUpdate
+  services.py      # CRUD, framework-free (unit-testable)
+  rate_limit.py    # Limiter + XFF-aware key_func
+  main.py          # FastAPI app + routers + lifespan
+tests/
+  conftest.py      # engine + session + TestClient fixtures
+  test_services.py # 5 service-layer tests
+  test_api.py      # 6 end-to-end TestClient tests
+  test_rate_limit.py # verifies the limiter actually blocks
+requirements.txt
+```
+
+## Pitfalls hit during build (real, not theoretical)
+
+1. **`from __future__ import annotations` breaks FastAPI response_model**
+   in Pydantic v2. The module-level route decorator runs at import time,
+   so when a type hint is a forward string it can't find the class in the
+   module namespace — you get `PydanticUndefinedAnnotation`. Fix: drop
+   `from __future__ import annotations` from any module that defines
+   routes. Service modules are fine to keep it.
+
+2. **`sqlite://` in-memory SQLite + multi-connection = empty DB.**
+   The default connection-per-checkout model means each new connection
+   sees a fresh empty database. Two consumers (the lifespan hook creating
+   tables, the dependency override inserting rows) end up talking to
+   different databases. Fix: `poolclass=StaticPool` to pin a single
+   connection.
+
+3. **Test fixture had to swap the module-level `app.database.engine`.**
+   The lifespan hook calls `init_db()` with no argument, so it uses the
+   module engine. To make tests point at the per-test in-memory engine,
+   the fixture reassigns `app_db.engine` and restores it on teardown.
+
+4. **Rate limit state leaks between tests.** SlowAPI keeps an in-memory
+   counter keyed by `(limit_string, key_func, request_path)`. Without a
+   `limiter.reset()` call, the last `test_api` case had already burned
+   through several POSTs before `test_rate_limit` started counting.
+   Fix: `limiter.reset()` at the top of the rate-limit test.
+
+5. **Deprecation: `@app.on_event("startup")`.** FastAPI now prefers the
+   `lifespan` async context manager. Switched the project to it to avoid
+   the runtime warning.
