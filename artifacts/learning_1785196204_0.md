+# logwatcher 實作思路與技術決策
+
+## 任務定位
+建立一個 Linux 系統日誌與資源監控腳本，在超過閾值時發出警告。
+
+## 設計核心原則
+
+### 1. 零外部依賴
+- 純 bash + Python 3 stdlib + 標準 Linux 工具（df, free, journalctl, awk, grep, nproc）
+- 不依賴 yq、PyYAML、jq、coreutils 額外套件
+- 為什麼：Server 環境最小化，第三方套件常衝突；維運 script 改一支就壞整組
+
+### 2. YAML 設定檔（不是 shell 環境變數）
+- 巢狀結構、註解、範例齊全
+- 自寫 mini YAML parser（支援 nested block + flow mapping `{key: value}` + flow list `[a, b, c]`）
+- 比環境變數可讀、比專用 DSL 易學
+- 為什麼：環境變數 10 個以上就失控；YAML 是人手寫最直覺的格式
+
+### 3. 三級警告 + 抑制冷卻
+- `WARN` / `ALERT` / `CRITICAL` 三層嚴重度
+- 同一 `(check, target, level)` 在 `cooldown_minutes`（預設 30 分鐘）內只發一次
+- 為什麼：避免 log bomb — 一次 disk 慢掉會每 5 分鐘都打 webhook 刷爆 dashboard
+
+### 4. 並發鎖 + Graceful Degradation
+- `locks/watcher.lock` 防止 cron 重疊跑（10 分鐘 stale 自動清）
+- journalctl 失敗 → fallback 到 `/var/log/syslog`
+- 為什麼：cron 上一輪沒跑完，下一輪又跑會同時打 webhook
+
+### 5. Self-test 不需 root
+- 14 個內建測試，包含 YAML 解析、check 函式、stamp/lock 機制
+- `webhook_url: ""` 時自動跳過 webhook（測試友善）
+- 為什麼：使用者隨時能驗證 script 沒壞，不需 sudo
+
+### 6. 環境變數覆寫路徑（測試 / 多實例用）
+- `LOGWATCHER_STATE_DIR`, `LOGWATCHER_LOCK_DIR`, `LOGWATCHER_REPORT_DIR`, `LOGWATCHER_CONFIG`
+- 整合測試可以平行跑、不污染 production state
+- 為什麼：production 跟 staging 共用同一份 script、不同實例要隔離
