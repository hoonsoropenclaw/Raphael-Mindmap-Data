+
+## 2. 為什麼選純標準庫（不引入 requests + bs4）
+
+考慮過 `requests + beautifulsoup4`，但**拒絕**：
+1. **PEP 668 環境** → 安裝外部套件需要 venv，多一層依賴管理
+2. **任務簡單** → 標準庫 `urllib + re` 30 行就能解析 GitHub Trending 的固定結構
+3. **可獨立執行** → 腳本不需要任何 `pip install` 就能跑
+
+權衡：標準庫 regex 解析犧牲了「結構化語意」，換來「零依賴 + 永遠可跑」。在 GitHub Trending 這種固定結構的網頁上是值得的（事先用 curl 驗證 DOM、確認 regex 可靠）。
+
+## 3. DOM 結構探勘（regex 試誤紀錄）
+
+用 curl 抓 `https://github.com/trending?since=daily` 後，發現 15 個 `<article class="Box-row">`，每個 row 內含：
+
+| 欄位 | 取得方式 | 觀察到的細節 |
+|------|---------|------------|
+| `repo slug` | `<h2><a href="/user/repo">` | data-view-component 屬性夾雜，需 regex 容忍 |
+| `description` | `<p class="col-9 ...">` | 通常純文字、可空 |
+| `language` | `<span itemprop="programmingLanguage">` | 可空（如 shell-only repo） |
+| `total_stars` | `<a href="/x/y/stargazers">` 內數字 | ⚠️ **數字在 `<svg>` 之後**，regex 必須先 `re.sub` 移除 svg 才能抓到 |
+| `forks` | `<a href="/x/y/forks">` 內數字 | ⚠️ GitHub 舊版用 `/network/members`、新版用 `/forks`，regex 同時 match 兩者 |
+| `today_stars` | `<span>N stars today</span>` | 依 `--since` 參數變成 `today` / `this week` / `this month` |
+
+**試誤 1**：第一次 regex `href="/x/y/stargazers"[^>]*>\s*([\d,]+)\s*</a>` 沒命中。改用 `href="...stargazers"[^>]*>(.*?)</a>` + `re.sub` SVG 後才正確。
+
+**試誤 2**：以為 fork 連結是 `/network/members`（舊版），實際是 `/forks`。regex 用 `(?:forks|network/members)` 同時涵蓋兩個版本，向前相容。
+
+## 4. 架構
+
+```
+main()
+  ↓
+fetch_html(url)              ← urllib + 偽裝 UA
+  ↓
+parse_trending(html, since)  ← re.findall 切 rows
+  ↓
+_parse_row(row_html, since)  ← 每 row → Repo dataclass
+  ↓
+render_markdown(repos, since) ← markdown 表格
+```
+
+**模組化要點**：
+- `Repo` 是 `@dataclass`，支援 `asdict()` 直接轉 JSON（給 `--json` flag 用）
+- `fetch_html` 把所有 HTTP 錯誤（HTTPError / URLError / TimeoutError）統一包成 `RuntimeError`，main 只需要一個 try/except
+- 解析和渲染分離：未來要加 `render_html()` 或 `render_csv()` 只需要新增一個函式，不動 parser
+
+## 5. 邊界處理
+
+- **空 repo 列表**：輸出 `_No trending repositories found._` 而不是 crash
+- **沒 description / 沒 language**：表格顯示 `—`
+- **description 含 `|`**：escape 成 `\|` 避免破壞 markdown 表格
+- **description 太長**：截斷到 200 字 + `...`
+- **數字解析失敗**：`_to_int` 回傳 0，不拋例外
+- **HTTP 失敗**：stderr 印錯誤訊息 + exit code 1
+- **寫檔失敗**：stderr 印錯誤 + exit code 2（跟 HTTP 失敗區分）
