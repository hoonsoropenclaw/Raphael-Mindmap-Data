# 交付任務（兩組共用，逐字相同）

依 `SPEC.md` 實作一支 Python 指令列工具 `audit_contract.py`。

- 輸入：一個 JSON 檔（路徑由命令列參數指定）。
- 輸出：把 `{"findings": [{"slide_id": ..., "category": ..., "evidence": ...}]}`
  印到 stdout，並可選擇另外寫到 `--out` 指定的檔案。
- 結束碼：0 = 沒有發現；1 = 有發現；2 = 執行錯誤（訊息要可行動）。
- 只用 Python 標準函式庫。不得連外、不得讀環境變數、不得寫出輸出檔以外的任何路徑。
- 可重跑：同樣輸入跑兩次，輸出逐位元相同。

## 實作要求（重要）

1. **不得寫死任何特定頁面 id、特定數字或特定來源字串。** 所有規則必須能套用到任意頁面。
2. **不得假設同一個來源在兩處逐字相同。** 同一個來源宣告兩次時，兩處文字可能有標點、
   日期後綴或空白差異。請做正規化（去空白、統一全形標點、去掉括號內容與日期）後再比對。
3. **同義詞組以 SPEC.md 列出的為準**，但比對時要能容忍同一個詞在句中出現。
4. 時間配額的正則要能抓到「90 秒」「2 分鐘」「1.5 分鐘」「二秒」這類寫法，
   但不能把「分成三部分」這種出現「分」字的普通句子誤判成時間配額。
5. `evidence` 必須是可在輸入檔中回頭定位的原始文字片段。
6. 錯誤訊息要指出是哪個檔、哪個欄位有問題。

## 驗收方式（決定是否交付）

程式必須通過 `tests/test_contract.py`：

- 在 `deck_fixture_sample.json` 上跑，輸出的 `findings` 必須與 `truth_sample.json` 完全一致
  （slide_id 與 category 的集合相同，且不得多報乾淨頁）。
- 同一支程式跑兩次，輸出必須逐位元相同。
- 對壞掉的輸入（檔案不存在、JSON 格式錯誤、slides 不是陣列）必須回 2 且有可行動訊息。

**測試決定是否交付**：測試沒過就修到過；不要為了讓測試能過而把規則寫死。
