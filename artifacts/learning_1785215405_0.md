+## 2. 設計決策（為什麼這樣切）
+
+### 2.1 一次跑一次 vs 常駐 daemon
+**選 Type=oneshot + systemd timer。** 原因：
+- 不搶 PID / 不怕 crash 沒人發現
+- 每次跑都是新狀態、不會累積內部狀態錯誤
+- systemd 本身就管 lifecycle（journal / restart / boot-after）
+- **反對的方案**：用 `while true; do` + `nohup` 自己跑（會和 systemd 搶資源、crash 沒人知道）
+
+### 2.2 純 stdlib
+**沒有 pip 任何套件。** 原因：
+- SOUL.md 強調 PEP 668 環境用 venv/uv
+- 監控腳本本身是系統信任基礎，多裝一個 pip 套件 = 多一個攻擊面
+- 全部用 `subprocess` + `urllib` + `/proc` + `os.umask`/`shutil.disk_usage`/`os.getloadavg` 都夠

+### 2.3 不是「grep 整個 /var/log/*

+- 同個問題連續觸發時不會洗版

+- cooldown 用 `state.json` 持久化、跑 cron 不會重置
