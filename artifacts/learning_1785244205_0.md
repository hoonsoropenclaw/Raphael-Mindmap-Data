+任務：撰寫一個自動化腳本，抓取 GitHub 上的 trending repositories 並輸出成 markdown 表格。
+
+## 技術選型
+
+### 為什麼 HTML scrape 而不是 API
+
+- GitHub **沒有提供** Trending 的官方 REST/GraphQL API
+- 公開頁面 `https://github.com/trending` 是 server-rendered HTML（一個 `<article class="Box-row">` per repo），不需要 JS 執行
+- 第三方服務（如 `https://api.gitterapp.com/redmine/`、`github-trending-api.de.a9sapp.eu/`）歷史紀錄都不穩定，且可能違反 GitHub TOS
+- 因此：**純 stdlib `urllib` + `html.parser`** 是最穩健、最少依賴的選擇
+
+### 為什麼用 stdlib `html.parser` 而不是 `BeautifulSoup`
+
+- 不增加依賴（Python 3.12 stdlib 已夠）
+- `html.parser` 是 streaming、token-based — 不會被中間的奇怪字元搞壞
+- 我只需要 4 個欄位（path / description / language / stars_today），其他都是雜訊
+
+### 為什麼不用 GitHub API（`/search/repositories`）
+
+- `/search/repositories` 不能按「trending」篩選
+- 即使可用，也需要 `GITHUB_TOKEN`（5000 req/hour 匿名、5000/hr authed）— 但 trending 這種短時間高頻請求容易被 rate-limit
+- 公開 trending 頁面**不需要任何 token**
+
+## 實作過程中的關鍵發現
+
+### 1. 頁面結構（HTML scrape 的契約）
+
+每個 repo 在 `<article class="Box-row">` 內：
+- **Repo path**（owner/name）：出現在所有 `<a href="/owner/repo">` 連結中（但要過濾掉 `/login`、`/sponsors`、`/apps` 等非 repo 連結）
+- **Description**：`<p class="col-9 ...">...</p>`
+- **Language**：`<span itemprop="programmingLanguage">...</span>`
+- **Stars today/week/month**：`<span class="d-inline-block float-sm-right">` 內含 SVG + 文字「`412 stars today`」
+
+### 2. 「stars today」抓取踩坑（記下來）
+
+第一次寫 `_row_depth == 2`（限制只在直接子標籤）→ 失敗，因為 stars span 被外層 layout div 包了，深度是 5-6
+第二次放寬到「任何深度」 → 但 stars span 內有 `<svg>` icon，`html.parser` 會把 SVG path data 也加到 capture buffer，導致 regex 不 match
+第三次解法：用 `_capture_depth` 追蹤 capture 起始深度，`handle_data` 只在 `row_depth == capture_depth` 時累積 — SVG 進入時 depth 變 3 != 2，所以 path 不會被加；SVG 關閉後 depth 回到 2，「412 stars today」就會被加
+
+### 3. URL pattern 的兩個誤區
+
+| 誤區 | 正確 |
+|---|---|
+| `?spoken_language_code=python` 過濾語言 | 這是 **natural language**（zh-CN、ja、ko）不是程式語言 |
+| `&language=python` 過濾語言 | 對 trending 來說也不對 |
+| `?since=weekly&language=python` | ❌ |
+| `/trending/python?since=weekly` | ✅ 正確 path-based filter |
+
+### 4. Wording 會隨 since 變
+
+- `since=daily` → 「412 stars **today**」
+- `since=weekly` → 「2,738 stars **this week**」
+- `since=monthly` → 「24,315 stars **this month**」
+
+regex 用 `^([\d,]+)\s+stars?\s+(today|this\s+\w+)$` 同時涵蓋三種。
+
+## 程式設計重點
+
+| 決策 | 為什麼 |
+|---|---|
+| `Repo` 用 `NamedTuple` | 不需要 mutable、欄位語意清楚、可直接 `_asdict()` |
+| `--output -` 預設 stdout | 跟 Unix 慣例一致；用 `>` 重導向即可 |
+| `--format {markdown, json}` | markdown 給人類看、json 給程式串接（cron / 排程 / dashboard） |
+| `urllib.parse.quote` 處理 language 參數 | 防 URL injection（雖然 trending 語言名都很簡單） |
+| `getattr(self, "_capture_depth", self._row_depth)` | 向後相容：若 `_capture_depth` 從未設定（舊 caller）預設用當前 depth |
+| 不寫 .pyc cache、不需要 .env | 完全無狀態、無 secret、無配置檔 |
