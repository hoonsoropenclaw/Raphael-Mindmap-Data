+## 設計重點
+
+- **不需 GitHub token**(github.com/trending 是公開頁面)
+- **失敗可重試**: 指數退避(2s → 4s), 最多 3 次
+- **markdown 表格 escape**: 自動處理 `|`、換行(表格 cell 不允許真實換行 → 統一成空格)
+- **selector 容錯**: 用屬性子串匹配(`p[class*="col-9"]`),不寫死精確 class 名 → GitHub 把 `pr-4` 改成 `tmp-pr-4` 之類的細節變動不會炸腳本
+- **CLI 友善**: argparse, `--help` 完整
+
+## 為什麼不用 GitHub API
+
+| 方案 | 抓法 | 跟 trending 的關係 |
+|---|---|---|
+| **A. HTML 爬蟲(本工具)** | GET github.com/trending | **就是真實 trending 頁**,source of truth |
+| B. Search API | `search/repositories?q=created:>...&sort=stars` | 只能近似「最近最受歡迎的新 repo」,**不等於 trending 排序** |
+
+## 為什麼不用 `gh-trending` 等套件
+
+- 多一層依賴, 底層還是爬 HTML → 結構變動時 debug 更遠
+- 自己寫 200 行可控、可讀、selector 容錯, 勝過套件
+

+
+```
+fetch_github_trending.py   # 主腳本(單檔, 標準庫 + requests + bs4)
+output/                    # 預設輸出目錄,trending_<period>_<timestamp>.md
