🧩 架構分層 (Implementation Notes)

透明交付:採用的微技能、設計權衡、未實作範圍。

微技能重用

  • ✅ calendar_integration_and_workflow_management — OAuth 流程、events.list mock、DAG 拓樸排序、simulation engine
  • ✅ rule_engine_declaration — Rule dataclass + AutomationEngine 結構
  • ✅ comprehensive_responsive_web_design — Flexbox/Grid 響應式佈局、@media 1023px 切換單欄
  • ✅ comprehensive_anti_patterns — 避免 sync → API 阻塞、避免無超時 polling

核心設計

  • 🎯 OAuth 2.0 Device Flow — N100 headless 唯一乾淨解
  • 🎯 DAG 拓樸排序 — 規則間有依賴時,DFS 避免無窮遞迴
  • 🎯 tearDown 訂閱模型 — monitor.subscribe(rule, handler) 避免輪詢
  • 🎯 shimmer 進度條 — 視覺化長時間操作

已知限制

  • ⚠️ 本頁是 demo 前端,不直接呼叫真實 Google/Telegram API
  • ⚠️ 規則匹配採 同步單執行緒,500+ 規則時建議改 worker pool
  • ⚠️ 派送目標僅 3 個示意群組,實際部署需串 webhook URL

未實作範圍

  • ❌ 真正的 OAuth Device Code polling (見 hermes-internal.md)
  • ❌ Google Calendar Push Notifications (watch API)
  • ❌ Telegram Bot long polling 與 inline keyboard
  • ❌ 持久化層 (本 demo 為記憶體)
