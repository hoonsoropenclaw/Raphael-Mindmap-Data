+寫一個 Telegram 機器人腳本，能接收文字並呼叫天氣 API 查詢天氣回傳。

+## 2. 技術選型理由
+
+| 項目 | 選擇 | 為什麼 |
+|------|------|--------|
+| 語言 | Python 3.12 | 環境已裝、`python-telegram-bot` 22.8 已就緒 |
+| 框架 | python-telegram-bot v22 | 環境已裝；用 asyncio 為基礎的 `Application` 架構（非舊版 Updater） |
+| 天氣 API | OpenWeatherMap `/data/2.5/weather` | 免費 tier 夠用；支援 `lang=zh_tw` 直接回傳中文 description |
+| HTTP | `requests` | 同步函式呼叫最直覺；用 `asyncio.to_thread` 丟到 thread pool 避免阻塞 event loop |
+| 設定 | `python-dotenv` + 環境變數 | 雙軌：開發期用 `.env`、部署期用 shell env；token 不入 git |
+
+## 3. 架構設計
+
+```
+┌──────────────────────────────────────────────┐
+│  Telegram Update (使用者按 /weather Taipei)  │
+└──────────────────┬───────────────────────────┘
+                   ▼
+        ┌──────────────────────┐
+        │  Application handler │
+        │  (註冊 4 個)         │
+        └──────┬───────────────┘
+               │
+   ┌───────────┼───────────┬─────────────┐
+   ▼           ▼           ▼             ▼
+/start       /help       /weather   fallback(純文字)
+   └───────────┴───────────┴─────────────┘
+                       │
+                       ▼
+           ┌──────────────────────┐
+           │  asyncio.to_thread   │  ← 避免阻塞
+           │  fetch_weather()     │
+           └──────┬───────────────┘
+                  ▼
+        ┌──────────────────┐
+        │  OpenWeatherMap  │
+        │  REST GET        │
+        └──────┬───────────┘
+               ▼
+       ┌─────────────────┐
+       │  狀態碼分層處理  │
+       │  200/401/404/   │
+       │  429/5xx/Timeout │
+       └────┬────────────┘
+            ▼
+      ┌────────────────┐
+      │ Telegram 回傳  │
+      │ Markdown 訊息  │
+      └────────────────┘
+```
+
+關鍵設計決策：
+
+1. **`asyncio.to_thread` 包裝同步函式** — `requests` 同步，若直接在 `async def` 裡 `await requests.get(...)` 會卡住 event loop。丟到 thread pool 是 PTB 社群建議做法。
+2. **HTTP 狀態碼分層** — 不是把所有非 200 都丟同一條「API 錯誤」訊息。401/404/429/5xx/Timeout 各有對應友善中文訊息，並 log 詳細錯誤供診斷。
+3. **城市名 regex 預過濾** — `^[\w\u4e00-\u9fff\s,.\-]{1,50}$` 擋掉奇怪輸入；早期 fail 不浪費一次 API 配額。
+4. **`drop_pending_updates=True`** — Bot 停機期間堆積的訊息不重送，避免重新部署時被過時訊息轟炸。
+5. **設定讀入後做 `preflight_check`** — 缺 token 直接 `sys.exit(1)`、不啟動 Application。失敗 fast 比啟動一半再爆好。
+6. **純函式 `fetch_weather` 與 Telegram handler 解耦** — 沒 telegram 物件依賴，可獨立測試（見驗證 3）。
